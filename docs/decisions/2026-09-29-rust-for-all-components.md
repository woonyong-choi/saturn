## 배경

Saturn은 공급자 연결을 맡는 엔진과 전체 화면을 그리는 화면으로 이루어졌다. 구성 요소 중 화면이 가장 큰 작업이었다. 화면의 요구는 Codex처럼 가벼운 전체 화면이었다. 2026-09-29에 MacBook Air에서 대화 없는 대기 상태의 메모리를 쟀다. Codex 0.158.0 본체는 약 55MB, Claude Code 2.1.284는 약 267MB였다. Codex 화면은 Rust의 `ratatui`와 `crossterm`으로 만들어졌고 Apache-2.0으로 공개되어 있었다. 판단 모델 학습은 MLX를 쓰기 때문에 Python이 필요했다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 모든 구성 요소 Rust, 학습만 Python | 네이티브 실행 파일, Codex 화면 코드와 `ratatui` 본보기 활용, 한 언어 관리 | 엔진과 화면 모두 비동기 Rust로 작성 |
| Kotlin/JVM과 JLine 화면 | JVM 라이브러리 생태계 활용 | JVM 런타임 동반, 화면 라이브러리 비교 조사와 GraalVM 네이티브 검토 필요 |
| 화면만 Rust, 엔진은 다른 언어 | 엔진 언어의 별도 선택 | 두 언어 관리 비용, 엔진 프로세스 메모리 추가 |

## 결정

모든 구성 요소 Rust, 학습만 Python을 골랐다. Codex 수준의 가벼운 화면, 한 언어 관리가 기준이었다.

## 결과

- 엔진과 화면의 타입, 라이브러리 공유
- Codex 코드 재사용 가능, 재사용 때 Apache-2.0 고지 유지
- 학습용 Python 환경 별도 관리
