## 배경

router 호출이 실패하면 입력을 대기로 보내고, 연속 3회 실패하면 새 입력 접수를 멈추는 규칙이 있었다. 새 패킷 규칙의 전환 품질 재측정에서 router 없이 순위 순서로 채운 패킷의 정답률은 20.6%로 패킷 없음(20.0%)과 같았다([재측정 결과](../experiments/handoff-packet-quality-v2/report.md)). 같은 측정에서 router 요청 실패는 0개여서 실패 빈도는 알 수 없다. 일시 실패는 다시 보내면 복구되고, router 장애가 사용자의 작업을 막지 않아야 한다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 5초 간격으로 두 번 다시 보내고 실패하면 판단 없이 현재 모델로 진행한다 | 일시 실패를 복구하고 장애 때도 입력과 전환이 멈추지 않는다 | 실패 때 모델과 처리 방식을 고르지 못하고 지연이 최대 10초 늘어난다 |
| 즉시 순위 순서로 채운다 | 전환 지연이 없다 | 실패 때 정답률이 패킷 없음 수준이다 |
| 재시도가 끝날 때까지 전환을 보류한다 | 판단 없는 패킷을 만들지 않는다 | router 장애 때 전환할 수 없다 |
| 순위 순서 대신 다른 판단 없는 규칙으로 채운다 | 지연이 없다 | 별도 측정이 필요하다 |

## 결정

5초 간격으로 두 번 다시 보내고, 10초가 지나도 실패하면 로그를 남기고 판단 없이 현재 모델로 진행한다. 판단 없는 패킷의 정답률, 전환 지연의 상한, router 장애 때 입력과 전환이 가능한지를 가장 중요하게 본다.

입력 처리 판단이 실패하면 입력을 대기로 보내지 않고 현재 에이전트와 현재 모델로 보낸다. `compact` 판단이 실패하면 router가 시작한 전환은 건너뛰고, 사용자가 고정했거나 맥락 크기 규칙이 시작한 전환은 순위 순서로 채운다. 연속 3회 실패는 입력 접수를 멈추지 않고 연결 끊김만 표시한다.

## 결과

- 일시 실패가 입력 처리와 전환을 막지 않는다.
- router가 시작한 전환은 판단 없는 패킷으로 이어 가지 않는다.
- 보낸 뒤 시간 초과도 다시 보내며, 처리됐을 수 있는 호출의 비용은 알 수 없다.
- 실패 때 모델 선택과 처리 방식 판단이 없어 입력에 맞지 않는 모델로 처리될 수 있다.

## 다시 볼 조건

- router 실패가 실측에서 자주 나타남
- 판단 없는 패킷의 정답률이 패킷 없음보다 높은 규칙이 측정됨
- 보낸 뒤 시간 초과의 재전송이 비용이나 중복 호출 문제를 일으킴
