# 판단 기록은 로컬에 쌓고 동의한 레코드만 서버로 올린다

| 항목 | 값 |
|---|---|
| 날짜 | 2026-09-29 |
| 상태 | 채택 |
| 대체 | 없음 |
| 관련 문서 | [아키텍처](../architecture.md), [router 학습](../design/router-training.md) |

## 배경

공용 Saturn 모델을 학습하려면 동의를 받은 여러 사용자의 판단 기록이 필요하다. 뒤집음, 취소, 실패 같은 사후 결과 신호는 사용자 컴퓨터에서 생긴다. Saturn 모델을 API 서버로 두면 판단 호출마다 상태가 서버로 간다. 판단 기록에는 사용자의 대화와 작업 폴더 내용 일부가 들어간다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 로컬 적재 뒤 동의한 레코드 업로드 | 오프라인 판단, 업로드 때만 동의 확인, 결과 신호를 레코드에 포함, 로컬 개인 어댑터 | 로컬 추론 속도에 좌우되는 지연, 업로드 경로 구현 |
| Saturn 모델 API 서버가 기록 | 서버의 기록 자동 집계 | 판단 호출마다 상태 전송, 시작 때 동의 필수, 오프라인 불가, 결과 신호 별도 전송, 사용자별 어댑터 서버 관리 |

## 결정

로컬 적재 뒤 동의한 레코드 업로드를 쓴다. 동의한 레코드만의 전송, 오프라인 판단을 가장 중요하게 본다.

## 결과

- `consent.share_with_server = true`인 레코드만 업로드, 동의 버전과 삭제 id 기록
- 삭제 요청 레코드는 다음 학습부터 제외
- 업로드 경로를 레코드 보내기 인터페이스 하나 뒤에 배치
- 원격 HTTP router도 붙는 router 연결 구조 유지
- 사용자 컴퓨터의 로컬 모델 실행 자원 부담

## 다시 볼 조건

- 로컬 판단 지연으로 입력 처리 지연
- 업로드 동의 레코드 수가 공용 학습에 부족
