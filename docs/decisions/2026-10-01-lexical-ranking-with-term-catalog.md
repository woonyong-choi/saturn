# 후보 순위는 임베딩 없이 단어 기반과 용어 카탈로그로 시작한다

| 항목 | 값 |
|---|---|
| 날짜 | 2026-10-01 |
| 상태 | 채택 |
| 대체 | 없음 |
| 관련 문서 | [맥락 고르기](../design/context-selection.md), [용어 카탈로그](../design/term-catalog.md) |

## 배경

후보 순위의 단어 겹침 채널은 같은 뜻의 다른 말과 한국어·영어 번역어를 찾지 못한다. 임베딩 모델은 글자가 겹치지 않아도 뜻이 가까운 글을 찾지만, 모델 파일을 배포하고 사용자 컴퓨터에서 실행해야 한다. 여러 검색 데이터셋을 비교한 BEIR(Thakur et al., NeurIPS 2021 Datasets and Benchmarks)는 BM25가 처음 보는 분야에서도 강한 기준선이고, 임베딩 기반 검색은 학습 분야 밖에서 BM25보다 약할 때가 있다고 보고한다. Saturn이 고르는 후보는 코드 식별자, 경로, 오류 문구가 많은 글이다. RRF는 순위 목록 수와 무관하게 같은 식으로 합친다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 단어 기반 채널과 용어 카탈로그로 시작 | 설치 즉시 동작, 모델 없음, 조회가 색인 한 번, 채널 추가가 RRF 목록 추가뿐 | 카탈로그에 없는 같은 뜻 누락, 카탈로그 성장에 기록 필요 |
| 임베딩 채널을 기본 포함 | 같은 뜻 전반 탐색 | 설치 크기 증가, 상주 메모리, 기록마다 임베딩 계산, core 밖 실행 필요, 이득 측정 전 |
| 임베딩을 따로 내려받는 선택 기능 | 설치는 가벼움 | 기능 경로 두 벌의 관리, 이득 측정 전 |

## 결정

단어 기반 채널과 용어 카탈로그로 시작하는 방식을 쓴다. 설치 즉시 쓸 수 있는 가벼움과 측정된 이득 없이 비용을 늘리지 않는 것을 가장 중요하게 본다.

## 결과

- 파일 겹침, 단어 겹침, 최근성 세 채널과 용어 카탈로그
- 기록에서 짝을 캐고 judge로 확인하는 카탈로그 성장
- 모델 배포와 상주 메모리 없음
- 카탈로그에 없는 같은 뜻의 누락
