# 같은 뜻 찾기는 router에 맡기고 용어 카탈로그를 두지 않는다

| 항목 | 값 |
|---|---|
| 날짜 | 2026-10-01 |
| 상태 | 채택 |
| 대체 | 대체한 결정: [후보 순위는 임베딩 없이 단어 기반과 용어 카탈로그로 시작한다](2026-10-01-lexical-ranking-with-term-catalog.md) |
| 관련 문서 | [맥락 고르기](../design/context-selection.md), [router](../design/router.md) |

## 배경

한국어 말과 영문 식별자처럼 글자가 겹치지 않는 같은 뜻은 단어 기반 순위 채널이 찾지 못한다. 이전 결정은 기록에서 용어 짝을 캐 카탈로그에 쌓는 방식으로 이를 메우려 했다. 짝 후보의 정밀도는 괄호 표기 1.5% [0.5, 4.3], 주석 아래 식별자 1.0% [0.3, 3.6], 같은 턴 함께 나옴 0.5% [0.1, 2.8]였다([실험 결과](../experiments/term-catalog-precision/report.md)). 작은 다국어 임베딩 모델 두 개의 짝 재현율은 0/60, 0.0% [0.0, 6.0]이었고 같은 뜻 질의의 상위 10개 재현율도 단어 기반 순위와 같은 0.0%였다. 설치 크기는 342.5MB 이상, 상주 메모리는 287.4MB 이상이었다([실험 결과](../experiments/embedding-synonym/report.md)). 사용자가 짝을 직접 고치는 방식은 두지 않는다. 한편 router는 후보 전체를 판단하므로 후보가 순위 상위에 들지 못해도 같은 뜻 판단은 router가 한다([결정 기록](2026-10-01-router-all-candidates.md)).

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 같은 뜻 찾기를 router에 맡기고 카탈로그 미도입 | 짝 저장소와 확인 질문 제거, 모델 배포 제거, 후보 전체 판단과 같은 경로 | router 전부 실패 때 대체 순서의 같은 뜻 누락 |
| 단어 기반 규칙으로 짝을 캐 카탈로그에 저장 | 조회가 색인 한 번 | 짝 후보 정밀도 0.5~1.5%, 오답 짝에 쓰는 확인 질문 |
| 임베딩으로 짝을 찾거나 순위 채널에 추가 | 글자가 겹치지 않는 뜻 탐색 | 짝 재현율 0.0%, 설치 342.5MB 이상, 상주 메모리 287.4MB 이상 |
| 사용자의 짝 직접 수정 | 확인된 짝만 사용 | 사용자 부담, 사용자 거부 |

## 결정

같은 뜻 찾기는 router가 후보 전체를 판단하면서 직접 하고 용어 카탈로그를 두지 않는다. 측정으로 확인된 정확도와 설치 비용, 사용자 부담 없음을 가장 중요하게 본다.

## 결과

- 용어 카탈로그 설계, 기록 저장소의 카탈로그 항목, `term` 질문 세트, `term_same`과 `term_reject` 기준값 제거
- 단어 조각에서 짝의 조각을 더하는 단계 제거
- 모델 배포와 상주 메모리 없음
- router가 모두 실패한 입력의 대체 순서에서 같은 뜻 후보 누락
