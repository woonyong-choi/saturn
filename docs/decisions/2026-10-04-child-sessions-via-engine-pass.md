# 하위 접속은 새 engine 대신 떠 있는 engine에 출입증으로 붙는다

| 항목 | 값 |
|---|---|
| 날짜 | 2026-10-04 |
| 상태 | 채택 |
| 대체 | 없음 |
| 관련 문서 | [하위 접속](../design/child-sessions.md), [engine 수명과 복구](../design/engine-lifecycle.md) |

## 배경

에이전트가 작업 중에 `saturn`을 실행하면 지금까지 거절했다. 에이전트가 Saturn에 일을 맡기고, 밖의 Claude나 Codex가 Saturn을 부르는 것을 허용하고 싶다. `engine`은 사용자당 하나이고 router 키는 `engine`만 쥔다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 떠 있는 engine에 출입증으로 접속 | engine 하나와 키 한 곳 유지, 범위와 상한을 engine이 지킴 | 출입증과 상한 구현 |
| 하위마다 독립 engine을 띄우고 결과 파일로 받기 | 구현이 단순 | 기록 저장소 쓰기가 둘, 키 전달 필요, 상한 없음 |
| 계속 거절 | 구현 없음 | 에이전트가 Saturn을 못 씀 |

## 결정

떠 있는 engine에 접속하게 하고 engine이 채팅마다 만든 출입증으로 하위 접속을 식별한다. 바깥 접속은 출입증 없이 사용자가 연 채팅과 같게 받는다. 상한은 부하 시험으로 정한다.

## 결과

- engine은 사용자당 하나, 쓰는 쪽도 하나로 유지된다.
- 하위 접속의 권한은 부모를 넘지 않고, 부모를 멈추면 함께 끝난다.
- 하위 채팅은 묻지 않고 거부하므로 부모가 `edit`이면 묻기 규칙에 걸리는 명령은 못 한다.
