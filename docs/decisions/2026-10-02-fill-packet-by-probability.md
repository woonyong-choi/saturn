## 배경

패킷의 경쟁 구역은 `compact` 판단의 남김 확률이 기준값 0.5 이상인 항목만 채웠다. 패킷 전환 품질 실험에서 `router-all` 패킷은 평균 1.6개 항목(867토큰)만 담아 예산 8,000토큰의 10분의 1만 썼다. 근거 항목 624개 중 549개(88.0%)가 0.5 미만이라 빠졌다. 근거 항목의 확률은 평균 0.372, 최댓값 0.65였고 비근거 항목 평균은 0.220이어서 확률은 둘을 잘 가른다(AUC 0.940). 같은 확률과 같은 예산으로 규칙만 바꿔 다시 계산하면 필요한 근거가 모두 든 질문이 기준값 0.5에서 11.7%, 기준값 0.3에서 53.4%, 기준값 없이 확률 순에서 65.6%였다. 근거가 패킷에 든 질문은 받는 쪽이 90.0%를 맞혔다([후속 분석](../experiments/handoff-packet-quality/report.md#후속-분석-원인)).

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 기준값 없이 확률 순으로 예산까지 채움 | 질문 단위 근거 포함 65.6%, 기준값 0.25 이하와 같은 포함률, 조정할 기준값 없음 | 패킷이 항상 예산까지 참, 예산에서 빠진 근거 항목 108개 |
| 기준값 0.5 유지 | 작은 패킷(평균 867토큰) | 근거 항목의 88.0%를 버림, 질문 단위 근거 포함 11.7% |
| 기준값을 0.3으로 낮춤 | 질문 단위 근거 포함 53.4% | 기준값이 router 확률 척도에 묶임, 근거 항목의 32.4%를 버림 |
| 확률 순에 최소 확률 0.1을 둠 | 기준값 없는 선택지와 같은 포함률 | 규칙이 하나 늘지만 걸러지는 항목은 5,520개 중 3개 |

## 결정

경쟁 구역을 기준값 없이 router의 남김 확률 순으로 예산이 찰 때까지 채운다. 항목의 확률은 호출과 결과 중 큰 값이고, 같은 확률이면 RRF 순, router 답이 없는 항목은 RRF 순으로 뒤에 둔다. 근거 포함률과 router 척도에 묶이지 않는 규칙을 가장 중요하게 본다.

## 결과

- 설정 `router.thresholds.compact_keep`과 `Thresholds`의 `compact_keep` 제거
- 확률이 낮은 항목도 예산 안에서 들어가는 경쟁 구역
- 원문, 축약본, 경로 형태 선택, 한 항목 상한 30%, 기록 번호 순 출력은 그대로
- 패킷이 항상 예산까지 차서 새 session의 입력 토큰 증가
- 받는 쪽 정답률 향상이 입력 토큰 증가를 넘는지는 재측정 필요

## 다시 볼 조건

- 패킷 크기 증가에 따른 입력 비용이 정답률 향상보다 커짐
- router를 바꾼 뒤 확률이 근거와 비근거를 가르지 못함(AUC 하락)
