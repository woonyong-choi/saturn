# 엔진만 판단기를 부르고 자식 프로세스 환경에서 판단기 키를 지운다

| 항목 | 값 |
|---|---|
| 날짜 | 2026-09-29 |
| 상태 | 채택 |
| 대체 | 없음 |
| 관련 문서 | [아키텍처](../architecture.md), [엔진 설계](../components/engine.md) |

## 배경

판단기는 입력마다 뜻을 판단하는 외부 API였고 키가 필요했다. 키를 환경 변수로 주면 공급자 자식 프로세스가 같은 환경을 그대로 받았다. 공급자와 하위 에이전트는 판단기를 부를 필요가 없었다. macOS `security` 명령으로 키체인에 저장하면 그 명령이 신뢰 앱이 되었다(2026-09-29 확인). 그러면 다른 프로세스도 같은 명령으로 확인 창 없이 키를 읽을 수 있었다(Silverfort 보고).

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 엔진 프록시, 키체인 OS API 저장, 자식 환경의 키 변수 제거 | 에이전트에 키 미전달, 저장 위치 보호 | 제거 목록과 훅 검사 유지 |
| 환경 변수로 키 전달 | 적은 구현량, 별도 저장소 없음 | 공급자와 하위 에이전트에 키 노출 |
| 암호문 파일 저장, 실행마다 암호 확인 | 운영체제와 무관한 동일 동작 | 실행마다 암호 입력 |

## 결정

엔진 프록시, 키체인 OS API 저장, 자식 환경의 키 변수 제거를 골랐다. 에이전트가 어떤 경로로도 키를 받지 않는 것이 기준이었다.

## 결과

- 판단기 호출 창구를 엔진 하나로 통일
- 자식 환경에 제거 목록의 이름이 없음을 테스트로 고정
- 제거 목록과 훅 검사의 유지 부담
