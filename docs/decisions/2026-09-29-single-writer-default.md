# 쓰기 에이전트는 기본으로 한 번에 하나만 실행한다

| 항목 | 값 |
|---|---|
| 날짜 | 2026-09-29 |
| 상태 | 채택 |
| 대체 | 없음 |
| 관련 문서 | [아키텍처](../architecture.md), [핵심 규칙 설계](../components/core.md) |

## 배경

무관한 새 입력은 새 작업으로 따로 실행될 수 있었다. 병렬 작업이 같은 작업 폴더에 쓰면 같은 파일을 동시에 고칠 수 있었다. 어떤 파일을 고칠지 미리 예측하는 방식은 추정이라 충돌을 막지 못했다. 작업의 권한은 입력을 접수할 때 정해졌다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 쓰기는 한 번에 하나(기본), 설정으로 worktree 방식 | 접수 때 권한으로 결정론 판정, worktree 방식에서 git 저장소 병렬 쓰기 | 쓰기 작업 대기 증가, worktree 합치기 때 사용자 확인 필요 |
| 파일 겹침 예측 뒤 병렬 실행 | 겹치지 않는 작업의 병렬 쓰기 | 예측 실패 때 같은 파일 동시 수정, 추정 기반 판정 |

## 결정

쓰기는 한 번에 하나(기본), 설정으로 worktree 방식을 골랐다. 추정이 아닌 결정론 판정이 기준이었다.

## 결과

- 읽기 전용 작업은 같은 폴더에서 병렬 실행
- 쓰기 작업은 쓰는 에이전트가 있으면 대기
- worktree 방식의 자동 병합 없음, git에 없는 파일은 누락 경고
- 쓰기 잠금 해제 기준을 트리 유휴로 통일

## 다시 볼 조건

- 쓰기 작업 대기 때문에 대부분의 사용자가 worktree 방식 사용
- 공급자의 파일 단위 잠금이나 충돌 감지 제공
