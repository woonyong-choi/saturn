# 반대 지시는 끼워 넣고, 끼워 넣을 수 없으면 사용자에게 멈출지 묻는다

| 항목 | 값 |
|---|---|
| 날짜 | 2026-10-03 |
| 상태 | 채택 |
| 대체 | 없음 |
| 관련 문서 | [입력 처리](../design/input-handling.md), [router](../design/router.md), [TUI](../design/tui.md) |

## 배경

실행 중인 작업과 반대되는 지시(`conflicts`)가 들어오면 하던 작업 다음으로 대기시켰다. 사용자는 작업을 되돌리려는데 반대 지시는 현재 작업이 끝난 뒤에야 반영된다. 반대로 충돌 판단이 틀렸을 때 멀쩡한 작업을 사용자 몰래 멈추면 작업과 수정 중인 파일이 중간 상태로 남는다. 멈춤은 사용자의 요청(`Ctrl+C`)만 하는 일이고, Claude Code와 Codex는 작업 중 입력을 진행 중인 턴에 넣는다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 진행 중인 턴에 끼워 넣고, 끼워 넣을 수 없으면 사용자에게 멈출지 묻는다 | 오판 때 작업이 멈추지 않고, 반대 지시가 다음 단계에 반영된다 | 끼워 넣기를 받지 않는 provider에서는 확인 전까지 작업이 계속된다 |
| 바로 멈추고 새 입력을 실행한다 | 잘못된 작업을 빨리 중단한다 | 오판이면 멀쩡한 작업이 사용자 몰래 멈춘다 |
| 모든 충돌을 사용자에게 확인한다 | 오판 손해가 없다 | 끼워 넣을 수 있는데도 매번 묻는다 |
| 대기를 유지한다 | 구현이 단순하다 | 반대 지시가 늦게 반영된다 |

## 결정

충돌로 판단한 입력은 진행 중인 턴에 끼워 넣는다. provider가 끼워 넣기를 받지 않으면(지원하지 않거나 거절) 입력을 대기열 맨 앞에 두고 `지금 멈추고 새 입력을 실행할까요?`를 묻는다. 오판 때 손해의 크기, 사용자 몰래 멈추지 않는 것을 가장 중요하게 본다.

`멈추고 실행`은 기존 멈춤 규칙으로 채팅을 멈춘 뒤 그 입력이 붙은 작업을 재개해 입력을 실행하고, `대기`는 맨 앞 대기를 그대로 둔다. 충돌이 아닌 입력은 확인 없이 기존 규칙(거절되면 맨 앞 대기)을 따른다.

## 결과

- 충돌 판단이 틀려도 작업이 멈추지 않고 모델이 다음 단계에서 입력을 읽고 방향을 정한다.
- engine은 사용자의 답 없이 멈추지 않는다.
- 끼워 넣기를 받지 않는 provider에서는 답이 오기 전까지 작업이 계속된다.
- 충돌을 잘못 판단해도 입력이 하던 작업에 더해질 뿐이라 손해가 작다.

## 다시 볼 조건

- 충돌 입력의 끼워 넣기가 실측에서 방향을 바꾸지 못함
- 끼워 넣기 거절 때 사용자가 대부분 `멈추고 실행`을 고름
