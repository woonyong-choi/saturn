# 수집 전 프로토콜 보정

정식 질문 수집 전에 합성 프로토콜 검사에서 두 문제가 관측되었다. 원래 검사와 준비 입력은 별도 보존하고 덮어쓰지 않는다.

- Codex exec resume의 `turn.completed.usage`는 이번 턴 값이 아닌 세션 누적값이었다. 해당 실험 세션의 `token_count` 이벤트에서 `total_token_usage`와 `last_token_usage`를 대조했다. 둘째 누적값에서 첫 누적값을 뺀 값을 둘째 턴으로 계산한다. 원래 누적 이벤트도 보존한다.
- Claude가 합성 검사 지시를 과거 주입 지시로 취급해 Ready와 정답 형식을 거부했다. 원응답은 실패로 남긴다. 개인 자동 맥락의 영향을 줄이기 위해 공식 CLI의 `--safe-mode`를 두 방식에 똑같이 적용한다. 사용자 인증·모델은 그대로 이용하고 사용자 설정 파일이나 비밀을 직접 읽지 않는다.

보정 뒤 합성 검사를 별도 실행한다. 원래 합성 결과는 정식 표본에 포함하지 않는다. 정식 실행의 조건·정답·반복 수·판정 기준은 바꾸지 않는다. Codex는 정확한 thread ID로 재개하며 누적 사용량이 감소하거나 원응답 대조에 실패하면 수집 오류로 판정한다. 이 변경은 정식 응답 열람 전에 고정한다.
