# 인계 자료 동시 전달: 실험 설계

[#624](https://github.com/woonyong-choi/saturn/issues/624)의 두 번째 후보다. [같은 전송의 문단 참조](../transmission-quotes/report.md)는 실제 입력을 줄이지 못했다. 이번에는 원문 선택을 고정하고 인계 자료를 보내는 시점만 바꾼다.

## 질문과 가설

| 가설 | 채택 기준 |
|---|---|
| H1 원문 보존 | 모든 조건의 인계 원문과 복원·질문 원문을 후보 입력에서 바이트 단위로 복구할 수 있다. |
| H2 비용 감소 | 두 모델 각각 두 턴 입력 합계가 기준보다 5% 이상 감소하고 입력·출력 합계도 감소한다. |
| H3 품질 유지 | 세 반복 모두 기준 정답을 후보가 놓치는 대응 문항이 없고 추가 문서의 알려진 답을 모두 맞힌다. |

세 기준을 함께 만족해야 engine 통합 검증으로 진행한다. engine의 전송 실패·재시작·제약 전달 기록 검증까지 통과해야 첫 단계를 채택하고 #625로 진행한다. Ready 호출 자체를 없애는 #627은 이번 범위가 아니다.

## 설계

| 항목 | 값 |
|---|---|
| 기준 | 현재 패킷을 첫 턴에 전달해 Ready를 받고, 같은 세션의 둘째 턴에 현재 복원·질문 입력 전달 |
| 후보 | 최소 Ready 요청을 첫 턴에 보내고, 둘째 턴에 원래 패킷 전체를 과거 자료로 감싸고 원래 복원·질문 입력을 뒤에 연결 |
| 원문 선택 | transmission-quotes의 고정 기준 출력, 예산 4,000. 문단 삭제·요약·참조 치환 없음 |
| 전송 구현 | Python 전송 시제품. Claude는 같은 stream 프로세스, Codex는 정확한 thread ID로 exec resume. engine 종단 측정과 구분 |
| 표본 | 이전에 열람한 실제 자료 18조건·104문항, 아직 모델에 질문하지 않은 실제 문서 2조건·8문항. 추가 문서의 대화 포장은 합성 |
| 반복 | 두 방식·두 모델·20조건·3반복 = 240세션 비교 실행, 480모델 턴. 예열 없음 |
| 배정 | 시드 7121, 순서 무작위, provider별 직렬 수집 |
| 모델 | Claude haiku, Codex gpt-6-sol. CLI 버전·실행 명령·현재 커밋 보존. 서버 샘플링 시드는 고정하지 못함 |
| 눈가림 | 입력 구성 함수에 정답표를 전달하지 않는다. 정답표는 이전 자료 그대로 복사하며 수집 뒤 변경하지 않는다. 작성자 눈가림은 없음 |
| 프로토콜 검사 | 별도 합성 사실을 기억하는 두 턴 실행을 provider별 1회. 원응답·비용 보존, 본 표본에 합산하지 않음 |

## 변수와 분석

| 변수 | 측정과 분석 |
|---|---|
| 입력 토큰 | Ready와 응답 턴의 사용량 합계. Claude의 cache read/write 포함. Codex cached input은 input의 부분집합이므로 중복 합산하지 않음 |
| 전체 토큰 | 입력과 출력 합계. 비용 결측을 0으로 대체하지 않음 |
| 정답 | 기존 분석기의 정규화와 고정 허용값 비교. provider·자료군·반복별 분모와 대응 손실·이득 공개 |
| 전송 유효성 | Ready 정확 일치, 같은 세션 ID, 두 사용량 이벤트, 도구 실행 없음, 정상 종료 |
| 효과 | 전체 합계의 절대 차이·백분율, 조건별 차이 최소·중앙·최대, 세 반복의 범위 |
| 불확실성 | 출처 중복과 동일 질문 반복으로 독립 모집단 신뢰구간을 만들지 않음. 이 자료의 사실 회수만 판단하고 일반적인 작업 품질·무손실을 주장하지 않음 |

## 중단과 판정

원문 보존이나 프로토콜 검사 실패 시 정식 수집 전에 원인을 수정하고 기록한다. 수집 중 실행 오류 연속 3회면 해당 provider를 중단한다. 오답은 중단·제외·재시도 사유가 아니다. 실패와 미실행은 계획 분모에 유지하며 부분 응답과 사용량도 보존한다. 모든 성공 실행이 수집되고 비용이 완결되기 전 H2·H3를 채택하지 않는다.

H1 또는 H3 실패는 후보 미채택이다. H2 기준 미달이나 실행 결측은 다음 단계 보류다. engine 통합은 시제품 통과 후 별도 코드·실패 경로 검사 결과를 남긴다. 정상 router·TUI 종단은 이번 시제품만으로 검증했다고 주장하지 않는다. 결과를 본 뒤 후보를 바꾸면 새 설계와 실행으로 분리한다.

## 타당성 위협

Ready 턴에 큰 자료를 먼저 읽는 방식과 질문과 함께 읽는 방식은 모델 해석에 영향을 줄 수 있다. 원문 일치만으로 품질을 보장하지 않는다. Codex는 두 프로세스에서 같은 저장 세션을 재개하므로 engine의 app-server 지연과 같다고 해석하지 않는다. 토큰 측정에는 두 턴의 실제 사용량을 모두 포함한다. 기존 기준선도 독립적인 무손실 제품으로 검증된 상태가 아니다.
