# 인계 자료 동시 전달: 실험 결과

## 요약

인계 원문을 Ready 턴에서 첫 실제 질문 턴으로 옮긴 시제품은 입력 토큰을 Claude 20.77%, Codex 6.35% 줄였다. 다만 Claude의 대응 정답 손실 1건과 추가 문서의 근거 누락이 남아 품질 유지 기준을 충족하지 못했다. engine 기본 경로에 채택하지 않고 다음 구조 개선 단계에도 진입하지 않는다.

## 방법

| 항목 | 값 |
|---|---|
| 설계 | [실험 설계](design.md), `0d748622` |
| 수집 보정 | `adebfc16`, `b3bda29f`: 누적 사용량·합성 프로토콜 보정 |
| 환경 | [env.json](env.json) |
| 기준 | 패킷 → Ready → 복원·질문 |
| 후보 | 최소 Ready → 원래 패킷과 복원·질문을 함께 전달 |
| 표본 | 20조건·112문항, 두 방식·두 모델·3반복 |

기준선은 앞선 실험의 개발 버전이다. Claude는 같은 stream 프로세스, Codex는 정확한 thread ID로 exec resume했다. 실제 engine 전환·정상 router·TUI를 실행한 결과가 아니다.

## 설계와 다른 점

| 변경 | 시점 | 이유와 영향 |
|---|---|---|
| Codex 재개 사용량 차분 계산 | 정식 수집 전 | CLI 응답은 누적값이었다. 원시 누적값과 native last_token_usage를 대조해 중복 집계를 막았다. |
| Claude safe mode와 합성 검사 내용 변경 | 정식 수집 전 | 지시 거부 응답을 보존했다. 일반 배포 기록의 회수 검사 통과 뒤 정식 수집을 시작했다. |
| 자동 스킬 목록 변동 분석 | 수집 중 발견 | 주 분석에서 제외하거나 비용을 빼지 않았다. 동일 첨부 구성의 부분집합은 탐색 분석으로만 제시한다. |
| Codex 명령 메타데이터 정본 구분 | 분석 중 | request.json command는 공용 수집기의 사용하지 않은 기본값이다. 실제 실행 직전에 저장한 ready-command.json·answer-command.json을 검증했다. 원자료를 수정하지 않았다. |

[프로토콜 보정](data/protocol.md)과 [합성 검사 변경](data/protocol-recheck.md)을 별도로 남겼다. 정식 표본의 정답·반복 수·채택 기준은 변경하지 않았다.

## 결과

### 흐름

| 단계 | 수 |
|---|---:|
| 계획한 정식 세션 실행 | 240 |
| 정상 완료·두 턴 원응답 대조 | 240 |
| 실행 오류·미실행·도구 호출·Ready 실패 | 0 |
| 합성 프로토콜 실행 | 6 |
| 합성 프로토콜 통과 / 실패 | 4 / 2 |

오답은 제외하지 않았다. 수치는 [집계](results/summary.json)에 있고 개별 원응답은 비공개 보관본에 있다.

### 확인 분석

| 모델 | 방식 | 정답 | 입력 | 출력 | 전체 토큰 |
|---|---|---:|---:|---:|---:|
| Claude | 기준 | 332/336 | 1,166,184 | 52,841 | 1,219,025 |
| Claude | 후보 | 332/336 | 923,945 | 51,488 | 975,433 |
| Codex | 기준 | 331/336 | 2,544,699 | 3,526 | 2,548,225 |
| Codex | 후보 | 333/336 | 2,383,149 | 3,066 | 2,386,215 |

| 모델 | 입력 절감 | 감소율 | 전체 토큰 절감 | 대응 손실 / 이득 | 추가 문서 후보 정답 |
|---|---:|---:|---:|---:|---:|
| Claude | 242,239 | 20.77% | 243,592 | 1 / 1 | 21/24 |
| Codex | 161,550 | 6.35% | 162,010 | 0 / 2 | 21/24 |

| 가설 | 판정 | 근거 |
|---|---|---|
| H1 원문 보존 | 충족 | 원래 선택된 패킷·복원 원문을 모든 조건에서 그대로 복구 |
| H2 비용 감소 | 충족 | 두 모델 입력 5% 이상·전체 토큰 감소. 자동 첨부 변동이 있어 단독 인과 효과로 일반화하지 않음 |
| H3 품질 유지 | 기각 | Claude 대응 손실과 추가 문서의 근거 누락 |

조건·반복별 입력 감소율의 최소·중앙·최대와 반복별 정답도 집계에 남겼다. 출처와 질문이 겹치는 반복이므로 독립 모집단 신뢰구간이나 무손실 보장을 제시하지 않는다.

### 실패 원인 대조

- `heldout-engine-lifecycle/backup`: 원문에는 백업을 14일 뒤 지운다는 근거가 있다. 기준 패킷과 복원 입력 모두 이 구절을 빠뜨렸다. 두 모델·두 방식에서 반복된 선택 결함이다.
- `document-records-batch-r1/changes`: Claude 기준은 맞히고 후보는 unknown을 답했다. 선택 자료에는 V11과 수정 파일 표를 연결하는 테스트 설명이 있지만 직접 정의 구절은 빠져 있었다. 근거 약화와 전송 위치 변경 중 하나를 단독 원인으로 단정하지 않는다.
- `audit-16-r2/new_path`는 Claude 후보만 맞혔다. `relay-r3/first,second`는 Codex 후보만 맞혔다.

기존 복원 테스트 8개는 통과했다. 실제 문서와 질문으로 추가한 `recall_keeps_retention_step_with_the_backup_procedure`는 수정 전 실패했다. 단위 테스트 통과 수만으로 실자료 맥락 보존을 입증할 수 없었다.

### 탐색 분석

Codex 120실행 중 자동 첨부 메시지 크기 구성이 기본인 것은 104개였고, 나머지 구성은 각각 8개였다. 대응 두 실행 모두 기본 구성인 45쌍만 보면 입력은 1,857,484 → 1,745,440토큰으로 6.03% 감소했다. 관측 뒤 정한 부분집합이므로 확인 분석이나 H3 실패를 대체하지 않는다.

## 논의

원래 선택된 입력을 그대로 복구할 수 있다는 사실은 선택 전 원문의 근거가 모두 남았다는 뜻이 아니다. 이번 백업 기간 누락이 그 차이를 드러냈다.

engine에 단순히 문자열을 뒤로 붙이는 변경은 적용하지 않았다. 현재 코드는 session을 연 뒤 전달 번호와 제약 인계 단계를 기록한다. Ready만 보낸 상태를 자료 수신으로 오인하지 않으려면 미전달 자료의 영속 저장과 실제 요청 수신 뒤 확정 처리가 필요하다. 이 계약 검토도 보관본에 남겼다.

| 타당성 위협 | 이 실험에서 |
|---|---|
| 출처·질문 반복 | 일반 작업 성공률의 독립 표본이 아님 |
| 원문 위치 변경 | 같은 선택 원문이어도 대응 정답 손실이 관측됨 |
| CLI 환경 | 자동 스킬 첨부 변동의 비용을 모두 포함하고 탐색 분석을 분리 |
| 시제품 범위 | engine 실패 복구·정상 router·TUI 종단 미검증 |
| 추가 문서 포장 | 실제 문서지만 대화 이벤트 포장은 합성 |

## 결론

전달 시점 변경에서 실제 입력 감소를 관측했지만 품질 기준을 충족하지 못했다. 기본 경로에 채택하지 않는다. 근거 누락과 자동 첨부 맥락 변동을 해결한 별도 비교가 필요하다. [맥락 정리](../../design/context-management.md)에 미채택 근거를 연결한다.
