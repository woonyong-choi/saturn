# Claude 압축 요약 전환 품질: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#122](https://github.com/woonyong-choi/saturn/issues/122) |
| 관련 설계 | [맥락 정리](../../design/context-management.md), [provider 연결과 session](../../design/providers-and-sessions.md) |
| 사전 데이터 | 없음. Claude Code 압축 기록과 사용자 기록은 설계 전에 열람하지 않았다 |
| 실행 조건 | 로그인된 Claude Code 2.1.285와 codex-cli 0.158.0을 실제로 실행할 수 있어야 한다. [#126](https://github.com/woonyong-choi/saturn/issues/126)의 `build_packet`을 부르는 명령을 `SATURN_PACKET_CMD`로 넘겨야 한다. 하나라도 없으면 `01-collect`는 원인 한 줄을 내고 끝난다 |

## 질문

`provider` 정리 모드의 Claude에서 Codex로 가는 전환에 Claude 압축 요약을 넣은 패킷을 써도 되는지 정하려고, 압축 요약을 로컬 기록에서 읽고 Saturn 기록 번호에 대응시키는 성공 비율을 잰다. 같은 전환에서 Claude 요약 패킷과 Saturn 원문 패킷을 Codex에 넘겼을 때 전환 뒤 질문 정답률 차이를 잰다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | Claude Code 자동 압축 한 번마다 요약을 로컬 기록에서 읽고 압축 시점을 Saturn 기록 번호 하나에 대응시키는 성공 비율은 95% 이상이다. | Claude Code 2.1.285, macOS, stream-json 상시 연결, `--autocompact 100000`, 합성 작업 |
| H2 | Claude 요약 패킷의 전환 뒤 질문 정답률은 Saturn 원문 패킷보다 5%p 넘게 낮지 않다. | Claude Code 2.1.285에서 codex-cli 0.158.0으로 전환, 패킷 상한 `P_max = 10000` 토큰, 합성 작업 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | H1: 단일 조건(`claude-read`). 시나리오는 `/compact`를 보내지 않으므로 압축 사건은 모두 자동 압축으로 본다. H2: `claude-summary`(고정 구역 + Claude 압축 요약을 경쟁 구역 첫 항목 + 요약 시점 뒤 기록에서 고른 항목), 기준 조건 `saturn-packet`(고정 구역 + Saturn 기록 원문에서 고른 경쟁 구역). 두 조건 모두 #126 `build_packet`으로 만든다 |
| 배정 | 같은 시나리오의 같은 질문 10개를 두 조건에 모두 묻는 대응 설계. 시나리오는 시드 122의 `random.Random`으로 만든 순서대로 실행하고, 시나리오마다 먼저 묻는 조건은 같은 난수열로 정한다 |
| 눈가림 | Codex는 조건 이름을 보지 않고 패킷 본문만 받는다. 채점은 `02-process`가 정답표와 정규화한 답의 일치로 하므로 사람이 조건을 보고 채점하지 않는다 |
| 환경 | macOS, Python 3.11 이상, Claude Code 2.1.285, codex-cli 0.158.0. 모델은 두 CLI의 기본 모델을 수집 시작 때 `env.json`에 기록하고 수집 중 바꾸지 않는다. 두 CLI는 샘플링 시드와 온도를 정할 수 없어 같은 입력도 답이 달라질 수 있다 |

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| `condition` | 조작 | `claude-read`, `claude-summary`, `saturn-packet` 중 하나 | 없음 |
| `local_boundary_found` | 측정 | 로컬 session 기록(`~/.claude/projects/<작업 폴더>/<session id>.jsonl`)에 `compact_boundary` 항목이 있다 | 참, 거짓 |
| `summary_text` | 측정 | 경계 바로 뒤 압축 요약 항목(`isCompactSummary` 참)의 글 | 글자 |
| `stream_boundary_record_no` | 측정 | stream-json 출력에서 같은 uuid의 `compact_boundary` 이벤트에 수집기가 붙인 Saturn 기록 번호 | 기록 번호 |
| `read_success` | 파생 | `local_boundary_found` 참, `summary_text`가 비지 않음, 경계 uuid와 같은 stream 이벤트가 정확히 하나라 기록 번호가 하나로 정해짐을 모두 만족 | 참, 거짓 |
| `answer` | 측정 | Codex가 질문마다 낸 답 | 문자열 |
| `correct` | 파생 | 공백과 대소문자를 정규화한 `answer`가 정답과 같은지 여부 | 참, 거짓 |
| `accuracy_diff` | 파생 | `claude-summary` 정답률 − `saturn-packet` 정답률(같은 질문 쌍) | %p |
| `summary_fallback` | 측정 | 요약이 경쟁 구역 예산을 넘어 `claude-summary` 패킷이 Saturn 원문으로 채워짐 | 참, 거짓 |
| `tool_used` | 측정 | Codex가 답하는 동안 명령이나 파일 읽기 도구를 실행했는지 여부 | 참, 거짓 |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | `01-collect`가 시드 122로 만드는 공개 가능한 합성 작업. 시나리오마다 가상 서비스 저장소, 큰 로그 파일 8개(파일마다 심은 6자리 값 하나), 제약 3개와 그중 하나를 대체하는 입력, 압축 뒤 3턴을 둔다. Claude와 Codex의 작업 폴더는 저장소 밖 `~/workspace/woon/.local/orchestration/saturn-experiments/claude-summary-handoff/work/`에 둔다. 사용자 비공개 기록은 확인 분석에 쓰지 않는다 |
| 크기 | 시나리오 40개. H1은 압축 사건 40개 이상, H2는 조건마다 질문 400개(시나리오마다 10개) |
| 크기 근거 | 정밀도. H1: 40건 모두 성공하면 95% Wilson 하한이 91.2%라 기준 90%를 넘는다. H2: 불일치 비율을 15%로 두면 대응 차이의 95% 신뢰구간 반폭은 1.96 × √(0.15 / 400) ≈ 3.8%p로 비열등 한계 5%p보다 좁다 |
| 중단 규칙 | 시나리오 40개를 한 번씩 실행하고 멈춘다. 자동 압축이 일어난 시나리오가 30개 미만이면 시드 순서로 시나리오를 더해 압축 시나리오 30개 또는 전체 60개에서 멈춘다 |
| 반복과 예열 | 시나리오와 조건마다 한 번 실행한다. 예열은 0개이고, 첫 시나리오 전에 두 CLI의 버전 확인만 한다 |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | `read_success` | `k/n`, 비율, 95% Wilson 신뢰구간. 90% 대비 단측 정확 이항 검정 | 95% Wilson 신뢰구간 하한 ≥ 90% |
| H2 | `accuracy_diff` | 2×2 표와 불일치 수 b, c. McNemar 검정(b+c < 25면 정확 이항 검정). 대응 차이의 95% Newcombe(Wilson 기반) 신뢰구간 | 차이의 95% 신뢰구간 하한 > −5%p |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | H1: 자동 압축이 한 번도 일어나지 않은 시나리오(압축 사건이 없다). H2: `read_success`가 거짓인 압축의 시나리오, 한 조건이라도 `tool_used`가 참이거나 Codex 실행이 실패한 질문 쌍 |
| 실패한 실행 | Claude 프로세스가 끝나거나 턴이 10분 안에 끝나지 않은 시나리오는 흐름 표에 실패로 세고 다시 실행하지 않는다. 그 시나리오에서 이미 일어난 압축은 H1에 넣고, H2에서는 그 시나리오를 뺀다. Codex가 0이 아닌 종료 코드로 끝나면 그 질문 쌍을 제외하고, 답이 JSON으로 읽히지 않으면 그 조건의 질문 10개를 모두 오답으로 센다 |
| 다중 비교 | 확인 가설 둘의 p값(H1 단측 이항 검정, H2 McNemar)에 Holm-Bonferroni 보정을 하고 보정 p값을 함께 보고한다. 판정은 각 가설의 채택 기준으로 한다 |

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 채택 | H1, H2 모두 채택이면 맥락 정리의 정리 모드와 패킷 구성 절에서 Claude 요약 전달을 실측 확인으로 바꾸고, provider 연결의 Claude Code 절에 압축 요약 읽기 경로와 확인 버전을 적는다 |
| 기각 | H1 기각(Wilson 상한 < 90%)이면 `provider` 모드 전환도 Saturn 패킷만 쓰도록 정리 모드 표를 고친다. H2 기각(차이 신뢰구간 상한 < 0)이면 결정 기록의 다시 볼 조건에 따라 결정을 대체하는 새 결정 기록을 쓰고 `provider` 모드 전환을 Saturn 패킷으로 바꾼다 |
| 보류 | 시나리오를 시드 순서로 40개 더해 같은 분석을 한 번 더 하고, 그때도 보류면 기본 `saturn` 모드를 유지하고 `provider` 모드 요약 전달을 실험 표시로 둔다 |

## 탐색 분석

- 질문 종류(로그 값, 파일 경로, 대체된 제약)별 정답률 차이
- 시나리오 단위 묶음 부트스트랩(반복 2000번, 시드 122)으로 본 차이 신뢰구간
- `summary_fallback`이 참인 시나리오를 뺀 차이
- 패킷 글자 수와 Claude 요약 글자 수의 분포
- 사용자 비공개 기록으로 같은 지표를 볼 때는 원문을 저장소 밖 `~/workspace/woon/.local/orchestration/saturn-experiments/claude-summary-handoff/raw/`에만 두고, 저장소에는 집계 수치만 남긴다

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | Codex가 작업 폴더의 파일을 직접 읽어 패킷 없이 답을 맞힌다. | Codex는 합성 파일이 없는 빈 폴더에서 읽기 전용 샌드박스로 실행하고, 도구를 쓴 질문 쌍은 제외한다. |
| 내적 | 같은 프롬프트에 묶은 질문 10개의 답이 서로 영향을 준다. | 두 조건에 같은 묶음을 쓰고, 탐색 분석에서 시나리오 단위 부트스트랩을 함께 본다. |
| 내적 | 실행 시각에 따라 CLI 기본 모델이나 서버 동작이 바뀐다. | 시나리오마다 두 조건을 연달아 실행하고 먼저 묻는 조건을 무작위로 정한다. |
| 구성 | 심은 6자리 값을 맞히는 질문은 실제 작업 맥락의 이해를 다 재지 못한다. | 파일 경로와 대체된 제약 질문을 섞고, 결론을 사실 회상 정답률로 한정해 쓴다. |
| 구성 | 수집기가 붙인 기록 번호는 engine 기록 저장소의 번호와 다르다. | 수집기는 stream-json 이벤트를 받은 순서대로 번호를 붙여 engine의 접수 순서를 흉내 내고, 대응 판정은 uuid 일치로만 한다. |
| 외적 | 합성 작업은 실제 사용자 작업보다 단순하고 로그 위주다. | 적용 범위를 합성 작업으로 적고, 비공개 기록 결과는 탐색 분석에만 둔다. |
| 외적 | Claude Code 기록 형식은 버전마다 바뀔 수 있다. | 결과를 Claude Code 2.1.285에 한정하고, 버전이 바뀌면 H1만 다시 잰다. |
