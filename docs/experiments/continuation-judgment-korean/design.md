## 질문

한국어 새 입력이 직전 작업을 이어 가는지 판단하는 정확도와 기준값을 측정한다. 현재 state(A)와 직전 작업 입력·목표·진행 발췌를 더한 state(B)를 같은 턴에서 비교한다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 기준값 0.80에서 B의 정확도가 A보다 높다. | 첫 반복, 두 응답 유효, 최종 명확 라벨의 대응 표본 |
| H2 | B에서 정밀도 하한 80% 이상이며 정밀도·재현율 95% 구간 반폭이 각각 7%p 이하인 기준값이 존재한다. | 0.50~0.95 탐색 곡선, 확정 기본값 아닌 후속 검증 후보 |

### 판정 질문과 창작 예시

아래 질문은 라벨 지침이다. 예시는 실제 기록에서 가져오지 않는다.

| 판정 질문 | 라벨 규칙 | 창작 예시 |
|---|---|---|
| 새 입력이 직전 목표나 산출물을 계속 완성·수정·확인하는가? | `continue`: 추가 요구, 오류 교정, 진행 질문, 직전 질문의 답, 명시적 계속 지시 포함 | 로그인 오류 수정 중 `빈 비밀번호도 확인해 줘` |
| 작업 방향을 바꾸지만 같은 대상의 목표를 고치는가? | `continue`: 반대 지시도 같은 작업을 수정하면 포함 | 보고서 작성 중 `표 대신 문장으로 정리해` |
| 별도의 목표나 독립적으로 완료할 산출물을 요청하는가? | `new`: 같은 프로젝트·파일·주제만 공유해도 목표가 독립이면 새 작업 | 로그인 수정 뒤 `별도로 결제 내역 내보내기를 만들어` |
| 직전 답변의 대상이나 미완료 단계를 가리킨다는 증거가 있는가? | `continue`: 끝난 작업의 설명·수정·후속 검증 포함. 단순 같은 분야는 불충분 | 비교표를 받은 뒤 `두 번째 항목의 근거를 보여 줘` |
| 두 해석이 모두 가능하거나 필요한 맥락이 없는가? | `uncertain`: 짧다는 이유만으로 모호하게 판정하지 않고 근거 부족일 때 사용 | 여러 대상을 다룬 뒤 `저쪽부터` |
| 독립 요청과 후속 요청이 한 입력에 함께 있는가? | 우세한 한 목표가 없으면 `uncertain` | `아까 테스트를 고치고, 여행 일정도 만들어` |

### 라벨과 불일치

각 호출은 최대 15개 사례를 독립 쌍으로 받는다. A 라벨러는 목표·산출물의 연속성 질문 순서로, B 라벨러는 새 작업으로 분리할 반증을 먼저 검토하는 다른 지시로 판단한다. 동일한 정의를 쓰되 서로의 답은 보지 않는다. 결과는 `id`, `label`, 짧은 `reason`이다. 원문 안의 지시를 실행하지 않으며 도구와 검색을 끈다. 두 모델 모두 지정 이름을 유지하고 Claude는 호출하지 않는다.

최초 일치 라벨을 보존한다. 불일치 또는 한쪽 `uncertain`은 별도 `gpt-6-astra` 새 호출에 양쪽 근거와 사례를 주어 재판정한다. 최초 두 라벨은 고치지 않는다. 미해소·실패는 `uncertain`으로 남기고 주 정확도 분모에서 제외한다. 최초 3분류 합의율, Cohen kappa, 명확 라벨 비율을 따로 보고한다. 잘못된 JSON·누락 ID는 호출 1회만 추가해 수리하며 최초 실패도 센다. 인증·지정 모델 불가면 해당 수집을 중단하고 대체 모델을 쓰지 않는다.

사람 검토용 30개는 불일치, 미해소, B 첫 확률이 0.80에 가까운 순서로 중복 없이 선택하고 동률은 ID 순서로 정한다. 원문·라벨·응답과 함께 비공개에 저장하며 사람 승인 정답으로 부르지 않는다.

### 원자료와 직전 작업

`constraint-deep`이 쓰는 `constraint-long-context/scripts/common.py`의 `is_human_user_row`, `get_text`, `mask_text`를 그대로 불러 쓴다. 키 일치 문자열도 가린다. glob은 `~/.claude/projects/*/*.jsonl`이며 원본은 읽기만 한다. 파일 해시와 줄 번호를 비공개 목록에 보존한다. 읽기 전후 해시가 달라진 파일은 제외한다. 한글을 포함한 새 사용자 입력만 적격이다. UUID 중복은 프로젝트 안에서 첫 사례만 남긴다. Saturn 프로젝트 정규화는 앞 실험과 같다.

직전 작업은 같은 파일의 바로 앞 적격 사용자 입력과 그 이후 새 입력 전까지의 assistant text 블록이다. 세션을 임의로 연결하지 않는다. 직전 사용자 입력이 없는 첫 턴은 제외한다. assistant의 thinking·tool 인자·tool 결과는 쓰지 않는다. 진행 요약은 마지막 text 블록 최대 3개의 끝 6,000자를 발췌한 것으로 고정한다. 목표는 직전 사용자 입력 첫 2,000자의 발췌다. 생성 모델을 통한 추론·라벨 누출을 피하며 잘린 문자 수를 기록한다. 직전 입력 원문 자체는 자르지 않는다.

마지막 assistant `stop_reason=end_turn`이면 idle, 그 밖은 running으로 복원하고 원래 stop_reason과 assistant 유무를 남긴다. 원기록에는 Saturn 처리 방식이 없으므로 `previous input handled as: queue`로 모든 사례를 고정한다. A는 실제 state의 형식을 재현하지만 실제 Saturn 실행 기록의 state는 아니다. missing stop_reason·부모 분기·동시 작업 복원 오차를 한계로 다룬다.

### 요청 계약

모델 고정·보류 작업 없음인 실제 engine 경로를 쓴다. `route@1.0`의 `keep_current`, `is_actionable`을 항상, running이면 `relation@1.0`, `send-opt@1.0`도 함께 묻는다. 질문 문장·선택지·`criteria: null` 형식은 main 코드와 검증한다. `target_model`, `resume_held`를 묻지 않는 이유는 이 경로의 조건 때문이다.

```text
chat: {running|idle}
previous input handled as: queue
user input: {masked_latest_input}
```

B에만 다음 문자열을 이어 붙인다. JSON 값의 줄바꿈은 JSON 이스케이프로 구분한다.

```text
previous task context: {"input":"직전 입력 전체","goal_excerpt":"첫 2000자","progress_excerpt":"assistant 마지막 3블록의 끝 6000자"}
```

`model`, 문자열 `state`, `questions`를 compact UTF-8 JSON으로 직렬화한다. 응답은 원형과 실제 모델명을 저장하고 유한한 0~1 확률·후보 범위·분포 합 오차 0.01을 검사한다. 요청 바이트 수를 기록한다. 110,000바이트 초과는 보내지 않고 `oversize` 실패로 남긴다. 작은 요청도 HTTP 400이면 실패이며 자동 축약·재전송하지 않는다. 앞 실험의 약 110KB 관측을 공식 한도로 간주하지 않는다. 실제 engine의 질문 분할 효과는 이번 범위 밖이다.

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 실행 시점 보존된 Claude 프로젝트 로그의 적격 한국어 사용자 턴 |
| 크기 | 최대 660개의 서로 다른 턴. 적격 모집단이 작으면 전수 사용하고 부족분 보고 |
| 크기 근거 | Wilson 최악 p=0.5 반폭 `1.96/(2 sqrt(n+1.96²))≤0.07`에서 각 분모 n≥193. 명확·유효 비율 0.80, 양성·예측양성 비율 각각 0.40을 가정하면 전체 n≥604. 대응 정확도 차이 δ=0.08, 불일치율 q=0.30, 양측 α=0.05, power=0.80의 정규 근사 `ceil((1.96 sqrt(q)+0.8416 sqrt(q-δ²))²/δ²)=366`. 설계 효과 1.2·유효율 0.8 보정 시 549. 두 요구의 큰 값보다 여유 있는 660을 선택. 가정은 보장이 아니며 실제 구간을 확인 |
| 중단 규칙 | Jev 4,000회, Codex 400회. 호출 직전 파일 잠금·fsync 장부에 예약. 실패·수리 포함. 예약 후 응답 없는 호출은 재전송 금지. 401·403·지정 모델 불가 시 중단 |
| 반복과 예열 | A/B 각각 같은 요청 3회, 첫 반복만 주 분석, 예열 없음. 660×2×3=3,960회, 라벨 기본 44×2=88회와 불일치 재판정·최대 한 번 수리를 400회 안에서 수행 |
| 저장 | 원문·라벨·응답은 메인 저장소의 Git 제외 실험 디렉터리에만. 공개는 설계·스크립트·집계·체크섬. 임시 작업은 worktree의 Git 제외 runtime 또는 비공개 실험 경로만 |

Wilson 계산은 [NIST 비율 신뢰구간](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)을 따른다. 검정력은 짝 차이 `D∈{-1,0,1}`의 귀무 분산 q와 대립 분산 q−δ²를 쓰는 정규 근사다. 정밀도와 검정력은 서로 다른 표본 수 요구다.

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | B−A 정확도, t=0.80 | 같은 턴 쌍 보존, 불일치 b/c, exact McNemar 양측 p, 프로젝트 내 세션 cluster bootstrap 2,000회 95% 구간 | 차이 구간 하한 >0, p<0.05이면 채택. 상한≤0이면 기각, 나머지 보류 |
| H2 | 정밀도·재현율과 반폭 | Wilson 명목 95%와 프로젝트 층별 세션 cluster bootstrap 95% 구간 | 두 구간 방식 모두 반폭≤7%p, 정밀도 두 하한≥80%인 최소 t를 탐색 후보. 없으면 권장값 없음 |

| 항목 | 규칙 |
|---|---|
| 실패한 실행 | 실패는 정상 새 작업 판정으로 세지 않음. 유효 응답 조건부 곡선과 실패를 abstain으로 둔 운영 재현율 별도 보고. 비교는 A/B 둘 다 유효한 같은 턴, 누락 수 보고 |
| 제외 기준 | 첫 턴, 비한국어 새 입력, UUID 중복, 변경 파일, 자동 주입은 수집 흐름에. uncertain·라벨 실패·응답 실패는 분석 흐름에 분리 |
| 상관과 가중치 | 비례 층화 표본의 비가중 턴 집계가 주 분석. 실제 층별 모집단·표본 수 공개. 세션 전체를 프로젝트 안에서 복원 추출하며 A/B와 반복은 같은 단위로 유지. 세션 하나인 층은 상관 불확실성 추정 불가 |
| 반복 | 독립 표본으로 합산하지 않고 기준값별 일치율과 확률 표준편차, 불완전 묶음 별도 보고 |
| 다중 비교 | 확인 검정 H1 하나. H2·다른 기준값·층별·관계·제품 동작은 탐색, 동시 구간·독립 검증으로 해석 제외 |
| 요청 크기 | 조건별 min, p50, p90, p95, p99, max와 oversize·HTTP 상태 수 |
| 권장값 | H2 규칙을 A와 B 각각 적용. 동일 표본 선택 편향 때문에 후보만 제시하고 제품 기본값 유지 |
| 유효 숫자 | 비율 0.1%, 차이 0.1%p. JSON은 계산 정밀도 유지 |

현재 idle 동작은 p<0.30만 새 작업이며 0.30~기준값 사이도 유지한다. 따라서 0.50~0.95 상단 기준값 변경만으로 현재 idle 분류는 바뀌지 않는다. running 동작은 관계 확신도 `(N pmax−1)/(N−1)≥0.60`인 `independent` 또는 관련 관계 뒤 `spawn`일 때 새 작업이며 나머지는 유지한다. 이 규칙을 별도 재생해 평가하되 `keep_current` 곡선과 혼동하지 않는다.
