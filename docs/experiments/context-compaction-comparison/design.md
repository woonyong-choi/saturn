# 같은 기록의 맥락 선별 방식 비교: 실험 설계

| 항목 | 값 |
|---|---|
| 관련 설계 | [맥락 정리](../../design/context-management.md), [맥락 고르기](../../design/context-selection.md) |
| 사전 데이터 | [패킷 품질 재측정](../handoff-packet-quality-v2/report.md)의 합성 시나리오 48개와 Jev 확률을 이미 보았다. 확인 분석에 쓰지 않는다. |

## 질문

같은 과거 대화와 같은 모델에 Saturn의 새 세션 패킷 또는 `fast-jev-compaction` 라이브러리가 Jev로 직접 선별한 원문을 주었을 때, 후속 질문 정답률과 맥락 크기가 어떻게 다른지 잰다.

## 가설

사전 데이터를 본 뒤 정한 비교이므로 확인 가설은 두지 않는다. 모든 결과는 탐색 분석이다.

## 설계

| 항목 | 값 |
|---|---|
| 조건 | `saturn-packet`: 저장된 `judge-all` 패킷. `fast-jev`: `fast-jev-compaction` 0.2.0의 `compact`와 실제 `JevClient`를 기본 선별 옵션으로 호출한 기록. |
| 배정 | 시나리오 48개 전수, 조건 순서는 시드 409로 시나리오별 무작위 배정 |
| 눈가림 | 답하는 모델은 조건 이름과 정답을 보지 않는다. 맥락 형식은 다르므로 완전 눈가림은 불가능하다. |
| 환경 | macOS, Claude Code 2.1.288, `claude-sonnet-5-5`, 도구 없음, 새 세션. Jev는 `jev-1.13.0`으로 고정한다. 실행 전 버전과 자료 해시를 기록한다. |

수집 전에 API 키가 확보되어 과거 점수의 임계값 대리 조건을 실제 라이브러리 실행으로 변경했다. 원본 저장소는 `e3f262a7f4d42bd8dd32ced30d26176f7cb545b0`에 고정한다. 합성 자료의 4개 세션을 순서대로 하나의 `Message[]`로 펴고 각 `tool` 항목을 호출 메시지와 결과 메시지로 나타낸다. `compact`의 기본 보존·절단 설정을 사용한다. 이는 Claude Code의 실제 세션 파일을 고쳐 넣는 hook 실행과 다르며, hook의 실패 시 기본 요약 fallback도 포함하지 않는다. 키는 표준입력으로만 받아 저장하지 않는다.

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| `condition` | 조작 | 두 맥락 구성 방식 | 없음 |
| `correct` | 측정 | 기존 시나리오 정답 규칙에 맞는 답 | 0 또는 1 |
| `context_chars` | 측정 | 모델에 전달한 맥락 문자 수 | 글자 |
| `elapsed_s` | 측정 | CLI 실행 시간 | 초 |
| `difference` | 파생 | 동일 질문의 `saturn-packet` 정답률 빼기 `fast-jev` 정답률 | %p |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 기존 공개 합성 시나리오 48개, 각 4세션·도구 호출 128개·질문 10개 |
| 크기 | 조건마다 48세션, 480질문 |
| 크기 근거 | 기존 자료 전수. 새로운 표본을 고르지 않는다. |
| 중단 규칙 | 같은 오류 5회 연속 또는 Claude 주간 사용률 시작 대비 3%p 상승이면 중단. 종료·파싱 오류를 남기고 재시도는 최대 2회. |
| 반복과 예열 | 각 시나리오·조건 한 번, 예열 없음 |

## 분석

| 항목 | 방법 |
|---|---|
| 주 지표 | 48개 시나리오의 대응 정답률 차이. 시나리오 단위 bootstrap 10,000회, 시드 409의 95% 백분위 구간. |
| 보조 지표 | 질문 종류별 정답률, 맥락 크기 중앙값과 차이, 실패·재시도 수. |
| 제외 기준 | 없음. 실패한 세션의 질문은 오답으로 센다. |
| 다중 비교 | 확인 검정이 없으므로 해당 없음. |

## 판정

이 결과만으로 세션 내부 축약 기능을 채택하지 않는다. 차이와 구간을 보고 실제 긴 provider 세션 검증의 우선순위를 정한다.

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 구성 | 합성 기록 4세션을 한 기록으로 펴며 실제 hook의 적용 지점과 다르다. | 라이브러리 선별 평가로 범위를 표시한다. |
| 외적 | 합성 기록의 근거가 도구 결과에 몰려 있다. | 실제 작업 성능으로 일반화하지 않는다. |
| 내적 | 맥락 길이와 형식이 조건별로 다르다. | 크기를 함께 보고, 대응 질문과 같은 실행 모델을 사용한다. |
