# 같은 기록의 맥락 선별 방식 비교: 실험 결과

## 요약

합성 시나리오 48개의 대응 질문 480개에서 새 세션용 Saturn 패킷은 347/480(72.3%), `fast-jev-compaction` 라이브러리가 선별한 원문은 96/480(20.0%)를 맞혔다. 차이는 +52.3%p이고 시나리오 단위 bootstrap 95% 구간은 [+46.3, +58.3]%p다. 이는 해당 합성 자료와 새 Sonnet 세션에서의 탐색 결과다. 실제 같은 provider 세션을 계속 쓰는 작업의 성능으로 일반화하지 않는다.

### 선별과 사용량

원본 라이브러리는 48개 시나리오에서 도구 호출 6,144개를 보았다. 첫·최근 메시지로 고정된 호출 96개를 제외한 6,048개 중 6,046개는 호출과 결과를 함께 지웠고, 2개는 호출을 남긴 채 결과를 앞부분과 생략 표시로 줄였다. 결과 전문을 남긴 후보 호출은 0개였다. 모든 Jev 판정 state는 원본 라이브러리의 `full` 단계에서 맞았다.

이번 선별에는 Jev 요청 48회, 보고된 입력 1,219,866토큰과 출력 231,744토큰을 썼다. 이는 이미 저장된 Saturn 패킷을 재생한 실행과 비용 조건이 다르므로 두 전략의 운영 비용 차이로 계산하지 않았다. Sonnet 조건별 실행 시간 합은 패킷 324.3초, fast-jev 245.3초였다. 순차 실행 순서와 호출 변동이 있어 지연 우열의 근거로 쓰지 않는다.

## 논의

### 해석

fast-jev는 후보를 기본 확률 0.5에서 삭제한다. 이 자료에서 Jev에 보낸 `history`에는 도구 결과 전문 대신 길이와 성공 표시가 있고, 후속 질문의 답은 오래된 결과 안에 있었다. 낮은 확률이 전부 삭제로 이어져 4개 정보 질문 종류의 정답이 사라졌다는 해석은 출력과 원본 코드에 부합한다. 반면 Saturn 패킷은 판단 확률을 예산 안의 순위로 사용하고, 근거가 실린 결과 일부를 전달했다. 두 방식의 질문, 입력 크기, 적용 시점도 달랐으므로 차이 전체를 한 규칙에 인과적으로 돌릴 수 없다.

따라서 현재의 `fast-jev-compaction` 기본 삭제 규칙을 Saturn의 같은 세션 경로에 그대로 채택할 근거는 없다. 원본 기록을 보존한 채 provider가 허용하는 내부 맥락 변경 경로를 따로 시험할 가치는 있다. 그 경로에서는 결과 근거가 Jev 판단 입력에 보이는지, 삭제된 항목과 이유를 기록하는지, 실제 후속 작업을 끝내는지를 확인해야 한다. 본 실험만으로 공통 축약 인터페이스를 런타임에 연결하지 않는다.

### 타당성 위협

| 종류 | 위협 | 이 실험에서 |
|---|---|---|
| 구성 | 여러 세션을 하나로 편 뒤 hook을 실행하지 않았다. | 원본 라이브러리 선별 결과와 새 세션 답만 검증했다. |
| 외적 | 합성 기록의 근거가 도구 결과에 몰림 | 실제 코딩 과제나 긴 provider 세션으로 일반화할 수 없다. |
| 내적 | 두 조건의 Jev 질문과 맥락 크기·형식이 다름 | 같은 시나리오와 질문, 같은 실행 모델로 대응시켰으나 전략의 개별 요소 효과는 분리하지 못했다. |
| 측정 | 생성된 질문의 정답 규칙 | 실제 사용자 만족이나 작업 완료가 아니라 문자열 기반 답변 정확도다. |

### 한계

- 같은 모델의 실제 연속 세션 안에서 축약 전후를 비교하지 않았다.
- 새 Sonnet 세션은 기존 Opus·Codex 실험과 다른 실행 모델이다.
- 사전 자료와 기존 결과를 본 뒤 설계한 탐색 분석이며 수집 전 설계 커밋이 없다.
- API 비용 단가와 캐시 절감액은 측정하지 않았다.

## 재현

```sh
./run.sh verify
./run.sh analyze
```

로컬 원자료가 있어야 분석을 재생할 수 있다. 입력 파일과 원자료의 해시는 [자료 설명](data/README.md)에 있다. `./run.sh analyze`를 두 번 실행해 `results/summary.json`의 바이트가 같음을 확인한다.

## 결론

이 합성 자료에서는 Saturn 새 세션 패킷이 fast-jev의 기본 선별 원문보다 후속 질문 근거를 많이 보존했다. 같은 세션 내부 축약의 효과는 측정하지 않았으므로 현재 Saturn의 패킷 전략을 유지하고 내부 축약 경로의 자동 적용은 보류한다. 후속 설계는 [맥락 정리](../../design/context-management.md)에 반영한다.
