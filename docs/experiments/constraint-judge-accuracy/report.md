# 제약 식별과 대체 판정 정확도: 실험 결과

## 요약

`is_constraint` 0.7 기준의 정밀도는 91.6% [84.8, 95.5](n=107), 재현율은 93.3% [86.9, 96.7](n=105)다. H1과 H2는 채택이고, `replaces_1` 구간과 간접 지시를 다룬 H3~H6은 신뢰구간이 기준을 가르지 못해 보류다. `is_constraint` 0.7을 확인된 값으로 두고, `replaces_<n>` 0.8과 0.5는 그대로 둔 채 보류 구간을 [#152](https://github.com/woonyong-choi/saturn/issues/152)에서 다시 잰다.

## 논의

### 해석

한국어 합성 입력에서 `is_constraint` 0.7 기준은 정밀도와 재현율 모두 80%를 넘으므로 기본값을 유지한다. `replaces_1`의 0.8 이상 구간은 대체를 잘 맞히지만 n=48로는 90% 기준을 가르지 못하고, 기록 없음 구간 정확도가 낮은 원인은 부분 쌍 30개 중 19개가 0.5 미만으로 떨어진 데 있다. 질문 문장이 `앞 제약을 지킬 수 없다`로 끝나 judge가 일부 범위의 예외를 대체로 보지 않는다고 해석하며, 0.5 기준을 낮출지보다 부분 충돌을 따로 묻는 문장이 필요한지를 [#152](https://github.com/woonyong-choi/saturn/issues/152)에서 함께 본다. 판정이 채택과 보류뿐이라 judge, 맥락 고르기, 설정 설계의 기준값은 바꾸지 않는다.

### 간접 지시

- 간접 지시 입력의 `is_constraint` 정확도는 80.0% [67.0, 88.8]로, 점추정이 기준 80%와 같아 기준을 넘었다고 볼 수 없다.
- `indirect-request`는 76.0% (19/25)로 앞 요청의 결과만 바꾸는 입력 6개를 제약으로 판정했다.
- `indirect-constraint`는 84.0% (21/25)로 앞 제약을 바꾸는 입력 4개를 놓쳤다.
- 겉모양이 같은 두 구간을 가르는 단서는 앞 입력 원문뿐이다. engine은 앞 입력이 제약으로 등록됐는지 알므로, 그 사실을 `route` state에 넣는 방안을 [#152](https://github.com/woonyong-choi/saturn/issues/152)에서 같은 평가 세트로 비교한다.
- 간접 지시 대체 쌍은 86.7% (26/30)가 0.8 이상이다. 약한 곳은 쌍 비교가 아니라 그 앞 단계인 제약 등록이다.
- 재측정 전까지 기준값은 그대로 둔다. 잘못 등록된 제약은 원문 그대로 패킷에 들어가 사용자가 볼 수 있고, 놓친 간접 지시 제약은 앞 제약의 대체만 늦춘다.

### 타당성 위협

| 종류 | 위협 | 이 실험에서 |
|---|---|---|
| 내적 | 문장과 라벨을 같은 사람이 써서 판정이 쉬운 문장으로 기운다. | 겉모양이 같은 간접 지시 구간의 정확도가 76.0%와 84.0%로 가장 낮았다. 라벨과 평가 세트는 수집 전 커밋 `8adcb79`에 고정됐다. |
| 내적 | judge 답이 같은 입력에서도 실행마다 달라질 수 있다. | 항목마다 한 번만 물었고 응답 모델은 모두 `jev-1.13.0`이었다. 반복 편차는 재지 않았다. |
| 구성 | 실제 엔진은 `is_constraint`를 `route` 질문 세트의 다른 질문과 함께 묻고 `replaces_<n>`을 최대 10쌍 함께 묻는데, 이 실험은 질문 하나씩 묻는다. | 함께 묻는 조건은 재지 않았다. 엔진의 판단 기록으로 judge 학습 채점에서 다시 확인한다. |
| 구성 | 질문 문장이 아직 코드에 없어 이 실험이 정한 문장을 잰다. | `eval/questions.json`의 문장을 그대로 썼다. 채택한 `is_constraint` 문장은 `judges`로 옮길 대상이다. |
| 외적 | 합성 문장은 실제 사용자 입력보다 짧고 규칙적이다. | 결론은 합성 한국어 입력에만 적용한다. 실제 입력의 정확도는 판단 기록의 취소 신호로 judge 학습에서 다시 잰다. |

### 한계

- 수집 스크립트는 429, 529 응답으로 다시 보낸 횟수를 기록하지 않는다. 360건 모두 기록된 HTTP 상태가 200이었다.
- 구간별 표본이 25~30건이라 구간별 신뢰구간 폭이 20%p 안팎이다.
- 부분 라벨의 정답 구간을 0.5 이상 0.8 미만으로 둔 것은 사전 등록 규칙이다. 부분 충돌을 대체 질문 하나로 잡을 수 있는지는 이 실험이 답하지 않는다.
