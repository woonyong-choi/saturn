# 전송 원문 중복: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#624](https://github.com/woonyong-choi/saturn/issues/624) |
| 순서 | [#623](https://github.com/woonyong-choi/saturn/issues/623)의 첫 단계. 통과 뒤에만 작업 상태 분리 단계 진행 |
| 관련 설계 | [맥락 정리](../../design/context-management.md) |
| 사전 데이터 | recall-selection의 18조건·104문항과 실패를 이미 열람. 두 추가 문서의 질문은 이번 비교에 처음 사용 |

## 질문

인계 패킷과 질문별 복원의 동일 전송 안에서 같은 문단을 한 번만 싣고 나머지를 내부 참조로 표현하면 실제 전체 토큰이 줄면서 사실 회수 품질을 유지하는지 측정한다. 원문을 다시 펼친 결과가 기존 전송과 바이트 단위로 같아야 한다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 모든 후보 입력을 펼친 결과가 기준 입력과 바이트 단위로 같다. | 패킷·복원 재생 전체 |
| H2 | 두 provider 각각의 입력 토큰 합계가 기준보다 5% 이상 줄고 입력·출력 합계도 줄어든다. | 대응 실행 전체 |
| H3 | 두 provider 모두 기준 정답을 후보가 놓치는 문항이 없으며 추가 문서의 답이 있는 문항을 모두 맞힌다. | 세 번 반복과 새 질문 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | 현재 작업 트리의 recall-selection 후보를 기준선으로 고정. 문단 참조 인코더만 더한 조건과 비교 |
| 선택 규칙 | 기존 패킷·복원 선택을 끝낸 뒤 동일 문단만 참조로 치환. 절감 공간을 새 후보로 채우지 않는다. |
| 인코딩 | 256자 이상이며 두 번 이상 나온 동일 문단. fenced code 내부의 빈 줄은 문단을 나누지 않는다.. 원문에 없는 태그 접두사 사용. 안내와 참조 비용을 포함해 글자 수가 줄지 않으면 원문 전송 |
| 메시지 경계 | 패킷과 복원은 각각 독립적으로 인코딩. 이전 턴의 참조·자동 압축 생존을 가정하지 않는다. |
| 배정 | 시드 7120으로 조건·방식·반복 순서를 섞고 provider별 직렬 실행 |
| 눈가림 | 검색·인코더에는 정답표를 전달하지 않는다.. 라벨 작성자는 원문을 읽으므로 사람 눈가림은 없다. |
| 환경 | macOS arm64, 실제 Claude haiku와 Codex gpt-6-sol CLI. 버전·소스·실행 파일 해시 보존 |

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| 방식 | 조작 | 현재 방식, 동일 문단 참조 방식 | 범주 |
| 원문 일치 | 측정 | 참조를 펼친 입력과 기존 입력의 바이트 비교 | 일치 수/전체 |
| 정답 | 측정 | 기존과 같은 정규화 후 고정 허용값 비교 | 정답 수/문항 관측 |
| 전체 토큰 | 측정 | 모든 실행의 입력·출력 토큰. 입력에는 cache read·write 포함 | 토큰 |
| 대응 손실 | 파생 | 기준 정답·후보 오답인 같은 문항·반복 쌍 | 건 |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 기존 실제 대화 6출처·저장소 문서 4개, 추가 실제 문서 input-handling·engine-lifecycle |
| 크기 | 기존 18조건·104문항과 추가 2조건·8문항. 두 방식·두 provider·3반복으로 240호출 |
| 크기 근거 | 기존 수집 규모와 시간·비용을 고려한 실행 예산. 독립 모집단의 정밀도나 검정력을 보장하지 않는다. |
| 중단 규칙 | 구현 검사·원문 왕복이 실패하면 모델 호출 전 수정. provider 실행 오류 연속 3회면 해당 수집 중단. 내용상 오답으로 실행을 제외하거나 조기 종료하지 않는다. |
| 반복과 예열 | 3회, 예열 없음. 기존 응답을 새 측정으로 재사용하지 않는다. |

추가 문서는 내용이 실제 자료이고 대화 포장은 합성이다. 추가 질문의 정답과 원문 줄을 수집 전에 고정한다. 기존 후보가 이미 무손실 검증에 실패한 개발 버전임을 전제로 하며 이번 결과를 제품 전체의 무손실 증명으로 해석하지 않는다.

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | 원문 일치 | 독립 Python 전개기로 Rust 출력 역변환 | 전체 일치 |
| H2 | 실제 입력과 전체 토큰 | provider별 합계, 절대 차이·비율, 조건별 최소·중앙·최대 | 두 provider 입력 5% 이상 감소, 전체 토큰도 감소 |
| H3 | 정답과 대응 손실 | provider·자료군·반복별 정답, 불일치 표 | 대응 손실 0, 추가 문서 답이 있는 문항 모두 정답 |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 잘못된 실행·도구 호출·Ready 실패·미실행은 성공에서 제외하되 계획 분모와 실패 내역에 유지 |
| 실패한 실행 | 원응답·오류·부분 사용량 보존. 비용 결측은 0으로 해석하지 않고 H2 판정 보류 |
| 다중 비교 | 모든 기준을 함께 만족해야 채택. 개별 유의성 검정 없음 |
| 불확실성 | 겹치는 출처와 같은 질문 반복이므로 독립 표본 가정의 신뢰구간을 만들지 않음. 세 반복의 범위와 대응 손실을 제시하고 미사용 모집단 보장은 하지 않는다. |

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 채택 | 세 가설과 구현 검사를 모두 통과하면 다음 단계 진행 |
| 기각 | 원문·품질 손실 또는 양쪽 모델에서 실제 비용 감소 실패면 후보를 기본 경로에 채택하지 않는다. |
| 보류 | 효과가 5% 미만이거나 실행·비용 결측이면 다음 단계에 진입하지 않는다. |

후보가 통과하지 못하면 이번 runtime 변경은 기준선으로 되돌리고 후보 코드·패치·바이너리·실패를 아카이브에 보존한다. 기존 작업의 변경은 되돌리지 않는다. 같은 문제에 맞춰 참조 문구나 정답표를 수정한 뒤 같은 결과를 확인 분석으로 제시하지 않는다.

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 모델 출력 변동과 실행 시점 차이가 존재한다. | 순서 무작위화, 같은 조건 3회 반복, 모든 실패 보존 |
| 구성 | 원문 왕복 일치가 모델의 참조 해석을 보장하지 않는다. | 실제 답의 대응 손실을 별도 판정 |
| 외적 | 같은 프로젝트와 기존 개발 질문에 한정된다. | 추가 문서 질문을 분리하고 일반적인 작업 성공률을 주장하지 않는다. |
| 비용 | 조회·도구 실행이 없는 제한된 질의 실험이다. | 이번 인코더의 입력·출력만 판정하고 정상 router·TUI 종단은 별도 범위로 명시 |
