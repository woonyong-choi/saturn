# 실제 기록의 맥락 보존: 실험 설계

| 항목 | 값 |
|---|---|
| 식별자 | real-context-replay |
| 관련 설계 | [맥락 정리](../../design/context-management.md) |
| 사전 데이터 | 합성 장문 시험과 실제 모델 예비 응답, 실제 기록의 입력과 표본 수를 보았다. 아래 비교는 탐색 분석이며 확인 검정으로 쓰지 않는다. |

## 질문

현재 engine의 패킷 생성 경로가 실제 기록에서 이전 지시와 구체적인 근거를 얼마나 보존하는지 확인한다. 압축으로 입력이 줄어도 후속 질문의 정답이 줄면 사용성을 입증했다고 판단하지 않는다.

## 설계

| 항목 | 값 |
|---|---|
| 조건 | 같은 원문과 engine의 1,000·4,000·16,000 추정 토큰 패킷 |
| 배정 | 시드 710으로 사례·조건 순서를 섞는다. provider별 같은 목록을 쓴다. |
| 눈가림 | 수신 모델에 조건 이름·정답을 주지 않는다. 원문과 패킷의 형식 차이는 가릴 수 없다. |
| 환경 | 현재 macOS와 Rust workspace. Claude Haiku와 Codex gpt-6-sol. 실제 반환 모델·사용량·버전은 env와 원응답에 보존한다. |
| 경계 | 실제 기록을 engine 순수 조립 함수로 재생한다. router·TUI·세션 자동 전환의 종단 검증은 아니다. |

## 표본과 정답

기존 대화 출처 목록 중 Saturn 폴더에서 자연어 입력이 다섯 번 이상인 실제 Codex 대화는 두 세션이다. 하나는 Rust 학습, 하나는 Saturn 감사·실험 작업이다. 세션별 앞부분·중간·끝부분 세 절단점을 사용한다. 실제 Saturn DB에서 파일 이어쓰기 두 건과 중단 복구 한 건을 더해 총 아홉 사례를 평가한다. 학습 대화와 기능 시험을 일반 개발 업무로 세지 않는다. 절단점은 서로 독립 표본이 아니다.

질문·기대 답·근거 위치를 호출 전에 고정한다. 이전 사용자 요청, 파일 내용, 식별자처럼 원문과 대조 가능한 질문만 채점한다. 사람 의도의 정답이나 실제 작업 완료를 추정하지 않는다. 원문에서 답을 확인할 수 없는 항목은 unknown을 정답으로 하는 대조군이다. 원자료의 비밀 문자열은 가린 뒤 출처 파일 hash와 가린 자료 hash를 별도로 보존한다.

| 항목 | 규칙 |
|---|---|
| 크기 근거 | 확보된 두 장문 대화와 세 기능 기록의 목적 표본 전수. 신뢰도 목표를 충족하기 위한 표본 수 계산이 아니다. |
| 반복·예열 | 사례·조건·provider 한 번, 예열 없음. 같은 원문 재실행을 독립 사례로 세지 않는다. |
| 중단 | 조건별 타임아웃 180초, 자동 재시도 없음. 같은 provider 실행 오류 세 번 연속이면 그 provider를 중단하고 미실행을 기록한다. |
| 실패·제외 | 파싱·프로세스·Ready 실패는 모두 실패로 남긴다. 후속 질문 점수의 분모에서 빼지 않는다. |
| 보존 | 전송 입력, 수신 stdout·stderr, 모델 응답, 종료 상태, 사용량, 채점과 실패를 파일별 hash로 남긴다. 비공개 추론 내부에 접근했다고 주장하지 않는다. |

## 분석과 판정

주 지표는 원문 대비 질문별 정답 수 차이와 실제 입력 토큰 수다. Claude는 패킷 인수와 질문을 같은 프로세스에서 두 턴으로 보내고, Codex는 도구 없이 답하도록 한 요청에 기록과 질문을 넣는다. 서로 다른 provider의 토큰·정답을 합쳐 하나의 성능 수치로 만들지 않는다. Claude 사용량은 각 result의 입력·cache 생성·cache 읽기를 합산하고 누적 modelUsage를 중복 합산하지 않는다.

독립 출처가 적고 의도적으로 고른 표본이므로 모집단 신뢰구간이나 p값을 만들지 않는다. 출처별·사례별 대응 값, 범위와 실패 목록을 전부 공개 집계한다. 같은 세션 질문 수를 n으로 삼은 신뢰구간은 금지한다. 모든 질문을 맞춰도 일반적인 무손실 또는 높은 신뢰도의 사용성은 채택 보류다. 실제 사용성 채택에는 별도로 모집한 독립적인 개발 과제와 사람이 확인한 작업 결과가 필요하다.

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 모델 샘플링·캐시·provider 실행 방식이 다름 | 입력과 반환 사용량, provider별 결과를 분리한다. 비용 절감을 토큰 차이와 동일시하지 않는다. |
| 구성 | 대화 재생은 CLI tool 실행과 사용자 만족도를 측정하지 않음 | 근거 회수 시험으로 한정하고 실제 end-to-end와 구별한다. |
| 외적 | 사용자 한 명·장문 두 세션·짧은 기능 시험 | 독립 모집단 신뢰도와 무손실을 주장하지 않는다. |
| 누출 | 질문 작성자가 원문을 이미 읽음 | 질문과 기대 답을 호출 전 hash로 봉인한다. 답을 패킷 순위에 주입하지 않는다. |
