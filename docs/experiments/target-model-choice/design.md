## 질문

Jev가 작업별로 고른 모델이 사후 기준에서 허용되는지 측정한다. 기본 모델을 고정한 매뉴얼보다 허용 적중률이 낮지 않은지 확인한다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | Jev 오토의 허용 적중률과 매뉴얼의 차이는 −5%p 이상이다. | 판단 가능한 표본, 첫 Jev 반복, 확신 대체 적용 뒤 |
| H2 | provider를 전환하는 Jev 선택의 허용 적중률은 80% 이상이다. | H1 중 기본 Codex에서 Claude로 실제 전환하는 선택 |

## 설계

### 후보와 기본 모델

[models.json](models.json)에 공식 `codex app-server --stdio`의 `model/list` 결과와 Claude 공식 CLI 응답 `modelUsage`를 고정한다. 후보 문자열은 실제 engine 순서 그대로 Claude 별칭 4개, Codex ID 7개다. 숨긴 모델은 제외한다. Claude 확인 4회는 예산에 포함하며 표본 질의에는 포함하지 않는다. 모델 목록 RPC는 추론 호출과 별도 계수한다.

| 선택지 | 실제 모델 |
|---|---|
| claude/default, claude/opus | claude-opus-5-5 |
| claude/sonnet | claude-sonnet-5-5 |
| claude/haiku | claude-haiku-4-5-20251001 |
| codex/gpt-6-astra | gpt-6-astra |
| codex/gpt-6-sol | gpt-6-sol |
| codex/gpt-6-luna | gpt-6-luna |
| codex/gpt-5.6-sol | gpt-5.6-sol |
| codex/gpt-5.6-terra | gpt-5.6-terra |
| codex/gpt-5.6-luna | gpt-5.6-luna |
| codex/gpt-5.5 | gpt-5.5 |

제품은 사용자가 기본 모델을 정하므로 공통 기본값은 없다. 주 비교 기본 모델은 균형 계열인 `codex/gpt-6-sol`로 가정한다. CLI가 표시한 기본값 astra를 포함해 후보 각각을 고정한 민감도 분석도 보고한다. 정답 라벨에는 `gpt-6-sol`만 사용한다. `gpt-5.6-luna`는 engine 후보에만 있고 정답 통로에 사용하지 않는다. 같은 실제 모델인 default·opus는 최선 후보 일치에서 동등하게 채점한다.

### 정답 지침

작업 입력과 뒤 최대 8개 사용자 입력으로 최선 후보 하나와 허용 집합을 판단한다. 짧은 질문·기계적 수정은 저비용·빠른 계열, 일반 코드·설계·조사는 균형 계열, 복합 추론·긴 작업·실질적 재작업은 상위 계열을 우선한다. 품질이 충분하지 않은 저비용 모델과 품질 필요 없이 지나치게 느리거나 비싼 모델은 허용하지 않는다. 이 계열 구분은 실험의 판정 가정이며 측정된 성능 서열이 아니다. 정확한 요금을 모르면 만들지 않는다. 같은 계열에서는 별도 이유가 없으면 최신 모델을 우선하고, 동률은 비용·속도 계열 다음 후보 순서로 푼다. 도구 요구가 명시된 경우만 provider 차이를 판단에 반영한다. 관측한 기록 provider를 정답 근거로 사용하지 않는다.

뒤 입력에서 성공·재작업·실패·혼합·불명확 신호를 별도 라벨로 남긴다. 응답·도구 기록을 읽지 않으므로 실제 작업 성공을 확정하지 않는다. 이어 가기만 있는 첫 입력, 누락 첨부에 의존하는 작업, 근거 부족은 판단 불가다. 정확한 지침과 JSON 계약은 [protocol.py](scripts/protocol.py)에 고정한다.

sol을 두 번 독립 호출한다. 최선 후보와 허용 집합 전체가 다르거나 형식 실패면 앞 답을 보여 주지 않고 세 번째 호출한다. 동일한 유효 표가 두 개면 다수결로 채택한다. 세 표가 모두 다르면 미해소, 다수 판단 불가도 제외하며 표본을 대체하지 않는다. 첫 두 표의 완전 일치율과 최선·허용 집합 각각의 일치율을 보고한다. 정답 해시를 봉인한 뒤 질의한다.

### 질의와 실제 engine 재현 범위

기준 소스는 main `03ec450`의 `routers/mod.rs`, `intake.rs`, `models.rs`다. 두 provider의 목록이 모두 준비된 새 채팅, 실행·보류·고정 모델 없음으로 제한한다. state는 다음 형식이다.

```text
chat: idle
previous input handled as: none
user input: {가린 사용자 입력}
```

`route`의 `keep_current`, `is_actionable`, `target_model`을 함께 보낸다. 질문 문장·후보·null criteria·문자열 state는 engine 계약을 따른다. `target_model` 질문은 `Which model should handle this input?`이다. 선택지는 11개 후보와 `other`다. 사후 맥락이나 모델 설명·정답 지침은 질의에 추가하지 않는다. 실제 원자료는 Saturn 상태 기록이 아니므로 이 초기 상태에서 재생하며 실행 중·중간 새 작업으로 일반화하지 않는다. 원문 가림은 constraint-deep이 참조하는 추출기의 비밀값·메일·절대 경로 가림을 재사용한다.

Jev는 `jev-1.13.0`으로 같은 입력을 3회 호출한다. 참고 모델은 같은 질문과 후보·state에서 각 1회 호출하고, 모든 선택지 확률을 같은 JSON 형식으로 반환하게 한다. CLI 출력용 JSON 지시만 추가하며 provider 자체 system prompt 차이는 통제하지 못한다. JSON 코드 블록 하나는 벗기고 채점한다. 스키마 강제·형식 수리·재질의는 하지 않는다.

확신은 `(N×pmax−1)/(N−1)`이며 N=12다. 0.6 미만, other, 누락·잘못된 확률·호출 실패는 기본 sol로 대체한다. 낮은 확신과 other·오류를 별도 센다. engine의 새 작업 판정 자체는 채점하지 않고, 새 작업으로 접수된 경우 모델 선택만 재생한다. 질의에 함께 실린 관계 질문의 오판이 제품 전체 성공률에 미치는 영향은 이번 범위 밖이다.

### 호출과 보존

Codex 500회, Claude 300회, Jev 400회가 상한이다. 정답 최대 300회와 참고 Codex 200회로 상한을 맞춘다. Claude 확인 4회와 참고 200회, Jev 300회가 계획이다. 호출 직전 파일 잠금·fsync 장부로 예약하며 실패와 미완료도 센다. 예약만 남은 호출은 자동 재전송하지 않는다. CLI 내부 재시도는 별도 제어할 수 없으며 여기서 호출은 프로세스 실행 또는 HTTP 요청이다.

정답은 최대 6개 병렬 작업, 질의는 모델별 5개 통로를 병렬 실행하며 통로 내부는 순차 실행한다. CLI 240초, HTTP 60초에서 중단하며 인증·CLI 프로세스 오류는 해당 통로를 멈춘다. 키는 지정 키체인에서 환경으로만 읽고 CLI 자식에서는 제거한다. TLS 검증을 유지하며 redirect를 거절한다. 원문·응답·정답·장부는 메인 저장소의 Git 제외 실험 저장소에만 보존한다. 공개하는 것은 코드·설계·집계·해시다. 사용자 설정·인증 파일을 읽어 출력·수정·복사하지 않는다. 임시 경로는 비공개 실험 runtime에 지정하고 시스템 임시 폴더와 사용자 캐시는 쓰지 않는다. Claude 작업 폴더는 지정 worktree의 `.runtime/claude-work/`이며 CLI가 자체 생성한 세션 기록 폴더 이름을 보고한다.

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | paired_delta | 같은 표본 차이, 프로젝트 군집 percentile bootstrap 10,000회, 시드 338100, 양측 95% | 하한 ≥−5%p면 채택, 상한 <−5%p면 기각, 나머지 보류 |
| H2 | switch_hit | k/n, Wilson 양측 95%, 프로젝트 군집 bootstrap 양측 95% 병기 | 두 구간 하한 모두 ≥80%면 채택, Wilson 상한 <80%면 기각, 나머지 보류 |

| 항목 | 규칙 |
|---|---|
| 제외 | 정답 판단 불가·다수결 미해소·라벨 형식 실패. 원인과 수 공개 |
| 실패 실행 | 원래 선택 적중에서는 오답, 운영 대체 후 적중에서는 기본 모델 적용. 성공 응답 조건부 값 별도 |
| 반복 | 주 분석은 첫 Jev 반복. 2·3회 별도와 세 번 완전 일치율 보고. 반복의 독립 표본 합산 제외 |
| 대응 | 불일치 b(오토만 적중)·c(매뉴얼만 적중), 효과 차이·구간, 정확 McNemar p값 |
| 비율 | k/n, Wilson 95%와 군집 구간. 빈 분모 null |
| 지연 | 중앙값·p90·범위, 예열 없음. 동시 자원 경쟁 포함, 실행 전 대기 제외 |
| 비용 | 사용량이 있는 응답만 API 상당 추정, 미상 수와 알려진 합계 별도. 구독 실제 추가 청구액과 구별 |
| 다중 비교 | 두 가설을 모두 통과해야 권고하는 교집합 판정. 각 단측 2.5% 경계에 해당하는 양측 95% 구간. 참고 모델·다른 기본값 비교는 탐색 |
| 정밀도 | 비율·%p 소수 한 자리, 시간 두 자리, 비용 여섯 자리 |

비율 구간은 [NIST Wilson 구간](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)을 따른다. 군집 bootstrap은 프로젝트를 복원 추출하고 해당 프로젝트의 모든 표본과 대응 관계를 유지한다. 표본 수가 작은 전환 집단의 구간은 넓어질 수 있다.

2026-10-04 확인한 [Jev 공식 단가](https://docs.typesafe.ai/models)는 입력 100만 토큰당 USD 0.042다. [Claude 공식 단가](https://platform.claude.com/docs/en/about-claude/pricing)의 Sonnet 5.5 입력·출력 2·10, Haiku 4.5 1·5 USD를 참고하며 CLI total_cost_usd를 별도 사용한다. [OpenAI 공식 요금](https://developers.openai.com/api/docs/pricing)의 일반 단가 astra 입력·캐시·출력 10·1·50, luna 0.10·0.01·0.50 USD를 쓴다. gpt-6-sol의 정확한 현재 단가는 확인하지 못했으므로 미상으로 두며 다른 세대 단가로 대체하지 않는다.

## 탐색 분석

- 기본 후보별 매뉴얼과 해당 후보로 대체하는 오토의 차이
- 작업 종류·기록 provider별 적중률과 원래 선택·대체 후 선택 비교
- 정답의 성공·재작업·실패 신호별 결과와 sol 자기 일치
