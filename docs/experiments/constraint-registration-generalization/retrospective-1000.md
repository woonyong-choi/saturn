# 이후 대화 기반 1,000건 정답지: 후속 실험 설계

기존 4,000건의 Jev 원응답과 질문·기준값은 바꾸지 않는다. 이 계획은 대량 Astra 판정을 중단한 뒤 작성한 사후 설계다. 중단 전 일부 Astra 라벨 분포를 확인했으므로 확인 분석이나 일반화 성능 채택의 근거로 쓰지 않는다.

## 목적과 가설

과거 입력과 그 뒤의 대화를 근거로 지속 제약 여부를 판정한 1,000건의 로컬 정답지 후보를 만든다. Jev 결과는 판정자에게 보여주지 않는다. 기술 가설은 고정 한국어 질문의 자동 기준 0.77이 높은 정밀도를 보이고, 확인 하한 0.43이 놓친 제약을 충분히 줄인다는 것이다. 기존 H1의 자동 후보 100건 이상 조건은 전체 4,000건에서 57건뿐이라 충족할 수 없다. 수치는 사후 진단으로 보고하고 제품 기본값을 바꾸지 않는다.

## 표본

원본과 연결된 4,000건을 모집단으로 한다. Jev 확률만으로 세 층을 나눈다. 0.77 이상 57건과 0.43 이상 0.77 미만 301건은 전수 포함한다. 0.43 미만 3,642건에서 SHA-256(`saturn-1000-20261005:` + 입력 ID) 순서 앞 642건을 뽑는다. 전체 1,000건이다. 표본 ID와 층별 수, 선택 코드 해시를 첫 추가 판정 전에 봉인한다. Astra 라벨은 표본 선택에 사용하지 않는다.

이 표본은 고득점 입력을 많이 포함하므로 단순 1,000건 비율은 모집단 성능이 아니다. 자동 정밀도와 확인 구간의 양성 수는 각각 전수로 계산한다. 낮은 점수층의 양성 수는 3,642/642를 곱해 4,000건의 재현율을 추정한다. 낮은 점수층의 표본오차를 구간으로 전파하고, 프로젝트·세션 의존성과 단일 사용자 한계를 밝힌다.

## 정답지 후보 판정

기존에 저장된 Astra 원응답은 같은 정의·프롬프트·모델·입력 자료로 정상 형식과 근거 위치를 검증한 경우 첫 판정으로 재사용한다. 나머지는 같은 봉인 프롬프트로 판정한다. 두 번째 Astra 실행은 1,000건 전부를 첫 결과와 Jev 결과 없이 독립 판정한다. 두 판정이 `constraint` 또는 `not_constraint`로 일치하고 양쪽 근거 위치가 유효하면 합의 라벨로 둔다. 불일치·불확실은 세 번째 독립 판정으로 재검토한다. 세 판정 중 유효 근거가 있는 같은 라벨 두 개가 나오면 합의하고, 그렇지 않으면 `uncertain`으로 남긴다. 판정 이유와 근거 위치, 원응답, 호출 실패·재시도는 로컬에 보존한다.

입력 자료의 명령은 판정 대상이지 실행 지시가 아니다. Astra 실행에는 도구를 제공하지 않는다. 절대 경로·이메일·알려진 키 패턴을 전송 전에 가린다. 이후 대화의 생략량을 기록하고, 생략이 판정에 중요하면 불확실로 둔다. 모델 합의는 사용자가 확인한 절대 정답이 아니다.

## 평가와 공개 범위

합의된 라벨로 Jev의 자동 정밀도, 자동 재현율, 확인 후보 포함 재현율을 계산한다. 불확실 사례는 따로 세고, 유리·불리한 경계값을 함께 보고한다. 원본 연결, 두 판정의 일치율, 세 번째 판정 수, 근거 위치 오류, 잘린 이후 대화 수, 판정 완료율을 공개 집계한다. 로컬 원자료·원응답은 버전 관리에서 제외된 `.local/experiments/constraint-registration-generalization/retrospective/`에 둔다. 공개 문서에는 원문을 쓰지 않는다.

첫 4,000건 호출 결과와 정답지 후보는 서로 다른 자료다. 이번 사후 평가가 기존 가설의 사전 등록 확인 분석을 대체하지 않는다.
