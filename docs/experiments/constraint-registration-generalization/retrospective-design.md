# 이후 대화 기반 Astra 판정: 추가 실험 설계

이 문서는 기존 Jev 4,000건 수집을 변경하지 않는 후속 판정 계획이다. 기존 질문·임계값·원응답은 그대로 둔다. 사용자 요청에 따라 같은 Claude·Codex 대화 로그에서 각 입력 이후의 대화를 찾아 Astra가 지속 제약 여부를 판정한다.

## 판정 대상과 순서

1. 기존 4,000개 표본의 `sample_id`를 원본 세션에서 다시 계산해 정확히 일치하는 위치만 연결한다. 원본이 없거나 내용이 바뀌어 일치하지 않으면 라벨을 만들지 않는다.
2. 현재 입력 시점까지의 상태와 이후 대화를 판정 자료로 만든다. Jev 점수·선택·응답은 Astra 요청에 넣지 않는다. 로컬 원자료에는 이후 대화 앞 20,000자와 끝 8,000자까지 보존한다. Astra에는 직전 메시지 최대 6개에서 각 1,000자, 대상 입력 원문, 이후 사용자 메시지 처음 15개·끝 5개와 처음 조수 메시지 6개에서 각 1,000자까지 보낸다. 생략량을 기록하고 생략 구간이 판정에 중요하면 `uncertain`으로 둔다.
3. `gpt-6-astra`를 별도 `codex exec --ephemeral --sandbox read-only` 실행으로 호출한다. 도구 사용 없이 입력별 `constraint`, `not_constraint`, `uncertain`과 근거 메시지 위치를 받는다. 이는 모델이 추론한 참고 정답이며 사용자 확인 정답이 아니다.
4. 원응답과 각 호출의 예약 기록을 비공개 `.local/experiments/constraint-registration-generalization/retrospective/`에 보존한다. 공개 문서는 집계·해시·한계만 보존한다.
5. Astra 라벨을 봉인한 뒤 기존 Jev 결과와 결합한다. 자동 기준 0.77·확인 하한 0.43을 그대로 쓴다. 유효 라벨에 대한 정밀도·자동 재현율·확인 후보를 포함한 재현율, 미확정 수, 원본 연결 실패 수를 모두 보고한다.

## 정의와 한계

지속 제약은 이번 작업이 끝난 뒤에도 같은 대화의 다른 작업에 적용할 방법·언어·형식·도구·금지 규칙이다. 한 작업의 목표·산출물 조건·그 작업이 여러 턴으로 이어질 때의 지시는 제외한다. 좁은 파일·프로젝트 범위도 다른 작업에 계속 적용되면 제약일 수 있다. 붙여넣은 지시문은 사용자가 지속 규칙으로 채택한 근거가 있어야 한다. 조수의 순응이나 사용자의 침묵만으로는 지속 의도를 증명하지 않는다.

원본 세션에는 추출 필터를 통과한 대화만 사용한다. 숨은 추론, 도구 출력, 설정·인증 파일은 읽지 않는다. 절대 경로·이메일·알려진 키 패턴을 전송 전에 가린다. Astra의 단일 판정은 독립적인 사람 정답과 동일하지 않다. 이 추가 분석에서 90%·70% 기준을 바꾸지 않지만, 이 라벨만으로 제품 채택을 확정하지 않는다. 라벨 누락·미확정·미연결 사례를 모두 오답으로 둔 민감도 분석을 함께 보고한다.

기존 설계의 사전 등록 가설 H1은 자동 예측 양성 100건 이상을 요구한다. 실제 자동 후보가 57건이므로 이 후속 판정만으로 H1을 채택할 수 없다. 수치는 관측 성능과 오류 유형을 밝히는 데 쓴다.

기존 사용자 커밋 금지 지시를 유지한다. 첫 호출 전에 이 문서와 판정 스크립트, 표본 연결 결과의 SHA-256과 UTC 시간을 로컬에 봉인한다. 커밋·push·이슈 수정은 하지 않는다.
