# 변환 수정 뒤 Codex와 Claude 기록의 전환 품질: 실험 결과

## 요약

받는 쪽 Opus 5.5와 GPT-6 Sol 모두에서 Codex 기록 패킷의 정답률은 98.7%(308/312)로 Claude Code 기록 패킷 98.7%(308/312)와 같았고, 차이는 0.0%p, 작업 군집 부트스트랩 95% 신뢰구간은 [0.0, 0.0], 근거 사실은 받는 쪽마다 312개다. 이 중 4개는 문구가 같아 정답을 가를 수 없는 질문이라, 뺀 308개의 정답률은 두 조건 모두 100.0%(308/308)다. 두 받는 쪽 모두 하한이 −10%p보다 커서 C2는 채택이다. C2의 채택은 근거 값이 패킷 글에 들고 구조 값에 거의 영향받지 않는 이 질문 형식과 `oracle` 판단에 한정하며, 변환 충실도 차이가 없다는 증거로 넓히지 않는다. 현재 변환을 유지하고 [provider 연결과 session](../../design/providers-and-sessions.md) 요구사항 표의 이 실험 행에 보고서 링크와 수치를 반영했다.

- 틀린 사실은 작업 `t03`과 `t12`의 실패 테스트 이름 질문 `t1-0`, `t1-1` 4개뿐이었고 두 기록과 두 받는 쪽 모두에서 틀렸다. 두 질문의 문구가 같아 받는 쪽이 어느 이름이 어느 질문의 정답인지 가를 수 없다.

## 논의

### 해석

수정된 변환으로 만든 Codex 기록 패킷과 Claude Code 기록 패킷은 받는 쪽을 고정했을 때 정답률이 같아, Codex 기록이 10%p 넘게 낮다는 1단계의 우려는 이 작업에서 확인되지 않았다. 변환 수정으로 종료 코드, 경로, 수정 줄 수가 두 기록에서 모두 얻어졌고(경로 120/120, 메모 필드 192/192 대 191/192) 근거 사실은 두 기록 모두 패킷에 전부 들었다. 다만 근거 사실이 모두 도구 결과 글에 있어 정답률은 변환이 구조 값을 얻는지보다 근거 값이 패킷에 드는지에 좌우되고, 이 실험은 예산 1,600토큰에서 그 조건을 맞췄다. 그래서 같은 정답률은 변환 충실도 차이가 없다는 증거로 읽지 않는다. 이 질문 형식은 구조 값 차이에 둔감하고, 변환 충실도는 탐색 분석의 포착률에서만 드러났다(메모 필드 192/192 대 191/192). 정답률이 같다는 말은 이 질문과 예산 1,600토큰, `oracle` 판단 조건에서만 성립한다.

### 타당성 위협

| 종류 | 위협 | 이 실험에서 |
|---|---|---|
| 내적 | 근거 사실은 같은 작업 안에서 서로 기대므로 사실 단위 독립 구간이 좁다. | 작업 단위 군집 부트스트랩으로 판정했다. 작업이 같은 틀이라 구간이 한 점으로 모였다. |
| 내적 | 받는 쪽의 샘플링이 고정되지 않는다. | 세션 순서를 시드로 섞었다. 세션을 다시 실행하지 않았다. |
| 내적 | provider가 지시와 다르게 도구를 더 부르면 기록이 달라진다. | 두 provider가 모두 거친 근거 사실만 물었고, Claude Code의 추가 읽기 22개는 질문에 영향을 주지 않았다. |
| 구성 | `oracle` 판단은 근거 기록을 항상 넣어 실제 judge가 놓치는 경우를 재지 않는다. | 근거 사실이 두 기록 패킷에 모두 들었다. judge 판단은 [#218](https://github.com/woonyong-choi/saturn/issues/218)에서 쟀다. |
| 구성 | 근거 사실이 도구 결과 글에 있어 구조 값은 정답률에 거의 영향을 주지 않는다. | 변환 충실도 지표를 탐색 분석으로 함께 냈다. 세 지표는 같았고 메모 필드만 192/192 대 191/192였다. |
| 외적 | 합성 작업은 읽기와 명령 위주라 실제 작업의 도구 다양성이 없다. | 파일 읽기, 셸 명령, 테스트 실행, 파일 수정 네 종류만 쟀다. |
| 외적 | 원시 줄이 1단계와 같아 provider 버전이 바뀐 뒤의 출력은 재지 않는다. | Codex CLI 0.158.0, Claude Code 2.1.285를 `env.json`에 남겼다. 1단계와 같은 버전이다. |

### 한계

- provider 작업을 다시 실행하지 않아 1단계와 같은 원시 줄의 재생이다. 같은 작업에서 새로 만든 기록의 변동은 재지 않았다.
- 정답률이 98.7%로 천장에 가까워 두 기록의 차이가 있어도 이 질문 형식으로는 드러나지 않을 수 있다.
- 작업 `t03`과 `t12`의 두 질문은 문구가 같아 정답을 가를 수 없다. 4개 사실이 모든 조건에서 틀렸고 308/312의 분모에 들어 있어 정답률을 실제보다 낮게 만든다. 이를 뺀 값은 결과 절에 함께 적었다.
- 같은 계정을 쓰는 다른 작업의 사용이 사용률에 섞여 이 실험만의 증가는 알 수 없다.
