# 인계 패킷 목표와 남은 일 채우기 방식: 실험 결과

## 요약

`rule`의 정답률은 53.5%로 `last-input`보다 33.8%p 높았고, 군집 부트스트랩 95% 신뢰구간은 [30.8, 36.7]%p였다. `summary`와 `rule`의 차이는 +0.8%p [−2.5, 4.0]%p였다. H1과 H2를 모두 채택해 B `rule`을 채택한다.

`summary`는 정답률이 `rule`과 다르지 않았지만 성공한 summary 호출의 평균 77,425토큰을 추가해 총 비용이 `rule`의 5.77배였다. 고정 구역은 `rule` 방식으로 설계 문서에 반영할 후속 변경을 남긴다.

## 설계와 다른 점

| 변경 | 시점 | 이유 | 결론에 미친 영향 |
|---|---|---|---|
| 첫 summary subprocess의 출력 추출 helper가 잘못 참조되어 첫 시나리오에서 중단됐다. helper를 수집기에 추가하고 같은 실행 id로 재개했다. | 수집 중 | summary 호출을 성공 packet으로 저장하지 못했다. | 성공 packet 24개에는 영향을 주지 않았다. 실패한 summary 호출 1회는 실제 호출 수에 포함하고 token 비용에는 포함하지 않았다. |
| evidence 포함 여부를 packet의 경쟁 구역 `included`와 packet 본문에 함께 대조했다. | 분석 중 | `included`는 고정 구역을 담지 않기 때문이다. | 정답률 판정에는 영향을 주지 않았고 고정 구역 포함률만 바로잡았다. |

## 논의

### 해석

첫 입력과 마지막 입력, 대기·보류·결과 미확인 입력을 규칙으로 넣는 방식은 마지막 입력만 넣는 방식보다 정답률이 높았다. summary model은 정답률을 추가로 높이지 못했지만 같은 고정 구역을 만들었다. summary 호출 토큰이 커서 B가 품질 기준과 비용 기준을 함께 만족한다.

### 타당성 위협

| 종류 | 위협 | 이 실험에서 |
|---|---|---|
| 내적 | 한 scenario의 질문 10개가 같은 packet을 읽어 시행이 독립이 아니다. | 신뢰구간을 scenario 24개 단위 군집 부트스트랩으로 계산했다. |
| 내적 | provider와 summary model의 샘플링이 고정되지 않는다. | 같은 시나리오의 조건을 섞어 실행했고 모델과 버전을 `env.json`에 기록했다. |
| 구성 | 문자열 포함 채점은 같은 의미의 다른 표현을 틀릴 수 있다. | 고정 구역 핵심어와 숫자를 정답 목록으로 두었고 합성 질문으로 범위를 제한했다. |
| 구성 | summary model 출력의 token usage를 첫 실패 호출에서는 보존하지 못했다. | 실패 호출을 실제 호출 수에는 세고 비용에는 제외했으며, 비용 결론은 성공 호출만의 하한으로 보고했다. |
| 외적 | 한 가상 서비스와 두 provider의 한 모델 버전만 사용했다. | 결론을 이 실험 환경의 고정 구역 선택에 한정한다. |

### 한계

- `contrast` 질문은 경쟁 구역이 충분한 근거를 넣지 못해 세 조건 모두 0.0%였다.
- 첫 목표 문장의 정답 표현이 길어 provider가 의미를 보존해도 문자열 채점에서 틀릴 수 있다.
- summary model의 실패 호출 비용은 측정하지 못했다.
