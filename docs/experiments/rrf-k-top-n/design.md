# 후보 순위의 k와 judge 상위 N: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#116](https://github.com/woonyong-choi/saturn/issues/116) |
| 관련 설계 | [맥락 고르기](../../design/context-selection.md) |
| 사전 데이터 | 세션 기록의 줄 종류와 키 이름, 조건에 맞는 입력 지점 수(session 13개, 87개)만 확인한다. 표본 크기를 정하기 위해서다. 입력 원문, 도구 결과, judge 판단은 수집 전에 보지 않는다. |

## 질문

RRF 합치기 상수 `k`와 judge에 넘기는 상위 개수 N의 기본값을 정한다. judge가 후보 전체를 판단해 남긴 항목 중 RRF 상위 N개에 드는 비율을 `k`와 N의 16개 조합마다 잰다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | `k`=60, N=10에서 judge가 남긴 항목이 RRF 상위 10개에 드는 비율의 95% Wilson 신뢰구간 하한은 90% 이상이다. | 패킷의 경쟁 구역(`compact` 질문), 이전 도구 호출 50~150개인 입력, Saturn 저장소 개발 중 Claude Code 기록, judge 모델 `jev-1.13.0`, 용어 카탈로그가 빈 상태 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | `k` 10, 30, 60, 100과 N 5, 10, 20, 40의 16개 조합. 기준 조건은 judge가 후보 전체를 판단한 결과(`full-judge`)다. 모든 조합은 같은 후보 세트에서 계산한다. |
| 배정 | 입력 지점 추출 순서와 judge 질문 순서를 시드 116의 `random.Random`으로 섞는다. |
| 눈가림 | judge는 질문 순서가 섞인 후보를 받아 RRF 순위와 기록 순서를 보지 않는다. 수집자는 `./run.sh analyze` 전에 judge 판단 분포를 보지 않는다. |
| 환경 | macOS, Python 3.9 이상 표준 라이브러리, judge `POST https://api.typesafe.ai/v1/systemone` 모델 `jev-1.13.0`(2026-10-01 확인). judge 샘플링은 시드로 고정할 수 없다. 수집에는 환경 변수 `SATURN_JUDGE_KEY`의 Jev 키가 필요하다. |

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| `k` | 조작 | RRF 점수 `Σ_c 1 / (k + r_c)`의 합치기 상수 | 없음 |
| `top_n` | 조작 | judge에 넘기는 RRF 상위 개수 N | 개 |
| `p_call` | 측정 | 후보마다 `call_<id>_keep` 질문에 judge가 답한 P(yes) | 확률 |
| `p_result` | 측정 | 후보마다 `result_<id>_keep` 질문에 judge가 답한 P(yes) | 확률 |
| `kept` | 파생 | `max(p_call, p_result) ≥ 0.5` | 참, 거짓 |
| `rank_file` | 파생 | 기준 파일과 겹치는 경로 수의 내림차순 순위. 겹침 0이면 순위 없음 | 순위 |
| `rank_word` | 파생 | 마지막 입력과의 BM25 점수(k1=1.2, b=0.75) 내림차순 순위. 점수 0이면 순위 없음 | 순위 |
| `rank_recent` | 파생 | 기록 번호 내림차순 순위 | 순위 |
| `rrf_rank` | 파생 | 세 채널 순위의 RRF 점수 내림차순 순위. 점수가 같으면 기록 번호가 큰 쪽이 위다. | 순위 |
| `covered` | 파생 | `kept`이고 `rrf_rank ≤ top_n` | 참, 거짓 |
| `recall` | 파생 | 조합마다 `covered` 수 / `kept` 수. 모든 후보 세트를 합쳐 센다. | % |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | `~/.claude/projects/` 아래 Saturn 저장소 개발 폴더(`workspace-oss-saturn*`, `orca-workspaces-saturn*`)의 메인 session 기록. 테스트 임시 폴더 기록은 뺀다. 이전 도구 호출이 50개 이상인 사용자 입력을 입력 지점으로 삼고, 직전 도구 호출 최대 150개를 후보로 둔다. 원문은 저장소 밖 비공개 폴더(기본 경로는 `scripts/01-collect.py`)에만 두고, 저장소에는 원문 없는 후보별 수치만 둔다. |
| 크기 | 조건마다 `kept` 항목 400개 이상, 후보 세트 40개 이상. 16개 조건은 같은 표본을 쓴다. |
| 크기 근거 | 정밀도. `recall`이 90% 근처일 때 Wilson 신뢰구간 반폭을 3%p 이하로 두려면 1.96² × 0.9 × 0.1 / 0.03² ≈ 384개가 필요하다. 시도 상한 120세트는 judge 질문 36,000개 예산이다. |
| 중단 규칙 | 정상 세트가 40개 이상이고 `kept` 항목이 400개 이상이면 멈춘다. 120세트를 시도했거나 입력 지점이 바닥나도 멈춘다. 2026-10-01 기준 입력 지점은 87개다. |
| 반복과 예열 | 판단은 후보마다 한 번이다. 처음 정상 세트 5개는 같은 질문을 한 번 더 보내 탐색 분석에만 쓴다. 예열은 없다. |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | `recall` (`k`=60, `top_n`=10) | 덮은 수 / 남긴 수와 95% Wilson 신뢰구간 | 95% Wilson 신뢰구간 하한 ≥ 90% |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | judge 답에 `invalid`가 하나라도 있는 세트는 뺀다. session 하나에서 입력 지점은 최대 10개만 뽑는다. |
| 실패한 실행 | 재시도 3회 뒤에도 응답이 없는 요청이 있는 세트는 실패로 세고 다음 입력 지점으로 넘어간다. 실패 세트는 중단 규칙의 시도 수에 든다. |
| 다중 비교 | 해당 없음. 확인 가설은 H1 하나다. 16개 조합의 `recall`은 추정값으로 보고하고 판정 절의 선택 규칙에만 쓴다. |

## 판정

선택 규칙은 95% Wilson 신뢰구간 하한이 95% 이상인 조합 중 N이 가장 작은 것을 고른다. N이 같으면 `recall`이 높은 `k`, 그것도 같으면 60에 가까운 `k`를 고른다.

| 결과 | 설계에 반영 |
|---|---|
| 채택 | 맥락 고르기의 N 기본값 10에서 `(초안)`을 뗀다. 선택 규칙의 조합이 N=10보다 작거나 `k`가 60이 아니면 그 값으로 바꾼다. |
| 기각 | 선택 규칙의 조합으로 `k`와 N 기본값을 바꾼다. 하한 95%에 닿는 조합이 없으면 N=40과 그때 `recall`이 가장 높은 `k`를 두고, judge에 넘기는 방식을 다시 정하는 design 이슈를 만든다. |
| 보류 | 쓰지 않은 입력 지점이 남았으면 새 실행 id로 더 모은다. 남은 지점이 없으면 기각과 같이 반영한다. |

## 탐색 분석

- `k`마다 N=1~60의 `recall` 곡선
- 세트별 `recall`의 분포와 session 단위 부트스트랩 신뢰구간(2,000회, 시드 116)
- 같은 질문을 두 번 보낸 5세트에서 `kept` 일치율
- 채널마다 순위가 없는 후보의 비율과, 채널 하나만 쓸 때의 `recall`

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 같은 session의 입력 지점은 후보가 겹쳐 서로 독립이 아니고, Wilson 구간이 실제보다 좁다. | session당 입력 지점을 10개로 묶고 session 단위 부트스트랩을 함께 본다. 부트스트랩 하한이 H1 기준과 다른 판정을 내면 보고서 논의에 적는다. |
| 내적 | judge 샘플링이 고정되지 않아 같은 질문에도 `kept`가 바뀔 수 있다. | 모델 버전을 고정하고 응답의 `model`을 기록하며, 5세트 재판단 일치율을 본다. |
| 구성 | judge 전체 판단은 정답이 아니다. `recall`은 judge와의 일치만 재고 전환 품질은 재지 않는다. | 품질 비교는 [#117](https://github.com/woonyong-choi/saturn/issues/117)에서 잰다. |
| 구성 | 실험은 후보를 질문 문장에 넣는다. 제품의 `compact` 질문 문장과 state 구성이 다르면 판단이 다를 수 있다. | 질문 문장을 `compact-exp@1`로 고정해 원문 기록에 남기고, 제품과 다른 점을 보고서에 적는다. |
| 구성 | 세 채널은 Python 재구현이라 `core` 구현과 순위가 다를 수 있다. | 수집 스크립트가 맥락 고르기 요구사항의 단어 조각 예를 먼저 확인한다. |
| 외적 | 한 사용자, 한 저장소, Claude Code 기록만 쓴다. Codex 기록과 다른 언어 비중에서는 결과가 다를 수 있다. | 적용 범위를 가설 표에 적고, 다른 기록은 새 실험으로 잰다. |
| 외적 | 용어 카탈로그가 빈 상태라 번역어 겹침이 빠진다. | 카탈로그가 자란 뒤의 `recall`은 이 실험 범위 밖으로 둔다. |
