# 후보 순위의 k와 judge 상위 N: 실험 결과

## 요약

`k`=60, N=10에서 judge가 후보 전체를 판단해 남긴 항목 중 RRF 상위 10개에 든 비율은 12.0% [9.2, 15.6]이다(48/400). H1은 기각이고, 16개 조합 중 95% Wilson 하한이 95%에 닿는 조합은 없다. 판정 규칙대로 맥락 고르기의 기본값을 `k`=30, N=40으로 바꾸고, judge에 넘기는 방식을 다시 정하는 design 이슈 [#153](https://github.com/woonyong-choi/saturn/issues/153)을 만들었다.

## 결과

### 흐름

| 단계 | 수 |
|---|---|
| 수집 | 50세트 |
| 제외: judge 답에 `invalid` | 0 |
| 실패한 실행 | 0 |
| 분석 | 50세트, 후보 5,943개, `kept` 400개 |

- 정상 세트 50개에서 `kept`가 400개에 닿아 중단 규칙대로 멈췄다.
- 처음 5세트는 같은 질문을 한 번 더 보냈다.

### 확인 분석

| 가설 | 지표 | 값 | 95% 신뢰구간 | n | 판정 |
|---|---|---|---|---|---|
| H1 | `recall` (`k`=60, `top_n`=10) | 12.0% (48/400) | [9.2, 15.6] | 400 | 기각 |

| `k` | N=5 | N=10 | N=20 | N=40 |
|---|---|---|---|---|
| 10 | 5.8% [3.9, 8.5] | 12.0% [9.2, 15.6] | 22.8% [18.9, 27.1] | 44.3% [39.5, 49.2] |
| 30 | 6.0% [4.1, 8.8] | 11.5% [8.7, 15.0] | 24.3% [20.3, 28.7] | 44.5% [39.7, 49.4] |
| 60 | 6.3% [4.3, 9.1] | 12.0% [9.2, 15.6] | 25.5% [21.5, 30.0] | 44.3% [39.5, 49.2] |
| 100 | 6.3% [4.3, 9.1] | 12.0% [9.2, 15.6] | 26.5% [22.4, 31.0] | 43.5% [38.7, 48.4] |

- 모든 칸의 n은 `kept` 400개다.
- 하한 95%에 닿는 조합이 없어 선택 규칙의 결과는 없었다. 판정 표의 기각 규칙대로 N=40에서 `recall`이 가장 높은 `k`=30(178/400)을 골랐다.

### 탐색 분석

같은 개수를 무작위로 고를 때 기대 `recall`은 N=5, 10, 20, 40에서 4.4%, 8.7%, 17.5%, 34.9%였다. `k`=60의 RRF는 모든 N에서 무작위보다 높았지만 차이는 1.9~9.4%p였다. `recall` 점추정이 95%에 닿는 가장 작은 N은 `k`=10에서 132, 나머지 `k`에서 133이었고, 세트당 후보 수 중앙값은 127개였다.

채널 하나만 쓸 때 `k`=60, N=10의 `recall`은 파일 겹침 5.8% [3.9, 8.5], 단어 겹침 18.3% [14.8, 22.3], 최근성 10.5% [7.9, 13.9]였다. 파일 겹침 순위가 없는 후보는 32.4%, 단어 겹침 순위가 없는 후보는 24.0%였다.

`kept`는 일부 세트에 몰렸다. 50세트 중 15세트는 `kept`가 0개였고, 세트당 `kept` 중앙값은 3개, 가장 많은 5세트가 전체의 47.3%를 차지했다. 세트별 H1 `recall` 중앙값은 6.1%였다. session 단위 부트스트랩 95% 구간은 [6.9, 26.8]로 Wilson 구간보다 넓었지만 상한도 H1 기준 90%보다 낮아 판정이 같았다.

judge가 답한 남김 확률 `max(p_call, p_result)`는 p5 0.17, 중앙값 0.30, p95 0.52였다. 후보의 20.7%가 0.4 이상 0.6 미만이었다. 같은 질문을 두 번 보낸 5세트의 `kept` 일치율은 98.4% (569/578) [97.1, 99.2]였다.

## 논의

### 해석

이 기록에서 세 채널의 RRF 순위는 judge가 남기는 항목을 무작위보다 조금 더 잘 고를 뿐이고, 95%를 덮으려면 후보 거의 전부를 넘겨야 한다. `k`는 10~100 사이에서 결과를 거의 바꾸지 않으므로 기본값보다 넘기는 방식 자체가 문제다. 기본값 `k`=30, N=40은 판정 규칙을 따른 값이고, judge에 후보 전체를 묻거나 다른 거르기를 쓸지는 [#153](https://github.com/woonyong-choi/saturn/issues/153)에서 정한다. RRF 상위 N이 전환 품질을 얼마나 낮추는지는 [#117](https://github.com/woonyong-choi/saturn/issues/117)에서 잰다.

### 타당성 위협

| 종류 | 위협 | 이 실험에서 |
|---|---|---|
| 내적 | 같은 session의 입력 지점은 후보가 겹쳐 서로 독립이 아니고, Wilson 구간이 실제보다 좁다. | 50세트가 session 10개에서 나왔다. session 단위 부트스트랩 구간 [6.9, 26.8]은 Wilson 구간보다 넓었지만 판정은 같았다. |
| 내적 | judge 샘플링이 고정되지 않아 같은 질문에도 `kept`가 바뀔 수 있다. | 응답 모델은 모두 `jev-1.13.0`이었다. 재판단 일치율은 98.4%였지만 `kept`가 드물어 일치의 대부분은 버림끼리의 일치다. |
| 구성 | judge 전체 판단은 정답이 아니다. `recall`은 judge와의 일치만 재고 전환 품질은 재지 않는다. | 남김 확률 중앙값이 0.30이고 20.7%가 0.4~0.6에 있어 `kept` 경계가 흔들리기 쉽다. 품질 비교는 #117에 남는다. |
| 구성 | 실험은 후보를 질문 문장에 넣는다. 제품의 `compact` 질문 문장과 state 구성이 다르면 판단이 다를 수 있다. | 질문 문장 `compact-exp@1`을 비공개 원문 기록에 남겼다. 제품 질문은 아직 구현 전이라 직접 비교하지 못했다. |
| 구성 | 세 채널은 Python 재구현이라 `core` 구현과 순위가 다를 수 있다. | 수집 스크립트의 단어 조각 예 확인은 통과했다. 파일 겹침과 단어 겹침 순위가 없는 후보가 각각 32.4%, 24.0%라 순위 없는 후보가 많았다. |
| 외적 | 한 사용자, 한 저장소, Claude Code 기록만 쓴다. Codex 기록과 다른 언어 비중에서는 결과가 다를 수 있다. | 적용 범위는 가설 표와 같다. 다른 기록은 재지 않았다. |
| 외적 | 용어 카탈로그가 빈 상태라 번역어 겹침이 빠진다. | 카탈로그가 빈 상태로 쟀다. 단어 겹침 채널 하나도 N=10에서 18.3%라 카탈로그만으로 95%에 닿기는 어렵다. |

### 한계

- 기준 파일과 단어 겹침 질의를 마지막 사용자 입력과 직전 3턴에서만 만들어, 짧은 입력에서는 두 채널이 거의 비었다.
- `kept`가 일부 세트에 몰려 전체 `recall`은 `kept`가 많은 몇 세트의 영향을 크게 받는다.
