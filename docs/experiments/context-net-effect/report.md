# 맥락 선별 순효과 측정: 실험 결과

## 요약

이 합성 저장소 과제에서 Saturn 패킷(`rrf`, `jev`)은 provider 압축(`provider`)보다 품질을 유지하면서 전체 비용과 시간을 줄였다는 근거를 만들지 못했다. 채택 조건을 만족한 트랙과 후보는 없다. Claude 트랙에서 후속 작업 3개를 모두 통과한 시도는 `none` 12/12, `provider` 11/12, `rrf` 7/12, `jev` 7/12였고, `rrf`−`provider` 대응 차이는 −33.3%p [−60.3, +0.9]였다. 전체 비용(가중 토큰)은 `none` 50,845, `provider` 64,798, `rrf` 93,123, `jev` 113,114였다. Jev 패킷은 `rrf`보다 비용이 평균 19,990 늘었고 품질 차이는 0.0%p [−32.0, +32.0]였다. `jev`를 쓴 패킷의 한 번만 읽히는 피드 호출은 12건 중 7건이 예산 때문에 빠졌다.

Jev `compact` 판단의 반복 일관성은 기준에 한참 못 미쳤다(항목 집합 일치 11/35, 31.4%, Wilson [18.6, 48.0]). 판정은 Claude 트랙 `rrf` 기각, `jev` 기각, Codex 두 트랙의 `rrf` 보류, `jev` 기각 또는 보류이며 자동 적용은 어느 트랙에서도 켜지 않는다([판정 표](#판정)). 이 결과는 후보가 예산의 4배 안팎인 축소 세션(`t_abs` 16000~20000)과 저렴한 모델 쌍에 한정한다. 같은 session 안의 개입은 `미지원`이고 실제 긴 세션은 `미측정`이다.

### 탐색 분석

- 한 번만 읽히는 피드(`incident.sh`)가 패킷에 들어간 형태: `claude` `rrf` `Full` 8, `Digest` 1, 예산 탈락 3. `claude` `jev` `Full` 3, `Digest` 2, 예산 탈락 7. `codex-t16` `rrf` 예산 탈락 7, `jev` 예산 탈락 7. 피드가 빠진 시도는 복구할 수 없어 F1, F2를 놓쳤다(`tool_calls`와 `incident_reruns`는 summary에 있다).
- 비용의 큰 차이는 새 session의 캐시 쓰기와 Jev 호출에서 왔다. `claude`에서 캐시 쓰기 평균은 `none` 3,475, `provider` 17,750, `rrf` 22,624, `jev` 24,316 토큰이다. `jev`의 router 토큰 평균은 7,244로 `rrf`의 1,711보다 5,533 많다. Codex는 캐시 쓰기를 보고하지 않아 같은 손실이 입력 토큰으로 나타난다.
- `claude-codex`의 `provider` 조건은 압축 요약을 넣은 패킷이 정정한 헤더 이름을 옛 값(`X-Req-Id`)으로 남겨 F1이 0/8이었다. 같은 조건의 F2(티켓 번호)는 8/8이었다. 제약 칸 항목은 패킷 8개 모두에 0개였다.
- Claude 트랙의 `none`이 모든 비교에서 앞섰다. 이 실험의 세션은 제품 기본 기준에서는 정리가 일어나지 않을 만큼 짧아, 정리 자체의 순비용을 보여 주는 값이다.

## 논의

이 표본에서 맥락을 정리하는 쪽이 정리하지 않는 쪽보다 비쌌고 품질도 낮았다. 축소한 `t_abs`로 정리를 일부러 일으켰기 때문이며 제품 기본에서 같은 일이 일어난다는 뜻은 아니다. 정리 방식들 사이에서는 한 번만 읽히는 근거를 예산 때문에 잃는 일이 품질 손실의 주된 경로였다. Jev 판단은 그 근거를 `rrf`보다 더 자주 빼는 쪽이었고(예: `claude` 7/12 대 3/12) 반복했을 때 선택도 안정적이지 않았다(31%). 이는 낮은 확신도 대체가 필요한 조건이 아니라 `compact` 확률의 변별력 부족으로 읽는다. 증거가 부족한 채택 후보는 없으므로 `context.select.packet` 기본값은 `rrf`로 유지한다.
