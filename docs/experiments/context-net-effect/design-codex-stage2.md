# 맥락 선별 순효과 측정, Codex 2단계: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#7](https://github.com/woonyong-choi/saturn/issues/7) |
| 관련 설계 | [1단계 설계](design.md) |
| 사전 데이터 | 1단계 `codex` 트랙의 수집 결과(경계 입력 끝 맥락 크기 분포 포함)를 열람했다. 2단계 기준값은 이 분포를 보고 정했다. 1단계 판정에는 영향을 주지 않는다. |

## 질문

1단계 `codex` 트랙에서 새 session을 여는 경계가 `rrf` 12건 중 3건, `jev` 12건 중 4건에서만 일어났다. 경계 입력 끝의 맥락이 기준 20000토큰에 못 미친 시도가 많았기 때문이다(조작 실패). 1단계와 같은 조건과 같은 판정 규칙으로 기준만 낮춰 새 프로젝트에서 다시 잰다.

## 설계

1단계 [design.md](design.md)의 가설, 조건, 변수, 분석, 판정을 그대로 쓴다. 다른 점은 아래 표뿐이다. 수집 뒤에 바꾸지 않는다.

| 항목 | 1단계 값 | 2단계 값 |
|---|---|---|
| 트랙 이름 | `codex` | `codex-t16` (엔진의 provider는 `codex`) |
| 경계 입력 `provider.codex.context.t_abs` | 20000 (`P_max` 2000) | 16000 (`P_max` 1600). 1단계 Codex 시도 48건의 경계 맥락 최솟값이 16606이라 모든 시도에서 경계가 일어난다. |
| 프로젝트 시드 | 1~12 | 21~32. 1단계 프로젝트와 겹치지 않는다. |
| provider 요청 상한 | 700 | 700(예상 약 540) |

H1~H4는 이 트랙에 같은 규칙으로 판정한다. H5, H6은 이 트랙의 `jev` 조건을 더해 같은 방식으로 본다. 경계가 일어나지 않은 `rrf`, `jev` 시도는 1단계와 같이 할당한 조건 그대로 분석하고, 경계 발생률을 조작 확인으로 함께 보고한다.
