# 후보를 줄인 제약 대체·해제 판단: 실험 설계

| 항목 | 값 |

| 관련 설계 | [제약](../../design/constraints.md), [router](../../design/router.md) |

## 질문

후보를 줄이고 요청을 100,000바이트 이하로 제한하면 대체·해제 판단을 자동 처리에 쓸 수 있는지 측정한다. 후보 검색 누락과 판단 오류를 분리한다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | C1에서 기준값 0.80의 대체·해제 정밀도가 각각 90% 이상 | 원래 표본의 첫 반복 |
| H2 | C2에서 기준값 0.80의 대체·해제 정밀도가 각각 90% 이상 | 원래 표본의 첫 반복 |

## 설계

| 항목 | 값 |
|---|---|
| C0 | 앞 실험 결과 재사용, 호출 없음. 실제 코드는 등록 확률 0.50 이상인 누적 후보에서 단어·파일 겹침 순으로 최대 10개 선택. 활성 후보 전체를 보냈다는 이슈 설명과 차이 |
| C1 | 같은 누적 후보 중 최근 k=8개, 최신순 |
| C2 | 같은 누적 후보 중 결정적 대상 키가 하나 이상 일치하는 항목, 최신순 |
| C3 | C2와 같은 후보 규칙, 대체·해제 질문 각 하나를 짧게 재작성. 탐색 조건 |
| 배정 | 원래 931턴을 프로젝트 ID·턴 순으로 놓고 Python Random(382).sample로 400턴 선택. 조건·턴 실행 순서는 같은 시드로 섞고 요청을 세 번 반복 |
| 눈가림 | C1·C2·C3 원래 후보 선택은 정답을 읽지 않음. 추가 두 라벨러는 상대 라벨과 Jev 응답을 보지 않음. 별도 판정만 두 라벨을 열람 |
| 환경 | Python 표준 라이브러리, macOS, Jev jev-1.13.0, 공식 codex exec gpt-6-astra·gpt-5.6-luna. 실제 환경은 env.json |

### 후보와 요청

앞 실험과 같은 등록 확률 0.50 이상 누적 후보를 재사용한다. 정답이나 새 관계 응답으로 후보 집합을 고치지 않는다. 실제 활성 집합이 아니라 고정된 등록 후보 목록을 비교하므로 관계 오류의 누적 효과는 측정하지 않는다.

사전 전이 대상 58개는 partial 56개와 replace 2개이며 release는 없다. 턴 거리 중앙값은 23.5, 최대는 207이다. 기존 등록 후보에 있는 54개 대상의 최근 순위는 1~8에 25개, 26~170에 29개다. 이 순위의 빈 구간 9~25 직전인 k=8을 고정한다. 58개 중 25개만 담는 보수적인 검색 범위이며 높은 재현율을 전제하지 않는다. C0의 질문 후보 상한 10개보다 작게 유지하면서 근거리 집단을 남기는 선택이다. 사전 관측 자료를 사용한 선택이므로 독립 일반화 검증으로 주장하지 않는다.

C2의 대상은 형태소 분석 모델 없이 NFKC·소문자 정규화 뒤 고정 사전의 명사군 또는 경로가 일치하면 같다. 명사군은 commit, pr, branch, document, comment, test, language, format, codex, claude, rust, python, kotlin, git, obsidian, wiki, browser, search, key, agent, terminal, file이다. 각 별칭·정규식은 봉인한 `scripts/candidates.py`의 TARGETS와 target_keys가 정본이다. ASCII 단어는 경계 일치, 한국어는 해당 명사 부분 문자열 일치, 경로는 전체 추출 문자열 일치다. 대상 키가 없으면 후보 없음이다. 일반 명사의 과잉 일치와 생략된 대상의 누락도 성능에 포함한다.

요청은 앞 실험과 같은 model/state/questions 구조와 후보별 earlier_constraint, later_constraint, turn_distance를 쓴다. 현재 입력의 반복도 유지해 직렬화 변경 효과를 섞지 않는다. UTF-8 JSON 전체가 100,000바이트를 넘으면 가장 오래된 후보부터 제거한다. 전후 바이트·제거 수·후보 ID를 기록한다. 현재 입력만으로도 초과하면 전송하지 않고 oversize_input으로 남긴다. 후보 없음은 호출 없이 행동 없음이다. C3는 질문 길이가 달라 최종 잘림이 달라질 수 있으며 C2와의 공통 후보 비교도 보고한다.

### 질문

C1·C2의 대체 질문은 `Following the later constraint makes it impossible to keep the earlier constraint.`이며 해제 질문은 `The later input says the earlier constraint no longer needs to be followed.`다. 대체는 constraint@1.0, 해제는 constraint@1.1의 보조 질문이다. 두 질문 모두 `For pair <n>:` 접두사를 붙인다.

C3 대체는 `Does the later input set a lasting rule for the same scope that cannot coexist with the earlier rule, excluding one-time exceptions?`다. 해제는 `Does the later input explicitly revoke the earlier rule for its whole scope, excluding one-time exceptions?`다. 앞 실험에서 부분 예외 56개를 완전 대체와 구분해야 했던 오류 구조를 근거로 지속성·전체 범위·일회성 제외를 명시한다. 개별 원문은 공개하지 않는다.

### 라벨 확장

원래 8개 프로젝트 정답은 수정하지 않는다. 이전 추출 규칙으로 이미 저장된 10턴 미만 프로젝트의 314턴을 전수 라벨링한다. 원본 재추출·복사·새 기록 검색은 하지 않는다. 각 대화의 상태는 독립이며 프로젝트를 합치지 않는다. 40턴 이하의 대화 묶음을 두 지정 모델이 독립 판정하고 별도 astra 호출이 재판정한다. 지침·필드·상태 재생 검사는 앞 실험 labels.py를 재사용한다. 출력 스키마를 처음부터 강제하고 검증 실패에만 최대 한 번 수리한다. 수리 실패 묶음은 제외하며 부분 접두부를 채택하지 않는다. 상대 답·Jev 답은 최초 라벨에 넣지 않는다. 추가 라벨의 최초 합의·모호함·실패·전이 수와 목표 부족분을 보고한다.

추가 표본은 과거 등록 확률이 없으므로 명확한 재판정 is_constraint=true를 후보 공급원으로 쓴다. 정답을 활용한 후보 공급 상한 실험으로 별도 보고하며 H1·H2와 합치지 않는다. 44턴 표본은 라벨 결과를 보기 전에 전체 314턴에서 고정한다. 짧은 기록에 충분한 전이가 없으면 목표 미달을 그대로 보고한다. 새 문장을 합성하거나 같은 정답을 반복해서 표본을 늘리지 않는다.

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | C1의 대체·해제 정밀도 | k/n·Wilson 95%, 프로젝트 cluster bootstrap 2,000회·시드 382, 정확 이항 p0=0.90 | 두 종류 모두 점추정 ≥0.90, Wilson 하한 ≥0.90, bootstrap 하한 ≥0.90, Bonferroni p≤0.0125 |
| H2 | C2의 같은 지표 | H1과 동일 | H1과 동일 |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 현재 턴 또는 앞 후보 라벨이 모호·누락이면 해당 쌍의 정밀도·정확도에서 제외. 현재 정답이 명확한 전이는 후보 밖도 재현율 분모에 남김 |
| 실패한 실행 | 무응답·invalid는 행동 없음, 종류 정확도는 오답. 유효 응답 조건부 결과도 병기. HTTP 실패·미완료·바이트 초과·후보 없음은 각각 집계 |
| 행동 | 해제 ≥threshold 우선, 그다음 대체 ≥threshold. 둘 중 하나라도 invalid면 행동 없음. 나머지는 대체 ≥0.50이면 partial, 아니면 compatible |
| 다중 비교 | C1·C2 × 대체·해제 네 정밀도에 Bonferroni. C3·기준값 곡선·C0 비교는 탐색 |
| 구간 | 비율 Wilson 95%는 독립 가정의 명목 구간. 원래 프로젝트를 복원 추출한 bootstrap도 병기, 유효 표본 없는 재추출 횟수 기록. 재현율·후보 포함률도 Wilson |
| 대응 비교 | 동일 표본 C1/C2/C3의 공통 후보쌍에서 종류 정확도 차이, b/c 불일치와 프로젝트 bootstrap 95%. C0는 이전 전수 결과와 이번 표본 재계산을 구분 |
| 거리 | 1~5, 6~20, 21~100, 101+ 턴. 후보쌍 정확도와 정답 전이 재현율을 구분 |
| 요청 크기 | 실제 호출의 최소·중앙·p95·최대. 기준 초과 요청은 전송하지 않으며 제한 전 크기도 별도 보고 |
| 유효 숫자 | 비율은 소수 첫째 자리 %, p값 유효 숫자 세 자리. 원시 집계 반올림 제외 |

## 판정

| 결과 | 보고할 권고 |
|---|---|
| H1 또는 H2 채택 | 해당 조건에서 자동 가능 후보. 범위와 재현율을 함께 제시 |
| 기각 또는 보류, 빈 예측·정답 양성 | 사용자 선택. 증거 부족을 성능 실패와 구분 |

설계 문서와 제품 설정은 변경하지 않는다. 결과는 보고서와 PR 한 개로만 남기며 머지·이슈 댓글은 하지 않는다.

## 탐색 분석

- C3 질문 변경과 0.50~0.95 곡선
- 추가 짧은 대화와 정답 기반 후보 공급의 결과
- C0와 같은 표본의 재계산 및 전체 표본의 결정적 후보 포함률
