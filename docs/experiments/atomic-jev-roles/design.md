# Jev 좁은 의미 판단: 개발 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#546](https://github.com/woonyong-choi/saturn/issues/546) |
| 관련 설계 | [router](../../design/router.md) |
| 사전 데이터 | 제약 인간 검토 40건의 분포와 이전 Jev 점수 일부를 이미 확인했다. 이 층은 탐색이다. 관찰 쌍은 이 설계의 생성 규칙으로 새로 만든다. |

## 질문

Jev가 짧고 후보가 정해진 두 의미 판단에서 코드 기준선보다 정확한지 따로 측정한다. 제약 후보의 지속 범위와 두 실행 관찰의 동일 원인 여부를 본다. 분류 점수와 실제 Saturn 작업 완료 이득은 구분한다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 실제 인간 검토의 확정 24건에서 좁은 질문의 Jev가 기존 제약 점수보다 오답을 3건 이상 줄인다. | 어려운 사례로 선별된 개발 표본. 확인 가설이 아닌 탐색 기준 |
| H2 | 새로 생성한 관찰 쌍의 미열람 80건에서 Jev의 정확도가 코드 기준선보다 5%p 이상 높고, 동일 관찰을 다른 것으로 놓친 건수가 4건 이하다. | 생성 규칙에 한정한 기능 확인 |
| H3 | 같은 요청을 두 번 보낸 경우 자동 행동 구간(0.2 이하·0.8 이상·그 사이)이 90% 이상 일치한다. | 두 역할, 실패를 불일치로 포함 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | 코드 기준선, 기존 Jev 점수(제약층만), 새 Jev 단일 `noul` 질문. 자동 적용 없음 |
| 배정 | 관찰 주제 30개 중 10개 개발, 20개 확인. 시드 54607. Jev 호출은 역할·항목·반복을 섞는다 |
| 눈가림 | Jev state에서 라벨·기존 답·생성 태그 제외. 생성 규칙의 문장 패턴은 질문에 넣지 않는다 |
| 환경 | 로컬 Python 표준 라이브러리, HTTPS TypeSafe Jev. 실제 모델·시각·usage는 원응답에 기록 |

인간 검토층은 이미 본 자료이며 사람도 16건을 `unsure`로 남겼다. 24건은 정답 확정 표본이나 제품 모집단이 아니다. 관찰 쌍은 30개 주제마다 같은 실패를 바꿔 쓴 쌍, 같은 대상의 성공·실패 충돌, 다른 실행의 비슷한 실패, 같은 실행의 다른 검사 4종을 생성한다. 같은 실패를 바꿔 쓴 쌍만 동일 관찰이다. 개발 주제에서 문자 3-gram Jaccard 기준을 고르고 확인 주제에는 고정 적용한다. 더 강한 규칙 기반 추출기는 탐색 분석에만 쓴다.

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| `role`, `label` | 조작 | 지속 제약 여부 또는 동일 관찰 여부 | 이진 |
| `score` | 측정 | Jev `noul` 확률. 형식·HTTP 실패는 판단 없음 | 0~1 |
| `correct`, `miss`, `agreement` | 파생 | 기준 0.5의 정답, 동일 관찰 누락, 두 반복 행동 구간 일치 | 건·비율 |
| `usage`, `latency` | 측정 | Jev 응답 토큰과 HTTPS 벽시계 | 토큰·ms |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 비공개 인간 검토 40건(확정 24, 미정 16), 생성 관찰 쌍 120건(개발 40, 확인 80) |
| 크기 | Jev 160항목 × 2반복 = 최대 320호출 |
| 크기 근거 | 기존 인간 검토 전수와 주제 20개 × 4쌍의 확인 단위. 80건에서 단순 비율 Wilson 95% 최악 반폭 약 10.8%p이므로 작은 효과 입증에는 부족하다 |
| 중단 규칙 | 호출 전 예약 기록. 인증 거절 시 즉시 중단. 실패·미완료 재전송 금지. 최대 320호출 |
| 반복과 예열 | 항목별 두 반복, 예열 없음. 첫 반복만 정확도 분모 |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | 새−기존 정답 수 | 같은 24건의 불일치 수와 차이. 이미 본 자료이므로 탐색 | 3건 이상은 확인 평가 후보만 |
| H2 | 코드 대비 정확도 차이·동일 관찰 누락 | 확인 20주제를 재표집하는 군집 bootstrap 95% 구간(2,000회, 시드 54607), 대응 승패 수 | 차이 점추정 ≥5%p, 구간 하한 >0, 누락 ≤4건 |
| H3 | 행동 구간 일치 | 두 반복의 같은 구간 수/160, Wilson 95% | 점추정 ≥90%, 구간 하한 ≥85% |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 인간 `unsure` 16건은 H1 정확도에서 제외, 호출·일관성에서는 포함. 확인 관찰 쌍 제외 없음 |
| 실패한 실행 | 정확도 오답, 반복 불일치. usage·지연 미상은 해당 통계에서만 결측으로 센다 |
| 다중 비교 | H1은 탐색. H2·H3 모두 통과해야 다음 확인 실험 후보. 둘을 제품 채택 검정으로 합치지 않는다 |

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 개발 기준 충족 | 실제 관찰·후속 작업에서 코드·작업 LLM과 대응 확인 실험을 설계한다. 기본값은 바꾸지 않는다 |
| 기각 | 해당 Jev 역할을 자동 경로에 넣지 않고 코드 또는 작업 LLM을 쓴다 |
| 보류 | 불확실성과 필요한 독립 표본을 기록한다 |

## 탐색 분석

- 인간 `unsure`에 대한 Jev 확률 분포와 코드의 명시적 규칙 검출.
- 주제별 오류와 호출당 토큰·지연. USD는 실제 청구 단가가 확인되지 않으면 계산하지 않는다.

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 인간 검토층과 이전 Jev 점수를 이미 열람 | 탐색으로만 보고 독립 확인이라 부르지 않는다 |
| 구성 | 문장 틀의 정답이 실제 관찰 중복을 대표하지 않는다 | 생성 기능 확인과 실제 업무 성과를 분리한다 |
| 외적 | 한 사용자의 한국어 입력과 합성 개발 로그 | Claude·Codex·혼합어로 일반화하지 않는다 |
