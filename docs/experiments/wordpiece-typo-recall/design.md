# 단어 조각 단위별 오타 재현율: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#118](https://github.com/woonyong-choi/saturn/issues/118) |
| 관련 설계 | [맥락 고르기](../../design/context-selection.md) |
| 사전 데이터 | 말뭉치 문서 수와 질의 후보 위치 수만 `scripts/01-collect.py plan`으로 확인했다. 질의 800개를 채울 수 있는지 보기 위해서다. 순위와 재현율은 보지 않았다. |

## 질문

맥락 고르기의 단어 겹침 채널이 한글을 글자 2개, 영문을 식별자 단어로 자르는 규칙을 유지할지 정한다. 이를 위해 오타를 넣은 질의에서 자모 단위와 영문 글자 4개 단위가 기준보다 정답 문서를 더 자주 상위 10개에 올리는지, 오타 없는 질의의 1위 정밀도를 잃지 않는지 잰다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 한글 오타 질의에서 자모 3개 단위의 상위 10개 재현율은 기준보다 3%p 이상 높다. | 이 말뭉치, 한글 2~4어절 질의, 오타 1개 |
| H2 | 오타 없는 한글 질의에서 자모 3개 단위의 1위 정밀도는 기준보다 2%p 넘게 낮지 않다. | 이 말뭉치, 한글 2~4어절 질의 |
| H3 | 영문 오타 질의에서 글자 4개 단위의 상위 10개 재현율은 기준보다 3%p 이상 높다. | 이 말뭉치, 영문 식별자 2~3개 질의, 오타 1개 |
| H4 | 오타 없는 영문 질의에서 글자 4개 단위의 1위 정밀도는 기준보다 2%p 넘게 낮지 않다. | 이 말뭉치, 영문 식별자 2~3개 질의 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | `base`(기준: 한글 글자 2개, 영문 식별자 단어), `ko-jamo3`(한글 자모 3개, 영문 식별자 단어), `en-char4`(한글 글자 2개, 영문 식별자 단어마다 글자 4개). 모든 조건은 NFC 정규화와 문자 종류별 분리 뒤 적용하고 숫자, 한자, 가나 규칙은 같다. |
| 배정 | 모든 질의를 모든 조건에 넣는다. 질의 후보 위치 섞기, 어절 수, 오타 종류와 위치는 `random.Random(118)` 하나로 정한다. |
| 눈가림 | 해당 없음. 질의와 정답은 스크립트가 만들고 사람 라벨이 없다. 수집 전에는 순위 결과를 보지 않는다. |
| 환경 | macOS, Python 3 표준 라이브러리, Git. 모델 호출 없음. 실제 값은 `env.json`에 기록한다. |

- 말뭉치는 커밋 `1279d4047f4eb93bb297da27ef7d6b4b7fd65acf`의 Saturn 저장소 파일만 쓴다. `git show`로 읽고 작업 트리는 읽지 않는다.
- 문서 집합은 `docs/` 아래와 루트의 Markdown 파일, 모든 `.rs` 파일이다. 비공개 기록과 Git이 추적하지 않는 파일은 쓰지 않는다.
- Markdown은 제목 줄마다 절 하나를 문서 하나로 둔다. `.rs` 파일은 40줄마다 문서 하나로 두고 주석 글과 식별자만 남긴다. 문자열 상수와 Rust 예약어는 뺀다.
- 한글 질의는 문서의 한 줄에서 한글 음절만으로 된 어절 2~4개를 이어서 자른다. 영문 질의는 코드 한 줄의 식별자 2~3개를 이어서 자른다.
- 정답 집합은 공백을 하나로 줄인 본문에 오타 없는 질의 문자열이 들어 있는 문서 전부다.
- 질의마다 오타 없는 질의와 오타 1개를 넣은 질의를 하나씩 만든다.
- 순위는 BM25(`k1`=1.2, `b`=0.75)로 매긴다. 점수가 0인 문서는 순위에 넣지 않고, 점수가 같으면 문서 id 순으로 둔다. 용어 카탈로그 짝은 더하지 않는다.

| 오타 종류 | 언어 | 만드는 법 |
|---|---|---|
| `jamo-sub` | 한글 | 음절 하나의 초성, 중성, 종성 중 하나를 같은 자리의 다른 자모로 바꾼다. |
| `jamo-del` | 한글 | 음절 하나의 종성을 지운다. 종성이 없으면 중성을 지워 초성 글자만 남긴다. |
| `letter-sub` | 영문 | 4글자 이상 식별자의 글자 하나를 다른 글자로 바꾼다. |
| `letter-ins` | 영문 | 4글자 이상 식별자에 글자 하나를 넣는다. |
| `letter-del` | 영문 | 4글자 이상 식별자의 글자 하나를 지운다. |
| `letter-swap` | 영문 | 4글자 이상 식별자에서 서로 다른 이웃 글자 둘의 순서를 바꾼다. |
| `space-drop` | 한글, 영문 | 질의의 공백 하나를 지운다. |

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| `condition` | 조작 | 단어 조각 조건 | 해당 없음 |
| `variant` | 조작 | `clean`(오타 없음) 또는 `typo`(오타 1개) | 해당 없음 |
| `typo_type` | 조작 | 오타 종류 표의 값. 언어마다 균등 무작위 | 해당 없음 |
| `gold_rank` | 측정 | 정답 집합 문서 중 가장 높은 순위. 순위에 없으면 결측 | 순위 |
| `hit_at_10` | 파생 | `gold_rank`가 10 이하면 1 | 0 또는 1 |
| `hit_at_1` | 파생 | `gold_rank`가 1이면 1 | 0 또는 1 |
| `recall_at_10` | 파생 | 질의 집합의 `hit_at_10` 평균. 상위 10개 재현율 | % |
| `precision_at_1` | 파생 | 질의 집합의 `hit_at_1` 평균. 1위 정밀도이고, 1에서 뺀 값은 엉뚱한 문서가 1위인 질의 비율이다. | % |
| `diff` | 파생 | 같은 질의에서 후보 조건 값 빼기 `base` 값 | %p |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 커밋 `1279d40`의 Saturn 문서와 코드에서 자른 질의 |
| 크기 | 언어마다 질의 800개, 질의마다 오타 없는 것과 오타 있는 것 하나씩. 조건마다 3,200개 |
| 크기 근거 | 정밀도. 불일치 질의 비율이 20%일 때 짝 차이 95% 신뢰구간 반폭은 1.96×√(0.2/800)≈3.1%p다. 단일 비율 반폭은 최대 3.5%p다. |
| 중단 규칙 | 언어마다 섞은 후보 위치를 차례로 보며 800개를 채우면 멈춘다. 후보가 모자라면 전수를 쓴다. 한 문서에서 8개, 정답 집합이 5개를 넘는 질의, 앞 질의와 같은 문자열이나 겹치는 구간은 건너뛴다. |
| 반복과 예열 | 해당 없음. 계산이 결정적이고 시간을 재지 않는다. `verify`가 한 번 다시 계산해 raw와 비교한다. |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | `recall_at_10`의 `diff`(`ko-jamo3`) | 2×2 표, McNemar 검정(b+c < 25면 정확 이항), Newcombe 방법 10 차이 신뢰구간 | 채택: Holm 보정 p < 0.05, 차이 95% 신뢰구간 하한 > 0, 차이 ≥ 3%p. 기각: 상한 < 3%p. 보류: 그 밖의 결과 |
| H2 | `precision_at_1`의 `diff`(`ko-jamo3`) | 2×2 표, Newcombe 방법 10 차이 신뢰구간 | 채택: 차이 95% 신뢰구간 하한 > −2%p. 기각: 그 밖의 결과 |
| H3 | `recall_at_10`의 `diff`(`en-char4`) | H1과 동일 | H1과 동일 |
| H4 | `precision_at_1`의 `diff`(`en-char4`) | H2와 동일 | H2와 동일 |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 질의 생성 규칙(중단 규칙 칸)으로 건너뛴 후보만 뺀다. 만든 질의는 하나도 빼지 않는다. |
| 실패한 실행 | 정답이 순위에 없거나 10위 밖이면 놓침으로 센다. 스크립트가 중간에 멈추면 그 실행 파일을 쓰지 않고 새 실행 id로 다시 수집하며 흐름 표에 한 행으로 남긴다. |
| 다중 비교 | H1과 H3의 McNemar p값에 Holm-Bonferroni 보정. H2와 H4는 신뢰구간으로만 판정한다. |

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 채택 | H1과 H2가 모두 채택이면 단어 조각 표의 한글 행을 자모 3개 단위로 바꾼다. H3과 H4가 모두 채택이면 라틴 문자 행을 식별자 단어마다 글자 4개 단위로 바꾼다. |
| 기각 | 그 언어의 기준 규칙을 유지하고 단어 조각 절의 #118 문장을 결과 보고서 링크로 바꾼다. |
| 보류 | 기준 규칙을 유지하고, 질의 수를 늘리거나 실제 입력 표본을 쓰는 후속 실험 이슈를 연다. |

## 탐색 분석

- 오타 종류별 상위 10개 재현율
- 자모 2개, 자모 4개, 글자 2개와 자모 3개 합침, 식별자 단어와 글자 4개 합침 조건
- 오타 없는 질의의 재현율, 오타 질의의 1위 정밀도, 상위 10개 MRR
- 조건별 색인 어휘 수와 posting 수

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 질의를 문서 원문에서 잘라 만들어 오타 없는 질의는 정답을 찾기 쉽다. | 모든 조건에 같은 질의를 넣고 조건 사이 차이만 해석한다. |
| 내적 | 문자열 포함으로 정한 정답 집합이 같은 구절을 가진 다른 문서까지 정답으로 센다. | 정답 집합이 5개를 넘는 질의는 만들지 않고, 모든 조건이 같은 정답 집합을 쓴다. |
| 구성 | 무작위 자모와 글자 오타는 실제 자판 오타(이웃 키, 두벌식 배치)와 분포가 다르다. | 오타 종류별 결과를 탐색 분석으로 따로 보고 적용 범위를 이 오타 모형으로 한정한다. |
| 구성 | 1위 정밀도는 엉뚱한 문서가 패킷에 섞이는 정도의 대리 지표다. | 상위 10개 MRR을 탐색 분석으로 함께 보고한다. |
| 외적 | Saturn 문서와 코드는 실제 채팅의 도구 결과, 로그, 사용자 입력과 다르다. | 적용 범위를 이 말뭉치로 적고, 실제 기록 표본이 필요하면 후속 실험 이슈로 넘긴다. |
| 외적 | 질의가 2~4어절, 식별자 2~3개로 짧아 긴 입력에서는 차이가 줄 수 있다. | 결론을 짧은 질의에 한정해 적는다. |
