# 임베딩 같은 뜻 찾기의 정확도와 비용: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#155](https://github.com/woonyong-choi/saturn/issues/155) |
| 관련 설계 | [맥락 고르기](../../design/context-selection.md), [용어 카탈로그](../../design/term-catalog.md) |
| 사전 데이터 | 모델을 고정하려고 두 모델 파일을 내려받아 크기와 SHA-256을 확인했다. ONNX Runtime과 tokenizers 배포 크기도 확인했다. 설명 추출 규칙을 고치려고 `scripts/01-collect.py plan`으로 개수만 보고, 첫 파일의 설명 8개를 읽었다. 짝 제안, 순위, 라벨은 보지 않았다. |

## 질문

한국어 말과 영문 식별자처럼 글자가 겹치지 않는 같은 뜻을 작은 로컬 다국어 임베딩 모델로 찾을 수 있는지 잰다. 짝 찾기의 정밀도와 재현율, 후보 순위에 임베딩 채널을 더했을 때의 재현율 차이, 설치 크기, 상주 메모리, 문장당 지연으로 [#154](https://github.com/woonyong-choi/saturn/issues/154)의 세 선택지 중 하나를 고른다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | multilingual-e5-small의 짝 제안 정밀도는 80% 이상이다. | Saturn 저장소 Rust 코드의 한국어 문서 주석 설명, 커밋 `1258e17`의 정의 이름 전체 |
| H2 | paraphrase-multilingual-MiniLM-L12-v2의 짝 제안 정밀도는 80% 이상이다. | H1과 같다. |
| H3 | multilingual-e5-small의 짝 찾기 재현율은 50% 이상이다. | H1과 같다. |
| H4 | paraphrase-multilingual-MiniLM-L12-v2의 짝 찾기 재현율은 50% 이상이다. | H1과 같다. |
| H5 | 같은 뜻 질의에서 단어 기반 순위에 multilingual-e5-small 채널을 RRF로 더하면 상위 10개 재현율이 10%p 이상 오른다. | 커밋 `1258e17`의 Saturn 문서 절과 코드 묶음, 짝이 `same`인 설명 질의 |
| H6 | H5와 같은 예측을 paraphrase-multilingual-MiniLM-L12-v2 채널로 한다. | H5와 같다. |
| H7 | 단어가 겹치는 질의에서 multilingual-e5-small 채널을 더한 순위의 상위 10개 재현율은 단어 기반 순위보다 2%p 넘게 낮지 않다. | H5의 말뭉치, 한글 2~4어절 질의와 영문 식별자 2~3개 질의 |
| H8 | H7과 같은 예측을 paraphrase-multilingual-MiniLM-L12-v2 채널로 한다. | H7과 같다. |
| H9 | multilingual-e5-small의 설치 크기는 200MB 이하, 상주 메모리 증가는 200MB 이하, 문장당 지연 p95는 20ms 이하다. | Apple M4, macOS, fastembed 0.8.1, ONNX Runtime 1.30.0 CPU |
| H10 | paraphrase-multilingual-MiniLM-L12-v2가 H9의 세 예산을 모두 지킨다. | H9와 같다. |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | 모델 두 개(`e5`, `minilm`)가 조건이다. 짝 찾기(H1~H4)는 모델끼리 기준 없이 목표값과 비교한다. 순위(H5~H8)는 단어 기반 순위 `base`가 기준이고 `base`와 임베딩 순위를 RRF로 합친 `rrf`가 후보다. 비용(H9, H10)은 예산과 비교한다. |
| 배정 | 모든 질의를 모든 조건에 넣는다. 설명 질의 추출, 접힘(fold) 배정, 순위 질의 추출, 라벨 시트 행 순서는 `random.Random(155)`로 정한다. |
| 눈가림 | 라벨을 붙이는 사람은 라벨 시트의 행 번호, 한국어 설명, 식별자만 본다. 어느 모델이 낸 제안인지, 정의 바로 위 주석에서 온 정답 짝인지, 유사도는 라벨이 끝날 때까지 보지 않는다. |
| 환경 | macOS, Apple M4, Python 3.13, fastembed 0.8.1, ONNX Runtime 1.30.0, 모델 두 개(아래 표). 실제 값은 `env.json`에 기록한다. 모델 파일은 fastembed 기본 캐시에 두고 저장소에 넣지 않는다. ONNX Runtime CPU 계산은 같은 컴퓨터에서 결정적이라고 보고 `verify`로 확인한다. |

| 조건 | 모델 | 출처와 revision | 모델 파일 | 크기 | SHA-256 |
|---|---|---|---|---|---|
| `e5` | `intfloat/multilingual-e5-small` | Hugging Face `intfloat/multilingual-e5-small`, `614241f622f53c4eeff9890bdc4f31cfecc418b3` | `onnx/model.onnx` | 470,268,510바이트 | `ca456c06b3a9505ddfd9131408916dd79290368331e7d76bb621f1cba6bc8665` |
| `minilm` | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` | Hugging Face `qdrant/paraphrase-multilingual-MiniLM-L12-v2-onnx-Q`, `faf4aa4225822f3bc6376869cb1164e8e3feedd0` | `model_optimized.onnx` | 235,052,644바이트 | `634d0f66c29dc934c8fa72b8a4fe91dd4d420a22f1d82a241058d4316e659a99` |

- 수집 스크립트는 모델 파일의 크기와 SHA-256이 표와 다르면 멈춘다.
- 임베딩은 L2 정규화하고 유사도는 내적(코사인)이다. `e5`는 짝 찾기에서 두 쪽 모두 `query: `를, 순위에서 질의에 `query: `, 문서에 `passage: `를 붙인다. `minilm`은 접두어를 붙이지 않는다.
- 입력이 모델 최대 길이를 넘으면 fastembed 기본값대로 자른다.

### 평가 세트

말뭉치는 커밋 `1258e17dd1a6d527249b0aaa9dccd96aef8aec2a`의 Saturn 저장소 파일만 쓴다. `git show`로 읽고 작업 트리는 읽지 않는다. 비공개 기록 폴더, 대화 기록, `docs/experiments/`는 쓰지 않는다.

| 집합 | 만드는 법 |
|---|---|
| 식별자 후보 | 모든 `.rs` 파일에서 `fn`, `struct`, `enum`, `trait`, `type`, `const`, `static`, `mod`, `union` 정의 이름과, 문서 주석(`///`)이 붙은 필드와 enum variant 이름. 이름마다 하나 |
| 설명 짝 후보 | 문서 주석 묶음 바로 아래(속성 줄 건너뜀)에 정의가 있으면 주석의 첫 문장과 정의 이름을 짝으로 삼는다. 첫 문장에서 코드 표시, 영문, 숫자, 기호를 지우고 한글 음절이 6개 이상 남을 때만 쓴다. |
| 설명 질의 | 설명 짝 후보에서 같은 설명을 하나로 줄이고 섞은 뒤 앞 200개. 질의마다 접힘 0 또는 1을 반씩 배정한다. |
| 순위 문서 | `docs/` 아래와 루트의 Markdown은 제목마다 절 하나, `.rs` 파일은 40줄마다 묶음 하나. 코드 묶음은 주석과 문자열 상수를 빼고 식별자만 남긴다. 20자 미만 문서는 뺀다. |
| 같은 뜻 질의 | 설명 질의 원문. 정답은 그 정의 줄이 든 코드 묶음 하나다. 코드 묶음에는 주석이 없어 한글 글자가 정답과 겹치지 않는다. 확인 분석은 정답 짝 라벨이 `same`인 질의만 쓴다. |
| 단어 겹침 질의 | Markdown 한 줄의 한글 어절 2~4개 200개와 코드 한 줄의 식별자 2~3개 200개. 정답은 공백을 하나로 줄인 본문에 질의 문자열이 든 문서 전부이고 5개를 넘으면 그 질의를 만들지 않는다. 한 문서에서 8개까지 뽑는다. |

- 임베딩에 넣는 식별자는 camelCase, snake_case 경계에서 나눈 소문자 단어를 공백으로 이은 글이다(`EffectScope`는 `effect scope`). 코드 묶음도 같은 규칙으로 바꿔 넣는다. BM25에는 원문을 넣는다.

### 라벨 판정 기준표

라벨 시트는 설명 질의마다 정답 짝 하나와 두 모델의 1위 제안을 모아 같은 행을 하나로 줄인 것이다. 라벨은 실험자 한 명이 아래 기준표로 붙인다.

| 라벨 | 기준 | 예 |
|---|---|---|
| `same` | 한국어 설명을 읽은 개발자가 찾으려는 대상이 그 식별자다. 설명이 그 식별자가 가리키는 값, 타입, 함수, 상태를 직접 설명하거나 이름을 옮긴다. | `채팅 트리 전체 기록의 연속 번호`와 `LedgerSeq`, `토큰 수`와 `input_tokens` |
| `different` | 설명이 다른 대상을 가리키거나, 설명이 그 대상의 조건, 예외, 사용법만 말해 설명만으로 그 식별자를 고를 수 없다. 상위와 하위 개념, 부분과 전체도 여기에 든다. | `읽지 못하면 없다`와 `id`, `큰 정수는 로 쓴다`와 `typescript` |
| `unclear` | 설명과 식별자만으로 판정할 수 없다. | 뜻을 알 수 없는 약어 식별자 |

- 확인 분석에서 `unclear`는 `same`이 아닌 것으로 센다.
- 라벨 파일은 `data/raw/labels-{실행 id}.csv`이고 열은 `run_id`, `trial_id`, `condition`, `ts_utc`, `row_id`, `label`이다. 라벨을 붙인 뒤 `scripts/01-collect.py seal`이 빈 라벨을 막고 `SHA256SUMS`를 만든다.

### 짝 제안과 기준값

1. 모델마다 설명 질의와 식별자 후보 전체의 유사도를 계산하고 1위 식별자를 그 질의의 제안으로 둔다.
2. 접힘마다 다른 접힘의 라벨로 기준값 τ를 고른다. τ는 다른 접힘의 제안 정밀도가 85% 이상인 값 중 재현율이 가장 큰 값이고, 같으면 큰 값이다. 그런 값이 없으면 그 접힘은 아무것도 제안하지 않는다.
3. 1위 유사도가 τ 이상인 제안만 낸다. 두 접힘의 결과를 모아 정밀도와 재현율을 센다.

- 기준값을 다른 접힘에서 고르는 것은 같은 라벨로 기준값을 고르고 평가해 정밀도가 부풀지 않게 하기 위해서다.

### 순위 조건

- `base`: [맥락 고르기](../../design/context-selection.md)의 기준 단어 조각(한글 글자 2개, 영문 식별자 단어)과 BM25(`k1`=1.2, `b`=0.75). 점수가 0인 문서는 순위에 넣지 않는다. 이 말뭉치에는 기록 번호와 건드린 파일이 없어 파일 겹침, 최근성 채널은 쓰지 않는다.
- `embedding`: 문서 전체를 질의와의 유사도 순으로 둔 목록. 탐색 분석에만 쓴다.
- `rrf`: `base`와 `embedding` 두 목록을 `k`=60 RRF로 합친 순위. 점수가 같으면 문서 순서가 앞인 것을 위에 둔다.

### 비용 측정

| 측정 | 방법 |
|---|---|
| 설치 크기 | 모델 snapshot 폴더의 모든 파일 크기 합 + `onnxruntime` 배포 파일 합 + `tokenizers` 배포 파일 합. Rust로 옮겨도 ONNX Runtime과 tokenizer가 필요하기 때문이다. |
| 상주 메모리 증가 | 모델마다 새 Python 프로세스에서 `fastembed`를 불러온 직후 RSS와, 모델을 올리고 지연 측정을 끝낸 뒤 RSS의 차이(`ps -o rss`) |
| 문장당 지연 | 같은 프로세스에서 설명 질의 200개를 한 문장씩(묶음 크기 1) 임베딩한다. 예열 20문장은 버리고 200문장을 3번 돌린 600개 값을 쓴다. ONNX Runtime 스레드는 기본값이다. |

- 예산은 설치 크기 200MB(10^6바이트 단위), 상주 메모리 증가 200MB, 지연 p95 20ms다. 설치 크기 예산은 이 컴퓨터의 Claude Code 설치 폴더 213MB(2026-10-01 확인)를 넘지 않게 정했다. Saturn이 감싸는 provider 하나보다 같은 뜻 찾기 하나가 더 크지 않게 하기 위해서다. 지연 예산은 한 턴에 새 기록 150개를 임베딩해도 3초 안에 끝나게 정했다.

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| `model` | 조작 | 임베딩 모델: `e5`, `minilm` | 해당 없음 |
| `ranking` | 조작 | 순위 조건: `base`, `embedding`, `rrf` | 해당 없음 |
| `fold` | 조작 | 설명 질의의 접힘: 0, 1 | 해당 없음 |
| `top1_score` | 측정 | 설명 질의와 1위 식별자의 코사인 유사도 | 없음 |
| `label` | 측정 | 기준표에 따른 라벨: `same`, `different`, `unclear` | 해당 없음 |
| `precision` | 파생 | τ 이상 제안 중 `same` 제안 수 ÷ τ 이상 제안 수 | % |
| `recall` | 파생 | 정답 짝이 `same`인 질의 중 τ 이상 `same` 제안을 받은 질의 수 ÷ 정답 짝이 `same`인 질의 수 | % |
| `gold_rank` | 측정 | 순위 질의의 정답 문서 중 가장 높은 순위. 순위에 없으면 결측 | 순위 |
| `recall_at_10` | 파생 | `gold_rank`가 10 이하인 질의 비율 | % |
| `diff` | 파생 | 같은 질의에서 `rrf`의 `recall_at_10` 빼기 `base`의 값 | %p |
| `install_bytes` | 측정 | 설치 크기 | MB |
| `rss_increase_bytes` | 측정 | 상주 메모리 증가 | MB |
| `latency_ms` | 측정 | 문장 하나 임베딩의 벽시계 시간 | ms |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 커밋 `1258e17`의 Saturn 문서와 Rust 코드 |
| 크기 | 설명 질의 200개(라벨 행은 최대 600개), 단어 겹침 질의 언어마다 200개, 지연 값 모델마다 600개 |
| 크기 근거 | 정밀도. 설명 질의의 정답 짝 중 `same`이 60%면 재현율 n=120이고 50%에서 95% Wilson 신뢰구간 반폭은 약 8.8%p다. 제안 정밀도 n=100이면 80%에서 반폭은 약 7.7%p다. 단어 겹침 질의 400개는 불일치 질의 5%일 때 짝 차이 반폭이 약 2.2%p다. 라벨 예산은 한 사람이 하루에 붙일 600행이다. |
| 중단 규칙 | 수집은 한 번 실행하고 끝낸다. 라벨은 시트의 모든 행에 붙인 뒤 멈춘다. 단어 겹침 질의는 섞은 후보 위치를 차례로 보며 200개를 채우면 멈춘다. |
| 반복과 예열 | 짝과 순위 계산은 결정적이라 반복하지 않고 `verify`가 한 번 다시 계산해 비교한다. 지연은 예열 20문장을 버리고 3번 반복한다. |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | `precision`(`e5`) | 비율과 95% Wilson 신뢰구간, 양쪽 정확 이항 검정(기준 80%) | 채택: 하한 ≥ 80%이고 Holm 보정 p < 0.05. 기각: 상한 < 80%이고 Holm 보정 p < 0.05, 또는 제안 0개. 보류: 그 밖의 결과 |
| H2 | `precision`(`minilm`) | H1과 동일 | H1과 동일 |
| H3 | `recall`(`e5`) | 비율과 95% Wilson 신뢰구간, 양쪽 정확 이항 검정(기준 50%) | 채택: 하한 ≥ 50%이고 Holm 보정 p < 0.05. 기각: 상한 < 50%이고 Holm 보정 p < 0.05. 보류: 그 밖의 결과 |
| H4 | `recall`(`minilm`) | H3과 동일 | H3과 동일 |
| H5 | `diff`(`e5`, 같은 뜻 질의) | 2×2 표, McNemar 검정(b+c < 25면 정확 이항), Newcombe 방법 10 차이 신뢰구간 | 채택: Holm 보정 p < 0.05, 차이 하한 > 0, 차이 ≥ 10%p. 기각: 상한 < 10%p. 보류: 그 밖의 결과 |
| H6 | `diff`(`minilm`, 같은 뜻 질의) | H5와 동일 | H5와 동일 |
| H7 | `diff`(`e5`, 단어 겹침 질의 400개) | 2×2 표, Newcombe 방법 10 차이 신뢰구간 | 채택: 차이 하한 > −2%p. 기각: 그 밖의 결과 |
| H8 | `diff`(`minilm`, 단어 겹침 질의 400개) | H7과 동일 | H7과 동일 |
| H9 | `install_bytes`, `rss_increase_bytes`, `latency_ms`(`e5`) | 설치 크기와 메모리는 측정값 하나, 지연은 평균, 표준편차, 중앙값, p5, p95와 이상치 수(경미 1.5 IQR, 심각 3 IQR) | 세 값이 모두 예산 이하면 채택, 아니면 기각 |
| H10 | H9의 세 값(`minilm`) | H9와 동일 | H9와 동일 |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 추출 규칙(한글 6음절 미만, 같은 설명, 정답 문서 5개 초과)으로 만들지 않은 질의만 뺀다. 같은 뜻 질의 확인 분석은 정답 짝 라벨이 `same`이 아닌 질의를 빼고 흐름 표에 센다. |
| 실패한 실행 | 정답이 순위에 없거나 10위 밖이면 놓침이다. 수집이 중간에 멈추면 그 실행 파일을 쓰지 않고 새 실행 id로 다시 수집하며 흐름 표에 한 행으로 남긴다. |
| 다중 비교 | H1~H6의 p값에 Holm-Bonferroni 보정을 한다. H7, H8은 신뢰구간으로만, H9, H10은 예산 비교로만 판정한다. |

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 채택 | 같은 모델의 H5(또는 H6), H7(또는 H8), H9(또는 H10)가 모두 채택이면 그 모델의 임베딩 채널을 RRF 네 번째 목록으로 더한다. [맥락 고르기](../../design/context-selection.md)의 순위 채널 표와 [용어 카탈로그](../../design/term-catalog.md)를 고치고, [결정 기록](../../decisions/2026-10-01-lexical-ranking-with-term-catalog.md)을 대체하는 새 결정 기록을 쓴다. 채널 조건은 아니지만 같은 모델의 H1(또는 H2), H3(또는 H4), 비용이 모두 채택이면 임베딩으로 짝을 찾아 카탈로그에 저장하는 방식으로 같은 문서들을 고친다. |
| 기각 | 위 조건을 채우는 모델이 없으면 같은 뜻 찾기 없이 judge에 맡긴다. 설계는 그대로 두고 보고서 논의에 이유를 적는다. 정확도 가설은 채택인데 비용만 기각이면 양자화 모델이나 더 작은 모델의 비용을 재는 후속 실험 이슈를 연다. |
| 보류 | 기각과 같이 설계를 두고, 설명 질의를 늘리거나 두 사람 라벨로 다시 재는 후속 실험 이슈를 연다. |

## 탐색 분석

- 정답 짝이 `same`인 질의에서 식별자 후보 전체 중 정답의 순위(1위, 5위, 10위 안 비율)
- 기준값 없이 1위 제안 전부의 정밀도와 두 모델의 McNemar 비교
- `unclear`를 뺀 정밀도
- 정의 종류(`fn`, `field`, `variant` 등)별 1위 정확도
- 질의 묶음별 `base`, `embedding`, `rrf`의 상위 10개 재현율
- 모델 올리는 시간과 최대 RSS

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 라벨을 붙이는 사람이 실험자 한 명이라 기대에 맞춰 라벨이 기울 수 있다. | 모델, 출처, 유사도를 가린 섞인 시트로 붙이고 기준표를 미리 고정한다. 두 사람 일치도는 재지 못한다고 보고서에 적는다. |
