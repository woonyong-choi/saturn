# 임베딩 같은 뜻 찾기의 정확도와 비용: 실험 결과

## 요약

두 모델 모두 한국어 설명과 식별자 짝을 찾지 못해 재현율이 0/60, 0.0% [0.0, 6.0]이고, 같은 뜻 질의의 상위 10개 재현율도 단어 기반 순위와 같은 0.0%였다(차이 0.0%p [−6.0, 6.0], n=60). 단어가 겹치는 질의에서는 임베딩 채널이 재현율을 10.5%p [−13.9, −7.6](multilingual-e5-small), 28.3%p [−32.9, −23.8](paraphrase-multilingual-MiniLM-L12-v2) 낮췄고, 설치 크기 577.7MB, 342.5MB와 상주 메모리 증가 406.0MB, 287.4MB가 예산 200MB를 넘었다. 열 가설이 모두 기각이다. 판정 표대로 같은 뜻 찾기 없이 judge에 맡기고 설계는 그대로 두며, 사용자가 짝을 직접 고치는 설정은 별도 결정에 따라 설계에서 뺐다.

- H1, H2: 두 접힘 모두 다른 접힘에서 정밀도 85%를 넘는 기준값이 없어 제안을 내지 않았다. 설계의 판정 규칙대로 제안 0개는 기각이다.
- H3, H4: 양쪽 정확 이항 검정 p = 1.735×10⁻¹⁸, Holm 보정 p = 1.041×10⁻¹⁷이다.
- H5, H6: 두 순위 모두 60개 질의 전부를 놓쳐 불일치 수 b = c = 0이고 McNemar p = 1.0이다. 차이 상한 6.0%p가 기준 10%p보다 낮아 기각이다.
- H7: 단어 기반 98.8% [97.1, 99.5]에서 e5를 더한 순위 88.2% [84.7, 91.0]로 내려갔다. 기준만 맞힌 질의 43개, 후보만 맞힌 질의 1개다(McNemar χ² = 38.205).
- H8: MiniLM을 더한 순위는 70.5% [65.9, 74.8]이다. 기준만 맞힌 질의 115개, 후보만 맞힌 질의 2개다(McNemar χ² = 107.214).
- H9: 설치 크기는 모델 파일 487.4MB, ONNX Runtime 82.4MB, tokenizers 7.9MB의 합이다. 지연은 평균 3.56ms, 표준편차 0.976ms, 중앙값 3.39ms, p5 2.6ms, p95 4.82ms이고 이상치는 경미 10개, 심각 11개다. 지연만 예산 안이다.

### 탐색 분석

기준값 없이 1위 제안 전부를 세면 정밀도는 e5 18/200, 9.0% [5.8, 13.8], MiniLM 8/200, 4.0% [2.0, 7.7]이다. e5가 MiniLM보다 5.0%p [0.9, 9.6] 높았다(정확 이항 p = 0.03088, 불일치 14 대 4). 정답 짝이 `same`인 60개 질의에서 식별자 후보 전체 중 정답의 순위는 두 모델 모두 1위 3.3% [0.9, 11.4], 10위 안 10.0% [4.7, 20.1]이다. e5의 1위 정확도는 정의 종류별로 `const` 3/15, `field` 3/15, `variant` 4/15, `struct` 1/5, `fn` 0/9였다. 같은 뜻 질의에서 임베딩 순위만 써도 상위 10개 재현율은 두 모델 모두 0.0% [0.0, 6.0]이다. 단어 겹침 질의에서 임베딩 순위만 쓴 재현율은 e5가 한글 60.5%, 영문 66.0%, MiniLM이 한글 9.0%, 영문 41.5%이다. 모델 올리는 시간은 e5 0.701초, MiniLM 0.446초, 최대 RSS는 1,066.2MB, 855.0MB였다.

## 논의

### 해석

작은 다국어 임베딩 모델 두 개는 한국어 설명을 영문 식별자로 잇지 못했고, 후보 순위에서는 한국어 질의가 한국어 문서 쪽으로 끌려 주석 없는 코드 묶음을 상위에 올리지 못했다. 임베딩 채널은 같은 뜻 질의에서 얻은 것이 없고 단어가 겹치는 질의의 재현율만 낮춘다. 비용도 지연을 빼면 설치 크기와 메모리가 예산을 넘어, 판정 표대로 같은 뜻 찾기 없이 judge에 맡긴다. 정확도 가설이 모두 기각이라 비용만 기각일 때의 후속 실험(양자화 모델)은 열지 않는다.

### 타당성 위협

| 종류 | 위협 | 이 실험에서 |
|---|---|---|
| 내적 | 라벨을 붙이는 사람이 실험자 한 명이라 기대에 맞춰 라벨이 기울 수 있다. | 모델, 출처, 유사도를 가린 시트로 583행에 붙였다. 정답 짝 200개 중 140개가 `same`이 아니어서 주석 첫 문장이 정의 이름을 설명하지 않는 경우가 많았다. 두 사람 일치도는 재지 못했다. |
| 내적 | 라벨 시트가 두 모델의 1위 제안과 정답 짝만 담아, 두 모델 모두 놓친 다른 `same` 식별자가 재현율 분모에서 빠진다. | 재현율 분모는 정답 짝이 `same`인 60개 질의였다. 1위 제안 중 `same`은 e5 18개, MiniLM 8개뿐이라 빠진 식별자가 결론을 바꿀 만큼 많지 않다. |
| 구성 | 문서 주석 설명은 사용자의 짧은 한국어 입력이나 `로그인` 같은 한 단어 용어와 모양이 다르다. | 설명에서 영문과 코드 표시를 지워 조각난 문장이 많았다. 결론은 설명 문장과 식별자의 짝에 한정된다. |
| 구성 | 같은 뜻 질의의 정답 코드 묶음에서 주석을 빼서, 실제 도구 결과보다 단어 기반 순위가 불리하다. | 단어 기반 순위의 같은 뜻 재현율은 설계대로 0.0%였다. 임베딩 순위도 0.0%라 이 조작이 차이를 만들지 않았다. |
| 구성 | `minilm`은 최대 128 토큰이라 긴 문서 절과 코드 묶음이 잘린다. | MiniLM의 단어 겹침 질의 임베딩 단독 재현율이 e5보다 낮았고 잘림이 원인일 수 있다. e5도 기각이라 결론은 같다. |
| 외적 | Saturn 저장소 하나와 Apple M4 한 대에서 잰다. | 지연은 이 CPU에서만 예산 안이었다. 설치 크기와 메모리는 CPU와 무관하게 예산을 넘었다. |
| 외적 | 설치 크기를 Python 배포 파일로 재서 Rust 배포와 다를 수 있다. | 모델 파일만으로 e5 487.4MB, MiniLM 252.1MB라 런타임을 빼도 예산을 넘는다. |

### 한계

- 라벨은 한 사람이 붙였고 일치도를 재지 못했다.
- 설명 질의 200개 중 정답 짝이 `same`인 질의가 60개라 재현율 신뢰구간 반폭이 설계 추정보다 넓다.
- 양자화 모델과 더 큰 다국어 모델은 재지 않았다.
- 실제 채팅의 사용자 입력과 도구 결과가 아닌 저장소 문서와 코드로 쟀다.
