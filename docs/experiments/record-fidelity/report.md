# 기록 변환 충실도와 전환 품질: 실험 결과

## 요약

두 provider가 모두 거친 항목에서 Codex 기록의 파일 경로 추출 정확도는 0.0%(0/120)로 Claude Code 기록 20.0%(24/120)보다 20.0%p 낮았고(차이의 95% 신뢰구간 [−28.0, −13.1]), 메모 필드 정확도는 0.0%(0/192)로 25.0%(48/192)보다 25.0%p 낮았다([−31.6, −19.1]). 근거 항목 포착률(312/312)과 도구 종류 변환 정확도(168/192)는 두 provider가 같았으므로 C1은 기각이고, 낮은 값은 Saturn의 변환이 Codex 결과의 종료 코드와 수정 내용을 버리기 때문이다. 진행 조건 (가)에 따라 2단계는 하지 않았고 변환 버그 이슈 3개를 열었다.

- 포착률과 도구 종류 정확도의 군집 부트스트랩 구간은 [0.0, 0.0]이었고 경로와 메모는 각각 [−20.0, −20.0], [−25.0, −25.0]이었다. 모든 작업이 같은 값이라 구간이 한 점으로 모였다. 두 구간의 판정은 모든 지표에서 같았다.
- 도구 종류 정확도 87.5%에서 틀린 24개는 두 provider 모두 테스트 실행이 셸 명령으로 바뀐 것이다.
- Claude Code의 경로 24개와 메모 48개는 수정 결과 글에 든 경로와 종료 코드가 0이 아닐 때 붙는 `Exit code N`에서 나왔다. 경로 필드나 종료 코드 필드에서 나온 것이 아니다.
- 근거 사실이 패킷에 든 비율은 `oracle` 조건에서 Codex 46.2%(144/312), Claude Code 45.5%(142/312)로 차이 0.6%p [−2.6, 3.9], `rrf-only` 조건에서 Codex 46.2%(144/312), Claude Code 41.7%(130/312)로 차이 4.5%p [1.3, 7.7]이었다. 예산 800토큰에서 근거 사실의 절반 안팎이 들어갔다. 패킷 포함률은 C1의 판정 지표가 아니다.

### 탐색 분석

Codex 기록에는 도구가 아닌 추론 항목이 `Thinking` 도구 호출로 53개 남았고(Claude Code 0개), 셸 명령 72개가 모두 `/bin/zsh -lc`로 감싸져 있었다(Claude Code 0개). Codex의 파일 수정 결과 24개가 모두 빈 글이었다(Claude Code 0개). Claude Code는 같은 작업에서 수정 전에 설정 파일을 먼저 읽어 읽기 호출이 118개였다(Codex 96개).

## 논의

### 해석

Saturn의 이벤트 변환은 값이 글로 남은 근거를 두 provider에서 같게 보존하지만, 종료 코드, 파일 경로, 수정 줄 수처럼 메모 틀이 요구하는 구조 값은 어느 provider에서도 얻지 못한다. Codex는 종료 코드와 수정 내용을 이벤트로 옮길 때 버려서, Claude Code가 결과 글에 우연히 싣는 값마저 없다. 패킷 포함률 차이는 작아 전환 품질이 낮아졌다고 볼 근거는 이 실험에 없고, 이것은 받는 쪽을 실행하지 않은 기계 측정의 결과다. 변환 문제는 [#203](https://github.com/woonyong-choi/saturn/issues/203), [#204](https://github.com/woonyong-choi/saturn/issues/204), [#205](https://github.com/woonyong-choi/saturn/issues/205)에서 고친다.

### 타당성 위협

| 종류 | 위협 | 이 실험에서 |
|---|---|---|
| 내적 | 근거 사실은 같은 작업 안에서 서로 기대므로 사실 단위 독립 구간이 좁다. | 작업 단위 군집 부트스트랩을 함께 구했고 판정이 같았다. 다만 작업이 같은 틀이라 구간이 한 점으로 모였다. |
| 내적 | provider가 지시와 다르게 도구를 더 부르면 항목 수가 달라진다. | 근거 사실 312개 모두 두 provider가 거쳤고, Claude Code의 추가 읽기 22개는 항목 대응에 영향을 주지 않았다. |
| 구성 | 경로와 메모 필드 규칙은 이벤트로 얻을 수 있는 최소 규칙이다. | 두 provider에 같은 규칙을 썼다. 변환이 필드를 갖게 되면 값이 달라지므로 수정 뒤 다시 잰다. |
| 구성 | 합성 작업은 읽기와 명령 위주라 실제 작업의 도구 다양성이 없다. | 파일 읽기, 셸 명령, 테스트 실행, 파일 수정 네 종류만 쟀다. |
| 외적 | Codex CLI 0.158.0, Claude Code 2.1.285 한 버전만 쟀다. | 버전을 `env.json`에 남겼다. |
| 외적 | 사용자 provider 설정이 두 provider의 이벤트에 다르게 섞인다. | Claude Code는 프로젝트 설정만, Codex는 사용자 설정을 그대로 썼고 원시 줄에서 개인 설정 줄을 지웠다. |

### 한계

- 받는 쪽을 실행하지 않아 전환 품질(정답률)은 재지 못했다. C2는 [#203](https://github.com/woonyong-choi/saturn/issues/203)과 [#204](https://github.com/woonyong-choi/saturn/issues/204)의 수정이 머지된 뒤 새 실행으로 정한다.
- 같은 계정을 쓰는 다른 실험의 사용이 사용률에 섞여 이 실험만의 증가는 알 수 없다.
- 2단계 수집과 분석 스크립트는 실제로 실행하지 않았다.
