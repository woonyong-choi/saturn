# Jev 역할별 효율: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#534](https://github.com/woonyong-choi/saturn/issues/534) |
| 관련 설계 | [router](../../design/router.md), [맥락 고르기](../../design/context-selection.md) |
| 사전 데이터 | 기존 1,000건 합의 라벨, constraint-scope, target-model-choice와 같은 session 축약 결과를 열람했다. 새 표본의 정답으로 사용하지 않는다. |

## 질문

기존 작업 LLM의 이해 능력을 유지하면서 Jev를 제한된 선택에 넣으면 실제 후속 성과와 총비용이 개선되는지 측정한다. 모델 선호 일치, 선택 정확도, 후속 작업 성공을 구분한다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 선호를 반영한 Jev 모델 선택은 고정 단계 정책 대비 성공률 손실이 3%p 이내이고 성공당 운영 비용 또는 중앙 지연을 15% 이상 줄인다. | 새 작업 모델 선택, 도구 없는 합성 과제부터 시작 |
| H2 | 기존 LLM 후보에 대한 Jev 선별은 코드 선별보다 잘못 적용된 제약을 30% 이상 줄이며 후속 성공률 손실은 3%p 이내다. | 근거·범위·시점이 붙은 동일한 후보 집합 |
| H3 | 동일한 기록 예산에서 Jev 선별은 최근 순서와 어휘 순위보다 후속 성공률이 각각 10%p 이상 높다. | 새 session에 원문 기록 블록을 전달하는 축약 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | H1: 단계 고정, Jev 직접 모델 선택, Jev 원자 판단과 단계 선호 결합. H2: 코드 선별, Jev 선별, 추가 Sol 재판정 참고 조건. H3: 원본 전체, 최근 순서, 어휘 순위, Jev 선별 |
| 배정 | 시드 534106. 같은 입력과 후보를 공유하고 모델 및 조건 실행 순서를 섞는다. 별도 session으로 실행한다. |
| 눈가림 | Jev와 실행 모델에는 정답·후속 결과를 주지 않는다. 프로그램 채점기는 모델 이름을 사용하지 않는다. 설계 검토는 실행 결과를 보기 전에 한다. |
| 환경 | 로컬 공식 Claude와 Codex CLI, TypeSafe Jev 1.13.0 HTTPS API. 실행 모델의 요청 이름과 실제 보고 이름을 따로 보존한다. 보고하지 않은 실제 이름은 unknown이다. |

### 모델 선호와 적용 규칙

사용자의 ops는 Opus로 해석한다. 초기 설계는 Opus, 설계 검증은 Sol을 기본으로 하고 위험도가 높은 검증은 Astra, 구현은 Sonnet을 기준선으로 둔다. 단순한 변환·추출은 Haiku를 기준선으로 두고 Luna와 Terra를 비교 후보로 둔다. 이 선호를 성능 정답으로 채점하지 않는다.

직접 선택 조건은 이 선호와 후보를 Jev에 준다. 분해 조건은 phase, mechanical, high_risk를 독립 질문으로 묻는다. phase 확신도 0.6 미만이나 응답 실패는 입력에 지정된 단계 기준선으로 돌아간다. mechanical이 0.9 이상이고 high_risk가 0.1 이하일 때만 Haiku로 내린다. 검증에서 high_risk가 0.7 이상이면 Astra, 그 밖에는 단계 기준선이다. 경계값은 첫 예비 실험을 위한 가정이며 정밀도나 실제 비용에서 도출한 최적값이 아니다. Luna와 Terra의 확대 적용은 같은 과제의 실행 결과를 보고 다음 설계에서 정한다.

사용자 고정 모델, 권한, 도구 지원, 맥락 한도는 결정적 필터다. Jev는 이를 해제하지 않는다. 내부 API 호출별 모델 교체를 현재 engine 지원으로 주장하지 않는다. 실제 적용 전 revision을 다시 비교하며, 실패하면 기존 모델을 유지한다.

### 기존 LLM 해석과 Jev의 경계

H2의 Sonnet은 작업 응답과 함께 제약 후보를 한 번 생성한다. 후보는 id, statement, evidence_ids, scope, active를 담는다. 세 조건은 같은 응답을 재사용한다. 코드 기준선은 유효한 근거 ID, 현재 범위, active만 검사한다. Jev는 원문 근거에 의해 지지되는지, 최신 원문에서 유효한지, 지금 작업에 적용되는지를 각각 묻고 세 확률이 모두 0.8 이상인 후보만 남긴다. 판단 실패는 코드 기준선이다.

추가 Sol 재판정은 비용이 드는 참고 조건이며 제품 경로로 제안하지 않는다. 후보를 만드는 실제 작업 응답의 추가 토큰과 지연도 비용이다. 이번 예비 실험은 해당 구조를 모사한 독립 호출이며 기존 제품 응답에 후보 생성이 연결되어 있다는 증거가 아니다. LLM이 후보를 누락하면 Jev가 복구할 수 없으므로 후보 재현율과 선택 이후 재현율을 따로 보고한다. 제약을 영구 등록하지 않으며 원문은 보존한다.

### 맥락 선별과 전환

H3는 고정 크기로 채운 12개 원문 블록 중 3개를 선택한다. 최근 순서, 단어 집합 교집합 순위, Jev 관련성 확률 순위를 비교한다. 세 조건 모두 같은 최대 UTF-8 바이트 예산을 사용한다. 실제 tokenizer 예산의 동일성을 주장하지 않으며 provider 입력 토큰을 별도로 기록한다. 전체 원문은 품질 상한 참고 조건이다. 답은 무작위 값의 결합, 최신 사실, 누락 시 unknown을 포함한다. 정답 위치는 앞·중간·뒤로 이동하고, 어휘가 겹치는 오답 기록과 폐기된 사실을 넣는다.

Jev는 현재 요청과 블록 전체를 받지만 숨겨진 기대 정답은 받지 않는다. Sonnet은 선별 블록만 받는다. 모든 조건의 출력 형식은 같다. 선택·생략 ID와 해시를 보존한다. 같은 provider session의 원문 삭제나 native compact는 이 실험의 실행 범위가 아니다. 같은 session 적용은 이 선별 효과가 독립 자료에서 확인된 뒤 provider가 지원하는 방식으로 별도 사전 등록한다.

### 호출·비용·채점 계약

각 과제의 질문은 같은 state를 쓰는 한 HTTP 요청에 묶는다. H1 8회, H2 최대 6회, H3 8회로 예비 Jev 호출은 최대 22회다. H2 후보는 12개까지이며 초과·중복 ID·스키마 오류는 후보 생성 실패다. 직접 모델 선택은 일곱 후보 모두를 허용한다. 분해 정책에서 Luna와 Terra 선택은 비교 결과에 따른 다음 설계로 남긴다. 수집 전 fixture, 질문, 채점기 해시를 커밋으로 봉인하고 키를 자식 CLI에서 제거한다.

H1의 정책 지연은 과제별 Jev 요청 시간과 선택 모델 실행 시간의 합이다. 단계 고정은 실행 시간만이다. H2는 공유 후보 생성 시간, 해당 선택 시간, 후속 실행 시간의 합이다. H3는 선택 시간과 후속 실행 시간의 합이다. 대기열 시간은 제외하고 독립 호출을 합성한 추정임을 표시한다. 운영 비용도 같은 범위로 더하되 미보고 비용이 하나라도 있으면 완전한 합계는 null이다. 전체 모델 행렬과 설계 검토 비용은 실험 비용이다. 본 실험 효율의 주 기준은 총지연 15% 감소이며 비용은 필수 보고 보조 지표다.

H2의 합성 정답은 fixture 작성 시 현재 언어·형식·검사 요구 값으로 고정한다. 후속 Sonnet은 선택 후보만 보고 세 필드 설정을 산출한다. 전체 설정의 정확 일치를 후속 성공으로 센다. 선택 후보가 기대 값과 다르면 잘못된 선택으로 센다. 올바른 값이지만 근거가 없는 후보를 자동 검출하지 못하므로 이 대리 지표로 H2의 근거 오류 감소를 채택하지 않는다. 기본값과 다른 제약의 후보 재현율을 따로 기록하고, 분모 0은 null이다. 기준선 오류가 0이면 상대 오류 감소는 정의하지 않는다.

예비 실험의 각 비율에는 Wilson 구간을 붙이고, 정책 비교에는 같은 과제의 성공 차이와 두 방향 불일치 수를 붙인다. 예비 대응 구간이나 p값으로 채택하지 않는다. 호출 실패·후보 실패도 분모에 남기고 fallback 뒤 성과를 구분한다.

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 새로 만든 합성 과제. 실제 사용자 원문과 이전 정답지는 사용하지 않는다. |
| 크기 | 예비 H1 8과제×7모델, H2 6과제×3정책, H3 8과제×4정책 |
| 크기 근거 | 예산 기반 계측 점검. 설계 검토를 포함해 CLI 최대 140회, Jev 최대 100회. 품질 채택 검정력이 있는 표본으로 보지 않는다. |
| 중단 규칙 | 예약 상한, 인증 거절, 원자료 해시 불일치에서 중단한다. 개별 오류·timeout은 보존하고 다음 독립 과제를 진행한다. 자동 재시도하지 않는다. |
| 반복과 예열 | 각 조합 1회, 제외 예열 없음. 반복 안정성이나 p95 운영 지연은 이 표본으로 확정하지 않는다. |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | 후속 성공 차이, 정책 선택 모델, 선호 일치, 지연, 비용 | 같은 과제 대응 결과와 95% Wilson 구간, 오류 포함 | 예비 표본에서는 채택하지 않는다. 본 실험의 품질 하한과 효율 상한이 모두 기준을 만족해야 한다. |
| H2 | 후보 생성 재현율, 선택 정밀도·재현율, 후속 성공 | 후보 누락과 잘못된 선별을 분리하고 과제별 집계 | 예비 표본에서는 채택하지 않는다. 근거 없는 영구 적용은 별도 중대 실패로 센다. |
| H3 | 후속 성공 차이, 근거 블록 보존, 실제 입력량 | 원본 전체 대비 손실과 두 기준선 대비 차이 | 예비 표본에서는 채택하지 않는다. 입력 축소만으로 품질 개선을 판정하지 않는다. |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 수집 전 스키마 검사에 실패한 fixture만 수정한다. 실행 뒤 실패한 조합은 제외하지 않는다. |
| 실패한 실행 | 요청 실패, 잘못된 JSON, 후보 밖 값은 실패로 집계한다. 가용성 실패와 내용 실패는 별도 열이다. 의도한 정책의 fallback 결과도 함께 보고한다. |
| 다중 비교 | 예비 분석은 탐색으로만 보고한다. 본 실험의 H1·H2·H3 및 H3 두 기준선 비교는 Holm 보정한다. |

정책의 실행 결과는 해당 모델의 독립 실행 행에 연결한다. 같은 모델이 여러 정책에서 선택되어도 독립 표본으로 늘리지 않는다. 전체 행렬 실행 비용은 실험 비용이며 실제 정책 비용은 선택한 실행과 판단 비용만이다. Codex 구독 토큰을 달러나 사용 한도 비율로 임의 환산하지 않는다. 비용 미상인 정책은 비용 절감 가설을 채택할 수 없다.

### 본 실험 확대 조건

예비 결과에서 스키마·원문 보존·판정 연결이 모두 검증되면 예비 과제와 겹치지 않는 자료를 수집 전 별도 커밋으로 고정한다. 각 역할은 최소 240개 독립 과제를 목표로 하며, 프로젝트·과제 계열 단위로 개발 20%와 봉인 평가 80%를 나눈다. 이 수는 시작 예산이고 충분한 검정력을 보장하지 않는다. 예비 불일치율을 이용해 비열등성 3%p, 검정력 80%, 보정 유의수준에서 필요한 표본을 계산한 뒤 수집한다. 예산이 부족하면 결론은 보류한다.

모델 선택은 실제 저장소의 설계 산출물·검토 결함·구현 테스트를 포함한다. 사전 고정된 테스트와 눈가림 검토를 사용하고 설계 모델의 자기 채점을 정답으로 쓰지 않는다. 본 실험은 프로젝트 단위 대응 bootstrap 10,000회와 불일치 수를 보고한다. 전부 일치해 bootstrap 구간이 0이 되는 경우 불일치율의 정확 구간을 함께 보고하며 비열등성을 자동 채택하지 않는다. 비용·지연에는 전환 패킷 생성, 캐시 손실, 재작업, escalation을 포함한다. 관측하지 않은 대안 모델 성과를 성공했다고 추정하지 않는다.

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 채택 | 독립 본 실험을 통과한 역할만 제한 적용한다. 선호와 사용자 고정값은 계속 우선한다. |
| 기각 | 해당 역할의 기준선을 유지한다. 다른 역할의 Jev 사용까지 함께 기각하지 않는다. |
| 보류 | 표본·가용성·비용·판정 근거 중 부족한 항목을 명시한다. 제품 자동 적용을 시작하지 않는다. |

## 탐색 분석

- 직접 모델 선택과 원자 판단 결합의 선택 차이, 낮은 모델의 성공 과제, 불필요한 상향 선택을 비교한다.
- 제약 후보 생성 토큰까지 포함한 손익분기와 추가 LLM 재판정 대비 Jev 비용을 분리한다.
- 맥락의 모르는 답, 최신 사실, 여러 기록 결합, 기록 위치에 따른 손실을 비교한다.
- 향후 전환 여부 자체의 판단, 같은 판단 묶음의 재사용, 캐시와 판단 생략을 별도 처치로 분리한다. 이번 결과에 포함하지 않는다.

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 호출 시각·캐시·서비스 혼잡이 지연을 바꾼다. | 순서를 섞고 원시 시간과 usage를 보존한다. 단일 반복을 운영 p95로 일반화하지 않는다. |
| 구성 | 작은 JSON·표현식 과제가 실제 설계·구현 능력과 다르다. | 예비 계측 점검으로 한정하고 저장소 과제를 별도 평가한다. |
| 외적 | 합성 제약과 바이트 예산이 실제 긴 세션과 다르다. | 원문 기반 본 실험과 provider 실제 token budget 실험을 별도로 고정한다. |
| 평가 | 정답 생성 규칙이 Jev state에 들어갈 수 있다. | 요청에는 task와 source만 넣고 expected·tests 필드를 재귀적으로 금지한다. |
| 비용 | 추가 LLM 후보 생성이 공짜라는 가정이 이득을 부풀린다. | 모든 호출을 기록하고 기존 응답에 부가된 비용과 별도 호출 비용을 구분한다. |

공식 [TypeSafe 문서](https://docs.typesafe.ai/introduction)는 state에 대한 독립된 typed 질문과 코드에서의 결합을 설명한다(2026-10-06 확인). 본 실험의 Jev는 TypeSafe 모델이며 Haiku·Luna·Terra로 대체한 일반 명칭이 아니다. [jev-codex-router](https://github.com/0xNatoshi/jev-codex-router)는 설계 참고이며 그 프로젝트의 비용 시뮬레이션을 Saturn의 실측으로 사용하지 않는다.
