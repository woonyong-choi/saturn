# Jev 역할별 효율: 실험 결과

## 요약

모델 선택은 고정 단계와 Jev 두 정책 모두 7/8 · 87.5% [52.9, 97.8]로 같았다. 제약 선별 뒤 설정 복원은 세 정책 모두 6/6 · 100.0% [61.0, 100.0]였다. 맥락 선별은 어휘 순위와 Jev 모두 8/8 · 100.0% [67.6, 100.0]였다. 구간은 각 비율의 Wilson 95% 구간이다. 과제가 작아 H1~H3는 모두 보류하며 제품 자동 적용 근거로 쓰지 않는다.

## 방법

| 항목 | 값 |
|---|---|
| 설계 | [실험 설계](design.md), 커밋 `054f9af92675b09b5e23f68d1bce4b1b3c3ca1a2` |
| 실행 id | `054f9af` |
| 환경 | [env.json](env.json) |
| 표본 | 모델 선택 8과제, 제약 6과제, 맥락 8과제 |

Opus에 초기 실험 설계를 요청하고 Sol에 수집 전 검토를 요청했다. 검토에서 나온 묶음 호출, 후보 상한, 지연 합산, 채점 경계를 설계 커밋에 반영했다. 실행기는 기존 CLI·HTTPS 호출 경계를 재사용했다. Sonnet을 제약 후보 생성과 제약·맥락 후속 실행 모델로 고정했다. 일곱 모델의 독립 실행 행에 Jev 선택을 연결했으며 제품 engine에서 자동 라우팅한 실험은 아니다.

## 설계와 다른 점

| 변경 | 시점 | 이유 | 결론에 미친 영향 |
|---|---|---|---|
| JSON 밖 설명을 제거한 내용 채점을 추가했다. | 분석 중 | 엄격한 JSON 실패가 내용 오류와 섞였다. | 탐색 진단으로만 보고하고 사전 점수는 유지했다. |
| 모든 역할의 호출 합산과 정규화 행을 후처리에 보완했다. | 분석 중 | 사전 분석기의 후속 실행 시간만으로 총지연을 판단하면 안 된다. | 기존 원응답으로 재계산하며 비용 미상은 그대로 남겼다. |
| 영상의 다섯 도구 비교를 별도 문서로 추가했다. | 수집 중 사용자 요청 이후 | 새 비교 조건을 이미 실행한 가설에 섞을 수 없다. | [소스 비교와 후속 조건](stack-comparison.md)은 추가 분석이며 실제 통합 실행 결과가 아니다. |
| 맥락 fixture는 다른 프로젝트의 폐기 기록을 사용했다. | 수집 전 fixture 고정 | 생성기에 동일 프로젝트의 최신·폐기 충돌이 없다. | 같은 프로젝트의 버전 충돌 성능을 검증하지 못했다. |

### 기존 LLM 후보의 제약 선별

| 정책 | 후속 설정 성공과 95% 구간 | 기대 값과 다른 선택 후보 값 | 후보 생성부터 합성 중앙 지연 초 |
|---|---|---|---|
| code | 6/6 · 100.0% [61.0, 100.0] | 2 | 8.813 |
| jev | 6/6 · 100.0% [61.0, 100.0] | 0 | 8.717 |
| llm | 6/6 · 100.0% [61.0, 100.0] | 1 | 16.889 |

Jev는 코드 기준선에 남은 상충 값을 걸러냈지만, 후속 Sonnet이 코드 기준선의 상충도 해소하여 최종 성공률 차이는 없었다. 근거 지원 오류와 값 오류는 같지 않다. 스키마가 맞는 허위 후보, 장기 범위, 암묵적 선호 전체를 검증한 결과로 확대하지 않는다. 추가 Sol 재판정은 운영 기준선보다 호출 단계가 하나 많다. Jev 경로도 후보 생성 비용을 포함해야 하며 공짜 전처리로 세지 않았다.

### 맥락 선별

| 정책 | 후속 정답과 95% 구간 | 근거 블록 평균 보존율 | 선택부터 합성 중앙 지연 초 |
|---|---|---|---|
| full | 8/8 · 100.0% [67.6, 100.0] | 100.0% | 3.144 |
| recency | 0/8 · 0.0% [0.0, 32.4] | 16.7% | 3.551 |
| lexical | 8/8 · 100.0% [67.6, 100.0] | 95.8% | 3.173 |
| jev | 8/8 · 100.0% [67.6, 100.0] | 100.0% | 3.435 |

세 선별 조건의 블록 본문 바이트는 전체보다 75% 작았다. 전체 API 입력 토큰이 그만큼 감소했다는 뜻은 아니다. Jev가 모든 근거 블록을 남겼지만 어휘 순위도 정답을 모두 맞혔다. 어휘 순위가 누락한 일부 블록은 값이 없다는 기록이어서 모델이 null로 답할 수 있었다. 최근 기록만 남긴 조건은 모두 틀렸으나 이것만으로 의미 판단 모델이 필요하다는 결론은 나오지 않는다.

Jev 선별에는 별도로 입력 15927토큰과 출력 1680토큰이 들었다. Jev 조건은 원본 전체보다 Sonnet 입력을 줄였지만 어휘 순위와 거의 같았고 추가 선택 호출이 있었다. 서로 다른 모델의 토큰을 같은 가격으로 환산하지 않는다. 이 과제에서는 Jev 없이도 같은 후속 정답률과 비슷한 Sonnet 입력량을 얻었다.

### 비용

CLI가 보고한 비용, usage, cache 토큰은 원응답과 [추가 집계](results/diagnostics.json)에 보존했다. Codex 구독과 Jev 응답은 이 실행에서 USD 비용을 직접 보고하지 않았다. 따라서 이 실험은 전체 USD 절감률을 확정하지 않는다. Claude 비용도 provider 보고 추정액이며 사용자의 구독 청구액으로 간주하지 않는다. 정책 시간은 독립 호출의 합산이며 실제 engine의 end-to-end 실행 시간이 아니다.

## 논의

### 해석

단계가 명확한 모델 선택과 현재 예비 맥락에서는 결정적 기준선으로 같은 결과를 얻었다. 이런 구간에 Jev를 항상 호출할 근거는 없다. 제약 선별에는 잘못된 후보를 줄이는 신호가 있지만 후속 성과 개선은 확인하지 못했다. 기존 LLM의 해석을 유지하고 불확실한 후보만 Jev에 맡기는 조건을 별도로 평가한다.

[영상 도구 비교](stack-comparison.md)는 단계별 검색·원문 재조회·구조적 압축·관찰 기록을 우선 기준선으로 삼는 방향을 제안한다. 다섯 도구 설치 조합과 Saturn을 실제 비교한 결과는 아니다.

### 타당성 위협

| 종류 | 위협 | 이 실험에서 |
|---|---|---|
| 내적 | cache와 호출 혼잡이 지연을 바꾼다. | 순서를 섞었지만 조합당 단일 실행이므로 지연 차이를 안정적인 성능 차이로 확정하지 않았다. |
| 구성 | JSON과 표현식이 실제 개발 작업을 대표하지 않는다. | 내용 오류와 출력 형식 오류를 분리했으며 제품 적용 판정을 보류했다. |
| 외적 | 합성 입력과 바이트 예산이 긴 실제 세션과 다르다. | 어휘 기준선이 충분한 쉬운 과제가 있었고 같은 프로젝트의 버전 충돌은 없었다. |
| 평가 | 정답이 판단 입력으로 새면 선택 효과가 부풀려진다. | Jev state에서 정답 필드 금지와 원문 해시 검사를 통과했다. |
| 비용 | 후보 생성과 재조회 비용을 누락할 수 있다. | 후보 생성 시간은 포함했고 재조회는 이번 과제에 없었다. 미보고 비용은 null로 남겼다. |

## 재현

```sh
./run.sh analyze
./run.sh verify
```
