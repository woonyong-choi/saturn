# 대응 실행 검증기: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#540](https://github.com/woonyong-choi/saturn/issues/540) |
| 관련 설계 | [records](../../design/records.md), [맥락 고르기](../../design/context-selection.md), [실제 provider 통합 확인](../../../scripts/e2e/README.md) |
| 사전 데이터 | [jev-role-efficiency](../jev-role-efficiency/design.md)의 맥락 선별 예비 표본(블록 12개 중 3개)과 결과를 열람했다. 같은 구조를 쓰되 새 표본의 정답이나 기준값으로 쓰지 않는다. |

## 질문

같은 후보 집합에서 선택 방법(원문 전체, 코드 검색, 작업 LLM 선택, Jev 선택)만 바꿨을 때 후속 작업의 성공, 토큰, 시간이 어떻게 달라지는지 재현 가능하게 측정할 수 있는가. 이 문서는 효과가 아니라 측정 장치를 먼저 고정한다. 장치가 잘못된 선별, 항상 성공하는 채점, 누락된 사용량, 중복된 child 사용량, 변조된 원자료를 실제로 거절하는지가 이번 실험의 대상이다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 검증기는 주입한 결함 16종(아래 표)을 모두 거절하고 결함 없는 자료는 통과시킨다. | 오프라인 단계, 호출기가 stub인 실행 |
| H2 | 같은 원응답에서 가공과 분석을 두 번 실행하면 바이트가 같다. | 오프라인 단계 |
| H3 | 실패·시간 초과·미보고 사용량을 제외하지 않고 분모에 남겨 집계한다. | 모든 단계 |

효과 가설(Jev 선택의 성공률 손실 3%p 이내, 총 토큰 또는 지연 절감)은 [jev-role-efficiency H3](../jev-role-efficiency/design.md)의 것을 따르며 이 단계에서는 채택하지 않는다. stub 실행의 성공률은 파이프라인 확인용이며 어떤 선택 방법의 근거도 아니다.

## 설계

| 항목 | 값 |
|---|---|
| 조건 | `full`(12블록 전부, 품질 상한 참고), `code`(단어 집합 교집합 순위 상위 3개), `llm`(작업 LLM이 3개 ID 선택), `jev`(블록별 필요 확률 상위 3개) |
| 배정 | 시드 540001. 한 과제의 네 조건은 같은 후보 12블록과 같은 바이트 예산(블록당 512바이트)을 받고 선택 ID만 다르다. 후속 실행 순서는 과제별로 섞는다. |
| 눈가림 | Jev와 선택 LLM의 요청에는 정답·검사 값을 넣지 않는다. 요청 상태에서 `expected`, `tests`, `gold`, `future`, `outcome` 키를 재귀로 금지한다. 채점기는 모델 이름을 쓰지 않는다. |
| 환경 | 실제 수집(`live`)은 로컬 공식 Claude CLI와 TypeSafe Jev 1.13.0 HTTPS API를 쓴다. 호출 경계는 [jev-role-efficiency의 runtime](../jev-role-efficiency/scripts/runtime.py)과 그 안의 target-model-choice 호출기를 그대로 재사용한다. 후속 실행 모델은 Sonnet이다. |

### 선택 규칙

| 항목 | 값 |
|---|---|
| 예산 | 3블록. `full`만 12블록이다. |
| 코드 검색 | 과제 문장과 블록의 소문자 단어 집합 교집합 크기 내림차순, 동점은 블록 ID 오름차순 |
| Jev | 블록마다 한 질문. 확률 내림차순 상위 3개를 고르고 3번째 확률이 0.5 미만이면 낮은 확신으로 본다. 응답 실패·스키마 오류·낮은 확신은 코드 검색 선택으로 돌아가며 추가 LLM을 부르지 않는다. 0.5는 첫 실험을 위한 가정이며 최적값이 아니다. |
| 작업 LLM | JSON `{"selected":[ID 3개]}`. 없는 ID·중복·개수 오류·형식 오류는 코드 검색 선택으로 돌아간다. |
| 채점 | 후속 실행의 JSON 답이 숨긴 기대 값과 정확히 같으면 성공. 호출 실패와 시간 초과는 실패로 분모에 남긴다. |

선택 ID는 원응답에서 다시 계산한다. 기록된 trial의 선택, 실제 후속 요청에 들어간 블록, 대체 여부가 모두 원응답에서 재현되어야 한다.

### trial 계약

모든 조건의 실행은 같은 trial 행을 만든다. 필드 목록의 정본은 [contract.py](scripts/contract.py)의 `TRIAL_FIELDS`다.

| 필드 | 뜻 | 오프라인 값 |
|---|---|---|
| task_id, family_id, split, fixture_hash | 과제, 계열, 개발·봉인 구분, 고정 입력 해시 | 필수 |
| arm, seed, policy_version | 조건, 시드, 정책 버전 | 필수 |
| provider, model, model_version | 요청한 실행 모델과 보고된 실제 이름. 미보고는 null | 필수 키 |
| input_id, run_id, session_id | Saturn 입력·실행·session 식별자 | null. 온라인에서는 필수 |
| decision_id | 선택 판단 식별자 | `<task_id>-<arm>` |
| started_at, ended_at, latency_s | 시작·종료 시각과 선택·실행 시간 합 | 원응답의 시각과 지연 |
| raw_files, raw_sha256 | 원응답 파일과 SHA-256, 이를 묶은 해시 | 필수 |
| selection | 선택 ID, 실제 선택 방법, 대체 여부와 이유, 후보 집합 해시 | 필수 |
| answer, check | 파싱한 답과 채점 결과 | 필수 |
| status | `ok`, `failed`, `delivery_unknown`, `incomplete` | 필수 |
| usage | 호출별 사용량 목록 | 필수 |

`delivery_unknown`은 시간 초과처럼 전송 여부가 불명확한 실행이다. 자동으로 다시 보내지 않고 별도 실패로 보존한다.

사용량은 호출 ID별 한 항목이며 입력, 캐시 생성, 캐시 읽기, 출력 토큰을 가진다. 보고되지 않은 값은 키를 두고 null로 쓴다. 키가 없는 것은 계약 위반이다. 합계는 호출 ID마다 한 번만 더하고 한 필드라도 미보고가 있으면 그 필드의 합은 null이며 알려진 값의 합과 미보고 호출 수를 따로 낸다. 부모가 child 사용량을 이미 포함한다고 표시했는데(`includes_children`) child 항목이 있거나, child에 부모 호출이 없거나, 같은 호출이 두 trial에 있으면 중복으로 거절한다.

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 새로 만든 합성 과제. 계열 24개(`fam540-NNN`), 계열마다 같은 기록 12블록 위의 두 과제(전체 설정, 갱신된 포트). 갱신된 값이 이전 값을 대체한다. |
| 크기 | 48과제 x 4조건 = 192 trial. 개발 20%와 봉인 평가 80%를 계열 단위로 나눈다. |
| 독립성 | 계열이 두 구간에 걸치지 않고, fixture 해시가 겹치지 않으며, 이전 실험 표본과 같은 기록 원문이 없다. 검증기가 매번 확인한다. |
| 크기 근거 | 계측 점검용 예산. 채택 검정력이 있는 표본으로 보지 않는다. 제품 채택은 온라인 실행에서 계열 240개 이상을 사전 등록해 따로 수집한다. |
| 중단 규칙 | 호출 상한, 인증 거절, 원자료 해시 불일치에서 중단한다. 개별 오류와 시간 초과는 보존하고 다음 독립 과제를 진행한다. 자동 재시도하지 않는다. |
| 예산 | live: Claude CLI 최대 240회(선택 48, 후속 192), Jev 최대 48회. 예약 상한 260회와 60회 |

## 분석

| 지표 | 방법 | 비고 |
|---|---|---|
| 성공률 | 조건별·구간별 Wilson 95% 구간 | 호출 실패와 시간 초과를 분모에 포함 |
| 대응 차이 | 같은 과제의 성공 차이와 한쪽만 성공한 수. `full`과 `code`를 기준으로 | 구간 검정으로 채택하지 않는다 |
| 적용률과 대체 | 의도한 선택기가 대체 없이 적용된 비율, 대체 이유별 수 | |
| 사용량·시간 | 알려진 합, 미보고 호출 수, 시간 합과 중앙값 | 미보고가 있는 합계로 절감률을 주장하지 않는다 |
| 실패·제외·재시도 | 상태별 수, 제외한 fixture 수, 재시도 수 | 제외와 재시도는 0이어야 하며 0이 아니면 보고한다 |

분석은 같은 원응답에서 두 번 실행해 같은 바이트를 내야 한다. 봉인 평가 구간만 판정에 쓰고 개발 구간은 별도로 보고한다.

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 채택 | 검증기가 모든 주입 결함을 거절하면 오프라인 단계가 닫힌다. 온라인 단계는 열린 상태다. |
| 기각 | 놓친 결함을 고치고 같은 주입을 추가한다. |
| 보류 | 어떤 선택기의 제품 채택, 효과 판정, 실제 provider 계측 검증은 이 단계에서 정하지 않는다. |

## 검증기 주입 결함

`run.sh verify`는 먼저 결함 없는 자료를 통과시킨 뒤 아래 결함을 하나씩 넣어 모두 거절되는지 확인한다.

| 결함 | 주입 방법 | 거절하는 검사 |
|---|---|---|
| 잘못된 선별 3종 | `code`, `llm`, `jev` trial의 선택 ID 하나를 다른 블록으로 교체 | 실제 요청 블록과 선택의 불일치 |
| 대체 가장 | 대체된 Jev 선택을 대체 아님으로 표시 | 원응답에서 선택 재계산 |
| 항상 성공·항상 실패 채점기 | 채점기를 상수 함수로 교체 | 알려진 정답·오답에 대한 채점기 자체 시험 |
| 뒤집힌 성공 표시 | 실패 trial의 성공 값을 참으로 변경 | 원응답에서 trial 재계산 |
| 사용량 누락 2종 | 사용량 필드 키 삭제, 성공 trial의 사용량 목록 비움 | 사용량 계약 |
| 중복 child 3종 | 같은 호출 ID 추가, 부모가 포함한 child 추가, 다른 trial과 같은 호출 공유 | 사용량 합산 계약 |
| 원자료 변조 2종 | 바이트 변경, 응답을 바꾸고 해시까지 갱신 | 해시 대조, trial 재계산 |
| 정답 누출 | Jev 요청 상태에 `expected` 키 추가 | 요청 상태 검사 |
| 온라인 필수 값 누락 | 식별자가 null인 trial을 온라인 입력으로 검증 | 온라인 trial 계약 |

## 온라인 실행 입력 계약

온라인 단계는 같은 후보를 실제 engine 경로에 넣고 검색, 재조회, provider 실행, 전체 사용량을 측정한다. 아래가 입력 계약이고, 구현과 실행은 다음 절이다.

| 항목 | 계약 |
|---|---|
| 입력 | 오프라인과 같은 과제·후보·fixture 해시. 조건마다 같은 후보 집합(#539의 CandidateSet)과 같은 전문 예산을 받고 선택 ID만 다르다. |
| 시험 범위 | 고정된 시작 저장소와 기록 스냅샷(해시 포함)을 `.runtime/` 안 전용 `SATURN_HOME`과 연습 폴더에 복원한다. 운영 `~/.saturn`, `~/.claude`, `~/.codex`는 쓰지 않는다. |
| 식별자 | `input_id`, `run_id`, `session_id`, 전달 패킷 해시(#538의 `handoff_packets`)는 모두 값이 있어야 하며 `contract.validate_trial(online=True)`가 확인한다. |
| 사용량 | parent, child(하위 에이전트), Jev, 선택 LLM 호출을 호출 ID별로 합친다. provider가 child를 부모에 이미 포함해 보고하면 `includes_children`을 참으로 두고 child 항목을 따로 넣지 않는다. |
| 전송 불명 | 자동 재전송 없이 `delivery_unknown`으로 보존한다. |
| 정답 | 확인 평가의 정답과 미래 대화는 router state, 사례 검색, 선택 호출 요청에 넣지 않는다. |
| 비밀 | router 키는 실행 셸의 환경 변수로만 넘기고 자식 CLI에서 제거한다. 기록과 로그에서 키 문자열 수를 센다. |
| 도구 조회 | Claude와 Codex 각각 생략 기록을 ID로 다시 읽는 한 과제로 호출, 입력, cache, 출력, 검사, 시간 계측이 맞는지 먼저 확인한 뒤 확대한다. |

선행 작업: #538(전달 패킷 근거 기록)과 #539(근거 검색과 원문 조회, 조건별 선택기). 두 작업 모두 main에 들어갔다(#555, #565).

## 온라인 단계: 도구 조회 실계측

효과가 아니라 계측이 맞는지를 한 과제로 먼저 확인한다. 과제 하나(`x000a`, 계열 `fam540-000`)를 Claude와 Codex 각각이 받는 쪽으로 두고, engine 경로의 패킷 전달, `saturn evidence` 조회, 사용량, 시간을 trial 계약으로 기록한다.

### 가설

| 가설 | 예측 | 판정 |
|---|---|---|
| O1 | 모든 trial이 `validate_trial(online=True)`를 통과한다(`input_id`, `run_id`, `session_id`, 모델 실제 이름, 패킷 해시). | 하나라도 실패하면 기각 |
| O2 | 기록 저장소의 `usage`, `judgments`, `handoff_packets`, `evidence_lookups` 행만으로 trial의 사용량 목록, 패킷 형태, 조회 수를 다시 만들 수 있고 같은 원자료에서 가공·분석을 두 번 돌리면 바이트가 같다. | 불일치 하나라도 있으면 기각 |
| O3 | 에이전트의 `saturn evidence` 명령 수와 `evidence_lookups` 행 수가 같다(조회 없이 0회도 그대로 기록). | 다르면 원인을 적고 보류 |
| O4 | 조건이 바꾸는 것은 패킷의 구성뿐이다. `full`은 후보 12개가 모두 전문(`Full`)으로, `code`와 `jev`는 한도 안의 일부만 전문이고 나머지는 `Digest` 또는 `budget` 생략이다. | 어긋나면 설정을 고치지 않고 그대로 보고 |

선택기 효과(성공률, 비용, 시간 이득)는 이 단계에서 판정하지 않는다. 한 과제 3회로는 구간이 넓어 채택·기각 근거가 되지 않는다.

### 설계

| 항목 | 값 |
|---|---|
| 엔진 | main 커밋의 `saturn-engine` 릴리스 빌드(커밋은 봉인 파일에 기록). 전용 `SATURN_HOME`과 연습 폴더는 `.runtime/ar/`, 시험마다 스냅샷을 복원한다. |
| 과제 | `x000a`의 12블록을 각 5,600글자 파일로 만들고 근거 문장은 끝에만 둔다(패킷 발췌 앞 300글자로는 답할 수 없다). 전문 예산 때문에 일부가 `Digest`나 생략이 되도록 한다. |
| 스냅샷 | source provider가 파일 12개를 각각 `cat`으로 읽어(블록마다 기록 한 건) 기록을 만들고, 파일을 지운 뒤 홈을 스냅샷으로 둔다. 방향은 Claude 기록을 Codex가 받는 경우와 Codex 기록을 Claude가 받는 경우 둘이다. |
| 조건 | `full`(안전 비율 100, 패킷 한도가 12블록 전문을 담음), `code`(engine RRF 순위, `context.select.packet=rrf`), `jev`(`context.select.packet=jev`). 한도는 약 5,000토큰: 안전 비율 Claude 5(창 크기 약 100만 토큰 기준), Codex 18(창 약 27만 토큰 기준). `llm` 조건은 engine에 작업 LLM 호출 연결이 없어 이 경로에서 측정하지 않는다(미지원으로 보고). |
| 설정 | 조건마다 `context.evidence.lookup=true`. 권한 모드는 기본 `edit`이고 허가 요청은 `saturn evidence search|read` 명령만 이번만 허용하고 나머지는 거절한다. 거절 목록은 trial에 남긴다. |
| 모델 | Claude haiku, Codex gpt-5.6-luna. 공식 CLI를 Saturn이 띄운다. |
| 입력 | 과제 문장만 보낸다. 정답, 기대 값, 지원 블록 ID는 입력과 설정에 넣지 않는다. 같은 문장·같은 후보·같은 예산으로 조건만 바꾼다. |
| 반복과 순서 | 방향 2 x 조건 3 x 3회 = 18 trial. 반복마다 조건 순서를 시드로 섞는다. 크기 근거는 계측 점검이며 검정력이 없다. |
| 재전송 | 하지 않는다. 시간 초과나 전송 불명은 해당 상태로 보존한다. |

사전 점검(설계 확정 전, 판정에서 제외): 구현 확인용으로 방향별 1회씩 4건을 돌려 근거 문장 위치, 패킷 한도 보정, `saturn` 실행 파일 경로, 허가 규칙을 고쳤다. 이 4건은 표본에 넣지 않았고 수집 때 새 홈에서 다시 시작한다.

### 기록

시험마다 알림 전체와 기록 저장소의 `handoff_packets`, `handoff_packet_items`, `evidence_lookups`, `usage`, `judgments`, `runs`, `sessions`, `events`를 원응답으로 보존하고 trial은 그 원자료에서만 만든다. 사용량은 Claude의 `MainTurn` 행을 호출마다 한 항목으로, Codex의 `ThreadCumulative` 행은 session마다 마지막 행 한 항목으로 합치고(누적값을 행마다 더하지 않는다), router 판단은 판단마다 한 항목으로 둔다. router 사용량은 캐시 필드가 없어 null(미보고)이다. 패킷 안내와 조회 때문에 맥락이 한도를 넘어 새 session으로 다시 시작하면(`Restart` 패킷) 그 패킷과 session 사용량도 같은 trial에 포함하고 횟수를 보고한다.

### 호출 상한과 중단

| 대상 | 상한 | 근거 |
|---|---|---|
| Claude 입력 | 40 | 스냅샷 1 + 9 trial x (입력 1 + 패킷 최대 2) 예상 28 이하. 여유 포함 |
| Codex 입력 | 40 | 같음 |
| router 판단 | 60 | trial마다 입력 판단 1 + `jev` 패킷 판단. 예상 30 이하 |

상한에 닿거나 인증 거절, 원자료 저장 실패, 키 문자열 검출에서 중단한다. 개별 trial의 실패와 시간 초과는 보존하고 다음 trial을 진행한다. router 키는 실행 셸 환경에서만 읽고 engine이 자식 CLI에서 제거하며, 끝에 원자료, 로그, 화면에서 키 문자열 수를 센다.

### 명령

| 명령 | 하는 일 |
|---|---|
| `ARM_ENGINE_BIN=<saturn-engine 경로> run.sh online-collect` | 설계와 실행기가 커밋된 상태에서만 시작. 스냅샷 2개를 만들고 18 trial을 수집한다. |
| `run.sh online-process` | 원자료에서 trial을 다시 만들고 해시 목록과 집계를 쓴다. |
| `run.sh online-verify` | 계약, 해시, 원자료 재계산, 집계 바이트 일치를 확인한다. |


## 재현

| 명령 | 하는 일 |
|---|---|
| `ARM_VERIFIER_CALLER=stub run.sh all` | 모델을 부르지 않는 결정적 호출기로 collect, process, analyze, verify를 한 번에 실행한다. 기본값이다. |
| `ARM_VERIFIER_CALLER=live run.sh collect` | 설계와 실행기가 커밋된 상태에서만 시작한다. 공식 CLI와 TypeSafe HTTPS를 호출하고 원응답을 비공개 폴더에 남긴다. |
| `run.sh process` | 원응답에서 trial을 다시 만들고 원자료 해시 목록을 쓴다. |
| `run.sh analyze` | 집계 JSON을 쓴다. |
| `run.sh verify` | 표본 독립성, 해시, 계약, 재계산, 두 번 분석의 일치, 주입 결함 거절을 확인한다. |

stub 결과와 live 결과는 비공개 폴더의 다른 하위 폴더에 두고 섞지 않는다. 집계 JSON의 `evidence` 필드가 호출기를 밝힌다.

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 호출 시각과 캐시가 지연을 바꾼다. | 순서를 섞고 원시 시각과 사용량을 보존한다. 단일 반복을 운영 지연으로 일반화하지 않는다. |
| 구성 | 합성 초소형 과제가 실제 긴 세션과 다르다. | 계측 점검으로 한정하고 실제 기록 기반 온라인 단계를 따로 둔다. |
| 구성 | 코드 검색이 실제 제품의 어휘·RRF 순위와 다르다. | 오프라인은 jev-role-efficiency의 단어 교집합 기준선을 쓰고, 온라인은 `ranking.rs` 경로를 쓴다. |
| 평가 | stub의 성공률을 효과로 읽을 수 있다. | 집계 JSON에 pipeline-only를 적고 문서에 효과 결론을 쓰지 않는다. |
| 평가 | 같은 규칙을 쓰는 수집과 검증이 같은 버그를 공유한다. | 채점기는 알려진 정답·오답으로, 선택은 원응답 재계산과 요청 블록 대조로 독립 확인한다. |
