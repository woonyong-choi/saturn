# 질문별 원문 복원: 실험 설계

| 항목 | 값 |
|---|---|
| 식별자 | context-recall |
| 관련 설계 | [맥락 정리](../../design/context-management.md) |
| 사전 데이터 | real-context-replay의 전체 결과와 마스킹된 실제 기록. 기존 질문으로 원문 검색 후보 다섯 변형을 탐색했다. 이 탐색은 확인 분석이 아니다. |

## 질문

작은 인계 패킷에서 빠진 근거를 새로 접수한 질문으로 원문에서 찾으면 답의 정확도를 회복하면서 전체 입력 토큰을 줄일 수 있는가? 복원 비용과 실패까지 포함해 비교한다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 복원 조건은 원문 전체 조건과 같은 정답률이며 압축만 조건보다 높다. | 고정한 실제 기록과 질문 |
| H2 | 복원 조건의 provider별 총 입력 토큰이 원문 전체보다 10% 이상 작다. | CLI 기본 비용, 복원 추가 입력, 캐시 사용을 포함한 합계 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | 원문 전체, 기존 4,000 추정 토큰 패킷, 같은 패킷에 현재 질문으로 검색한 원문 최대 4,000자를 추가한 조건 |
| 배정 | seed 7108로 조건 순서를 섞는다. provider별 직렬, 두 provider는 동시에 실행한다. |
| 눈가림 | 검색 함수에는 현재 질문과 원문만 전달한다. 정답표와 모델 답은 전달하지 않는다. 작성자는 기존 실패를 알고 있으므로 완전한 눈가림은 아니다. |
| 환경 | 기존 설치 CLI의 Claude haiku와 Codex gpt-6-sol. 실행 시 실제 버전·응답 모델·코드 해시를 보존한다. |
| 경로 | engine의 실제 전송 함수와 실험 진입점이 같은 원문 복원 함수를 사용한다. 실제 전송은 다른 session의 기록에만 적용한다. |

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| 정답 | 측정 | questions.json의 문자열을 기존 normalize 규칙으로 대조한다. | 문항 |
| 유효 실행 | 측정 | 정상 종료, 도구 호출 없음. Claude는 같은 session과 Ready 응답도 요구한다. | 실행 |
| 입력 토큰 | 측정 | 실제 CLI 사용량. Claude input·cache creation·cache read 합계, Codex input 합계. | 토큰 |
| 토큰 절감률 | 파생 | 1 - 복원 조건 합계 / 원문 전체 합계. provider를 합치지 않는다. | 비율 |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 앞 실험에서 고정한 실제 일반 대화 2개와 실제 실행 DB 3개. 긴 대화의 겹치는 접두부를 포함한 9조건이다. |
| 질문 | 기존 개발 질문 36개와 새 질문 36개. 새 질문은 이미 본 기록에서 만들었으므로 독립된 외부 검증 자료가 아니다. |
| 크기 | 9기록 × 3조건 × 2provider × 3반복 = 162실행, 실행당 8문항. |
| 크기 근거 | 기존 실패 전수와 새 질문 전수를 반복한다. 반복은 출력 변동을 확인하며 원자료 독립성을 늘리지 않는다. |
| 중단 규칙 | provider별 연속 프로세스 실패 3회면 해당 provider 수집을 중단한다. 실패·미실행은 제외하지 않는다. |
| 반복과 예열 | 3회 반복, 예열과 유리한 결과 선택 없음. 세 반복 도중 구현과 판정은 변경하지 않는다. |

## 분석

| 가설 | 지표 | 채택 기준 |
|---|---|---|
| H1 | provider·질문 집합별 유효 정답과 오류 유형 | 두 provider 모든 반복에서 원문 전체와 복원 모두 전 문항 정답이며 압축만 조건의 오류가 복원된다. |
| H2 | provider별 전체 입력 토큰 합계 | 두 provider 각각 10% 이상 절감. 정확도 조건을 함께 만족해야 개선으로 채택한다. |

누락, 오답, 잘못된 과거 기록 인용, 실행 실패를 구분한다. 원응답에서 다시 계산하고, 모든 입력·출력·사용량·실패·실행 코드의 해시를 보존한다. 이 작은 의도 표본에 모집단 신뢰구간을 붙이지 않는다.

## 판정

알려진 실패가 남으면 원인과 실행 증거를 보존하고 다음 수정 실험을 분리한다. 통과해도 일반적인 무손실이나 정상 router·TUI 검증으로 확대하지 않는다. 정상 router 자격증명이 없는 동안 이 경계는 미검증으로 기록한다.

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 외적 | 실제 일반 대화가 둘뿐이며 질문을 작성자가 만든다. | 출처·중복·새 질문의 한계를 그대로 보고한다. |
| 구성 | 사용자 원문과 도구 결과 우선 검색은 오래된 답의 회수를 방해할 수 있다. | 새 질문에는 이전 답에만 있는 이름·필드·타입·메서드도 포함한다. |
| 내적 | CLI 고정 비용과 캐시가 절감률에 영향을 준다. | 같은 실행 방법, 조건 순서 섞기, 실제 사용량 합계로 대조한다. |
