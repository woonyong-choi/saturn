# 복원 결과 반복 확인: 실험 설계

## 질문

원문 종류별 공간 배분 비교에서 통과한 복원 입력을 새 provider 실행으로 반복해도 같은 정답을 얻는가?

## 사전 데이터

이 설계는 `balanced` 수집 뒤 복원 조건의 반복을 정의한다. 작성 시 Codex의 80문항 정답을 확인했고 Claude 수집은 끝나지 않았다. 두 provider의 최초 복원 조건이 80문항 모두 유효 정답일 때 실행한다. 자료·질문·복원 방식은 앞 실험과 같다. 새 독립 표본을 확보한 것으로 해석하지 않는다.

## 설계

| 항목 | 값 |
|---|---|
| 표본 | 10기록 × 2provider × 추가 2회 = 40실행, 320문항 응답 |
| 입력 | balanced의 복원 조건 입력을 바이트 단위로 재사용한다. 정답표는 provider에 주지 않는다. |
| 배정 | seed 7109로 순서를 섞는다. provider별 직렬, provider 간 동시 실행 |
| 기준선 | 토큰 절감 판정은 balanced의 동시 비교를 사용한다. 이 반복에는 새로운 원문 전체 조건을 추가하지 않는다. |
| 중단 | 연속 프로세스 실패 3회. 문항·원자료 오염이 드러나면 판정을 폐기하고 원출력을 보존한다. |
| 판정 | 추가 320문항 모두 유효 정답이면 이 고정 입력의 반복 확인 통과다. 한 문항이라도 실패하면 실패 유형과 출처를 보고한다. |

원응답·사용량·실패를 보존하며 기존 두 반복을 골라 버리거나 성공 응답만 남기지 않는다. 최초와 추가 반복을 합친 480문항 응답은 독립 문항 480개가 아니다. 일반 무손실 주장과 정상 router·TUI 검증으로 확대하지 않는다.
