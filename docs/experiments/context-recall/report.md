# 질문별 원문 복원과 토큰 사용량

## 요약

후속 질문을 받은 뒤 저장된 원문을 복원하도록 engine을 수정했다. 최종 대응 비교에서 원문 전체와 복원 조건은 두 provider 모두 80문항에 정답을 냈다. 복원 비용까지 포함한 실제 입력 토큰은 원문 전체보다 Claude에서 33.96%, Codex에서 18.06% 줄었다.

같은 복원 입력을 추가로 반복한 결과까지 합치면 엄격 판정은 Claude 239/240, Codex 240/240이다. 남은 실패는 기대값 `한국어`에 `Korean`을 답한 경우다. 이 실패를 유지하므로 추가 반복의 전 문항 통과 기준은 미충족이다. 제한된 실제 자료에서 정답 회복과 토큰 절감은 확인했지만, 일반적인 무손실이나 모든 실사용 환경의 신뢰도를 입증한 것은 아니다.

모든 수치는 [summary.json](results/summary.json)에서 계산했다. 앞 실험의 실패와 후속 수정은 [최초 설계](design.md), [종류별 공간 배분](balanced-design.md), [기록 경계](boundary-design.md), [반복 설계](replication-design.md)에 구분했다.

## 문제와 수정

기존 인계 패킷은 이전 턴의 입력으로 기록 순위를 정했다. 나중에 들어온 질문에 필요한 원문이 이미 빠졌으면, 열린 session에 그 근거를 다시 공급하지 않았다. 최근 대화와 무관한 오래된 예제나 규칙을 다시 물었을 때 답을 보류했다.

`engine`의 실제 새 턴 전송 경로에 원문 복원을 연결했다. 접수된 입력과 해당 입력에 고정한 설정을 사용하고, 같은 채팅의 다른 session 기록에서 근거를 골랐다. 저장된 입력은 바꾸지 않고 provider에 보낼 때 인용 근거를 앞에 붙였다. 복원은 메인 새 턴에 적용하며 `provider` 모드와 실행 중 끼워 넣기는 제외했다.

사용자 입력·도구 결과와 과거 답에 별도의 공간을 배정했다. 사용자 기록만 먼저 채우면 과거 답에만 있는 예제가 밀리는 실패가 관측됐기 때문이다. 인계 기록 끝과 후속 입력 앞에는 과거 요청과 현재 요청의 경계를 명시했다. 끝 지시도 패킷 예산에 포함했다.

구현은 [handoff_recall.rs](../../../saturn-terminal/engine/src/handoff_recall.rs), 전송 연결은 [delivery.rs](../../../saturn-terminal/engine/src/delivery.rs), 기록 경계는 [packet.rs](../../../saturn-terminal/core/src/sessions/packet.rs)에 있다.

## 방법

| 항목 | 내용 |
|---|---|
| 설계 기준점 | 종류별 배분 `e93a6836`, 기록 경계 `b0674134` |
| 환경 | [env.json](env.json). Claude 응답 모델 `claude-haiku-4-5-20251001`, Codex 요청 모델 `gpt-6-sol`. Codex의 내부 모델 리비전은 응답에 없었다. |
| 자료 | 실제 학습·검토 대화, 실제 실행 DB, 별도 설계 대화의 총 6출처 묶음에서 만든 10조건 |
| 질문 | 조건당 8문항. 합계 80문항이며 긴 대화의 겹치는 접두부가 포함됐다. |
| 원문 전체 | 마스킹된 원문과 시작·끝 경계 지시 |
| 패킷만 | 현재 engine이 만든 4,000 추정 토큰 인계 패킷 |
| 패킷과 복원 | 같은 패킷에 현재 질문으로 찾은 원문 최대 8,000자를 추가 |
| 예산 | 기존 추정은 4자당 1토큰이다. 복원 원문은 약 2,000 추정 토큰이며 현재 질문·후속 경계 지시는 별도로 붙는다. 실제 토큰은 CLI 사용량으로 계산했다. |
| 실행 | provider별 직렬 실행, 조건 순서는 설계에 고정한 시드로 섞었다. |
| Claude | 처음 패킷을 보내 Ready를 받은 같은 프로세스에 질문을 보냈다. |
| Codex | 기록과 현재 질문을 하나의 입력으로 보냈다. 두 provider의 수치를 서로 합쳐 절감률을 만들지 않았다. |
| 판정 | 값의 공백·인용부호·대소문자·숫자 문자열을 정규화했다. 정상 종료와 도구 호출 없음, Claude의 Ready 및 같은 session도 확인했다. |
| 사용량 | Claude의 input·cache creation·cache read 합계, Codex의 input 합계. 기본 CLI 비용과 복원 입력도 포함했다. 금전 청구액 절감률은 아니다. |

추가 설계 자료의 사용자 역할 항목에는 실제 요청 2개, 주입된 스킬 문서 2개, 중단 표지 1개가 있었다. 이를 독립 사용자 요청 5개로 세지 않았다. 이 출처는 종류별 공간 배분 실험에서 처음 사용했고, 기록 경계 수정 단계부터는 이미 본 개발 자료다. 원문 변환은 원본 해시와 줄 번호를 보존했으며 별도 실행으로 바이트 단위 재현을 확인했다.

질문과 정답은 작성자가 원문에서 정했다. 검색 함수에 정답표와 모델 출력을 주지 않았다. 도구를 막은 질의 실험이므로 실제 도구 실행 권한을 가진 세션의 주입 공격 내성을 검증한 결과로 해석하지 않는다.

## 결과

### 최종 대응 비교

| Provider | 조건 | 유효 정답 | 실제 입력 토큰 | 원문 전체 대비 감소 |
|---|---|---:|---:|---:|
| Claude | 원문 전체 | 80/80 | 605,472 | — |
| Claude | 패킷만 | 66/80 | 354,809 | 41.40% |
| Claude | 패킷과 복원 | 80/80 | 399,824 | 33.96% |
| Codex | 원문 전체 | 80/80 | 308,472 | — |
| Codex | 패킷만 | 64/80 | 227,097 | 26.38% |
| Codex | 패킷과 복원 | 80/80 | 252,764 | 18.06% |

압축만 적용했을 때보다 복원 비용이 늘었지만, 원문 전체보다 입력 토큰이 적으면서 정답을 회복했다. 이 대응 비교는 사전 기준을 충족했다.

### 추가 반복

| Provider | 최초 복원 | 추가 반복 | 합계 |
|---|---:|---:|---:|
| Claude | 80/80 | 159/160 | 239/240 |
| Codex | 80/80 | 160/160 | 240/240 |

추가 반복의 실패는 `interruption`, 반복 3의 `new_language`였다. 질문은 요약 언어를 한국어 언어명으로 요구했고 기대값은 `한국어`, 실제 값은 `Korean`이었다. 언어의 의미는 같지만 요청한 표기를 따르지 않아 엄격 정답에서 제외했다. 따라서 반복까지 포함한 전 문항 통과 기준은 충족하지 않았다. 이 구분은 탐색적 오류 분류이며 정답 수를 바꾸지 않는다.

## 설계와 다른 점

| 단계 | 완료 실행 | 관측과 처리 |
|---|---:|---|
| 최초 복원 | 118 | 새 질문의 코드 표기가 다른 질문의 답을 노출해 중단했다. 확인 분석에서 제외했다. 중단된 실행 1개와 시작하지 않은 계획 43개도 분모와 자료에 남겼다. |
| 종류별 공간 배분 | 60 | Codex 80/80, Claude 79/80. Claude는 입력에 있는 디렉터리 경로에도 unknown을 답했다. 원문 전체 조건에는 과거 요청을 출력한 Ready 계약 위반도 있었다. |
| 기록 경계 보강 | 60 | 원문 전체와 복원 모두 두 provider에서 80/80. |
| 추가 반복 | 40 | 표기 오류를 포함해 319/320. |

후속 작업에서 완료한 모델 실행은 총 278개다. 중단·실패·부분 출력과 원문 노출이 있던 평가도 보존했다. 최초 중단은 처음 정한 중단 규칙에서 벗어난 조치이며, 문항 오염 발견을 이유로 기록했다. 다음 설계부터는 이 경우를 중단 규칙에 포함했다.

종류별 공간 배분 수집은 모델 실행이 끝난 뒤 실행 중 수정한 셸 파일 때문에 셸 종료 오류가 났다. 해당 원응답은 완결됐으며 후속 수집은 Python 진입점을 직접 사용했다. 기록 경계 단계의 준비 중 테스트 전용 import 누락도 발견해 수정했고, 모델 호출 전 실패 로그를 별도로 보존했다.

## 구현 검증

| 확인 | 결과 |
|---|---|
| 전체 자동 테스트 | 1,917개 통과 |
| 명시 실행한 부하 테스트 | 3개 통과. 가짜 provider와 실제 자식 프로세스 부하이며 실제 모델 처리량 시험은 아니다. |
| 원자료 변환기 | 3개 통과. 별도 설계 원본과 재생 자료의 바이트 단위 재현도 확인했다. |
| engine 전송 경로·가짜 provider | 복원 근거가 provider로 전달되고, 대기열과 DB의 사용자 원문은 유지됐다. provider 모드에서는 원문 복원이 꺼졌다. |
| 코드 검사 | rustfmt, Clippy 경고 금지, Python Ruff, diff 공백 검사 통과 |
| 실제 TUI | 격리 홈에서 키 입력 창 표시와 Escape 종료, 해당 engine 종료를 확인했다. 바이너리 해시와 화면을 보존했다. |
| 정상 router 종단 시험 | 승인된 SATURN_KEY가 없어 미검증. 빈 키로 확인한 화면을 정상 router 성공으로 계산하지 않았다. |

레거시 점검에서 삭제된 학습 명령의 남은 주석과 미구현 `collect` 설정의 신규 노출을 제거했다. 이전 설정 스냅샷의 해석은 유지했다. 로컬 router의 HTTP 경로는 공통 HTTPS 전송기로 바꿔 TLS 검증과 리다이렉트 차단을 유지했다.

## 한계

- 긴 일반 대화의 출처가 적고 접두부가 겹친다. 반복 응답을 독립 표본으로 간주하거나 모집단 신뢰구간을 제시하지 않는다.
- 최종 질문들은 구현 과정에서 본 개발 자료다. 별도 설계 출처도 경계 보강 단계에서는 이미 관측한 자료였다.
- 실험은 기록 기반 질의와 실제 CLI 응답을 검증했다. 정상 router를 포함한 지속적인 코딩 작업 전체의 성공률을 뜻하지 않는다.
- 원문 검색은 채팅 기록 전체를 읽는다. 매우 큰 저장소의 검색 지연과 장기 누적 비용은 별도 측정이 필요하다.
- 현재 session 안에서 provider가 자동 압축해 잃은 기록, 진행 중 끼워 넣기, 각 공간보다 큰 원문 조각은 이 복원 경로의 검증 범위 밖이다.
- 추가 반복에 표기 오류가 남았다. 모델 출력이 항상 요청 형식을 따른다는 보장은 없다.

## 재현과 보관

[자료 안내](data/README.md)의 경로에 원자료를 복원한 뒤 다음 명령으로 재계산한다.

```sh
bash docs/experiments/context-recall/run.sh analyze
bash docs/experiments/context-recall/run.sh verify
```

`collect`는 기존 수집 경로를 덮어쓰지 않는다. 실제 모델 호출을 다시 할 때는 새 경로와 실험 조건을 지정해야 한다. 각 단계의 입력·원응답·사용량·부분 출력·코드 스냅샷·설계·검증 로그를 비공개 아카이브에 보관했다. 새 보관 영수증은 [archive.json](data/archive.json), 파일별 해시는 [SHA256SUMS](data/SHA256SUMS)에 있다.
