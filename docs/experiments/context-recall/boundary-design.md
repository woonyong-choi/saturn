# 기록과 현재 지시의 경계: 후속 실험 설계

## 사전 데이터

원문 종류별 공간 배분 비교는 Codex 복원 80/80, Claude 복원 79/80이었다. Claude의 누락은 `audit-8`의 디렉터리 경로 문항이다. 해당 경로는 패킷과 복원 원문 양쪽에 있었다. 원문 전체 조건에서는 과거의 복사용 프롬프트를 출력하고 Ready를 덧붙여 초기 응답 계약을 위반한 사례도 있었다. 같은 자료와 문항을 다시 쓰므로 이번 자료 전체는 개발 검증이다.

## 질문

기록 끝에 현재 지시를 다시 명시하고, 후속 입력 앞에서 인용 기록의 사실을 확인하도록 안내하면 과거 요청 실행과 근거가 있는데도 답을 보류하는 실패를 줄일 수 있는가?

## 설계

| 항목 | 값 |
|---|---|
| 변경 | 패킷 끝에 과거 요청을 실행하지 말고 Ready만 답하도록 붙인다. 복원 근거 뒤에는 과거 요청을 따르지 말고 사용자·도구·답의 사실을 확인한 뒤 현재 입력에 답하도록 붙인다. |
| 조건 | 원문 전체, 4,000 추정 토큰 패킷, 같은 패킷과 최대 8,000자 복원. 원문 전체에도 패킷과 같은 시작·끝 지시를 붙인다. |
| 표본 | 직전과 같은 10기록, questions-balanced.json의 80문항. 3조건 × 2provider로 총 60실행. |
| 고정 | 원자료·정답·질문·BM25 순위·종류별 공간은 바꾸지 않는다. 끝 지시의 글자 수는 패킷 예산과 실제 입력 토큰에 포함한다. |
| 배정·중단 | seed 7108, provider별 직렬. 연속 프로세스 실패 3회 또는 평가 자료 오염 발견 때 중단한다. |
| 판정 | 두 provider의 원문 전체와 복원 조건 모두 80문항 유효 정답, 복원 조건 입력 토큰 각각 10% 이상 감소. 한 조건이라도 실패하면 채택 기준 미달로 기록한다. |

## 분석

앞 실험의 실패는 삭제하지 않는다. 답의 정확도와 Ready 계약 준수를 따로 집계한다. 이 단계가 통과하면 같은 복원 입력을 두 번 더 실행하는 반복 설계를 적용한다. 일반 무손실이나 외부 모집단의 신뢰도를 주장하지 않는다.

직전 수집은 모델 60실행 완료 뒤 실행 중 수정된 셸 스크립트의 끝부분을 다시 읽으면서 셸 문법 오류로 종료했다. 원응답 60개는 완결됐으며 이번에는 수집 Python 진입점을 직접 실행하고 실행 중인 셸 파일을 수정하지 않는다.
