| 항목 | 값 |
|---|---|

| 관련 설계 | [맥락 고르기](../../design/context-selection.md), [보존 우선 비교](../context-preservation/design.md), [대응 실행 검증기](../arm-execution-verifier/design.md) |
| 사전 데이터 | [대응 실행 검증기](../arm-execution-verifier/report.md)와 [오래된 현재 근거 선별](../packet-selector-oldest/report.md)의 결과를 열람했다. 둘 다 이 평가의 표본, 정답, 효과 추정, 임계값 결정에 쓰지 않는다. #540의 96칸 중 20칸만 실행 가능했고 12칸을 수집했으며 8칸은 source 재생에 실패했다. 이 진단은 별도 흐름 표에 남긴다. |

## 질문

실제 개발 과제의 같은 출발 기록, 보호 본문, 도구 후보와 예산에서 Jev 패킷 선별이 RRF보다 최종 작업 품질을 낮추지 않으면서 재조회와 재작업을 포함한 토큰, API 단가 환산 비용, 완료 시간을 줄이는가. 합성 자료의 오래된 근거 위치를 강제하지 않고 실제 과제에서 그 상황이 얼마나 자주 나타나는지도 센다.

현재 작업 트리의 기존 94개 `saturn.db`는 앞선 합성·장치 실험 폴더에 있으며 독립 실과제의 source 스냅샷은 0개다. 현재 실행 가능한 새 실제 과제 대응쌍은 0쌍이다. 실제 과제의 source 대화, 작업 폴더, 완료 조건을 확보한 뒤 아래 진단을 먼저 실행한다. 이 가용성 값은 2026-10-07의 수집 전 파일 조사이며 효과 결과가 아니다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 최종 품질 성공의 대응 차이 `J−R`의 95% 구간 하한이 0 이상이다. 품질 허용폭은 0이다. | 예정한 실제 과제 80쌍 전체 |
| H2 | 작업 시작부터 마지막 채점까지 총 토큰, API 단가 환산 비용, 벽시계 시간의 `J−R` 대응 평균 차이 95% 구간 상한이 모두 0 미만이다. | 세 값이 모두 완전 계측된 대응쌍 |
| H3 | Jev 판단의 실제 적용률과 같은 요청의 선택 집합 일치율은 각각 Wilson 95% 하한이 90% 이상이다. | 예정 Jev 실행과 실제 `compact` 요청 |
| H4 | 보호 본문의 역할·번호·해시·순서 불일치가 0이고 두 조건의 보호 본문·후보 집합·예산·출발 스냅샷이 모든 쌍에서 일치한다. | 실제 전달이 확인된 쌍 |

H1~H4는 순서대로 판정한다. 앞 단계가 실패하면 뒤의 수치는 보고하되 효과 채택의 근거로 쓰지 않는다. #544의 일관성 기준과 품질 허용폭 0은 수집 뒤 바꾸지 않는다.

## 설계

| 항목 | 값 |
|---|---|
| 조건 | R: 보존 본문과 RRF 도구 선별. J: 같은 본문과 Jev `compact` 선별. `context.select.packet`만 바꾼다. N의 전체 정책 비교는 이 대응 비교에 넣지 않는다. |
| 배정 | 시드 7007로 과제별 R/J 실행 순서를 섞는다. 각 조건은 같은 읽기 전용 source 홈과 작업 폴더 스냅샷을 독립 복사한다. 실행은 한 번에 하나만 한다. |
| 눈가림 | 후속 provider와 Jev에는 숨긴 검사, 수정 정답, 다른 조건의 결과를 넣지 않는다. 채점자는 조건을 가린 작업 결과만 보고, 자동 검사와 독립 채점자의 판정을 합친다. |
| 환경 | 실제 Saturn engine과 공식 provider CLI를 쓴다. 격리 작업 폴더에서 `permission.mode=full`, `model.mode=manual`을 공통 적용한다. 제품 커밋·실험 커밋·바이너리 SHA-256·CLI 버전·실제 모델·TypeSafe Jev 버전·운영체제·가격표 조회일을 수집 전 봉인한다. Claude→Codex 40쌍, Codex→Claude 40쌍을 별도 층으로도 보고한다. 모델은 source가 Claude인 경우 Codex `gpt-5.6-sol`, source가 Codex인 경우 Claude `sonnet`으로 고정한다. 공급자가 모델을 제공하지 않으면 수집을 멈추고 대체하지 않는다. |
| 후속 작업 | 원래 이슈에서 출발 커밋 시점에 실제 요청된 수정 또는 확인 작업 하나를 보낸다. 첫 실행이 실패하면 봉인한 사용자 피드백 문장 하나만 보내 재작업을 한 번 허용한다. 둘 다 비용과 시간에 포함한다. 재조회는 모든 조건에서 허용한다. |
| 패킷 | 실제 engine이 전송한 첫 `Switch` 패킷을 캡처한다. 보호 본문, 후보 ID·원문 해시, 패킷 예산, 실제 적용 방식, 대체 사유를 독립 검증한다. 발신 캡처만 있고 수신 증거가 없으면 전송 확인으로 세지 않는다. |

### 기능 진단

실제 source 스냅샷과 확인 가능한 완료 조건을 가진 독립 과제 1~8개를 등록한다. 출처가 실제 개발 요청인지, source를 두 조건에 동일하게 복제할 수 있는지, 보호 본문·후보·예산이 일치하는지, 패킷 발신 본문을 캡처할 수 있는지, 재조회·재작업·사용량을 기록할 수 있는지만 검사한다. source 생성에 실패한 후보도 흐름 표에 남긴다. 기능 진단의 성공률·비용·시간은 확인 평가의 가설 판정에 쓰지 않는다. 실과제 source가 0개인 동안 진단의 provider 호출은 시작하지 않는다.

기능 진단 후보 모집단은 2026-10-05~2026-10-06에 생성되어 닫힌 공개 Saturn 이슈 24건이다. 전체 목록과 선정 이유를 [적격성 기록](data/eligibility-audit.csv)에 고정한다. 첫 재생 후보 #577은 따옴표 없는 다중 단어 검색을 CLI가 거절한 결함이다. 요청문은 공개 이슈 원문이며 작업 폴더는 수정 직전 커밋 `7f533049a32233332e70020aff05f2bbf98702ad`의 파일만으로 만든다. 먼저 새 Saturn source 대화에서 실제 코드를 읽고 이 출발 상태를 저장한다. 이 대화는 이슈가 처음 처리될 때의 역사적 대화가 아니라 공개 실과제의 새 재생 source다. source와 target에게 미래 수정 커밋, 그 테스트, 숨긴 검사 결과를 보이지 않는다. 패킷 차이나 답을 본 뒤 후보를 바꾸지 않는다.

#577 source는 Codex `gpt-5.6-luna`가 실제 CLI 인자 정의와 명령 경로를 읽고 파일을 고치지 않은 상태로 고정한다. R/J는 같은 source 홈과 작업 폴더를 각자 복사해 Claude `sonnet`으로 이슈 수정 요청을 수행한다. 도구 경쟁 예산은 [보존 우선 비교](../context-preservation/design.md)의 3,500토큰을 쓴다. Claude 창 100,000토큰과 `context.safety_percent=35`로 패킷 한도 약 3,500토큰을 만들며, 실제 후보 수나 패킷 차이를 본 뒤 이 값을 조정하지 않는다. 후보가 모두 들어가거나 R/J 본문이 같으면 그 사실을 진단 결과로 남긴다. 원자료와 기능 확인은 80쌍 확인 평가에 합치지 않는다.

발신 본문 캡처는 provider 수신 증거가 아니다. 현재 CLI에서 수신 본문을 독립적으로 관측할 수 없으면 `receipt_unobserved`로 기록하고 H4의 수신 일치 판정을 보류한다. 발신 캡처를 수신으로 바꾸어 부르지 않는다.

진단 runner는 `ARM_ENGINE_BIN`과 `SATURN_DIAGNOSTIC_KEY_FILE` 환경 변수에서 실행 바이너리 경로와 무시 대상 로컬 키 파일 경로를 받는다. 키 값은 실행 순간 메모리에서만 읽어 engine 환경에 전달하고 provider 접속 환경에는 넣지 않는다. 원응답과 engine 로그에서 일치 문자열을 검사해 발견하면 은닉하고 해당 시도를 보안 실패로 남긴다. 경로와 키 값은 공개 문서·원자료 요약·오류 출력에 넣지 않는다. 전송 전 확정 거절은 새 시도 ID로만 다시 수행하고 원래 실패 기록은 보존한다.

### 과제 등록과 독립성

2026-07-01부터 2026-09-30까지 완료된 공개 개발 이슈 또는 실제 사용자가 남긴 수정 요청을 대상으로 한다. 요청 시점의 저장소 커밋과 source 대화 원문이 남아 있고, 도구 결과 후보가 패킷 예산을 자연스럽게 넘으며, 숨긴 검사 또는 사전에 작성한 관찰 가능한 완료 조건이 있는 과제만 등록한다. 합성 fixture, 앞선 실험의 원문·시드·숫자, 모델 출력을 보고 만든 요청은 배제한다. 4개 이상 서로 다른 저장소에서 저장소당 최대 20과제를 뽑는다. 수집 전에 후보 전수를 식별자와 제외 사유로 남기고, 적격 목록을 식별자 SHA-256 순서로 정렬해 방향마다 앞의 40개를 봉인한다. 시간순으로 가장 오래된 근거를 일부러 놓지 않는다.

등록 파일은 과제 ID, 출처 URL과 시점, 시작 커밋, source 대화 해시, source 홈·작업 폴더 스냅샷, 후속 요청, 미리 쓴 피드백, 검사 명령, 평가자 지침, 패킷 예산과 예상 방향을 가진다. 숨긴 검사는 provider 작업 폴더 밖에 둔다. 같은 이슈의 변형이나 같은 출발 대화는 한 계열로 묶어 한 번만 뽑는다. 인간 평가자는 source 이슈의 완료 조건으로 정정 준수, 요구 기능, 부작용을 조건명 없이 평가한다. 불일치 시 제3자가 봉인된 지침만으로 판정하고 원판정 둘을 보존한다.

기능 진단 96칸과 이 확인 평가 80쌍은 다른 모집단이다. 진단의 실패·미지원·사후 보정 수치를 80쌍의 성공 분모나 효과 추정에 넣지 않는다. 다만 새 수집기가 동일한 source와 전달 본문을 만들지 못하는 경우 그 쌍은 예정 분모에 실패로 남긴다.

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 위 기간의 실제 과제 전수에서 적격 목록을 만든 뒤 SHA-256 순서로 선택한 80계열. 두 provider 방향 각 40계열 |
| 크기 | 80대응 쌍, 160실행. 방향별 수치와 전체 수치를 모두 낸다. 자연 발생한 오래된 근거 층은 탐색 분석만 한다. |
| 크기 근거 | 비용 상한을 고려한 확인 평가 예산이다. 품질 허용폭 0에서는 모두 동률이어도 차이 구간 하한이 0 미만일 수 있다. 이 경우 채택 대신 보류한다. 검정력을 보장한다고 주장하지 않는다. |
| 중단 규칙 | 80쌍 또는 provider 입력 960회·Jev 호출 320회·벽시계 80시간 중 먼저 닿는 한도. 인증 거절, 키 문자열 검출, 원자료 해시 불일치, source 복제 불일치가 있으면 즉시 중단한다. 남은 예정 쌍은 미수집으로 흐름 표에 남긴다. |
| 반복과 예열 | 쌍마다 조건별 한 번, 예열 없음. 자동 재전송 없음. 전송 여부 불명은 그대로 실패로 기록한다. |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | 성공 대응 차이 `J−R` | 둘 다 성공·J만 성공·R만 성공·둘 다 실패 수와 대응 Newcombe 95% 구간 | 구간 하한 ≥ 0 |
| H2 | 총 토큰·API 환산 비용·시간의 쌍별 `J−R` | 계열 단위 복원 추출 10,000회, 시드 7007, percentile 95% 구간. 중앙값·최솟값·최댓값과 원시 합도 보고 | 세 구간 상한 모두 < 0 |
| H3 | 실제 적용률·선택 집합 일치율 | `k/n`과 Wilson 95% 구간. 같은 `compact` 요청은 원결과를 포함해 6회 평가 | 두 하한 모두 ≥ 0.90 |
| H4 | 보호 본문·후보·예산·source 일치 | 독립 해시 대조. 수신 본문 확인이 없는 쌍 수 별도 | 불일치 0, 수신 미확인 0 |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 봉인 전 부적격만 제외한다. 봉인 뒤 source 실패, provider 실패, 미적용, 시간 초과, 채점 불능은 80쌍의 품질 분모에 남긴다. |
| 실패한 실행 | `success=0`으로 센다. 비용·시간은 관측한 값과 결측 사유를 남긴다. 비용 결측을 0으로 채우지 않으며 H2는 완전한 쌍 수가 80보다 작으면 채택하지 않는다. |
| 다중 비교 | H1→H2→H3→H4 순차 게이트다. 방향별·오래된 근거 층별 분석은 탐색으로 표시한다. |

가격은 수집 직전 공식 자료의 모델별 입력·캐시 쓰기·캐시 읽기·출력 단가를 URL과 조회일로 봉인한다. provider가 캐시나 child 사용량을 보고하지 않으면 비용은 계산 불가다. 서로 다른 모델의 토큰 합만으로 비용 우위를 주장하지 않는다. provider 출력에 추론 토큰이 포함되면 다시 더하지 않는다. 시간은 시간 초과 한도 900초로 기록하되 900초를 완료 시간으로 대체하지 않는다.

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 채택 | H1~H4 모두 통과하면 이 방향과 모델 조합에서 Jev 기본값 변경을 별도 설계 변경으로 제안한다. 이번 실험은 기본값을 바꾸지 않는다. |
| 기각 | H1 구간 상한이 0 미만이거나 비용·시간 중 한 지표의 구간 하한이 0 초과이면 Jev 순효과 주장을 기각한다. |
| 보류 | 그 밖의 구간, 적용 부족, 계측 결측, 수신 미확인은 보류한다. 기준을 바꾸지 않고 필요한 추가 표본이나 계측 수정을 기록한다. |

## 수집

`run.sh inventory`는 비공개 후보 목록에서 실제 source 스냅샷의 가용성을 센다. `run.sh seal`은 설계와 사전 검사기가 커밋된 뒤 봉인 파일에 단계, 적격 목록, 선택된 과제, source 스냅샷 해시, 실행 바이너리, 가격과 환경을 고정한다. 현재 `run.sh collect`는 source가 없거나 raw 수집기가 연결되지 않은 상태에서 외부 호출 전에 종료한다. raw 수집기, 독립 품질 채점, 사용량·가격·패킷 대조는 실제 source를 확보한 뒤 사전 검증하고 별도 커밋으로 고정한다. 원자료에는 이슈의 사적 내용과 provider 응답이 있으므로 공개 저장소에 넣지 않는다. 공개 `data/README.md`와 결과에는 가린 식별자, 해시, 분모와 집계만 둔다. 이 설계 단계에서는 봉인과 수집을 실행하지 않는다.

## 탐색 분석

- 자연 발생한 오래된 현재 근거의 비율, 그 층의 품질 불일치, 재조회와 재작업의 기여를 별도로 보고한다.
- 패킷 후보가 모두 들어간 쌍과 경쟁이 실제 있었던 쌍을 구분해 본다. 본 분석의 전체 분모는 유지한다.

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | provider 응답과 캐시가 순서에 따라 변한다. | 같은 source 복제, 조건 순서 무작위화, 호출 시각과 캐시 사용량 보존 |
| 구성 | 실과제의 숨긴 검사가 요구 품질을 모두 포착하지 못한다. | 독립 채점자 둘과 사전 지침, 정정·부작용 항목 별도 보존 |
| 외적 | 공개 저장소 과제와 선택한 두 모델은 Saturn 전체 사용자 과제를 대표하지 않는다. | 출처와 모델별 층을 보고하고 다른 모델에 일반화하지 않는다. |
| 계측 | CLI 구독 사용량과 API 단가 환산액은 실제 청구액이 다르다. | 원시 토큰과 환산 비용을 나누고 단가 출처·조회일을 고정한다. |
