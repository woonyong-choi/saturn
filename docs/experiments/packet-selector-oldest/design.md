# 오래된 현재 근거 선별: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#540](https://github.com/woonyong-choi/saturn/issues/540) |
| 관련 설계 | [맥락 고르기](../../design/context-selection.md), [패킷 선별 차이](../packet-selector-contrast/report.md) |
| 사전 데이터 | 앞선 인위적 예산 실험은 12계열 중 source 7개만 유효했고, Jev만 정답인 쌍 2개는 모두 현재 로그가 오래된 경우였다. 이를 확인할 별도 표본이다. 기존 실행의 값과 원문을 재사용하지 않는다 |

## 질문

현재 근거가 세 도구 결과 중 가장 오래되고, 최신 두 결과가 과거 릴리스인 고정 조건에서 Jev가 RRF보다 현재 근거를 더 자주 전달하는가? 후속 답과 전체 비용·시간의 차이가 반복되는가?

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 첫 전환 패킷 본문과 경쟁 항목 집합이 함께 다른 쌍이 12쌍 중 9쌍 이상이고 보호 본문 불일치는 0이다 | 아래 인위적 압박 조건 |
| H2 | Jev에서만 정답인 쌍이 6쌍 이상이고 RRF에서만 정답인 쌍은 0이다 | Codex→Claude 단일 숫자 질문 |
| H3 | Jev의 API 단가 환산 비용과 벽시계 시간 대응 차이의 계열 bootstrap 95% 구간 상한이 모두 0 미만이다 | 완전한 12쌍 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | RRF(`rank`)와 Jev(`compact`). 두 조건의 나머지 설정은 `context.safety_percent=5`, Claude 창 100,000으로 동일 |
| 배정 | 새 seed 54026008의 합성 값 12계열. `build.log`가 현재, `archive.log`와 `deploy.log`가 과거인 순서를 고정하고 R/J 실행 순서만 계열별 섞음 |
| 눈가림 | target은 조건명과 현재 숫자를 받지 않고 작업 폴더의 원본 로그도 볼 수 없다. 채점은 숫자 동일성만 검사 |
| 환경 | 기존 패킷 선별 실험의 봉인된 engine/CLI/가격/호출 경계를 재사용하되 이 실험의 설계·실행기·바이너리 해시를 새로 봉인 |

Codex source에게 파일 세 개를 별도의 턴에서 각각 `cat`으로 출력하도록 지시한다. 도구 결과에서 파일의 첫 줄을 실제 확인하지 못하면 두 조건을 실행하지 않는다. 같은 source 저장소를 복제해 R/J를 각각 한 번만 실행한다. 오류와 결과 불명은 재전송하지 않는다. target에게 도구 사용을 금지하고 현재 timeout 숫자만 묻는다.

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| `joint_contrast` | 측정 | 첫 Switch 본문 해시와 경쟁 항목의 ID·형태·생략 사유 집합이 모두 다른지 | 쌍 |
| `protected_match` | 측정 | 사용자·assistant 보호 항목의 역할·ID·해시·순서 일치 | 쌍 |
| `success` | 측정 | 정확한 현재 숫자 하나를 답했는지 | 실행 |
| `api_equivalent_cost` | 파생 | 후속 provider·Jev 보고 토큰에 공식 API 단가를 적용한 금액 | USD |
| `duration` | 측정 | 후속 입력부터 완료·실패까지 시간 | 초 |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 이전 실행과 다른 seed의 합성 로그 12계열 |
| 크기 | 12대응 쌍, target 24실행 |
| 크기 근거 | 앞선 탐색의 oldest 근거 사례를 재현하는 진단 예산. 제품 전체 품질 보장 검정력은 없다 |
| 중단 규칙 | 12계열 또는 provider 입력 120회·Jev 호출 120회 중 먼저 도달. 실패도 예정 분모에 둠 |
| 반복과 예열 | 조건별 계열당 한 번, 예열 없음 |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | `joint_contrast`, `protected_match` | 예정 12쌍을 모두 분모로 직접 셈 | 공동 차이 9쌍 이상·보호 불일치 0 |
| H2 | Jev만 정답 `b`, RRF만 정답 `c` | 대응 불일치 수와 정확 양측 McNemar p값 표시 | H1 통과 뒤 `b>=6`, `c=0`, p<0.05 |
| H3 | Jev−RRF 비용·시간 | 계열 bootstrap 10,000회, seed 54026008, 백분위 95% 구간 | H1·H2 통과와 완전 12쌍, 두 상한 모두 0 미만 |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 없음. source 실패·미전달도 예정 분모에 남긴다 |
| 실패한 실행 | 실패·빈 답·미적용은 오답. 비용 null은 0으로 채우지 않는다 |
| 다중 비교 | H1→H2→H3 순서로 판정, 앞 단계 실패 뒤 수치는 탐색 관측만 보고한다 |

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 채택 | 세 가설이 모두 통과하면 oldest 근거라는 좁은 조건의 실과제 확인 평가를 설계한다. 기본값은 바꾸지 않는다 |
| 기각 | 하나라도 기준에 못 미치면 이 조건에도 Jev 자동 적용을 권하지 않는다 |
| 보류 | source 실패나 사용량 결측은 범위를 한정해 보고한다 |

## 탐색 분석

- 파일별 선택 형태, 첫 패킷 바이트, provider 재시작 수를 분리한다.

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 같은 입력이라도 모델 답이 변한다 | source 복제와 R/J 순서 무작위화, 한 번씩 실행한 한계 표시 |
| 구성 | 현재 근거를 가장 오래된 파일에 고정하고 창을 낮췄다 | worst-case 진단으로만 해석 |
| 외적 | 합성 숫자 찾기가 실제 코딩 작업을 대표하지 않는다 | 기본값 승격 금지와 별도 실과제 확인 |
| 계측 | API 환산액이 구독 청구액과 다르다 | 가격 출처와 날짜 봉인, 청구액으로 주장하지 않음 |
