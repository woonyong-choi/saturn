# 오래된 현재 근거 선별: 실험 결과

## 요약

사전 등록한 12개 대응 쌍에서 실제 첫 전환 패킷과 경쟁 항목 집합이 모두 달랐고 보호 본문은 모두 같았다. 현재 릴리스 숫자를 Jev 조건은 12/12, RRF 조건은 0/12 맞혔다(정확 대응 검정 양측 p=0.000488). H1·H2는 이 좁은 합성 조건에서 채택한다. 비용과 시간의 대응 95% 구간은 모두 0을 지나 H3은 기각한다. Jev가 오래된 현재 근거를 살리는 효과는 확인됐지만, 토큰·비용·속도 절감이나 제품 기본값 승격은 입증되지 않았다.

## 방법

| 항목 | 값 |
|---|---|
| 설계 | [실험 설계](design.md), 수집 전 커밋 `e742d698` |
| 실행 식별 | 봉인 파일 SHA-256 `4777a004918fbd2fc745e2ea9d2c2696a2c8217739ef03d8763f9e010805beef` |
| 환경 | [env.json](env.json), Codex Luna 출발, Claude Haiku 후속, Jev 1.13.0 |
| 표본 | 예정 12쌍·target 24개, 실제 source 12개와 target 24개 모두 유효 |
| 원자료 | [데이터 설명](data/README.md), 로컬 원자료 36개와 [SHA-256 목록](data/SHA256SUMS) |

출발 Codex가 `build.log`, `archive.log`, `deploy.log`를 각각 별도 턴에 `cat`으로 읽었다. `build.log`의 첫 줄만 현재 릴리스였다. 같은 출발 기록 저장소를 복제해 후속 Claude에게 동일한 숫자 질문을 보냈다. target 작업 폴더에는 파일을 두지 않았다. RRF·Jev 실행 순서를 계열별 시드로 섞었다. 첫 `Switch` 패킷의 실제 캡처와 저장 행을 대조했다.

## 설계와 다른 점

설계의 가설·판정 기준과 수집·분석 코드는 봉인 뒤 바꾸지 않았다. 수집 뒤 [독립 검증기](verify-posthoc.py)를 추가해 12계열의 로그 본문이 실제 `ToolResult`와 완전히 같은지, target 도구 호출이 없는지, 정답이 입력에 없었는지를 보강 확인했다. 확인 분석 수치는 바꾸지 않았다.

## 결과

### 흐름

| 단계 | 수 |
|---|---:|
| 예정·수집 source | 12/12 |
| 세 로그의 도구 결과 전문 일치 | 36/36 |
| 예정·수집 target | 24/24 |
| 요청한 선별기 실제 적용 | RRF 12/12, Jev 12/12 |
| 첫 패킷 본문·경쟁 집합 공동 차이 | 12/12 |
| 보호 본문 불일치 | 0/12 |

### 확인 분석

| 가설 | 지표 | 값 | 사전 기준 | n | 판정 |
|---|---|---|---|---:|---|
| H1 | 본문·경쟁 집합 차이, 보호 본문 일치 | 12/12, 불일치 0 | 9쌍 이상·불일치 0 | 12쌍 | 채택 |
| H2 | Jev만 정답 `b`, RRF만 정답 `c` | `b=12`, `c=0`, 정확 양측 p=0.000488 | `b>=6`, `c=0`, p<0.05 | 12쌍 | 채택 |
| H3 | Jev−RRF 비용·시간 대응 평균 | +$0.00002175, −0.118초 | 두 95% 구간 상한 0 미만 | 12쌍 | 기각 |

비용의 계열 bootstrap 95% 구간은 −$0.000574~+$0.000527, 시간 구간은 −1.29~+0.89초였다. 판정과 원행은 [summary.json](results/summary.json)에 있다. `success`는 정확한 숫자 하나와 일치할 때만 참이다.

### 탐색 분석

첫 패킷 본문 합계는 두 조건 모두 21,819바이트였다. Jev가 남긴 오래된 `build.log` 대신 RRF가 최근 과거 로그를 남겨 RRF는 10개에서 과거 숫자를 답했고 2개는 현재 값이 없다고 답했다. Jev 판단을 포함한 공식 API 단가 환산 후속 비용은 RRF 합계 $0.29915717, Jev 합계 $0.29941820으로 Jev가 $0.00026103 더 들었다. 후속 벽시계 시간 합계는 RRF 107.22초, Jev 105.81초였다. 판단 행은 RRF 12, Jev 36개다. 비용은 구독 청구액이 아니다.

## 논의

### 해석

이 결과는 Jev가 실제 Saturn 패킷에서 관련성이 높은 오래된 근거를 선택해 후속 정답을 지킨다는 좁은 인과 근거다. 두 조건은 같은 출발 기록, 후속 모델, 질문, 예산을 썼고 첫 전송 본문만 선별 때문에 달랐다. 한 번의 후속 실행에서 Jev가 토큰·비용·시간을 줄인다는 가설은 실패했다. 잘못된 답의 재작업 비용은 이번에 측정하지 않았으므로 순효율을 주장하지 않는다.

### 타당성 위협

| 종류 | 위협 | 이 실험에서 |
|---|---|---|
| 내적 | 모델 출력 변동 | 조건당 한 번만 실행했다. 12쌍 모두 같은 방향이지만 반복 변동은 별도로 측정하지 않았다 |
| 구성 | 오래된 첫 로그가 현재이고 창을 낮춤 | 의도적 worst-case 조건이다. 일반 세션 분포의 발생률은 모른다 |
| 외적 | 합성 숫자 찾기 | 코딩 작업 완료나 Claude→Codex 방향으로 일반화하지 않는다 |
| 계측 | API 환산액과 구독 청구액 차이 | 공식 단가를 봉인했고 실제 청구액이라고 쓰지 않는다 |

### 한계

- 첫 패킷 캡처는 engine이 provider 호출 직전에 내보낸 본문이지 provider 수신 증거는 아니다.
- RRF의 오답 뒤 재조회나 재작업은 실행하지 않았다. 후속 총비용에서 Jev가 이길 수 있는지 아직 모른다.
- 원자료는 로컬에서만 보관한다. 공개 저장소에는 봉인·원자료 해시와 파생 집계만 있다.
