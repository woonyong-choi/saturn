# 맥락 복구 순효과: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#587](https://github.com/woonyong-choi/saturn/issues/587) |
| 관련 설계 | [맥락 정리](../../design/context-management.md), [근거 조회](../../design/context-selection.md) |
| 사전 데이터 | context-net-effect의 설계·보고서·실행기를 열람했다. 기존 31.4%는 여섯 응답의 항목 집합 전체 일치율이며 비용 차이는 가중 토큰이다. 새 시드는 기존 결과와 분리한다. |

## 질문

원문 조회를 켠 Saturn 패킷이 provider 압축보다 품질을 유지하면서 전체 사용량과 시간을 줄이는지 실제 engine에서 잰다. 이미 읽은 필수 근거를 보강한 진단 조건으로 근거 손실과 session 재시작 비용을 구분한다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | RRF 조회 조건은 provider 압축보다 후속 작업 성공률이 낮지 않고 전체 가중 토큰과 시간이 줄어든다. | provider별 신규 합성 과제 |
| H2 | Jev 조회 조건은 같은 기준을 충족하고 RRF 조회 조건보다 효율이 높다. | 같은 과제 |
| D1 | 필수 근거 보강은 RRF의 실패를 회복한다. | 원인 진단이며 제품 채택 근거가 아니다. |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | provider: 기존 session에서 compact. rrf: 조회 안내를 끈 새 패킷. rrf_lookup: 조회 안내를 켠 RRF. jev_lookup: 조회 안내를 켠 Jev. rescue: RRF 뒤 첫 후속 질문에 이미 읽은 incident 원문·정정 규칙·지표 근거를 보강한다. rescue는 최적 선별 구현도 최소 비용 하한도 아니며 근거를 돌려주었을 때의 진단이다. |
| 배정 | 시드 58701로 provider·과제·조건의 실행 순서를 섞는다. 같은 시드는 같은 초기 저장소와 입력을 받는다. 초기 모델의 도구 선택은 달라질 수 있다. |
| 눈가림 | 채점 함수는 조건을 읽지 않는다. facts 파일과 숨긴 검사 파일은 provider 시작 전에 제거한다. rescue에만 정답 근거를 보강하며 이 조건은 제품 효과 판정에서 제외한다. |
| 환경 | main 7413264에서 빌드한 실제 Saturn. Claude haiku와 Codex gpt-5.6-luna를 사용하고 실제 모델 ID·CLI 버전·binary hash를 기록한다. 키는 기존 키체인에서 메모리로 읽고 출력·파일에 저장하지 않는다. |
| 개입 | 기존 설정 7턴 뒤 신규 로그 파일 4개를 읽고 경계 입력을 보낸다. 새 패킷 조건의 경계 t_abs는 35000이다. 이는 실제 기본값 200000을 검증하는 실험이 아니다. 실제 경계 사용량과 패킷 생성 여부를 관측하며 미개입을 성공으로 세지 않는다. |
| 조회 | 모든 조건의 권한은 같고 설정에 따른 조회 안내의 유무만 다르다. 조회 시도·성공·실패를 저장소에서 센다. 보이지 않은 정답을 lookup에 넣지 않는다. |

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| composite | 측정 | 헤더·timeout·ticket·최대 p99 endpoint 및 원래 공개 테스트가 모두 맞는다. 테스트 수정은 실패다. | 0/1 |
| usage | 측정 | 입력·cache read·cache write·출력·router를 각각 보존한다. 결측은 null이며 확정 효율 판정에서 보류한다. | 토큰 |
| weighted_cost | 파생 | 입력 1, cache read 0.1, cache write Claude 1.25/Codex 1, 출력 5에 router 원시 토큰을 더한다. 실제 금액도 원시 토큰 합도 아니다. | 가중 토큰 |
| elapsed | 측정 | 경계 직후부터 후속 3턴 끝까지 걸린 시간이다. 준비와 진단 보강 비용을 숨기지 않는다. | 초 |
| recovery | 측정 | 실제 조회·재실행 횟수와 결과다. | 건 |
| boundary_context | 측정 | 경계 session의 마지막 보고 입력·cache 지표다. 누적값과 현재 창 크기를 혼동하지 않는다. | 토큰 |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 기존 합성 Python 서비스 생성기의 신규 시드 101~104. 로그를 추가한다. 실제 공개 프로젝트를 대표한다고 주장하지 않는다. |
| 크기 | 2 provider × 4시드 × 5조건 = 40 trial. 후속 작업 120개. |
| 크기 근거 | 실패 원인과 효과의 방향을 확인할 진단 예산이다. 4쌍으로 품질 동등성이나 일반적인 무오류를 입증할 수 없다. 긍정 결과도 제품 채택은 보류하며 별도 미열람 확인 실험이 필요하다. |
| 중단 규칙 | formal의 Saturn 입력은 trial당 최대 16개, 총 640개다. 도구 실행 중 provider 내부 요청 수와 같은 단위가 아니며 실제 사용량을 따로 보고한다. 입력당 300초에서 실패로 보존하고 재전송하지 않는다. 인증 불가·키 노출·무결성 실패는 수집을 멈춘다. 준비 단계 실패도 보존한다. 결과를 보고 표본이나 기준을 바꾸지 않는다. |
| 반복과 예열 | 각 조건 1회. 실행기 점검은 시드 9901의 두 provider 조회 조건만 사용하며 formal에서 제외한다. 예비 실행 뒤 수정은 formal 전에 별도 커밋으로 고정하고 공개한다. |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1, H2 | composite 대응 차이 | 기존 Newcombe 대응 구간 구현을 검증해 재사용하고 성공·실패 짝 수를 모두 보고한다. | 차이 하한이 0 이상이어야 품질 통과다. |
| H1, H2 | 비용·시간 대응 차이 | 시드 단위 bootstrap 10000회, seed 58701, 95% 구간을 쓴다. 분해 항목과 모든 개별값을 함께 보고한다. | 차이 상한이 모두 0 미만이어야 효율 통과다. |
| D1 | rescue와 rrf의 개별 성공·비용 | 대응 표로 보고한다. | 원인 단서만 제공하며 채택 판정에 쓰지 않는다. |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | formal에서 제외하지 않는다. 미완료·미개입·평가 누락을 별도 표시하고 성공 0으로 센다. 비용 비교의 결측 쌍 수를 표시한다. |
| 실패한 실행 | 원문·사용량을 보존한다. 재개 시 완료 원자료를 덮어쓰거나 불명 입력을 재전송하지 않는다. |
| 다중 비교 | 진단의 명목 95% 구간은 보정하지 않는다. 여러 비교 중 좋은 결과를 골라 채택하지 않는다. |

## 판정

| 결과 | 설계에 반영 |
|---|---|
| 채택 | 이 진단 표본만으로 제품을 채택하지 않는다. 모든 기준을 만족하면 확인 실험 후보로만 남긴다. |
| 기각 | 품질 차이 상한이 0 미만이거나 가중 비용 차이 하한이 0 초과면 해당 조건을 기각한다. |
| 보류 | 그 밖의 경우, 계측 누락, 새 session 미생성, 실제 조회 미작동은 보류한다. 미측정을 효과 없음으로 표시하지 않는다. |

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 초기 응답·서버 부하·cache 차이가 있다. | 같은 시드의 대응 비교와 순서 무작위화, 최대 두 trial 동시 실행을 사용한다. |
| 구성 | rescue는 미래 필요 근거를 안다. | 원인 진단으로만 표시하고 제품 비교에서 제외한다. |
| 구성 | 가중 비용은 실제 청구 금액이 아니다. | 원시 항목과 가중치를 따로 보고하며 지불 비용 절감을 주장하지 않는다. |
| 외적 | 같은 합성 틀과 저렴한 모델 두 개다. | 실제 프로젝트·Sonnet·Sol·기본 압축 시점에 일반화하지 않는다. |

예비 실행을 수집한 뒤 확인한 변경은 정답 파일 사전 제거·AST 채점, 사용량 결측 검사, 승인된 시험 engine만 정리하는 절차다. 예비 실행의 성공률과 비용은 formal 판정에 넣지 않는다. 동일한 raw에서 이전 보고서 재집계는 반올림 0.1 및 부동소수점 말단 차이가 있어, 새 실험의 Python 버전과 재집계 바이트 검사를 고정한다.
