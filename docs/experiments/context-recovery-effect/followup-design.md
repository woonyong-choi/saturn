# 맥락 복구 수정 확인: 추가 설계

## 질문

수집 도중 병합된 정정 입력 보존 수정(#591)이 같은 과제의 누락을 줄이는지 확인한다. 기존 40회 결과와 원자료를 바꾸지 않는다.

## 사전 열람과 범위

기존 실행에서 정정 헤더가 Jev 요청에 없고 최종 코드에도 남지 않는 사례를 보았다. 같은 시드의 결과를 이미 열람했으므로 이 추가 실행은 수정 확인을 위한 탐색 분석이다. 미열람 확인 실험이나 제품 채택 근거로 사용하지 않는다.

| 항목 | 고정 값 |
|---|---|
| 제품 | main 7d099e6. #588과 #591을 포함한다. 실행 전 바이너리 해시와 빌드 기준을 별도 환경 파일에 남긴다. |
| 조건 | rrf_lookup, jev_lookup |
| 표본 | Claude·Codex 각각 시드 101~104, 총 16회 |
| 순서 | 시드 58702로 두 provider·네 시드·두 조건을 섞고 최대 두 회 동시에 실행한다. |
| 입력 | 원래 설계와 동일한 단일 행 입력 15개. rescue 보강은 넣지 않는다. |
| 예산 | 최대 240개 Saturn 입력, 입력당 300초. 실패도 보존하고 재전송하지 않는다. |
| 채점 | 원래 F1~F3와 공개 검사 불변 조건. 입력 ID는 저장된 실제 질문으로 대조한다. |
| 보존 | 별도 followup 원자료 폴더와 해시. 기존 자료를 덮어쓰지 않는다. |

## 판정

- 먼저 정정 헤더가 최종 코드에 남았는지와 전체 세 후속 작업이 통과했는지를 구분한다.
- 새 버전 RRF 조회와 Jev 조회는 같은 시드로 대응 비교하고 원래 분석법·비용 가중치를 그대로 쓴다.
- 이전 버전과의 차이는 수정 전후 관측이다. 실행 시점과 모델 응답이 달라 코드 수정만의 인과 효과로 단정하지 않는다.
- 기본 압축 작업의 미계측 비용을 0으로 보충하지 않는다. 이 추가 실행으로 기본 압축 대비 전체 비용 우위를 주장하지 않는다.
- 근거 조회를 하지 않았다면 조회가 효과를 냈다고 판정하지 않는다.
- 성공률이 좋아져도 네 시드만으로 품질 유지·일관성·배포 효과를 입증하지 않는다. 실패는 재현 가능한 결함과 후속 검증 과제로 남긴다.
