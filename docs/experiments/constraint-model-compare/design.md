## 질문

실제 뒤 대화로 정한 제약 여부를 앞 맥락만 본 모델들이 얼마나 맞히는지 측정한다. Jev 자동 등록 정밀도와 놓치는 제약, 사용자 확인 부담을 함께 보고 기준값 후보를 정한다.

| H2 | Jev 0.70 이상 자동·묻기 결합 재현율은 80% 이상이다. | H1과 같음 |

### 정답 지침

제약은 사용자가 앞으로의 작업 방식에 적용하라고 한 말이다. 언어·도구·형식·금지처럼 어떻게 일할지를 제한하며, 현재 작업 하나가 끝날 때까지만 해당하면 제약이 아니다. 산출물 요구가 영구적으로 남는다는 이유만으로 지속 제약으로 보지 않는다. 좁은 파일·프로젝트 범위라도 여러 작업에 계속 적용되면 제약이다. 한 입력에 여러 규칙이 있으면 하나 이상 지속할 때 제약이다. 인용이나 붙여넣기 문구는 실제로 채택한 지속 규칙일 때만 센다.

sol은 그 입력 뒤의 사용자 입력과 assistant 진행에서 규칙을 계속 따랐거나 따라야 했는지를 사후 판단한다. assistant의 순응만으로 사용자 의도를 확정하지 않고, 한 작업의 여러 후속 단계도 한 작업으로 본다. 뒤 대화로 일회성과 지속성을 가를 수 없으면 판단 불가다. 명시적 해제는 그전까지 지속했다는 근거가 될 수 있다. `constraint`, `not_constraint`, `uncertain`과 뒤 진행에 근거한 한국어 한 문장을 반환한다. 정확한 프롬프트는 [protocol.py](scripts/protocol.py)에 고정한다.

같은 지침·같은 자료로 sol을 두 번 독립 호출한다. 불일치 또는 형식 실패에만 같은 지침으로 세 번째 독립 호출하며 앞선 답을 보여 주지 않는다. 유효한 같은 표가 두 개 이상이면 다수결, 그렇지 않으면 판단 불가다. 판단 불가도 자기 일치율에는 별도 범주로 포함한다. 판단 불가·라벨 실패는 정확도 분석에서 제외하고 수를 보고하며 표본을 대체하지 않는다. 정답 파일을 해시로 봉인한 뒤 평가를 시작한다.

### 사전 정보 질의

모든 LLM에 같은 정의·지시·state와 정확히 같은 JSON 계약을 준다. 출력은 `{"is_constraint":true,"confidence":0.8}` 한 줄이다. confidence는 선택한 답에 대한 확신이 아니라 P(제약)이며 bool은 p≥0.5와 일치해야 한다. CLI 고유 system prompt는 통제할 수 없으며 명시적 데이터 취급 지시를 넣는다. Codex는 공식 `codex exec -m`, ephemeral·read-only·사용자 설정 무시·shell/apply_patch/multi_agent 비활성화를 사용한다. Claude는 공식 `claude -p --model`, safe-mode·tools 빈 목록·설정과 MCP 미사용·max-turns 1을 사용한다. 사용자 설정·토큰은 읽어 출력하거나 수정·복사하지 않는다. 도구 실행이 응답에 있으면 실패다.

JSON 코드 블록이 정확히 하나이면 그 안을 꺼내고 추출 여부를 기록한다. JSON 내부 줄바꿈은 별도 계약 이탈로 기록하되 구조·키·값이 맞으면 채점한다. 블록 밖 문장은 판단에 사용하지 않는다. 블록이 여러 개거나 여분 키·잘못된 타입·확률 범위·bool 모순은 형식 실패다. 판단 오류와 형식 실패를 분리한다. 스키마 강제·형식 수리·자동 재질의는 하지 않는다.

Jev 질문은 constraint-deep의 `route@1.1/is_constraint` 문장과 `noul` 형식을 그대로 사용한다. `The user's latest input sets a rule that applies beyond this single request and limits how the work is done (language, tool, format, or prohibition) rather than what to do.` state는 LLM과 같은 `previous_context`, `latest_user_input`이다. 현재 main f2db0e0의 core·engine Rust 소스에는 is_constraint 질문 구현이 없으므로 실제 engine 전체 route 호출을 재현했다고 주장하지 않는다. 다른 route 질문·활성 제약 상태를 합성하지 않는다. HTTP 요청·응답 형식은 현재 remote router와 같은 systemone/noul 계약이다. 이 차이는 제품 적용의 한계다.

### 호출과 보존

정답 6개 병렬 작업 뒤 모델 8개 통로를 병렬 실행한다. 통로마다 표본은 순서대로 1회, Jev만 같은 요청 3회다. 지연에는 CLI 시작과 서비스 시간을 포함하며 로컬 대기열은 뺀다. 예열은 없다. 동시 실행의 자원 경쟁은 실제 지연에 포함된다.

Codex 전체 700회, Claude 전체 400회, Jev 400회가 상한이다. 실패·모델 확인·미완료도 프로세스/HTTP 시작 전 잠금 장부에 예약해 센다. Codex 최대치는 정답 200+재판정 100+평가 400이다. 예약만 남은 호출은 재전송하지 않는다. 완료 응답을 읽어 단계별 재개하며 시간 초과는 CLI 300초·HTTP 60초다. 인증 거절이나 사용 불가 모델은 해당 통로를 멈추고 대체 모델을 쓰지 않는다. CLI 내부 네트워크 재시도는 외부 프로세스 호출 수와 구별한다.

원문·응답·정답·장부는 메인 저장소의 Git 제외 실험 저장소에만 둔다. 공개 자료는 설계·스크립트·집계·해시다. 키는 키체인 서비스 saturn-experiments-judge에서 프로세스 환경으로만 전달하고 자식 CLI 환경에서 제거한다. 정확 키 문자열을 저장 전에 가린다. TLS 검증을 유지하고 redirect를 거절한다. 임시 경로·캐시는 비공개 실험의 runtime 아래로 지정하며 /tmp·/private/tmp·사용자 cache를 사용하지 않는다. Claude 작업 폴더는 이 worktree의 `.runtime/claude-work`이고 CLI 고유 세션 기록 폴더 이름을 보고한다.

입력 형태 규칙은 라벨·응답을 보기 전에 고정한다. 500자 이상·Markdown 제목 2개 이상·목록 항목 3개 이상이면 `ai_instruction_likely`다. 또는 300자 이상·인수인계 표현(다음 세션/대화/에이전트, 이어서 작업, 작업 지시, 완료 조건, 인수인계, handoff)·목록 3개 이상이면 같은 범주다. 나머지는 `human_likely`다. 이는 작성자 인증이 아닌 붙여넣기 형태의 대리 지표다. 사람의 구조화된 글과 AI의 짧은 글을 오분류할 수 있으므로 결과 제목에 추정을 붙이며 실제 작성자별 인과 차이로 해석하지 않는다.

| 변수 | 종류 | 정의·단위 |

실패는 정확도 분모에 남겨 오답으로 처리한다. 정밀도는 유효 예측 양성의 TP/(TP+FP), 재현율은 실패한 양성까지 포함한 전체 정답 양성의 TP/P다. 실패한 음성은 TN으로 인정하지 않는다. 성공 조건부 정확도도 병기한다. 형식 실패율은 정답 불가를 포함한 전체 질의 100개 기준이고 프로세스·HTTP 실패는 별도 집계한다. 빈 분모는 null이다.

비율은 k/n과 Wilson 95% 구간을 쓰며 명목 독립 구간임을 밝힌다. F1과 같은 표본 두 모델 정확도 차이는 시드 고정 2,000회 percentile bootstrap으로 계산한다. 프로젝트 단위 군집 bootstrap 구간을 주 정확도·정밀도·재현율·F1에 함께 보고한다. 집단별 표본 수를 공개하고 동일 표본의 대응 관계를 보존한다. 모델 순위·입력 형태 차이·기준값 선택은 탐색이다. 확인 가설 두 개는 Bonferroni 동시 97.5% Wilson 구간으로 하한이 목표 이상이면 채택, 상한이 목표 미만이면 기각, 나머지는 보류한다. 통계 근거는 [NIST 비율 구간](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm), 군집 bootstrap은 프로젝트 재표집이다.

### 기준값 선택

첫 Jev 응답에서 0.50~0.95 곡선을 만든다. 자동 등록 후보는 예측 양성 최소 10개이고 정밀도 점추정 ≥90%인 가장 낮은 값이다. 동시에 명목·프로젝트 군집 95% 하한이 모두 90% 이상인지 보고하며 통과하지 않으면 독립 검증 전 잠정 후보다. 없으면 자동 기준값 권장 없음이다.

묻기 하한은 0.50부터 자동 기준값 미만까지 0.05 간격이다. 결합 재현율 ≥90%와 전체 100개 중 묻기 비율 ≤25%를 모두 만족하는 값 중 가장 높은 값을 고른다. 없으면 묻기 ≤25% 안에서 결합 재현율 최대인 값, 동률이면 더 높은 값을 잠정 후보로 두고 목표 미달을 밝힌다. 자동 후보가 없으면 현재 0.80을 고정해 묻기 후보만 탐색한다. 묻기에 사용자가 항상 정답을 준다고 가정한 결합 재현율이므로 실제 확인 결과와 다르다. 현재 사용자 결정 0.80/0.70과 같은 표를 제공한다. main 문서에 남은 0.70/0.50은 이번 기준선이 아니다.

[Claude 공식 단가](https://platform.claude.com/docs/en/about-claude/pricing)는 Sonnet 5.5 입력/출력 2/10, Opus 5.5 4/20, Haiku 4.5 1/5 USD/100만 토큰이다. 캐시 쓰기 5분은 입력의 1.25배, 1시간은 2배, 캐시 읽기는 각각 0.20/0.20/0.10이다. CLI total_cost_usd도 별도 보존한다.

[OpenAI 공식 요금](https://developers.openai.com/api/docs/pricing)의 일반 단가로 astra 입력/캐시 읽기/출력 10/1/50, luna 0.10/0.01/0.50 USD/100만 토큰을 쓴다. 노출 페이지에서 정확한 gpt-6-sol·gpt-5.6-terra 단가를 확인하지 못하면 비용 null로 두며 다른 세대 값으로 대체하지 않는다. usage 없는 호출도 비용 null이다. 토큰 수를 바이트로 대체하지 않으며 구독의 실제 추가 청구액으로 해석하지 않는다. 비용 미상 수와 알려진 비용 합을 함께 보고한다.
