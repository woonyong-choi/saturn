# 입력 관계 이진 판단: 실험 결과

## 요약

두 Jev 질문은 개발 자료의 새 작업 72턴을 한 번도 기존 작업에 붙이지 않았으나, 이어 가기 재현율은 302/515(58.6%)로 기준 60%의 신뢰구간 하한에 못 미쳤다. 묻기는 262/608(43.1%)로 기준 40%를 넘었고 판단 토큰 감소도 확인되지 않았다. 개발 관문은 미통과이며 실제 입력 처리 기본값은 바꾸지 않는다.

## 방법

| 항목 | 값 |
|---|---|
| 설계 | [실험 설계](design.md), 수집 전 커밋 `ac733b3d` |
| 실행 ID | `20261006T211341Z-ac733b3` |
| 환경 | [env.json](env.json), 실제 Jev 1.13.0 HTTPS |
| 표본 | 기존 개발 표본 608턴 전수. 명확 라벨 587턴 |

기존 B 첫 응답과 동일하게 직전 입력·목표·진행을 state에 넣었다. 새 요청에는 같은 작업인지와 독립 목표인지를 각각 `noul`로 물었다. 신규 요청에는 기존 답·라벨·미래 입력을 넣지 않았다. 원자료·예약·실패는 Git 제외 로컬 폴더에 남겼다.

## 설계와 다른 점

설계의 가설·경계·제외 기준은 수집 뒤 바꾸지 않았다. 분석 표본은 기존 실험의 가린 입력과 두 모델의 사후 라벨을 재사용한 개발 표본이다. 독립 확인 자료로 간주하지 않는다.

## 결과

### 흐름

| 단계 | 수 |
|---|---:|
| 입력·예약·실제 Jev 호출 | 각 608 |
| HTTP 성공 | 607 |
| HTTP 520 | 1 |
| 기존 명확 라벨: 이어 가기·새 작업 | 515·72 |
| 불확실 라벨 | 21 |

HTTP 오류는 묻기로 처리하고 분모에 남겼다. 원자료 해시와 분석 재실행은 통과했다.

### 확인 분석

| 가설 | 지표 | 값 | 사전 기준 | 판정 |
|---|---|---|---|---|
| H1 | 새 작업 오접합 | 0/72, Wilson 95% [0.0, 5.07]% | 점추정 5% 이하, 상한 10% 이하 | 충족 |
| H2 | 이어 가기 재현율 | 302/515(58.6%), [54.34, 62.81]% | 하한 60% 이상 | 미충족 |
| H3 | 묻기·Jev 토큰 차이 | 262/608(43.1%), [39.21, 47.06]%; 새−기존 평균 −2.22토큰, 세션 군집 95% [−13.14, +2.57] | 묻기 40% 이하, 토큰 차이 상한 0 미만 | 미충족 |

기존 B를 0.50에서 바로 이진 판정하면 같은 표본의 새 작업 오접합은 38/72, 이어 가기는 488/515였다. 두 작은 질문의 안전 신호는 상당 부분 묻기 증가와 이어 가기 누락으로 얻은 것이다. 기존 B의 원제품 행동 전체와 새 제안의 실제 engine 행동을 대응 실행한 수치는 아니다.

### 탐색 분석

이 결과만으로 확률 경계를 완화하지 않는다. 특히 H1의 개발 상한 5.07%는 독립 확인 목표 5%보다 높다. 실패와 불확실 라벨을 빼서 성공률을 높이지 않았다.

## 논의

### 해석

질문을 두 개로 나누면 위험한 오접합을 줄일 수 있다는 개발 신호는 있다. 현재 결합 규칙은 유효한 이어 가기 213턴을 자동 처리하지 못했고 묻기 부담과 판단 비용 기준을 통과하지 못했다. 이를 실제 제품의 품질·속도·비용 이득으로 부르지 않는다.

### 타당성 위협

| 종류 | 위협 | 이 실험에서 |
|---|---|---|
| 내적 | 기존 표본과 결과를 보고 질문을 설계 | 개발 판정으로만 제한하고 별도 확인 자료를 섞지 않았다 |
| 구성 | 두 모델의 합의 라벨이 사용자 확정 정답이 아님 | `uncertain` 21턴을 재현율·오접합에서 제외하고 묻기에 포함했다 |
| 외적 | Claude 한국어 대화에 한정 | Codex·혼합어·새 세션에서는 검증하지 않았다 |

### 한계

- LLM 작업 완료, 사용자의 후속 수정, provider 실행 시간은 측정하지 않았다.
- Jev 토큰은 직접 보고된 입력·출력 합계이며 실제 청구액은 아니다.
- 기존 개발 표본의 반복 사용이므로 결과가 좋아도 독립 성능 검증이 아니다.
