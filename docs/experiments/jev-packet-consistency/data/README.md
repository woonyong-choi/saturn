# 데이터

## 출처

| 항목 | 값 |
|---|---|
| 수집 방법 | 봉인된 첫 `compact` 요청의 원문을 개발에서는 5회씩 재전송한다. 확인에서는 #7 새 J trial과 사전 검토 변형을 쓴다. |
| 수집 기간 | 수집 전 |
| 개수 | 수집 전. 개발 예정 12 fixture × 5회 = 60회 |
| 표본 여부 | 개발은 봉인된 12개 전수, 확인은 새 프로젝트 계열에서 사전 고정한 표본 |
| 라벨 | 개발의 선택 집합에는 정답 라벨을 붙이지 않는다. 확인의 필수 근거와 변형 의미는 수집 전 두 사람이 검토한다. |
| 알려진 문제 | 개발 12개는 확인 판정의 독립 표본이 아니다. |
| 개인정보 | 새 확인 원문은 공개 파일에 복사하지 않고 로컬 Git 제외 기록에 둔다. |
| 라이선스 | Saturn 프로젝트 자체 생성 자료. 외부 원문은 별도 확인 전 공개하지 않는다. |

## 파일

| 파일 | 내용 | 만드는 스크립트 |
|---|---|---|
| 로컬 개발 원자료 JSONL | 시도 전 `start`와 완료 후 `end`를 각각 보존한다. | `scripts/dev_replay.py` |
| 로컬 확인 원자료 JSONL | 같은 장부 형식의 변형별 응답을 보존한다. | `scripts/consistency.py` |
| `eval/dev-source-lock.json` | 개발 소스 manifest·원자료·첫 요청의 SHA-256과 선택 개수 | 수집 전 봉인 |
| `results/dev-summary.json` | 개발 관측의 공개 가능한 수치만 수집 후 옮긴다. | 수집 후 검토 |

## 필드

### 원자료 JSONL

| 필드 | 타입 | 단위 | 제약 | 뜻 | 예 |
|---|---|---|---|---|---|
| `event` | string | 없음 | `start` 또는 `end` | 전송 전 장부 또는 응답 기록 | `start` |
| `id` | string | 없음 | 필수 | fixture 식별자 | `t00J` |
| `rep` | integer | 없음 | 1~5 | 같은 원요청의 반복 번호 | `1` |
| `request_sha256` | string | 없음 | 필수 | 실제 보낸 요청 바이트의 해시 | `sha256` |
| `status` | integer 또는 null | HTTP | `end`에서만 | 응답 상태 | `200` |
| `received` | string | 없음 | `end`에서만 | 키 문자열을 가린 응답 원문 | `{"answers":{}}` |

`start`만 남은 시도는 전송 여부를 알 수 없는 실패로 세고 자동 재전송하지 않는다. 수집 뒤 원자료를 고치지 않는다. 새 수집은 다른 실행 파일에 남긴다. 보고서에는 수집 뒤 `설계와 다른 점` 절을 반드시 넣는다.
