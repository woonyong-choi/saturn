# 제약 등록 기준값의 사람 확인과 Astra 정답 곡선: 실험 결과

> [!NOTE]
> 사후 탐색 분석이다. 사전 등록한 가설과 판정 기준이 없고 [프로젝트 대화 전수 측정](../constraint-deep/report.md)의 비공개 원자료를 다시 계산했다. 아래 수치는 등록 기준값을 정하는 근거이며 확인 분석의 채택·기각이 아니다.

## 요약

사람 확인 40건 중 사용자가 확실하다고 한 24건에서 정답 라벨러 gpt-6-astra는 21건, 재판정은 21건, gpt-5.6-luna는 5건 일치했다. 지난 수치의 정답 라벨에 Luna를 쓴 것이 한계이고, 이후 정답은 Astra를 기준으로 한다. Astra 판정(애매 표시 제외) 868턴을 정답으로 다시 그린 Jev `is_constraint` 곡선에서 0.80 이상은 정밀도 91.3%, 0.70 이상은 정밀도 84.8%, 재현율 77.2%였다. 0.70 이상 0.80 미만은 입력의 12.6%이고 그중 67.0%가 제약이다. 이 값으로 0.8 이상 자동 등록, 0.7 이상 0.8 미만 묻기, 0.7 미만 미등록을 정한다.

## 방법

| 항목 | 값 |
|---|---|
| 입력 | 프로젝트 대화 전수 측정의 비공개 원자료. 원문은 공개하지 않고 판정, 라벨, 확률만 썼다 |
| 사람 확인 | 라벨러 불일치·경계 사례 40건을 사용자가 `제약`, `제약 아님`, `모르겠다`로 판정 |
| 곡선 | Jev `route@1.1`의 `is_constraint` 확률(`repeat=1`, `status=ok`)과 gpt-6-astra 라벨(`ambiguous` 제외) |
| 계산 | [scripts/01-analyze.py](scripts/01-analyze.py), 구간은 Wilson 95% |

기준값 이상을 양성으로 본다. 재현율의 분모는 정답 양성 전체다.

재현 명령은 아래와 같다. 원자료 폴더를 인자로 주지 않으면 메인 저장소의 `.local/experiments/constraint-deep`을 읽는다.

```sh
docs/experiments/constraint-human-check/run.sh analyze
```

결과는 [results/summary.json](results/summary.json)에 쓰며, 보고서의 모든 수치는 이 파일의 값이다. 이 보고서를 쓸 때 실행해 아래 표와 같은 값을 확인했다.

## 설계와 다른 점

사전 등록이 없다. 사람 확인은 정답 라벨러가 갈린 경계 사례만 모은 표본이어서 전체 입력의 성능을 대표하지 않는다.

## 결과

### 사람 확인 40건

| 판정 | 건수 |
|---|---|
| 제약 | 14 |
| 제약 아님 | 10 |
| 모르겠다 | 16 |

확실한 24건에서 라벨러와 사용자 판정의 일치는 다음과 같았다.

| 라벨 | 일치 |
|---|---|
| gpt-6-astra | 21/24 |
| 재판정 | 21/24 |
| gpt-5.6-luna | 5/24 |

같은 24건에서 Jev 기준값별 정밀도와 재현율이다.

| 기준값 | 정밀도 | 재현율 |
|---|---|---|
| 0.50 | 14/16, 87.5% [64.0, 96.5] | 14/14, 100.0% [78.5, 100.0] |
| 0.70 | 10/11, 90.9% [62.3, 98.4] | 10/14, 71.4% [45.4, 88.3] |
| 0.75 | 8/8, 100.0% [67.6, 100.0] | 8/14, 57.1% [32.6, 78.6] |
| 0.80 | 6/6, 100.0% [61.0, 100.0] | 6/14, 42.9% [21.4, 67.4] |

표본이 경계 사례 24건이라 구간이 넓다. 사용자는 입력의 절반가량이 AI가 쓴 지시문을 붙여 넣은 것이라 앞뒤 맥락 없이 제약인지 가리기 어렵다고 관찰했다. 이 때문에 모르겠다가 16건이다.

### Astra 정답 868턴 곡선

868턴 중 정답 양성은 448개였다.

| 기준값 | 정밀도 | 재현율 |
|---|---|---|
| 0.50 | 422/577, 73.1% [69.4, 76.6] | 422/448, 94.2% [91.6, 96.0] |
| 0.60 | 397/517, 76.8% [73.0, 80.2] | 397/448, 88.6% [85.3, 91.2] |
| 0.65 | 367/452, 81.2% [77.3, 84.5] | 367/448, 81.9% [78.1, 85.2] |
| 0.70 | 346/408, 84.8% [81.0, 88.0] | 346/448, 77.2% [73.1, 80.9] |
| 0.75 | 310/349, 88.8% [85.1, 91.7] | 310/448, 69.2% [64.8, 73.3] |
| 0.80 | 273/299, 91.3% [87.6, 94.0] | 273/448, 60.9% [56.3, 65.3] |
| 0.85 | 219/228, 96.1% [92.7, 97.9] | 219/448, 48.9% [44.3, 53.5] |
| 0.90 | 46/47, 97.9% [88.9, 99.6] | 46/448, 10.3% [7.8, 13.4] |

0.80 이상 299턴은 자동 등록 대상이고, 0.70 이상 0.80 미만 109턴(868턴의 12.6%)은 사용자에게 묻는 대상이다. 그 109턴 중 정답 양성은 73턴(67.0%)이다. 자동 등록과 묻기를 합쳐 0.70 이상으로 보면 재현율은 77.2%다.

## 논의

0.70 아래는 정밀도가 84.8%를 밑돌고 0.65에서 81.2%로 떨어져 사용자 확인 없이 등록하기엔 낮다. 0.80 이상은 정밀도 91.3%이고 틀린 자동 등록은 `/constraints`와 등록 기록 줄로 되돌릴 수 있다. 0.70~0.80은 세 건 중 둘이 제약이라 묻는 비용을 치를 만하다. 한계는 세 가지다. 정답이 Astra 판정이라 사람 판정과 다를 수 있고(확실 24건에서 21건 일치), 사람 확인은 경계 사례만이고, AI가 쓴 지시문이 섞여 작업 하나에만 해당하는 규칙이 많다. 지난 전수 측정의 정답 라벨은 Luna였고 사람 판정과의 일치가 5/24여서 그 수치는 근거로 약하다.

## 결론

| 결정 | 근거 |
|---|---|
| 0.8 이상 자동 등록 | Astra 정답 곡선 정밀도 91.3% [87.6, 94.0], 사람 확인 24건에서 6/6 |
| 0.7 이상 0.8 미만 사용자에게 묻기 | 입력의 12.6%, 그중 67.0%가 제약 |
| 0.7 미만 미등록 | 0.65에서 정밀도 81.2%, 0.50에서 73.1% |
