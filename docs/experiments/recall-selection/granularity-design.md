# 복원 목록 단위: 후속 실험 설계

## 질문

첫 비교의 문서 평가에서 기존 복원과 새 복원 모두 `direct_installs`, `last_active` 원문을 보내지 않았다. 목록을 큰 조각에 묶는 비용을 줄이면 이 근거를 유지할 수 있는지 확인한다.

## 설계

첫 비교의 기준과 질문·정답표를 유지한다. 질문을 본 뒤 수정하므로 추가 문서도 이제 개발 자료이며, 새 독립 평가로 보고하지 않는다. 첫 비교는 중단하지 않고 끝까지 보존한다.

후속 후보는 목록 항목을 문단 경계로 인식하고, 코드가 아닌 조각의 목표 크기를 1,200자에서 600자로 줄인다. fenced code는 통째로 남기고 조건·예외의 인접 문단 규칙은 유지한다. 사용자 입력은 초점을 좁힌 뒤 4,000자 이하이면 여전히 한 조각이다. 예산 8,000자, 출처별 절반 배분, 상대 점수 0.25와 상위 2개 유지, 중복 통합 규칙은 바꾸지 않는다.

같은 18조건의 원문 전체·기존 복원·후속 복원을 두 provider에서 다시 수집한다. 시드는 7110이다. 첫 비교의 원응답을 후속 대응 비교의 대조군으로 재사용하지 않는다. 108실행 후 기존 복원에서 맞던 문항의 손실이 없고 두 provider의 토큰 합계가 감소하면 추가 반복 두 번을 수행한다. 반복 실패는 실패로 유지한다. 정답표와 임계값을 결과에 맞춰 수정하지 않는다.

실행 오류·제외·분모·사용량 판정과 한계는 [최초 설계](design.md)를 따른다. 추가 문서는 기존 회수 결함을 드러낸 사례이며 실제 코딩 작업 성공률을 뜻하지 않는다.
