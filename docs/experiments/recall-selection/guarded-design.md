# 코드 주변 조건 보존: 후속 실험 설계

## 질문

추가 회귀 테스트에서 긴 Agent 코드 블록은 선택됐지만 바로 앞의 실행 금지 조건이 빠졌다. 문단 선택 뒤 다시 조각을 나누면서 코드와 조건이 다른 후보가 된 것이 원인이다.

## 설계

fenced code와 바로 앞뒤 문단을 하나의 후보로 묶는다. 인접한 보호 범위는 합친다. 이 후보가 공간에 들어가지 않으면 부분 코드만 보내지 않고 후보 전체를 제외한다. 그 밖의 규칙은 [복수 질문 배분](coverage-design.md)과 같다.

`guarded` 폴더에 동일한 18조건의 새 입력을 내보낸다. `coverage`와 context·question 문자열이 모두 같을 때만 해당 실행을 재사용한다. 원응답의 성공 여부는 재사용 조건으로 쓰지 않는다. 문자열이 달라진 조건은 두 provider를 다시 호출하고 새 원응답을 남긴다. 대조군은 `coverage`의 동일 원문 전체·기존 복원 실행이다. 이는 새로운 독립 대응 실험이 아니라 코드 수정에 따른 입력 변경 사례의 재검증이며 실행 시점 차이를 한계로 보고한다.

기존 정답 손실 없음, 원문 전체가 맞힌 문항 모두 회수, 두 provider의 입력 토큰 감소를 확인하면 새 복원 입력 18개를 두 번 더 실제 호출한다. 반복마다 원응답과 사용량을 보존한다. 최초 설계의 실패·제외·형식 판정은 유지한다. 정답표와 질문은 바꾸지 않는다.

보고서는 단계별 고유 실제 호출 수와 재사용 수를 구분한다. 입력 재사용으로 복사된 응답을 새 모델 실행으로 세지 않는다. 중단된 실행과 모델을 부르지 않은 준비 단계도 보존한다.
