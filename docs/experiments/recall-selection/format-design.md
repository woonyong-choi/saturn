# 현재 요청의 응답 형식 보존: 최종 반복 설계

## 질문

단일 질문 검색 폭을 복구한 조합에서 Claude가 `gitconfig` 키 대신 `decision`으로 `ask`를 답했다. 엄격 판정은 103/104이며 반복 진입 기준을 통과하지 못했다. 동일 현상은 앞 단계의 원문 전체와 기존 복원에서도 관측됐지만 실패를 제외하지 않는다.

## 설계

원문 복원 뒤 현재 입력 앞에 요청된 출력 형식과 필드 이름을 그대로 따르라는 일반 지시를 붙인다. 특정 평가 키·정답·JSON 값은 넣지 않는다. 실제 engine 전송 경로의 `attach_evidence`를 변경하고 선택 규칙과 질문·정답표는 유지한다.

`format` 폴더에서 같은 18조건의 새 복원 입력을 내보내고 두 provider에서 36번 새로 호출한다. 원문 전체와 기존 복원은 `coverage`의 동일 입력을 재사용한다. 채택 기준은 두 provider의 전 문항 통과, 기존 대비 입력 토큰 감소다. 이는 개발 자료에서 일반 형식 지시를 보강한 탐색 분석이다.

기준을 통과하면 새 입력으로 두 번 더 반복해 72실행을 추가한다. 시드 7111로 섞고 provider마다 직렬 실행한다. 반복 실패와 앞 단계 실패를 모두 보존한다. 원문·패킷·복원·경계 지시의 실제 입력 비용을 모두 포함한다. 토큰 절감률을 금전 청구액 감소율로 해석하지 않는다.
