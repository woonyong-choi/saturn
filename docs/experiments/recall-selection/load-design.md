# 긴 기록의 복원 시간: 측정 설계

## 질문

선택 규칙이 복잡해진 뒤 긴 기록의 검색 시간이 늘어나는지 실제 engine 복원 함수를 측정한다.

## 설계

실제 학습 대화 `learning-59`의 마스킹된 행을 그대로 사용한 조건과 같은 행을 10배·100배 복제한 합성 부하 조건을 만든다. 복제할 때 기록·실행·작업 번호를 서로 다르게 부여한다. 복제 조건은 실제 장기 대화의 정확도 자료가 아니다.

기존 복원의 보존된 테스트 바이너리와 현재 코드의 테스트 바이너리에서 `export_recalled_evidence`를 직접 실행한다. 빌드는 시간에 포함하지 않고 프로세스 시작·JSON 읽기·복원·JSON 쓰기를 포함한 경과 시간을 잰다. 같은 질문과 8,000자 상한을 사용한다. 크기마다 두 방식을 번갈아 세 번 실행하고 예열을 제외하지 않는다. 합계 18실행이며 모델 호출은 없다.

크기별 중앙값·최소·최대 시간을 보고하고 원래 기록 조건과 합성 조건을 분리한다. 같은 실제 대화에서 복제한 부하이므로 독립 실제 사용자 표본으로 세지 않는다. CI 시간 기준이나 일반 성능 보장을 만들지 않는다. 명령·종료 상태·출력·환경과 기준 바이너리 해시를 보존한다.
