# 응답 계약을 명시한 대응 비교: 실험 설계

## 질문

형식 지시 보강 후에도 Claude는 단일 권한 질문에 올바른 값 `ask`를 다른 키로 답했다. 평가 질문은 JSON 객체를 요구했지만 문항 ID를 출력 키로 쓰라는 조건을 명시하지 않았다. 앞 단계의 엄격 실패는 유지하고, 계약을 명시한 새 대응 비교를 한다.

## 설계

모든 조건의 질문 머리에 문항 ID를 JSON 키로 사용하고, 키를 바꾸거나 더하지 말라는 문장을 추가한다. 요구하는 키 목록도 질문에서 자동으로 만든다. 키 이름은 이미 질문에 있던 식별자이고 정답이나 답의 일부를 넣지 않는다. 질문 본문과 정답표는 그대로다. 검색에도 이 실제 입력을 사용한다.

효과가 확인되지 않은 일반 형식 지시는 runtime에서 제거한다. 최종 선택 코드는 [단일 질문 검색 폭 유지](conservative-design.md)의 규칙이다. 같은 전송 안의 중복 통합, 관련 문단 선택, 코드 주변 조건 보호, 복수 질문별 상위 두 후보에서 종료를 적용한다. 단일 질문 상위 세 후보 제한은 적용하지 않는다.

`explicit` 폴더에서 18조건 × 3방식 × 2provider, 108실행을 모두 새로 수집한다. 원문 전체와 기존 복원도 동일한 명시적 질문으로 다시 부른다. 앞 단계 응답을 재사용하지 않는다. 시드는 7110이고 provider마다 직렬 실행한다. 변경된 평가 계약을 앞 결과에 소급 적용하지 않는다.

두 provider에서 기존 정답 손실이 없고 원문 전체가 맞힌 문항을 모두 회수하며 입력 토큰이 감소하면 후보 입력을 두 번 더 실제 호출한다. 추가 72실행의 시드는 7111이다. 실패와 부분 출력, 사용량을 모두 남긴다. 일반화 평가가 아니라 이미 본 자료에서 계약을 고친 대응 회귀 검증이며, 같은 문제 반복을 독립 표본으로 세지 않는다.

지표·실패 분모·원응답 대조는 최초 설계를 따른다. 현재까지 평가 키 불일치를 실패에서 제거하지 않는다. 새 결과로 옛 실패를 덮어쓰지 않는다.
