# 단일 질문 검색 폭 유지: 최종 회귀 검증 설계

## 질문

단일 질문의 상위 세 후보 제한에서 Codex가 두 문항을 `unknown`으로 답했다. 단일 질문의 이 제한을 제거하고 복수 질문의 상위 근거 선택 종료만 유지한다.

## 설계

최종 규칙은 다음과 같다. 같은 전송 안의 중복 원문을 출처와 함께 통합한다. 관련 문단과 양옆 문단을 선택하고 긴 코드는 양옆 조건과 한 후보로 묶는다. 코드가 아닌 조각의 목표는 600자다. 서로 다른 줄에 물음표가 하나씩 있는 복수 질문은 질문별 상위 두 후보에서 선택을 마친다. 그 밖의 입력은 상대 점수 0.25 및 상위 두 후보 유지 규칙을 사용하며 세 후보 제한을 두지 않는다. 원문 예산은 최대 8,000자다.

`conservative` 폴더의 입력을 최종 코드에서 다시 내보낸다. `focused`, `coverage` 순서로 context·question이 모두 같은 실행만 찾아 재사용한다. 실패 여부는 재사용 기준이 아니다. 모두 같으면 새 호출은 하지 않는다. 이 조합 결과는 개발 자료의 탐색 분석이다.

두 provider에서 기존 정답 손실이 없고 원문 전체가 맞힌 문항을 모두 회수하며 입력 토큰 합계가 감소하면 최종 복원 입력 18개를 두 번 더 호출한다. 시드 7111로 반복 순서를 섞고 provider마다 직렬로 실행한다. 추가 72실행은 재사용하지 않는다. 현재 코드에서 내보낸 입력이 재사용 입력과 바이트 단위로 같은지도 검사한다. 반복 실패를 유지하고 무손실·일반화 성능을 주장하지 않는다.

이 설계는 이미 본 질문의 실패에 따른 변경이다. 새 독립 확인 실험으로 표현하지 않는다. 최초 원응답·실패·비호출 준비 자료를 모두 보존한다. 최종 결과는 실제 호출 수, 재사용 수, 엄격 정답, 기존 대비 및 원문 전체 대비 입력 토큰으로 보고한다.
