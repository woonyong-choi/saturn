# 릴리스 빌드의 복원 시간: 측정 설계

## 질문

디버그 테스트 바이너리의 시간을 실제 배포 빌드 지연으로 해석하지 않도록 같은 비교를 release 프로파일에서도 수행한다.

## 설계

이전 복원은 별도 비공개 소스 사본에 보존한 두 원본 파일을 적용해 빌드한다. 현재 복원은 작업 공간의 현재 코드로 빌드한다. 각 `cargo test -p saturn-engine --lib --release --no-run --message-format=json`이 반환한 실행 파일 경로에서 바이너리를 복사하고 해시를 남긴다. 다른 프로파일의 예전 파일을 경로 추정으로 선택하지 않는다.

동일 입력의 패킷·복원 결과가 기존 수집 입력과 같은지 확인한다. 부하의 크기·반복·시간 범위는 [첫 부하 설계](load-design.md)를 따른다. `load-release`에 18실행을 새로 보존한다. 디버그 결과와 release 결과를 섞어 중앙값을 만들지 않는다. 빌드와 모델 호출 시간은 포함하지 않는다. 이 측정은 전체 TUI·router 종단 지연이 아니다.
