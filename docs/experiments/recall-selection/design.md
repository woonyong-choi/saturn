# 복원 근거 선택: 실험 설계

## 질문

중복 원문 통합, 문단 선택, 상대 관련도 기준을 적용하면 기존 복원보다 실제 입력 토큰이 줄면서 사실 회수 정확도를 유지하는지 비교한다. 턴 사이 근거 생략은 provider 자동 압축 뒤 원문 생존 여부를 알 수 없어 적용하지 않는다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 두 provider에서 새 복원의 엄격 정답 수가 기존 복원 이상이고 실제 입력 토큰 합계가 감소한다. | 고정한 실제 대화 재생 및 문서 질의 |
| H2 | 새 문서의 단일 질문에서도 새 복원이 기존 복원 이상으로 정답을 낸다. | 새 문서에서 따로 실행한 첫 질문 |

## 설계

| 항목 | 값 |
|---|---|
| 식별자 | recall-selection |
| 관련 설계 | [맥락 정리](../../design/context-management.md) |
| 사전 데이터 | context-recall의 10조건·80문항은 개발 자료. 추가 자료는 permissions, router-key-security, settings, records 설계 문서의 수집 시점 원문 |
| 조건 | 원문 전체, 이전 복원, 새 복원. 패킷과 질문은 대응 조건에서 동일 |
| 선택 규칙 | BM25 최고 점수의 0.25 이상. 각 출처 종류의 상위 2개는 유지. 예산은 이전과 같이 최대 8,000자 |
| 문단 규칙 | 질문과 겹치는 문단 및 양옆 문단 유지. fenced code는 한 단위로 취급. 생략 표지 포함 |
| 중복 규칙 | 같은 전송 안의 바이트가 같은 원문을 통합하고 모든 출처 표지 유지. 이전 턴 전송 여부로 생략하지 않는다. |
| 배정 | 시드 7110으로 조건 순서를 섞고 provider별 직렬 실행 |
| 눈가림 | 검색은 정답표를 받지 않음. 작성자는 정답을 원문에서 정하므로 사람 눈가림 없음 |
| 환경 | 기존과 같은 Claude haiku, Codex gpt-6-sol 실제 CLI. 버전·원문·코드 해시는 수집 전에 보존 |

## 표본

기존 10조건은 6출처가 겹치므로 독립 표본으로 세지 않는다. 추가 문서 4개는 각 5문항 묶음과 첫 문항 단독 실행을 만든다. 합계 18조건, provider마다 조건별 104문항이다. 추가 문서는 실제 저장소 문서지만 재생 대화의 포장은 합성 입력이다. 문서에 적힌 정책 회수를 검사하며 정책의 실제 구현 상태를 판정하지 않는다.

1차 비교는 18조건 × 3방식 × 2provider의 108실행이다. 예산에 따른 표본이며 모집단 신뢰구간과 유의성 검정을 하지 않는다. 채택 기준을 통과한 경우 새 복원 조건을 두 번 더 반복한다. 같은 문제 반복은 독립 표본이 아니다. 예열은 없다. provider 오류가 연속 3번 나면 해당 provider 수집을 중단하고 미실행까지 보고한다. 내용상 실패로 수집을 멈추거나 정답표를 고치지 않는다.

## 분석

정답은 앞 실험과 같은 공백·인용부호·대소문자 정규화 뒤 허용값과 비교한다. 정상 종료, 도구 호출 없음, Claude의 같은 session과 Ready도 유효 조건이다. 실패는 분모에 남기며 미실행을 성공으로 취급하지 않는다. 원응답에서 사용량을 다시 읽어 결과 파일과 대조한다.

Claude 입력·캐시 생성·캐시 읽기와 Codex 입력 토큰을 집계한다. 재시도와 반복은 별도로 보존한다. provider·자료군별 정답, 대응한 정답→오답 수, 토큰 합계·절감률·조건별 차이를 보고한다. 한 provider라도 새 복원 때문에 맞던 문항이 틀리면 전체 채택을 보류하고 오류를 공개한다. 전체 통과 뒤 수정하면 새 단계로 재등록하며 이전 결과를 확인 분석으로 재사용하지 않는다.

## 판정

H1과 H2를 통과하고 추가 반복에서도 기존 정답 손실이 없으면 적용한다. 실패하면 실패 원인을 보존하고 해당 규칙을 수정하거나 적용하지 않는다. 미관측 실사용 작업 성공률이나 무손실을 주장하지 않는다.

## 타당성 위협

- 기존 질문은 개발에 쓰였으므로 일반화 평가가 아니다.
- 새 문서는 같은 프로젝트의 자료이고 작성자가 라벨을 만들었다. 독립 외부 평가가 아니다.
- 단일·복수 질문과 예외 규칙은 검사하지만 정상 router, 실제 코드 수정 작업, provider 자동 압축 뒤 생존 여부는 검사하지 않는다.
- 상대 관련도 임계값은 경험적 후보이며 확률이나 신뢰도 수치가 아니다.
