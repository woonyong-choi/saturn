# 복수 질문의 근거 배분: 후속 실험 설계

## 질문

목록 단위를 줄인 비호출 재생에서도 `direct_installs` 근거가 빠졌다. 여러 질문을 한 질의로 점수화하면 공통 표현이 특정 질문의 식별자보다 많은 공간을 차지할 수 있다.

## 설계

[목록 단위 설계](granularity-design.md)의 후보에서 질문별 첫 후보를 우선 배치한다. 입력의 서로 다른 줄에 물음표가 있는 질문이 두 개 이상이면 질문마다 최고 후보를 하나씩 둔 뒤 둘째 후보를 하나씩 둔다. 중복 후보는 한 번만 선택한다. 이후에는 전체 질의의 상대 점수 순서를 따른다. 물음표 줄이 두 개 미만이면 기존 전체 질의 순서다. 원문 정답, 특정 질문 id, 특정 파일 이름은 선택 규칙에 넣지 않는다.

목록 단위만 바꾼 단계는 원문 선택만 재생했고 모델 호출은 하지 않는다. 해당 입력과 계획도 보존한다. 이 단계는 `coverage` 실행 폴더에서 같은 18조건 × 3방식 × 2provider, 108실행을 새로 수집한다. 원문·질문·정답은 최초 단계와 같다. 이미 개발에 사용한 자료라는 한계를 유지한다.

최초 설계의 회귀 금지와 토큰 감소 기준을 적용한다. 추가로 원문 전체가 맞힌 문항을 후속 복원도 모두 맞혀야 반복 단계로 넘어간다. 이를 통과하면 동일 입력으로 두 번 더 반복하고 실패를 유지한다. 실패하면 원인과 적용 범위를 보고하고 실패한 규칙을 기본 경로에 넣지 않는다.
