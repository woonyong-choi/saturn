# 복원 근거 선택: 실험 결과

## 요약

중복 원문 통합, 문단 선택, 질문별 후보 배분을 구현하고 실제 모델 호출 604건을 보존했다. 최종 세 차례 대응 비교에서 이전 복원 대비 실제 입력 토큰은 Claude 0.98%, Codex 0.95% 줄었다. 정답은 각각 296/312에서 310/312, 300/312에서 312/312로 늘었다. 그러나 Claude에서 이전 복원이 맞힌 문항을 새 복원이 틀린 사례가 2건 있어 사전 지정한 무손실 채택 기준은 통과하지 못했다.

현재 작업 트리에 후보 구현이 있으며 릴리스 채택은 보류한다. 원문 전체도 Claude 311/312였으므로 원문을 보내면 항상 정답이라는 결론도 성립하지 않는다. 이 실험은 고정 질문의 사실 회수 평가이며 일반적인 작업 품질 보증이 아니다.

문서의 내용은 실제 자료지만 이를 대화 기록처럼 감싼 입력은 합성이다. 고유 질문 문자열은 68개이며 같은 질문이 대화 길이와 반복에 따라 재등장한다. 한 차례의 104문항 중 원문에 답이 있는 문항은 87개, 답이 없어 `unknown`이어야 하는 대조 문항은 17개다. 추가 문서의 정답 근거 줄은 비공개 `gold-provenance.json`에 보존했다. 검색 함수에는 정답표를 전달하지 않았다.

세 방식은 원문 전체, 이전 복원, 새 복원이다. 복원 방식의 인계 패킷은 4,000 추정 토큰 예산으로 같고 복원 상한은 8,000자다. 최종 비교에서는 모든 방식의 사용자 질문에 JSON 키 목록을 명시했다. Claude는 같은 프로세스에 자료를 넣고 Ready 응답 뒤 질문했으며, Codex는 자료와 질문을 한 요청으로 보냈다. 도구 실행은 막았다. 두 provider의 입력 구조가 다르므로 서로의 절감률을 평균 내지 않는다.

채점은 기존 평가와 같은 공백·인용부호·대소문자 정규화 뒤 허용 답과 비교한다. 값이 숫자로 반환돼도 문자열로 정규화한다. 따라서 정답 수는 JSON 형식·자료형까지 엄격하게 지켰다는 증거가 아니다. 누락된 키와 틀린 답은 실패로 남겼다. Claude의 입력·캐시 생성·캐시 읽기 토큰과 Codex의 입력 토큰을 원응답에서 합산했다. CLI 부가 입력을 포함하며 과금액이나 출력 토큰 절감률은 아니다.

## 구현과 보존 범위

| 변경 | 현재 구현 | 한계 |
|---|---|---|
| 중복 제거 | 같은 전송에서 원문이 바이트 단위로 같은 조각을 합치고 출처 표지는 모두 유지 | 이전 턴이나 패킷에 보냈다는 이유로 생략하지 않는다. provider 자동 압축 뒤 생존 여부를 추적할 수 없기 때문이다. |
| 필요한 문단 선택 | 질문과 겹치는 문단 및 양옆 문단 선택, 목록 경계 사용, 일반 조각 약 600자 | 인접한 일반 문단은 최종 예산 선택에서 빠질 수 있다. |
| 코드 보존 | fenced code와 양옆 문단을 한 후보로 묶고 겹치는 보호 범위 통합 | 후보 전체가 예산보다 크면 제외. 모든 선언·부정·예외의 의미 보존을 증명한 것은 아니다. |
| 질문별 배분 | 서로 다른 줄에 물음표가 하나씩 있는 여러 질문은 질문당 상위 두 후보를 합침 | 질문 난이도나 근거 충분성을 판정하는 알고리즘은 아니다. |
| 그 밖의 질문 | 출처 종류별 상위 두 후보와 최고 관련도의 25% 이상 후보 유지 | 단일 질문의 상위 세 개 제한은 실제 사실 누락이 생겨 제거 |
| 검색 비용 | 후보 집합의 역색인과 질문 토큰 재사용 | 이전 복원보다 실행 비용은 여전히 증가 |

기록 저장소와 대기열에는 원래 사용자 입력을 남기고 provider 전송 직전에만 근거를 붙인다. 가짜 provider를 사용한 engine 통합 검증은 같은 살아 있는 session의 후속 질문에도 필요한 옛 근거를 다시 보내는 것을 확인한다. 이는 provider의 실제 자동 압축을 재현한 시험은 아니다.

새 복원의 원문 전체 대비 절감은 Claude 45.50%, Codex 24.88%다. 이는 이전 실험의 80문항과 다른 104문항 구성에서 나온 값이므로 과거 33.96%, 18.06%와 직접 비교해 이번 변경의 개선 폭으로 삼지 않는다. 이번 변경의 대응 개선 폭은 이전 복원 대비 약 1%다.

### 보존한 실패

Claude 새 복원의 `audit-8-r2`, `audit-16-r3`에서 provider 이름 분기 허용 디렉터리를 물었을 때 `providers/codex` 대신 `unknown`을 반환했다. 두 실행 모두 해당 문자열이 실제 인계 패킷과 복원 근거에 각각 들어 있었다. 따라서 단순한 문자열 누락으로 설명할 수 없지만 주변 맥락 선택과 응답 변동 중 무엇이 원인인지는 분리하지 못했다. 모델 변동으로 단정해 실패를 제외하지 않았다.

같은 반복 번호의 이전 복원과 원문 전체는 이 두 문항을 맞혔다. 원문 전체의 Claude 오류 한 건은 `audit-16-r3`의 다른 `prompt` 문항이다. 원문 전체도 틀렸다는 이유로 새 복원의 실패를 상쇄하지 않는다. 원응답, 실제 질문·자료, 사용량, 정답표와 개별 판정을 모두 보존했다.

## 설계 변경과 전체 실행 내역

처음의 세 규칙에서 문서 스키마 사실 누락을 확인해 후보 배분과 조각 크기를 고쳤다. 모든 변경은 별도 단계에 남겼으며 첫 설계를 통과한 단일 확인 실험으로 묶지 않는다. 문서는 첫 실행 이후 개발 자료가 됐으므로 최종 결과도 독립 미사용 자료 평가가 아니다.

초기 질문은 JSON 객체를 요구했지만 키 이름 계약이 충분히 명확하지 않았다. Claude가 `gitconfig` 대신 `decision`이나 한국어 키를 반환한 실패도 원래 판정 그대로 남겼다. 명시적 계약 단계는 모든 방식에 같은 변경을 적용하고 새로 호출했다. 옛 실패를 사후 정답으로 바꾸지 않았다. 대조군 반복은 새 복원의 실패를 본 뒤 추가했으므로 시간상 섞여 실행된 확인 실험이 아니라 추가 탐색 비교다.

## 실행 비용과 코드 검증

| 자료 규모 | 이전 복원 release 중앙값 | 새 복원 release 중앙값 | 각 방식 반복 |
|---|---:|---:|---:|
| 실제 기록 59행 | 0.0099초 | 0.0196초 | 3 |
| 복제한 590행 | 0.0377초 | 0.0705초 | 3 |
| 복제한 5,900행 | 0.2876초 | 0.5015초 | 3 |

측정은 테스트 실행 파일 시작, JSON 읽기, 복원, 결과 쓰기를 포함한다. 모델 호출·빌드는 포함하지 않으며 전체 TUI 지연도 아니다. 작은 조건은 프로세스 시작과 측정 오차의 영향을 크게 받는다. 590행·5,900행은 같은 기록의 복제 부하로, 새로운 실제 대화 표본이 아니다. 순서는 이전 복원 다음 후보로 고정돼 있다.

초기 디버그 구현의 5,900행 중앙값 21.61초는 인덱스와 토큰 재사용 뒤 4.07초가 됐다. 같은 최종 디버그 비교의 이전 복원은 2.41초다. release 결과와 디버그 결과를 섞어 개선율을 만들지 않는다. 인덱스 측정의 첫 `load-index`는 오래된 바이너리를 잘못 복사한 것이 해시로 드러나 성능 결론에서 제외했다. 이후에는 Cargo가 반환한 실행 파일을 사용했다. release 기준선은 별도 소스와 별도 target에서 다시 빌드했다. 잘못된 측정도 삭제하지 않았다.

자동 테스트는 1,922개 통과, 실패 0개, 기본 제외 5개다. 제외된 재생 exporter 두 개는 실험에서 별도로 실행했다. 이전 코드에서 실패하는 새 계약 시험과 수정 뒤 통과 로그를 보존했다. workspace Clippy 경고 금지 검사도 통과했다. 이는 구현 계약 검증이며 1,922개의 독립 모델 품질 시험이라는 뜻은 아니다.

검색 최적화 뒤 디버그 바이너리의 복원 입력 18개·패킷 54개가 수집 입력과 바이트 단위로 같았다. 최종 release 후보의 복원 18개·패킷 54개와 release 기준선 복원 18개도 각각 일치했다. 따라서 보고한 모델 응답은 최종 선택 알고리즘이 생성하는 입력과 대응한다. 새 인덱스의 일반적인 모든 입력 동등성을 증명한 것은 아니다.

| 반복에서 이전 정답 손실 없음 | 미충족 | Claude의 대응 정답 손실 2건 |
| 전체 채택 | 보류 | 사전 지정한 개별 손실 기준 미충족 |

세 변경을 합쳐 비교했으므로 중복 제거만의 절감이나 문단 선택만의 정확도 효과는 분리할 수 없다. 같은 프로젝트 자료와 작성자 라벨, 개발에 노출된 질문, 겹치는 대화 구간, 후속 대조군의 수집 시점 차이로 일반화가 제한된다. 일부 대조 문항의 ID 자체가 `unknown`이므로 답 없음 판정의 독립 평가로도 부족하다.

정상 router를 통한 TUI 종단 사용, 실제 코드 수정의 성공, provider 자동 압축 직후의 근거 생존, 장기간 대화, 의미상 먼 부정·예외, 코드 조각 전체가 예산보다 큰 경우의 작업 성공률은 입증하지 않았다. 더 강한 압축이 안전하다고 결론 내리지 않는다. 후속 검증은 이 자료를 다시 맞히도록 조정하기보다 새 출처의 미사용 과제와 근거 충분성 기준을 먼저 고정해야 한다.

## 재현과 보관

```sh
bash docs/experiments/recall-selection/run.sh analyze
bash docs/experiments/recall-selection/run.sh verify
```

원자료를 다시 분석하는 명령이며 모델을 새로 호출하지 않는다. [데이터 설명](data/README.md), [원응답 검증](results/verification.json), [보관 영수증](data/archive.json), [파일별 SHA-256](data/SHA256SUMS)에 재현 범위와 검증 결과가 있다. 비공개 아카이브에는 성공·실패 응답, 준비만 한 입력, 코드·기준 바이너리, 환경, 실행 로그와 최종 변경분을 포함한다. 숨겨진 모델 추론은 API가 제공하지 않으므로 수집했다고 주장하지 않는다. 수집 가능한 원응답과 관측·판정의 근거를 보존했다.

구현 계약과 채택 보류 상태는 [맥락 정리](../../design/context-management.md)에 반영했다. 후보는 현재 작업 트리에 남기고 릴리스·병합은 하지 않았다.
