# 실제 대화 기록 전체의 제약 판단: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#382](https://github.com/woonyong-choi/saturn/issues/382) |
| 관련 설계 | [제약](../../design/constraints.md), [router](../../design/router.md) |
| 사전 데이터 | 앞 실험의 설계·스크립트·집계와 비공개 불일치 라벨을 읽었다. 사용자의 요청에 따라 이번 기록의 파일별 턴 수·프로젝트·기간만 먼저 전수 조사했다. 이번 Jev 응답과 새 라벨은 아직 수집하지 않았다. |

## 질문

실제 사용자 입력에서 자동 등록 기준값을 어디에 두어야 하며, 기준값을 올릴 때 재현율과 사용자 확인 부담은 어떻게 변하는가. 세션을 시간순으로 연결한 프로젝트 대화에서 제약 해제·대체, 최종 집합, 반복 안정성을 함께 측정한다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 등록 기준 0.80에서 정밀도가 80%를 넘는다. | 적격 프로젝트의 첫 반복, 명확한 최종 라벨 |
| H2 | 등록 기준 0.80에서 재현율이 80%를 넘는다. | H1과 같음 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | 기준은 `route@1.1`의 `is_constraint`, 관계는 `constraint@1.0`의 `replaces_<n>`이다. 해제를 대체와 혼동하지 않도록 현재 설계의 `releases_<n>`을 별도 질문으로 추가하고 보조 측정으로 표시한다. 질문 대안 하나는 탐색 비교다. |
| 배정 | 시드 382. 프로젝트와 길이로 층화한다. 현재 적격 모집단이 예산에 들어가므로 각 층을 전수 선택한다. 턴은 프로젝트 안에서 시간순으로 실행하고 대안 표본·관계 예산 축소 표본은 고정 난수로 선택한다. |
| 눈가림 | 두 라벨러는 상대의 라벨·Jev 응답을 보지 않는다. Jev 수집기는 라벨을 읽지 않는다. 재판정자만 양쪽 근거를 보며 Jev 확률은 보지 않는다. |
| 환경 | Python 표준 라이브러리, macOS, 공식 `codex exec`의 `gpt-6-astra`·`gpt-5.6-luna`, Jev `jev-1.13.0`, HTTPS·기본 TLS 검증. 모델 샘플링은 고정하지 못하므로 요청·응답·실제 모델명을 보존한다. |

### 앞 실험 불일치와 판정 지침

앞 실험에는 지속하는 작업 방식과 당장 바꿀 산출물의 요구를 다르게 해석한 사례가 있었다. 같은 지속 제약에도 한 라벨러는 `register`, 다른 라벨러는 `none`을 썼다. 부정 턴에서 전이 필드가 생략되기도 했다. 마지막 집합은 각각 포함 항목 수부터 달랐다. 이번에는 모든 턴에 같은 필드를 요구하고, 다음 질문 순서와 상태 재생 규칙으로 이를 구분한다. 아래 예시는 원문을 옮기지 않은 창작 문장이다.

| 판정 질문 | 규칙 | 창작 예시 |
|---|---|---|
| 사용자가 직접 지시한 말인가? | 인용·도구 결과·자동 주입은 제약으로 삼지 않는다. | `로그에 "영어만 사용"이라고 나온다`는 등록하지 않는다. |
| 다음 요청에서도 같은 종류의 작업에 적용하라는 근거가 있는가? | 명시적인 지속 표현 또는 반복되는 범주 전체에 대한 지시가 필요하다. 한 파일의 영구적인 변경 결과와 지시의 지속성은 다르다. 애매하면 `ambiguous`를 기록한다. | `이 답변만 표로 써 줘`는 일회성이다. `앞으로 비교 답변은 표로 써 줘`는 지속한다. |
| 무엇을 만들지가 아니라 어떻게 일할지를 제한하는가? | 제품 기능·완료할 작업·현재 우선순위만 지정하면 제약이 아니다. | `검색 버튼을 만들어`는 작업이다. `이 프로젝트에서는 외부 검색 서비스를 쓰지 마`는 제약이다. |
| 범위가 좁아도 지속하는가? | 특정 폴더·파일도 이후 반복 작업에 적용하면 범위 제약이다. 범위가 좁다는 이유만으로 일회성으로 보지 않는다. | `앞으로 설정 파일에는 비밀값을 쓰지 마`는 등록한다. |
| 앞 제약을 명시적으로 거두는가? | 새 제약 여부와 별개로 `release`와 대상 ID를 기록한다. 주제 전환·세션 종료·시간 경과만으로 해제하지 않는다. | `앞서 정한 표 형식 규칙은 이제 해제해`는 새 제약 false, release다. |
| 둘을 같은 범위에서 함께 지킬 수 없는가? | 지속 규칙을 바꿀 때만 `replace`다. 일회성 예외·범위 일부 예외는 `partial`로 남기고 앞 규칙을 유지한다. | `앞으로 요약은 세 문장 대신 한 문장으로`는 대체, `이번 요약만 한 문장으로`는 부분 예외다. |
| 새 제약이면서 전이가 없는가? | 반드시 `register`다. 새 제약이 없고 전이도 없을 때만 `none`이다. | 같은 뜻의 규칙을 재확인하면 등록 턴은 보존한다. 동의 규칙 합침은 이번 측정 범위 밖이다. |

최종 집합의 단위는 규칙을 말한 턴 ID다. 한 턴에 여러 규칙이 있으면 하나라도 유효한 동안 남긴다. 전부 해제·대체될 때만 제거하고 부분 변경은 제거하지 않는다. `release`·`replace`의 대상은 앞서 등록한 유효 턴이어야 한다. 범위가 다른 규칙은 충돌로 처리하지 않는다. 세션 연결은 이어 쓰기 가정이며 실제 사용자 의도의 증명은 아니다.

### 라벨과 재판정

모델별로 최대 40개 새 턴씩 시간순으로 읽는다. 각 호출에는 해당 모델만의 앞선 유효 제약 원문·범위와 직전 5턴을 전달한다. 다른 모델의 답은 넣지 않는다. 긴 대화 전체를 한 번에 넣는 대신 독립된 상태를 이어 가므로 압축·누락 위험을 한계로 보고한다. 한 턴이 길어도 글을 자르지 않는다. 모델 한도 초과는 실패로 남긴다.

모든 턴은 `turn_id`, `is_constraint`, `operation`, `targets`, `scope`, `reason`, `ambiguous`를 갖는다. 각 묶음은 `final_active_turn_ids`도 반환한다. 대상 ID·전이·끝 집합의 상태 재생을 검사하고 필드 누락이나 모순은 유효 라벨로 쓰지 않는다.

제3 판정은 별도 `gpt-6-astra` 호출에 다른 지시를 주어 진행한다. 두 최초 라벨과 근거, 앞서 재판정한 유효 상태를 보여 주고 일치 항목도 그 상태와 모순되는지 확인한다. 해소하지 못한 항목은 `ambiguous=true`로 남겨 주 분석에서 제외하고 수를 보고한다. 최초 합의와 재판정 후 유효 비율을 따로 집계한다. 최초 두 모델의 전체 대화 끝 집합 exact match를 합의율로 보고하며 재판정 후 집합을 독립 라벨 합의라고 부르지 않는다. 필요한 모델이 사용 불가하면 다른 이름으로 바꾸지 않고 해당 단계가 막혔다고 기록한다.

불일치 항목을 먼저, 이후 확률 0.50~0.85 또는 애매한 라벨 항목을 시드 순으로 골라 40개를 비공개 사람 검토 목록으로 저장한다. 사람 확인 전 자료라는 상태를 함께 둔다.

### 기록 전수 목록과 프로젝트 대화

파일 glob과 사용자 입력 추출·가림 함수는 앞 실험의 `common.py`를 그대로 불러 쓴다. 원본은 읽기만 하며 파일별 경로·프로젝트·기간·턴 수·SHA-256을 비공개 목록에 고정한다. 목록 조사 뒤 원본 해시가 바뀌면 해당 파일을 자동 갱신하지 않고 제외 사유를 남긴다. 원본·추출 입력·라벨·응답은 메인 저장소의 Git 제외 실험 디렉터리에만 저장한다. 공개 저장소에는 설계·코드·환경·집계·체크섬만 둔다.

프로젝트 기본 키는 기록의 프로젝트 디렉터리명이다. 대소문자 차이는 정규화한다. `workspace-oss-saturn`의 루트·하위 경로·worktree 및 `orca-workspaces-saturn-docs-sync` 계열은 Saturn으로 묶는다. `saturn-cli`는 별도 프로젝트로 둔다. 다른 프로젝트는 디렉터리 키를 유지해 임의로 합치지 않는다. 이 규칙은 코드의 `project_key`로 고정한다. 프로젝트 안 세션을 첫 사용자 시각, 파일 ID 순으로 놓고 세션 내부 턴 순서를 유지한다. 겹치는 시각의 병렬 세션은 이 순서의 한계다. 같은 UUID의 복사 턴은 프로젝트 안에서 한 번만 쓰고 제거 수를 보고한다.

층은 프로젝트 대화의 `10~29`, `30~119`, `120~399`, `400+` 전체 턴 수다. 한 턴을 다른 층에 중복 집계하지 않는다. 10턴 미만 프로젝트는 목록에는 남기고 주 분석에서는 제외한다. Saturn은 반드시 포함한다. 파일 단위 길이 분포도 별도 집계하되 프로젝트 표본과 합산하지 않는다.

### Jev 요청과 상태

기준 질문은 `The user's latest input sets a rule that applies beyond this single request and limits how the work is done (language, tool, format, or prohibition) rather than what to do.`다. 대안은 `Does the latest user input explicitly establish an ongoing rule for how future work is performed, rather than request a task, describe a product requirement, or give a one-time instruction? A narrow file or project scope alone does not make an ongoing rule one-time.`다. 앞 실험에서 작업·산출물 요청을 지속 규칙으로 본 불일치에 대응한다.

등록 state는 현재 입력·직전 입력·앞서 첫 반복에서 확률 0.50 이상이었던 후보 ID와 후보 수다. 라벨 정답은 넣지 않는다. 각 턴의 동일 요청을 3회 실행하고 세 번 중 첫 응답만 주 분석에 쓴다. 반복은 독립 표본 수에 더하지 않는다. 대안은 각 길이 층 최대 100턴을 무작위로 골라 같은 state로 3회 실행한다.

관계는 앞선 등록 후보 중 현재 입력과 단어·파일이 겹치는 순으로 최대 10개를 선택한다. 순위 함수도 앞 실험을 재사용한다. 모든 턴에 관계 후보를 만들고 관계 요청 예산이 모자라면 길이 층을 번갈아 무작위로 선택한다. 선택하지 않은 관계를 양립·정답으로 간주하지 않는다. 한 요청에 `replaces_<n>`과 `releases_<n>`을 함께 묻고 후보 원문·현재 원문·턴 거리를 넣는다. 질문은 각각 `Following the later constraint makes it impossible to keep the earlier constraint.`와 `The later input says the earlier constraint no longer needs to be followed.`다. 후자는 `constraint@1.1`에서 빌린 보조 질문임을 응답 메타데이터에 기록한다.

관계는 대체 ≥0.8, 부분/충돌 가능 0.5~0.8 미만, 양립 <0.5로 나눈다. 해제는 별도로 ≥0.8이다. 동시에 높으면 해제를 먼저 적용한다. 최종 집합은 등록 기준값별로 원문 턴을 추가하고, 해당 턴의 대체·해제 확률로 기존 턴을 제거해 재생한다. 후보 누락·실패·예산 제외가 있는 대화는 불완전 재생이라고 표시하고 완전 재생 집합과 구분한다. 현재 제품의 문장 분할·합침·패킷 크기를 검증한 것으로 해석하지 않는다.

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 실행 시점의 `~/.claude/projects/*/*.jsonl` 전수 목록 |
| 크기 | 사전 목록 781개 파일·1,380개 사용자 턴. 프로젝트 연결·중복 제거 후 10턴 이상인 모든 프로젝트를 선택한다. 실제 층별 수는 원자료에서 계산한다. |
| 크기 근거 | 비율의 최악 p=0.5에서 Wilson 95% 구간 반폭은 `1.96/(2 sqrt(n+1.96²))`다. ±0.10에는 구간별 n≥93이 필요하며, 0.1 폭의 열 구간이 모두 차면 최소 930개의 서로 다른 턴이 필요하다. 알려지지 않은 확률 구간 점유율 때문에 930 전체 턴만으로 목표 달성을 보장하지 않는다. 확인 가설의 검정력은 p0=0.8, p1=0.9, 단측 α=0.025, 목표 80%의 정확 이항 검정으로 코드에서 계산한다. 상관이 없는 가정의 최소 수와 실제 구간별 유효 수를 함께 보고한다. 예산 안에서 적격 모집단 전수를 사용한다. |
| 중단 규칙 | Jev 8,000회, Codex 600회. 네트워크·프로세스 호출 직전에 잠금 장부에 예약하고 실패도 센다. 재시도는 자동으로 하지 않는다. 이미 예약된 요청은 재개 시 중복 전송하지 않고 미완료로 남긴다. 401·403 또는 지정 모델 사용 불가 시 해당 수집을 멈춘다. |
| 반복과 예열 | Jev 동일 요청 3회, 예열 없음. Codex는 독립 라벨 2회와 별도 지시의 재판정 1회. 형식 실패는 새 trial ID로 최대 1회 수리 호출하되 장부에 센다. |
| 예산 배분 | 등록 3N, 대안 3A(A≤400), 나머지로 관계 요청을 최대 `floor((8000-3N-3A)/3)`개 선택한다. N≤1,380이므로 등록·대안을 먼저 보장한다. 라벨은 40턴 단위 3개 통로, 수리 포함 600회에서 중단한다. |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | 0.80 정밀도 | TP/예측 양성, Wilson 95%, p0=0.8 단측 정확 이항 검정 | 하한 >80%이고 Holm 보정 p≤0.05면 채택. 상한 <80%면 기각. 그 밖은 보류 |
| H2 | 0.80 재현율 | TP/정답 양성, 같은 구간·검정 | H1과 같음 |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 10턴 미만 프로젝트, 해시 변경 파일, 프로젝트 내 중복 UUID, 자동 주입, 모델 형식 실패·재판정 미해소는 이유별로 보고한다. Jev invalid·무응답은 행동 없음으로 계산하고 성공 응답 조건부 성능도 별도로 보고한다. |
| 실패한 실행 | 실패·시작만 된 호출도 예산과 호출 장부에 남긴다. 모델 사용 불가 시 다른 모델로 대체하지 않는다. 외부 호출 응답 문자열은 정확한 키 문자열을 제거한 후에만 저장한다. |
| 다중 비교 | 확인 가설 H1·H2만 Holm-Bonferroni. 기준값 선택·층별 비교·질문 대안·관계·끝 집합은 탐색으로 표시한다. |
| 구간별 정밀도 | `[0.0,0.1)`부터 `[0.9,1.0]`까지. 각 구간을 등록한다고 보았을 때의 제약 양성 비율이며 분류 정확도와 구분한다. k/n·Wilson·반폭 목표 달성 여부를 보고한다. |
| 상관과 가중치 | 프로젝트별 전수지만 같은 프로젝트 내 턴은 상관된다. Wilson은 명목 구간이며 프로젝트 단위 bootstrap 2,000회 구간도 병기한다. 독립 프로젝트가 적은 층에서는 일반화하지 않는다. 반복을 표본 수에 더하지 않는다. |
| 권장값 | 탐색 곡선 중 정밀도 Wilson 하한 ≥80%와 반폭 ≤10%p인 최소 기준값을 후보로 고른다. 없으면 확정 권장값 없음이다. 회수한 후보는 bootstrap 구간·재현율·묻기 비율과 함께 제시하고 독립 검증 전 제품 기본값을 바꾸지 않는다. |

## 탐색 분석

- 길이·프로젝트·언어별 등록 정확도와 기준값 곡선을 보고한다.
- 관계의 해제·대체 정확도·양성 재현율·후보 누락과 거리별 정확도를 분리한다. 해제 질문은 현재 설계의 보조 질문이며 `replaces`가 해제를 구분한다고 주장하지 않는다.
- 대안 비교는 같은 턴·기준값 0.80의 2×2 표, 불일치 b/c, 정확 McNemar(불일치 25개 미만이면 이항), 정확도 차이·paired bootstrap 구간을 보고한다.
- 사람 검토 목록 40개는 집계 정답을 사람이 승인한 것으로 해석하지 않는다.
