## 질문

사용자가 `제약 등록됨 · <규칙>` 기록을 보고 명시적으로 해제를 요청할 때 Jev가 요청과 대상을 구분하는지 측정한다. 기록 없는 실제 대화의 암묵적 전이를 찾았던 앞 실험과 모집단이 다르다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 해제 요청 식별 정밀도는 90%, 재현율은 85% 이상이다. | 기록 있음, 쌍별 형식, 기준값 0.80, 첫 반복 |
| H2 | 식별한 실제 해제 요청의 대상 정확도는 직전 등록 95%, 내용 지칭 85% 이상이다. | H1 조건, 활성 제약 1·3·10개를 별도로 보고 |
| H3 | 해제 요청이 아닌 입력에서 하나 이상 자동 해제하는 비율은 2% 이하이다. | H1 조건, 합성·실제 비해제 표본 |
| H4 | 기록 줄을 넣으면 요청·대상 결합 정확도가 높아진다. | 쌍별 형식, 같은 입력 대응, 기준값 0.80 |
| H5 | 선택형은 쌍별보다 요청·대상 결합 정확도가 높고 요청 바이트가 작다. | 기록 있음, 같은 입력 대응, 기준값 0.80 |

### 상태와 질문

활성 제약은 10개 이하이므로 제품의 후보 선택 규칙대로 모두 포함한다. 후보 검색이나 등록 성능은 측정하지 않는다. 원문은 앞 실험 세 라벨에서 모두 제약이며 모호하지 않은 8~200자 단일 줄을 그대로 쓴다. 짧은 규칙만 고르는 선택 편향을 보고한다. 규칙 번호와 등록 순서는 두 기록 조건에 동일하게 남긴다. 따라서 H4는 활성 목록과 순서 위에 정확한 등록 기록 문구를 추가하는 효과다.

state는 active_constraints(id, rule, registration_order), previous_context, latest_user_input으로 구성한다. 기록 조건만 chat_record에 `제약 등록됨 · <규칙>`을 등록 순서대로 넣는다. 제약 해제 결과 줄은 판단 뒤에 생길 정보이므로 입력하지 않는다. 최근 등록 이후 다른 작업 대화를 합성해 넣지 않는다. 실제 비해제 턴에는 앞 사용자 두 턴을 유지하되 활성 목록·등록 기록을 붙인다. 실제 Saturn 관찰 자료가 아니라 실제 문장을 합성 상태에 넣은 스트레스 표본이다.

pair는 기존 `releases_<n>` 문장 `The later input says the earlier constraint no longer needs to be followed.`를 각 후보에 묻는다. 같은 요청에 `is_release`와 기존 `is_constraint`를 넣는다. 해제 식별 질문은 `The user's latest input asks to stop following an existing constraint, wholly, partly, or temporarily, rather than cancel or stop a task.`다. 제품의 직렬 게이트 호출을 한 요청에 합친 실험이므로 실행 시간·호출 비용을 제품값으로 일반화하지 않는다.

choice는 질문 하나 `Does the latest user input ask to stop following one of the active constraints, wholly, partly, or temporarily? Select its constraint ID, or none if it does not request release of a constraint. Canceling or stopping a task is not releasing a constraint.`를 묻고 c1..cN, none을 선택지로 쓴다. 원문 질문은 scripts/02-collect.py에 봉인한다.

### 라벨과 행동

요청 라벨은 release(전체), partial(부분), conditional(일시), none이다. 앞 세 종류는 H1 요청 식별의 양성이지만 제약 행 전체를 영구 해제해도 되는 것은 release만이다. partial·conditional에서 자동 해제하는 비율을 별도 안전 지표로 보고한다. 한 입력의 의도한 대상은 하나다. 두 대상 이상이거나 모호하면 제외한다.

pair 요청 점수는 is_release, 선택형 요청 점수는 1-P(none)이다. H1은 이 점수 ≥ 기준값으로 판정한다. H2는 실제 요청이면서 H1 양성인 입력에서 후보 확률 최대값의 대상이 맞는지 측정한다. 동률은 번호가 작은 후보다. H2와 함께 모든 실제 요청을 분모로 하는 대상 도달률도 보고해 게이트 누락을 숨기지 않는다.

pair 자동 해제는 is_constraint < 0.70, is_release ≥ 0.50이고 releases_n ≥ 기준값인 모든 후보다. choice 자동 해제는 최대 확률 선택지가 none이 아니고 그 확률 ≥ 기준값일 때 한 개다. 요청·대상 결합 정확도는 실제 요청에 H1 양성·최대 대상 일치를, none에 H1 음성을 요구한다. 자동 해제 정확도는 release에 정확히 한 정답 대상, 나머지에 해제 없음이다. 묻기 비율은 자동 행동이 없고 게이트를 통과한 후보 최고 확률이 0.50 이상 기준값 미만인 입력 비율이다. 선택형에서 none이 최대이면 묻지 않는다. 실패·invalid는 행동도 묻기도 없고 결합 정확도에서는 오답이다.

### 유형별 크기와 검정력

단측 정확 이항 α=0.05에서 p0=0.85, p1=0.99의 유형별 식별 정확도 검정은 n=30, 성공 29개 이상에서 검정력 96.4%다. 해제 8유형(직접·지시어·내용·번호·부분·조건부·간접·한영 혼합)과 비해제 5유형(작업·단어 중복·작업 중지·강화·새 제약)에 각각 적용한다. 실제 표본 10개는 같은 검정력을 확보하지 못하며 말투 차이의 기술 통계만 제시한다.

H1 정밀도 분모 180개 가정에서 p0=0.90, p1=0.97, 성공 169개 이상이면 검정력 99.1%다. 재현율 n=240, p0=0.85, p1=0.94, 성공 214개 이상이면 99.9%다. 예측 양성 분모는 수집 뒤 정해지므로 확보를 보장하지 않는다. H3 n=160, p0=0.02, p1=0.001에서 오해제 0개일 때 85.2%다. 실제 오류율이 0.5%이면 이 검정력은 약 44.8%로 내려간다.

직전 등록은 direct·deictic·indirect·mixed 120개다. p0=0.95, p1=0.995, 119개 이상 정답의 검정력은 87.8%다. 활성 개수별 40개로 나누면 완전 정답이어도 단측 5% 검정으로 95%를 입증하지 못한다. 내용 지칭 30개도 활성 개수별 10개에 불과하다. H2 세부 조건, H4·H5의 작은 차이는 검정력 부족 가능성을 명시하고 구간이 기준을 가로지르면 보류한다. 이는 5,000회·완전 교차·3회 반복 제약 안의 한계다. 다중 비교 보정 뒤의 검정력은 위 개별 계산보다 낮다.

### 생성과 독립 재라벨

15개 명세씩 gpt-6-astra에 유형·활성 목록·대상·정답 의미를 주고 문장을 만든다. gpt-5.6-luna는 상태와 생성 문장만 보고 요청 종류·대상·모호함을 독립 판정한다. 정답 의미·대상이 모두 일치하고 모호하지 않은 것만 채택한다. 불일치·형식 오류는 수리나 재판정 없이 제외한다. 묶음 형식 오류면 해당 묶음 전부 제외하고 이유를 보존한다. 모델 실행 실패는 수집을 멈춘다.

실제 문장은 앞 실험 사용자 턴에서 취소·빼·없던 걸로·하지 마가 있고 1,500자 이하인 것을 시드로 섞는다. 앞 사용자 두 턴과 함께 두 모델이 독립 라벨하고 none·대상 없음·명확함에 합의한 앞 10개만 사용한다. 최대 전체 후보까지 확인하고 부족하면 그대로 보고한다. 생성·라벨 호출은 통상 52회와 실제 후보 검사 호출, 검토 호출이며 모두 400회 안에 센다. 기존 키 가림·이메일·절대 경로 가림 함수를 재사용한다. 실제 규칙·실제 사용자 문장은 공개하지 않고 생성 문장과 가명 원규칙 ID만 공개한다.

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | 요청 정밀도·재현율 | k/n, Wilson 95%, 단측 정확 이항, 규칙 원천별 cluster bootstrap | 두 점추정과 단측 검정이 각각 0.90·0.85 통과하고 bootstrap 하한도 경계 이상 |
| H2 | 직전·내용 대상 정확도 | 같은 비율 분석, 활성 수별 표 | 각각 0.95·0.85 통과. 세부 조건 입증과 통합 입증 구분 |
| H3 | 잘못된 자동 해제 | k/n, Wilson 95%, 하측 정확 이항 | 점추정 ≤0.02, 보정 p<0.05, bootstrap 상한 ≤0.02 |
| H4 | 기록 있음−없음 결합 정확도 | 대응 불일치 수, 정확 McNemar, 입력 대응 bootstrap 차이 | 차이 양수, bootstrap 하한 >0, 보정 p<0.05 |
| H5 | choice−pair 결합 정확도와 바이트 | 같은 대응 분석, 바이트 차이 중앙값·구간 | 정확도 차이 양수·하한 >0·보정 p<0.05이고 바이트 차이 상한 <0 |

| 항목 | 규칙 |
|---|---|
| 신뢰구간 | 비율은 NIST Wilson 95%. 같은 원규칙을 공유하는 합성 입력의 상관은 대상 규칙(음성은 직전 규칙) 군집 bootstrap 2,000회·시드 38201로 병기. 실제 문장은 출처 대화를 군집으로 사용 |
| 실패한 실행 | 첫 응답 실패를 다른 반복으로 대체하지 않음. 요청 식별은 음성, 행동·묻기 없음, 결합 정확도는 오답. 상태별 수 보고 |
| 제외 기준 | 생성 의도와 독립 라벨 불일치·모호함·중복 문장·잘못된 대상·잘못된 묶음. 모델 결과를 보고 제외하지 않음 |

| 판정 | 채택 조건 통과 시 채택. 명목 95% 구간이 목표 반대쪽에 완전히 있으면 기각. 나머지는 보류. 분모 0이면 측정 불가·보류 |
| 유효 숫자 | 비율·구간 0.1%p, 바이트 정수·중앙값 0.5바이트, p값 유효 3자리. 원정밀도 JSON 병존 |
| 추천 | 확인 기준값은 0.80으로 고정. 탐색 곡선에서 정밀도 하한≥0.90·재현율 하한≥0.85·오해제 상한≤0.02인 형식·최소 기준값을 후보로 고름. 통과 후보가 없으면 자동 해제 권장 없음. 부분·조건부에서 영구 해제가 있으면 전체 해제에 한정한 권고도 명시 |

통계 방법은 [NIST 비율 신뢰구간](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)을 따른다. 정확 검정은 이항 확률 질량 합으로 직접 계산하며 대응 차이는 입력을 짝으로 재추출한다. bootstrap의 빈 분모 횟수도 기록한다. H4·H5는 원규칙 군집 재추출 구간도 병기하고 채택에는 두 구간의 하한을 모두 요구한다.

사용자 지시에 따라 docs/design 수정·머지·이슈 댓글은 하지 않는다. 제품 코드나 실제 제약을 변경하지 않는다.

## 타당성 위협

| 종류 | 위협 | 대응 |
|---|---|---|
| 내적 | 생성 의도에 맞고 두 모델이 합의한 쉬운 문장만 남음 | 최초 합의율·제외 유형 공개, 사람 정답 아님을 표시 |
| 구성 | 부분·일시 해제와 제약 전체 해제는 다름 | 요청 양성과 영구 행동 안전성을 별도 집계 |
| 구성 | 짧은 규칙·정답 대상 후보 포함·직렬 게이트 생략 | 등록·검색·제품 전체 동작 검증으로 주장하지 않음 |
| 외적 | 실제 사용자가 등록 기록을 본 해제 턴이 없음 | 실제 문장 비해제와 합성 결과 분리, 실제 문장도 합성 상태임을 표시 |
| 통계 | 같은 규칙 반복·낮은 실제 해제 발생률·조건별 분모 부족 | 군집 구간·원천 수·표본 양성 비율 공개, 제품 정밀도로 일반화하지 않음 |
| 시간 | 모델 응답 변동·서비스 변경 | 모델 버전 기록, 같은 요청 세 반복, 실패 보존 |
