## 질문

작업 하나가 끝나면 효력이 끝나는 지시를 제약에서 제외한다. 이 정의를 Jev에 명시하거나 작업 범위를 따로 물으면 자동 등록의 오탐을 줄이면서 사용자 확인 부담과 재현율을 지킬 수 있는지 측정한다.

## 앞 실험 점검

설계 봉인 전에 기존 정답 90건을 gpt-6-astra로 독립 재판정했다. 정의는 model-compare의 DEFINITION 그대로이며 판정 순서와 근거 참조 지시만 바꿨다. sol 정답과 Astra는 77건에서 일치했고 13건에서 달랐다. 기존 양성 16건 중 일치 양성은 7건이다. 새 사용자 판정은 아니며, 두 모델이 합의해도 객관적 정답을 보장하지 않는다. [집계](results/audit.json)에 전이표를 남긴다.

원자료의 Jev 요청 300개는 모두 같은 질문과 앞 맥락·최신 입력 state를 사용했다. 작업 하나짜리 지시 제외를 명시한 정의는 질문·state의 별도 지침에 없었다. LLM에는 그 정의가 있었다. 현재 core에는 질문 구현이 있으며 문장이 의문형이라는 점 외에 같은 경계를 쓴다. 따라서 앞 실험의 모델 차이에 질문 차이가 섞였다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | 범위를 명시한 단일 질문은 현재 질문보다 자동 기준 0.8과 0.9 각각에서 정밀도를 5%p 이상 높인다. | 같은 유효 정답 입력의 첫 반복 |
| H2 | 자동 기준 0.9와 묻기 하한 0.7·0.75·0.8·0.85 중 하나의 조합이 자동 정밀도 90% 이상, 결합 재현율 70% 이상, 묻기 비율 20% 이하를 만족한다. | 세 Jev 조건, 첫 반복 |
| H3 | 범위 보조 질문으로 작업 한정 입력을 거르면 단일 범위 질문보다 0.8과 0.9 각각에서 정밀도를 5%p 이상 높인다. | 같은 입력의 첫 반복 |
| H4 | 범위 단일 질문과 두 질문 조건 모두 요청 지연 p95가 1초 미만이고 평균 입력당 비용이 현재 질문의 1.5배 이하다. | 세 반복 전체, 조건별 입력을 군집으로 취급 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | current: 현 core 질문, scope: 작업 한정 제외 명시, scope_gate: scope와 task_only를 한 HTTP 요청으로 질문. Astra는 앞 맥락만 받는 참고 분류기 |
| 배정 | 시드 382104. 층 안과 층 순환 순서를 고정 난수로 정한다. Jev 조건·입력·반복 전체를 섞는다. |
| 눈가림 | 정답 판정은 다른 판정·평가 응답 미제공. 평가에는 정답·뒤 맥락·프로젝트 이름·입력 형태·사전 열람 여부 미제공 |
| 환경 | macOS, Python 표준 라이브러리, 공식 Codex exec medium, gpt-6-sol·gpt-6-astra, Jev 1.13.0. 모델 내부 난수는 고정 불가 |

### 정의와 정답

제약은 언어·도구·형식·금지 등 앞으로 일하는 방식을 제한하며, 모델 변경이나 맥락 정리 뒤에도 이 대화의 다른 작업에 계속 적용할 규칙이다. 파일·프로젝트 범위가 좁아도 여러 작업에 지속하면 제약이다. 현재 작업의 여러 요청·수정·검토는 하나의 작업이다. 산출물 요구나 일회성 형식은 제외한다. 인용·붙여넣기는 지속 규칙으로 실제 채택한 경우만 포함한다. 입력에 하나라도 지속 규칙이 있으면 양성이다.

목표 입력과 같은 세션의 앞뒤 맥락을 sol과 Astra가 같은 정의·같은 지시로 독립 판정한다. 1단계 판정은 재사용하지 않는다. 각자 label, 분류 이유, 근거 메시지 위치를 반환한다. 서로 같은 유효 판정이면 채택한다. 다르면 다른 지시의 Astra가 두 판정을 보지 않고 다시 판단하며, 같은 라벨 두 표 이상일 때만 채택한다. 판단 불가도 하나의 범주다. 두 유효 표를 확보하지 못하거나 판단 불가가 다수면 성능 정답에서 제외하고 수를 보고한다. 묶음 형식 실패는 전부 결측이며 새 수리 호출은 없다.

정답 통로는 최대 4건, 직렬화 300,000바이트 이하로 묶는다. 각 사례는 독립 자료임을 명시한다. 묶음마다 새 ephemeral CLI를 사용하며 도구·웹·사용자 설정을 끈다. 앞뒤 최대 다섯 사용자 입력과 assistant 텍스트를 제공한다. 뒤 입력이 세 개 미만이거나 앞 state 80,000바이트·뒤 맥락 180,000바이트를 넘으면 신규 표본에서 제외한다. 도구 출력·숨은 reasoning은 제공하지 않는다. 정답과 해시를 봉인한 뒤 평가한다.

### 질문과 결합

정확한 영어 문장은 [protocol.py](scripts/protocol.py)에 고정한다. current는 현재 core의 IS_CONSTRAINT_TEXT와 같은 의문형이다. scope는 다른 작업·모델 변경·맥락 정리 뒤의 지속, 한 작업의 여러 요청 제외, 산출물 요구 제외, 붙여넣기 채택 조건을 명시한다. scope_gate는 같은 질문에 모든 작업 방식 규칙이 이번 작업에만 해당하는지를 묻는 task_only를 더한다.

scope_gate의 점수는 task_only가 0.5 이상이면 0, 아니면 is_constraint 확률이다. 둘 중 하나라도 형식·모델 검증에 실패하면 결측이다. 단일 확률의 곱이나 독립 확률 해석은 하지 않는다. 모든 조건의 state는 동일한 앞 맥락과 최신 입력이며 정의를 state에 중복하지 않는다. engine 전체 route와 다른 질문들의 상호작용은 측정하지 않는다.

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 기존 model-compare 100건과 현재 로컬 Claude 실제 대화 기록의 추가 300건. 이 실험과 앞 비교 실험 실행 기록 제외 |
| 크기 | 400건 고정. 판단 불가 제외 후 유효 정답 수 감소 가능 |
| 크기 근거 | 검정력: 결합 재현율 p0=0.70, p1=0.90, 단측 α=0.0125, power=0.80의 정규 근사에 연속성 보정 1/0.20을 더하면 양성 46건. 기존 양성 16/90, 유효율 0.90을 가정하면 입력 288건. 사용자 최소 300건과 군집·불확실성 여유를 위해 400건 |
| 층화 | 프로젝트·프로젝트 길이·직접 입력 추정과 AI 지시문 붙여넣기 추정. 기존 100건을 유지하고 신규 층을 순환 추출 |
| 중단 규칙 | 400건 또는 호출 상한. 자료 부족·미해소를 합성 표본이나 추가 결과 기반 추출로 대체하지 않는다. |
| 반복과 예열 | Jev 조건별 3회, 첫 회만 성능 분모. Astra 참고 분류는 1회. 예열 없음 |

크기 공식은 [NIST 비율 검정 표본 수](https://www.itl.nist.gov/div898/handbook/prc/section2/prc242.htm)의 단측 식이다. 이는 정답 양성의 독립성·발생률을 가정한 계획값이며, 정밀도의 예측 양성 수나 군집 상관·다중 정책 선택에 대한 검정력을 보장하지 않는다. 실제 정답 양성 수와 구간으로 한계를 보고한다.

입력 형태 추정은 앞 실험의 고정 규칙을 재사용한다. 구조화된 긴 지시문 또는 인수인계 표현·목록을 갖춘 입력을 붙여넣기 추정으로 둔다. 실제 작성자를 인증하지 않는다. 기존 100건을 유지하므로 이전 표본에 있던 희소 형태도 보존된다. 신규 300건만의 분석과 두 입력 형태별 분석을 별도로 보고한다. 순수 독립 재현이나 제품의 자연 발생률 표본으로 부르지 않는다.

## 분석

비율은 분자·분모, Wilson 95% 구간을 보고한다. 첫 반복의 같은 입력 대응을 유지하고 프로젝트 재표집 5,000회의 percentile 구간을 함께 계산한다. H1·H3 차이는 프로젝트 군집 bootstrap을 주 분석, 입력 bootstrap을 민감도 분석으로 둔다. 정밀도 차이가 정의되지 않는 재표집이 5%를 넘으면 그 비교는 보류한다. 양성 예측이 없는 조건의 정밀도는 null이며 100%로 처리하지 않는다.

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | scope−current 정밀도 차이 | 두 기준값의 대응 군집 bootstrap. 가설 α=0.0125를 두 비교로 나눈 99.375% 양측 구간 | 두 차이의 하한 모두 0 이상이고 두 점추정 모두 5%p 이상. 한 구간 상한이 5%p 미만이면 기각, 그 밖은 보류 |
| H2 | 자동 정밀도·결합 재현율·묻기 비율 | 0.9의 12정책×3지표, α=0.0125 Bonferroni Wilson 동시 구간 | 한 정책의 정밀도 하한≥0.90, 결합 재현율 하한≥0.70, 묻기 상한≤0.20. 모든 정책이 적어도 한 지표의 반대 구간으로 목표 미달이면 기각, 그 밖은 보류 |
| H3 | scope_gate−scope 정밀도 차이 | H1과 같은 대응 군집 방법 | H1과 같은 경계 |
| H4 | p95 지연, 평균 비용비 | 입력 단위로 세 반복을 묶은 bootstrap. 두 조건×두 지표에 α=0.0125를 나눈 99.6875% 구간 | 두 조건 모두 지연 상한<1초, 비용비 상한≤1.5. 어느 지표 하한이 목표를 넘으면 기각, 그 밖은 보류 |

가설 가족 네 개에 Bonferroni α=0.0125를 배분한다. H1·H3의 차이에는 군집별 조건 교환을 통한 단측 순열 p값도 보고한다. 프로젝트 수가 적으면 가능한 2^프로젝트 수 배정을 전수 계산한다. p값은 보조이고 구간·효과 경계가 판정 규칙이다. H2의 후보 선택은 같은 표본의 탐색이며 동시 구간과 구별한다. 숫자는 비율 한 자리 %, 시간 세 자리 유효 숫자, 비용 네 자리 유효 숫자로 표시한다.

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 판단 불가 정답만 정확도·정밀도·재현율에서 제외. 묻기·형식 실패·지연에는 전체 입력 유지 |
| 실패한 실행 | 호출 상한에 포함. 정확도에서는 오답, 양성 재현율에서는 놓침. 정밀도는 유효 예측 양성만. 반복 일치에서는 실패 |
| 다중 비교 | 네 가설과 그 안의 비교에 위 배분. 전체 곡선·집단별 결과는 탐색 |

### 의사 판단 기준

자동 기준 0.8·0.9, 묻기 하한 0.7·0.75·0.8·0.85 중 자동 기준보다 작은 조합을 검사한다. 자동 정밀도 점추정≥90%, 결합 재현율≥70%, 묻기≤20%, 자동 예측 양성 최소 10건을 모두 만족하는 후보 중 current, scope, scope_gate 순으로 가장 단순한 것을 고른다. 같은 조건에서는 자동 기준이 낮은 것, 그 안에서는 묻기 하한이 높은 것을 고른다. 하나도 없으면 권장 질문·기준값 없음이다. 통계 구간이 목표를 보장하지 못하면 잠정 후보로만 보고한다. 요청한 0.9의 모든 하한 조합을 표로 남긴다.

묻기에서 사용자가 언제나 올바른 답을 준다는 가정으로 결합 재현율을 계산한다. 실제 사용자 응답이나 UI 완료율의 측정값은 아니다. Astra는 가능한 참고 정확도 수준이며 이론적 상한이나 모델 선택 근거로 쓰지 않는다.

### 호출과 비용

Jev는 400×3×3=3,600회다. 두 질문도 한 요청이므로 한 호출로 센다. Codex는 1단계 23회와 확대 라벨·불일치 재판정·Astra 참고 분류의 묶음 호출을 모두 센다. 상한은 Jev 4,000회, Codex 800회이며 시작 전 잠금 장부에 예약한다. 실패·중단·수리도 포함하고 예약만 남은 요청은 자동 재전송하지 않는다. 단계별 파일과 해시로 재개한다. CLI 내부 재시도는 프로세스 호출 수와 구별한다. 정답 모델·인증 거절 시 대체 모델 없이 중단한다.

Jev 동시 요청은 4개, Codex 판정은 4개다. 정답과 Astra 참고 분류가 끝난 뒤 Jev만 실행해 서로의 자원 경쟁을 줄인다. CLI 제한은 300초, HTTP 제한은 60초다. 키체인 saturn-experiments-judge의 키는 프로세스 환경으로만 전달하고 Codex 자식 환경에서 제거한다. 저장 전에 정확 키를 가린다. TLS 검증 유지·redirect 거절이며 원문·응답·캐시는 Git 제외 실험 경로에만 둔다. 원자료 사본·시스템 임시 경로를 만들지 않는다.

2026-10-04 확인한 [Jev 단가](https://docs.typesafe.ai/models)는 입력 100만 토큰당 USD 0.042, 출력 무료다. [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)는 입력·캐시 읽기·출력 10/1/50, [Sol](https://developers.openai.com/api/docs/models/gpt-6-sol)은 2/0.2/10 USD/100만 토큰이다. 캐시 쓰기는 각각 12.5와 2.5다. usage가 없으면 비용 null로 남긴다. 실제 구독 추가 청구액은 아니며 묶음 Astra 지연은 요청 단위와 입력당 상각값을 구분한다.
