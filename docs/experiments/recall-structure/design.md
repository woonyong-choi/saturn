# 복원 단위와 동시 전달: 실험 설계

[#628](https://github.com/woonyong-choi/saturn/issues/628)의 근거 누락 수정과 [#624](https://github.com/woonyong-choi/saturn/issues/624)의 첫 단계 후보를 순서대로 판정한다. 앞선 [동시 전달 비교](../joint-context-delivery/report.md)는 비용 감소를 관측했지만 품질 기준에 실패했다. 다음 구조 개선 단계에는 아직 진입하지 않는다.

## 사전 열람과 구현 후보

이전 실제 20조건·112문항의 응답과 실패를 열람했다. 번호 목록의 뒤 항목 누락은 실제 문서 회귀 테스트로 재현했고, 목록 전체를 같은 후보로 두자 통과했다. 스키마의 직접 정의가 비슷한 테스트 이름보다 밀리고, 사용자 기록용으로 남은 예산을 답의 근거에 쓰지 못해 탈락하는 경로도 재현했다.

후보는 번호 목록 보존, 질문의 정확한 식별자 우선, 사용자·도구 기록을 먼저 고른 뒤 남은 전체 상한 안에서 Agent 근거 선택을 적용한다. 정답·문서명·특정 숫자를 선택 규칙에 사용하지 않는다. 기존 사용자·도구 기록의 우선 몫과 전체 글자 상한은 유지한다.

## 가설과 판정

| 가설 | 기준 |
|---|---|
| H1 구현 계약 | 실제 누락 회귀와 기존 검사 통과, 전체 복원 상한·출처 보존. joint의 원문을 펼치면 repaired의 패킷·복원 입력과 바이트 일치 |
| H2 복원 품질 | baseline 정답을 repaired가 놓치는 대응 문항 0. 이전 누락 확인용 두 문서와 새 문서의 repaired 정답 전부 일치 |
| H3 전달 품질 | repaired 정답을 joint가 놓치는 대응 문항 0. 이전 누락 확인용 두 문서와 새 문서의 joint 정답 전부 일치 |
| H4 전체 비용 | 두 모델 각각 joint가 baseline보다 입력 5% 이상 감소·입력과 출력 합계 감소. repaired 대비 joint도 같은 조건 충족 |

H1·H2는 복원 결함 수정의 실측 판정이다. H1~H4와 실제 engine 전달·실패·재시작 검증을 모두 충족해야 #624를 채택하고 #625로 진행한다. 코드 단위 테스트나 시제품만으로 engine 전환·정상 router·TUI 검증을 대신하지 않는다.

## 설계

| 항목 | 값 |
|---|---|
| baseline | 이전 선택 코드의 패킷→Ready→이전 복원·질문 |
| repaired | 동일 패킷→Ready→수정한 복원·질문 |
| joint | 최소 Ready→동일 패킷 전체와 수정한 복원·질문을 함께 전송 |
| 비교 범위 | 세 방식 모두 두 턴. Ready 호출 제거는 하지 않음 |
| 기존 자료 | 20조건·112문항. 모두 개발 자료로 취급하며 이전 추가 문서는 regression으로 표시 |
| 새 자료 | 실제 extensions·input-requests 문서, 각 4문항. 원문·근거 줄·해시·허용 답을 수집 전 고정 |
| 크기 | 22조건·120문항·3방식·2모델·3반복 = 396세션, 792모델 턴 |
| 배정 | 시드 7122, 방식·조건·반복을 섞고 provider별 직렬 실행 |
| 모델 | Claude haiku, Codex gpt-6-sol. 서버 샘플링 시드는 고정하지 못함 |
| 환경 | 빈 임시 작업 폴더, Claude safe mode. Codex는 호스트 스킬 발견·플러그인·앱·스킬 검색을 실행 인자로 끔. 사용자 설정·인증 파일을 수정하지 않음 |
| 프로토콜 | 고정 배포 기록의 동일 두 턴 검사를 모델별 3회. 전부 보존하고 정식 표본과 분리 |

## 측정과 분석

Ready와 응답 턴을 모두 센다. Claude는 입력·cache read·cache write를 합하고 모델별 누적값과 대조한다. Codex는 재개 응답의 누적 사용량 차분을 내고 native total/last token usage와 대조한다. 실제 실행 명령은 각 턴 실행 직전에 저장한다.

정답은 기존 정규화와 고정 허용값으로 비교한다. 문항별 대응 손실·이득, 자료군·반복별 정답, 전체 입력·출력 합계, 절대 차이·백분율, 조건별 감소율 최소·중앙·최대를 제시한다. 과거 응답을 이번 대응 실행으로 재사용하지 않는다. 출처 중복과 동일 질문 반복이므로 독립 모집단 신뢰구간이나 일반 무손실 보장을 만들지 않는다.

프로토콜에서 Codex의 자동 첨부 스킬 목록 변동이 다시 발견되면 정식 수집 전에 원인을 기록하고 수집 환경을 수정한다. 정식 수집 뒤 발견하면 실행을 삭제하지 않고 주 분석에 비용을 포함하며 환경 타당성을 별도 판정한다.

## 중단·실패·채택

구현·원문 검사가 실패하면 정식 모델 수집 전에 수정과 실패 기록을 남긴다. provider 실행 오류 연속 3회면 해당 수집을 중단한다. 내용상 오답은 중단·제외·재시도 사유가 아니다. 계획 분모에 실패·미실행을 유지하고 완결 사용량이 없으면 비용을 0으로 취급하지 않는다.

모든 가설을 정해진 기준 그대로 판정한다. 결과를 본 뒤 질문·정답·허용값·기준을 바꿔 같은 실행을 통과시키지 않는다. 후속 수정은 새로운 조건으로 분리한다. 자료 추가·비교 조건 증가 때문에 이번 실험은 이전 실패를 무효화하지 않는다.

## 타당성 위협

새 자료도 같은 프로젝트 문서이며 대화 이벤트 포장은 합성이다. 사실 회수와 일반 개발 작업 성공률은 다르다. 정확한 식별자 우선과 예산 공유는 이전 선택과 다른 근거를 선택할 수 있으므로 모든 기존 질문을 다시 실행한다. 자동 첨부를 끈 환경의 토큰 비율을 사용자의 모든 확장이 켜진 환경으로 일반화하지 않는다. CLI 세션 재개 지연은 engine app-server 지연과 다르다.
