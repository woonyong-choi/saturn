# 복원 단위와 동시 전달: 실험 결과

## 요약

동시 전달 후보는 기준 방식보다 실제 입력을 Claude 17.07%, Codex 5.26% 줄였다. 후보 정답은 각각 358/360과 360/360이었다. Claude의 대응 정답 손실이 남아 H3를 충족하지 못했고, 복원 수정만 비교한 H2도 충족하지 못했다. 다음 구조 개선 단계의 채택 조건은 통과하지 못했다.

## 방법

| 항목 | 값 |
|---|---|
| 설계 | [실험 설계](design.md), `0ac5b974` |
| 수집 코드 | `19148dac`, 정식 수집 전 고정 |
| 환경 | [env.json](env.json) |
| 자료 | 실제 기록과 저장소 문서 22조건·120문항 |
| 반복 | 세 방식·두 모델·3반복, 396세션·792턴 |
| 모델 | Claude haiku, Codex gpt-6-sol |
| baseline | 기존 패킷 → Ready → 기존 복원·질문 |
| repaired | 같은 패킷 → Ready → 수정 복원·질문 |
| joint | 최소 Ready → 같은 패킷과 수정 복원·질문을 함께 전달 |

기존 20조건은 이전 응답을 열람한 개발 자료로 취급했다. 새 문서 두 건은 정답·원문 구절·줄·해시를 수집 전에 고정했다. 과거 응답을 이번 비교에 재사용하지 않았다. 문서 원문은 실제 자료지만 대화 이벤트 포장은 합성이다.

실행 파일은 기존 미커밋 구현을 포함한 작업 트리에서 빌드했다. 수정 전·후 실행 파일과 소스 해시, 현재 소스 스냅숏을 함께 보존했다. Git 커밋만으로 해당 실행 상태를 재현할 수 있다고 표기하지 않는다.

## 설계와 다른 점

| 변경 | 시점 | 이유와 영향 |
|---|---|---|
| 시작 경고의 도구 호출 오집계 수정 | 정식 수집 전 | 합성 검사 원응답을 다시 수집하지 않고 독립 파서로 확인했다. 원래 파생 결과와 수정 판정을 모두 보존했다. |
| 전체 H1 검사와 첨부 맥락 대조를 분석에 연결 | 수집 중 | 원문 가역성뿐 아니라 실행 소스·바이너리 해시와 기존 구현 검사도 판정에 포함했다. 설계의 H1 기준은 바꾸지 않았다. |
| 12개 예산의 경계 검사 추가 | 수집 중 | 실제 자료에서 글자 상한과 출처를 검사했다. 모델 품질 검사의 대체 근거로 쓰지 않았다. |
| 동일 입력 부분집합 분석 | 수집 중 | 입력이 같은데 정답이 달라진 사례를 확인했다. 탐색 분석이며 주 분석의 실패를 제외하지 않았다. |

질문·정답·허용값·반복 수·채택 기준과 정식 수집 프롬프트는 바꾸지 않았다. [프로토콜 기록](data/protocol.md)에 초기 오집계를 남겼다.

### 실패 원인 대조

- `regression-engine-lifecycle/backup`은 두 모델의 세 반복 모두 기준 방식에서 실패하고 repaired·joint에서 맞혔다. 번호 목록 뒤의 보관 기간을 실제 전송 문자열에 복원한 개선이다.
- Claude `audit-26-r1/new_path`는 repaired에서, `audit-26-r3/new_path`는 joint에서 unknown을 답했다. 해당 경로 문자열은 수정 복원문에도 남아 있었다. 선택 원문의 누락만으로 이 응답을 설명할 수 없다.
- Claude `interruption-r2/new_language`는 joint에서 한국어 대신 Korean을 답했다. 기존 허용 답을 바꾸지 않고 엄격 판정의 실패로 유지했다.
- Codex `relay-r3/first,second`는 repaired에서 틀렸다. 이 실행의 기준·수정 입력과 시작 명령은 바이트가 같았다. 복원 코드가 바꾼 입력 때문에 생겼다고 단정하지 않는다.

### 탐색 분석

baseline과 repaired의 패킷·질문 문자열이 모두 같은 조건을 따로 비교했다. 모델마다 18대응쌍이 있었고 Claude는 손실·이득이 모두 0이었다. Codex는 손실 2건·이득 0건이었다. 동일 입력에서도 응답 변동이 관측됐지만 이 부분집합으로 H2를 통과 처리하지 않았다. [동일 입력 분석](results/identical-input.json)에 대응쌍과 입력 해시를 남겼다.

## 논의

근거 누락 결함은 실제 문서 회귀와 반복 응답에서 개선됐다. 그러나 모든 원문을 복구할 수 있는 전송도 모델의 같은 답을 보장하지 않았다. 입력 비용 감소와 사실 회수의 엄격 판정은 별도의 조건으로 유지한다.

| 타당성 위협 | 이 실험에서 |
|---|---|
| 출처와 질문 반복 | 기존 자료는 개발 자료로 분리. 일반 작업 성공률의 독립 표본이 아님 |
| 새 자료의 범위 | 같은 프로젝트 문서 두 건이며 대화 포장은 합성 |
| 정확한 식별자 우선과 예산 공유 | 기존 모든 질문을 새로 실행했고 대응 손실을 관측했다. |
| provider 응답 변동 | 동일 입력의 오답 변동을 관측했다. 주 분석에 포함했다. |
| 자동 첨부 환경 | Codex 지문은 일정했다. 모든 사용자 확장을 켠 환경은 검증 범위 밖이다. |
| 시제품과 engine 차이 | 실제 전달 확정·실패 복구·정상 router·TUI 종단은 이 비교의 검증 범위 밖 |

engine의 동시 전달 방식은 변경하지 않았다. 최소 Ready를 자료 수신으로 오인하지 않으려면 미전달 패킷의 영속 저장과 수신 뒤 확정 처리가 필요하다. 품질 기준에 실패한 시제품을 이 경로에 적용하지 않는다.

## 결론

실제 입력 감소와 누락된 절차의 회수 개선은 확인했다. H2·H3를 충족하지 못해 무손실 후보로 채택하지 않는다. [맥락 정리](../../design/context-management.md)에 후보의 범위와 미채택 근거를 연결한다. 후속 수정은 이번 실패를 보존한 별도 비교로 판정한다.
