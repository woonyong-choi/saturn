# 프로세스 유지 축약: 추가 검증 설계

## 이유와 사전 관측

본 실험은 축약 뒤 CLI를 종료하고 같은 session ID로 다시 열었다. 이 조건에서 무축약·기본 축약·fast-jev는 각각 48/48을 맞혔다. fast-jev는 호출을 제거했다고 보고했지만 후속 요청 입력 토큰은 무축약과 비슷했고, 축약 뒤 도구 결과의 부모 ID가 이전 기록을 가리켰다. 이 관측만으로 삭제된 기록이 실제 후속 모델 입력에서 빠졌다고 확정할 수 없다.

Saturn의 Claude 어댑터는 프로세스 하나를 stream-json 연결로 유지한다. 따라서 축약과 질문 사이에 프로세스를 끝내지 않는 추가 비교가 필요하다. 기본 축약 한 건으로 stream-json 수신과 지정 메시지까지의 재개가 가능한지 확인했고, 이 탐색 실행은 아래 표본에 합치지 않는다.

## 고정 조건

- 본 실험의 같은 48개 사전 대화와 후속 질문을 모두 쓴다. 사례를 정답률에 따라 고르지 않는다.
- `base_4`의 마지막 assistant UUID를 `--resume-session-at`에 지정하고 `--fork-session`으로 분기한다. 본 실험에서 나중에 추가한 질문·답이 들어가지 않았는지 `compact_boundary.logical_parent_uuid`로 검사한다.
- 두 조건은 기본 `/compact`와 fast-jev의 실제 `session.compact` 훅이다. 같은 프로세스와 session에서 축약 응답을 받은 뒤 후속 질문을 보낸다. 도구는 끈다.
- 홀수 시나리오는 fast-jev를 먼저, 짝수는 기본 축약을 먼저 실행한다. 원본은 바꾸지 않고 별도 결과 폴더에 보존한다.
- 실제 훅 적용, 분기 조상, session ID, 프로세스 ID, 오류 결과, 후속 도구 호출 수, 정확한 코드 포함 여부와 Claude 보고 비용을 검사한다. 비용은 마지막 누적에서 공통 사전 대화 누적을 뺀다.
- 같은 시나리오의 fast-jev와 기본 축약 차이를 10,000회 대응 bootstrap으로 계산한다. 시드는 20261009다. 비율은 Wilson 95% 구간, 대응 차이는 95% 구간과 불일치쌍 수를 보고한다.
- 세 번 연속 실행 실패면 중단한다. 실패·누락을 보존하고 원인을 확인하기 전 재시도하지 않는다.

## 판정 범위

이 비교는 사후에 필요성이 드러난 탐색 분석이다. 본 실험의 H1을 덮어쓰거나 새 확인 분석이라고 부르지 않는다. 같은 프로세스의 축약 효과와 CLI 재시작 뒤 같은 session을 재개한 효과를 구분한다. 큰 차이가 있어도 합성 Read 기록의 첫 후속 코드 회수에만 적용하며 실제 코드 수정 완료율이나 Codex 품질로 일반화하지 않는다.
