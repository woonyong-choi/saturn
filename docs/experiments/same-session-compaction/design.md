# 같은 Claude session 축약 비교: 실험 설계

| 항목 | 값 |
|---|---|
| 이슈 | [#529](https://github.com/woonyong-choi/saturn/issues/529) |
| 관련 설계 | [맥락 정리](../../design/context-management.md), [router](../../design/router.md) |
| 사전 데이터 | 4턴·8개 Read 도구 호출을 만든 뒤 fast-jev 훅이 6개 호출을 제거한 탐색 실행을 보았다. 탐색 입력의 주소는 규칙적으로 만들어져 정답률 측정에 쓰지 않는다. |

## 질문

동일한 원자료와 후속 질문에서 실제 Claude Code의 같은 session 축약은 후속 질문의 근거를 얼마나 보존하는가. 새 session의 Saturn 패킷은 별도 적용 지점으로 보고 결과를 나란히 측정한다.

## 가설

| 가설 | 예측 | 적용 범위 |
|---|---|---|
| H1 | fast-jev와 Claude 기본 `/compact`의 후속 코드 회수율 차이가 20%p 이상이다. 방향은 고정하지 않는다. | 아래 합성 Read 대화, Claude Code 2.1.288, Sonnet |
| H2 | 새 session의 Saturn 패킷은 같은 원자료의 코드 회수율에서 무축약 session 대비 20%p 이상 낮지 않다. | `packet` 예제의 RRF 조건과 2,048토큰 예산 |

## 설계

| 항목 | 값 |
|---|---|
| 조건 | 무축약 session, 기본 `/compact` fork, fast-jev `session.compact` fork, Saturn `packet` 예제를 받은 새 session |
| 배정 | 시드 20261005로 만든 48개 시나리오. 각 8개 기록을 여섯 번씩 후속 질문 대상으로 고른다. 조건 호출 순서는 시나리오 번호 홀짝으로 바꾼다. |
| 눈가림 | 정답 문자열은 실행기가 보관하고 provider의 후속 질문에는 넣지 않는다. 채점은 결과에서 정답 문자열의 정확한 포함 여부로 자동화한다. |
| 환경 | macOS, Claude Code 설치본과 Sonnet 모델의 실행 시점 버전을 `env.json`에 기록한다. function hook은 fast-jev-compaction `e3f262a`, Saturn packet 예제는 현재 커밋에서 빌드한다. |

각 시나리오의 파일 8개에는 서로 독립적인 12자리 코드와 같은 길이의 무관한 메모를 넣는다. 초기 목표는 어느 기록의 코드를 나중에 물을지 모른다고 알린다. 실제 `Read` 도구로 두 파일씩 네 턴에 읽고, 답에는 기록 번호만 쓰게 한다. 후속 질문에서는 도구를 끈 채 한 기록의 코드를 묻는다. 같은 session 세 조건은 같은 사전 대화에서 분기한다. 패킷 조건은 그 대화의 정규화된 기록을 `packet` 예제에 넣고 새 session에 전달한다. `packet`은 현재 engine 연결이 아닌 예제 실행이므로 실제 제품 경로라고 주장하지 않는다.

## 변수

| 변수 | 종류 | 정의 | 단위 |
|---|---|---|---|
| `exact` | 측정 | 첫 후속 답에 해당 기록의 12자리 코드가 정확히 있는지 | 이진 |
| `hook_applied` | 측정 | fast-jev의 `ui_log`에 요약 없는 유지 결과가 있고 기본 요약 대체가 없는지 | 이진 |
| `retained_calls` | 측정 | 훅이 유지한 Read 호출 수 | 건 |
| `packet_tokens` | 측정 | Saturn 예제가 보고한 패킷 토큰 수 | 토큰 |
| `cost` | 측정 | 각 Claude 호출의 보고 비용 합계 | 달러 |
| `failure` | 측정 | CLI 오류, 훅 대체, 세션 분기 실패, packet 오류 | 건 |

## 표본

| 항목 | 값 |
|---|---|
| 출처 | 시드 20261005로 생성한 합성 파일 48묶음. 실제 사용자 자료를 넣지 않는다. |
| 크기 | 각 조건 48개 후속 질문, 같은 48개 시나리오에 대응 |
| 크기 근거 | 48쌍에서 20%p 이상의 큰 차이를 탐지하는 탐색 규모다. 비율 50%의 단일 조건 Wilson 95% 구간 반폭은 약 14%p라 작은 차이를 결론 내리지 않는다. |
| 중단 규칙 | 48묶음을 끝까지 실행한다. 인증·서비스 장애가 3묶음 연속이면 중단하고 실패를 모두 보고한다. |
| 반복과 예열 | 예열 없음. 시나리오당 각 조건 한 번. |

## 분석

| 가설 | 지표 | 방법 | 채택 기준 |
|---|---|---|---|
| H1 | fast-jev와 기본 축약의 `exact` 대응 차이 | 시나리오 재표집 10,000회 95% 구간, 불일치쌍 수 | 차이 절댓값 20%p 이상, 구간에서 0 제외 |
| H2 | 패킷과 무축약의 `exact` 대응 차이 | 같은 재표집 | 하한 -20%p 초과 |

| 항목 | 규칙 |
|---|---|
| 제외 기준 | 초기 네 턴에 Read가 8개 미만인 묶음은 구성 실패로 세고 네 조건의 품질 비교에서 제외한다. 제외 수와 이유를 보존한다. |
| 실패한 실행 | 분기·호출 실패는 오답으로 세는 보수적 분석과 성공 실행만 보는 분석을 함께 낸다. fast-jev가 기본 요약으로 대체되면 fast-jev 효과 분석에서 따로 표시한다. |
| 다중 비교 | H1은 같은 session 축약 선택, H2는 새 session 패킷 유지라는 별도 결정에만 쓴다. 두 결과를 합쳐 전체 우월성 주장을 하지 않으므로 가족 단위 유의성 판정은 하지 않는다. |

## 판정

| 결과 | 설계에 반영 |
|---|---|
| H1 채택 | 더 나은 같은 session 축약 경로를 Claude 어댑터의 실험 옵션 후보로 둔다. Codex 지원은 별도 실측한다. |
| H1 기각 | 두 방식의 우열을 주장하지 않고 기본 provider 축약을 유지한다. |
| H2 채택 | 새 session 패킷 경로를 유지하되 같은 session 축약 우열과 섞지 않는다. |
| H2 기각 | 패킷 예산과 후보 선별을 재검토한다. |
| 보류 | 훅 대체나 실패가 많으면 적용 판단을 미룬다. |

## 탐색 분석

- 대상 기록의 위치별 회수율과 훅의 도구 호출 제거율을 본다.
- 첫 답 뒤 Read를 허용한 재질문에서 회복되는 비율은 후속 별도 실행이 필요하다.

## 보존

원본 CLI JSONL, session ID, 합성 fixture, packet 출력과 자동 채점은 `.local/experiments/same-session-compaction/`에 둔다. 공개 결과에는 코드 원문을 싣지 않고 원자료 SHA-256, 실패 수, 집계만 싣는다. 비밀 키는 숨김 표준 입력으로 받아 프로세스 환경에만 둔다.
