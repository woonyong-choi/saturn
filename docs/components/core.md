# 핵심 규칙 설계

핵심 규칙은 기록 저장소, 네트워크, 프로세스를 모른 채 순수 규칙과 외부 연결 trait을 정의한다. 아키텍처는 [아키텍처](../architecture.md)에 있다.

## 모듈

| 모듈 | 하는 일 | 위치 |
|---|---|---|
| `providers` | 공급자 연결 공통 규격 `ProviderClient` trait | `saturn-terminal/core/src/providers/mod.rs` |
| `judges` | 판단기 공통 규격 `JudgeClient` trait, 질문 정의, 기준값 조정, 피드백 | `saturn-terminal/core/src/judges/mod.rs` |
| `agents` | `AgentTracker`의 공급자 에이전트 트리 추적, 사용량 보고 행, 트리 유휴 판정 | `saturn-terminal/core/src/agents/mod.rs` |
| `sessions` | `SessionManager`의 세션 세대, 맥락 측정, 정리·인수 패킷, 유예 뒤 종료 | `saturn-terminal/core/src/sessions/mod.rs` |
| `queue` | `Queue`의 입력 접수, 상태 전이, 대기·취소·보류·재개, 쓰기 규칙 | `saturn-terminal/core/src/queue/mod.rs` |

## 동작

### 입력 접수와 판단

1. `queue`: 입력 접수(ACK), 설정 번호와 권한 고정
2. `queue`: 사용자가 모델을 고정한 입력이면 판단기 호출 생략
3. `queue`: 같은 채팅 입력의 ACK 순서대로 판단 차례 배정
4. `queue`: 판단 시점의 채팅 revision 고정(작업 상태, 대기열 맨 앞, 마지막 판단)
5. `judges`: 앞 입력의 판단 결과를 state에 넣은 요청 한 건으로 필요한 질문 일괄 판단
6. `judges`: `keep_current`가 이어 가는 입력이면 하던 에이전트로 전달 결정
7. `judges`: 새 작업이면 `is_actionable`, 모델 선택 순서로 판정
8. `queue`: 적용 직전 revision 비교(CAS)
9. `queue`: 판단 결과대로 끼워 넣기, 새 작업, 대기 중 하나 적용

### 입력 전송

1. `queue`: 대기열 맨 앞 입력의 접수 때 권한으로 쓰기 규칙 판정
2. `queue`: 읽기 전용 권한이면 같은 폴더에서 병렬 실행
3. `queue`: 쓰기 권한이고 쓰는 에이전트가 있으면 대기
4. `sessions`: 보내는 순간 대상 세션 결정
5. `providers`: 끼워 넣기면 진행 중인 턴에 입력 추가
6. `queue`: 입력 상태를 `전달 중`, `반영됨` 순서로 전이

### 멈춤과 보류 재개

1. `queue`: 멈춤 요청이면 실행 중 작업과 보내지 않은 대기 입력 보류
2. `agents`: 추적된 하위 에이전트부터 멈춤 신호 대상 순서 결정
3. `queue`: 대상이 있는 재개 요청이면 그 작업만 재개
4. `queue`: 대상이 없는 재개 요청이면 채팅의 보류 전부를 접수 순서대로 재개
5. `queue`: 쓰기 규칙에 따라 한 번에 하나씩 실행
6. `sessions`: 확인된 상태로 만든 새 입력 전송(같은 패킷 재전송 없음)
7. `judges`: 새 입력의 `resume_held`가 0.85 이상이면 보류 작업 재개
8. `queue`: 재개 뜻이 없는 새 입력 3개 누적이나 Saturn 세션 종료 시 보류 종료
9. `sessions`: 보류 종료 때 에이전트 세션 종료, 보내지 않은 입력 취소 처리

### 에이전트 트리 추적

1. `agents`: 이벤트에서 하위 에이전트의 시작, 진행, 끝 기록
2. `agents`: 하위 에이전트를 부모 에이전트 아래 등록
3. `agents`: 부모 턴 완료만 작업 끝 후보로 판정
4. `agents`: 답이 먼저 나오고 하위 에이전트가 남으면 `answered-tree-running`
5. `agents`: 에이전트와 모든 하위 에이전트가 끝나면 트리 유휴 판정
6. `agents`: 입력 없이 공급자가 시작한 턴은 `origin = provider-wake` 기록

### 사용량 턴 값 계산

1. `agents`: 사용량 보고 원값, 범위, 대상 에이전트, 모델을 한 행으로 기록
2. `agents`: 범위는 `main-turn`, `tree-total`, `thread-cumulative` 중 하나
3. `agents`: 턴 값은 저장 없이 필요할 때 기록 순서로 계산
4. `agents`: 누적 범위면 같은 세션의 이번 누적에서 직전 누적 차감
5. `agents`: 턴 범위면 보고값을 턴 값으로 사용
6. `agents`: 세션이 바뀌면 누적 계산 새로 시작

### 맥락 정리 판정

1. `sessions`: 턴 종료마다 활성 맥락 A 측정
2. `sessions`: 트리 유휴가 아니거나 A에 합칠 대기 입력이 있으면 다음 턴 경계까지 연기
3. `sessions`: 마지막 턴 뒤 경과 시간이 캐시 유지 시간을 넘고 P < A면 재시작
4. `sessions`: A < T면 그대로 계속
5. `sessions`: A ≥ T이고 k*가 기대 잔여 턴 이하면 재시작(잔여 턴을 모르면 3)
6. `sessions`: 그 밖이면 그대로 계속

### 패킷 구성

1. `sessions`: 사용자가 명시한 제약과 결정 원문 고정
2. `sessions`: 현재 목표와 마지막 사용자 입력 원문 추가
3. `sessions`: 끝나지 않은 항목과 효과를 모르는 항목 추가
4. `sessions`: 최근 3턴 원문 추가
5. `judges`: 그 이전 도구 호출 중 `compact` 질문이 남기라고 한 것만 선택
6. `sessions`: 선택한 도구 결과를 앞부분 300자와 한 줄 메모로 축약
7. `sessions`: 파일은 내용 대신 경로만 추가
8. `sessions`: `P_max = T / 10` 초과 시 뒤쪽 항목부터 축소

### 메인과 서브 에이전트 수명

1. `sessions`: 채팅마다 메인 에이전트 하나 유지
2. `sessions`: 모델이나 공급자가 바뀌면 새 메인 시작, 이전 메인은 인수 뒤 종료
3. `queue`: 판단기가 무관한 작업으로 판단하면 채팅 소속 서브 에이전트 시작
4. `sessions`: 트리 유휴 뒤 유예 5분이 지나면 세션 종료, 세션 ID 보관
5. `sessions`: 새 입력이 오면 보관한 세션 ID로 재개
6. `sessions`: 서브 에이전트는 끝나면 결과 전달 뒤 바로 종료
7. `sessions`: 세션마다 전달받은 기록 번호 기록
8. `sessions`: 다음 입력 때 그 기록 번호 뒤 다른 에이전트의 결과 요약과 수정 파일 경로 첨부
9. `judges`: 쌓인 양이 많을 때만 관련 항목 선택

### 크래시 뒤 재개

1. `queue`: 크래시 뒤 실행마다 기록한 `effect_scope` 확인
2. `queue`: `proven-by-config`나 `proven-by-observation`이면 자동 재개
3. `sessions`: 자동 재개 때 파일 상태 확인 뒤 새 입력으로 전송
4. `queue`: `network-possible`이나 `unobserved`면 보류와 재개 제안 한 줄

### 기준값 조정

1. `judges`: 판단 뒤 관찰 시간(다음 입력 3개 또는 10분) 경과 시 신호 확정
2. `judges`: 행동 뒤 사용자가 뒤집거나 취소하면 틀림 신호
3. `judges`: 행동하지 않았는데 사용자가 같은 행동을 직접 하면 놓침 신호
4. `judges`: 반응이 없으면 정답이 아닌 미확정 처리
5. `judges`: 판단마다 빠른 조정으로 중심값 ±0.05 안에서 기준값 이동
6. `judges`: `/train`이면 채점된 판단 전부로 질문별 중심값 재계산
7. `judges`: 새 중심값이 잡히면 빠른 조정 차이를 0으로 초기화

### 채점과 승격

1. `judges`: 결과 신호가 있거나 확신도가 낮거나 판단기끼리 갈린 판단 우선 선택
2. `judges`: 채점 모델마다 선택지 순서를 두 번 바꿔 풀고 같은 답만 채택
3. `judges`: 결정 이후 대화로 그때 알 수 있던 정보 기준의 사후 판정
4. `judges`: 채점 모델, 사후 판정, 결과 신호를 label model로 결합
5. `judges`: 품질 게이트 통과 라벨만 학습용과 평가용으로 분리
6. `judges`: 승격 게이트를 통과한 모델만 현재 판단기 버전으로 승격
7. `judges`: 베이스 모델이 바뀌면 판단 기록으로 다시 학습, 게이트 비교 뒤 사용자 승인 때만 교체

## 규칙

| 규칙 | 이유 |
|---|---|
| 제어 명령이 아닌 입력마다 판단기를 한 번 부르고 필요한 질문을 한 요청에 묶는다. | 입력당 판단기 호출을 한 번으로 묶기 위해서다. |
| 기계적으로 판단할 수 있으면 코드가, 뜻을 이해해야 하면 판단기가 정한다. | 판단기를 뜻 판단에만 쓰기 위해서다. |
| `keep_current`를 `is_actionable`보다 먼저 읽는다. | 이어 가는 입력이 파일 탐색으로 빠지는 일을 막기 위해서다. |
| 쓰기는 한 번에 한 에이전트만 한다. | 병렬 에이전트가 같은 작업 폴더에 쓰는 충돌을 막기 위해서다. |
| 쓰기 규칙 판정은 접수 때 고정된 권한으로 한다. | 쓰기 여부를 추정 없이 결정론으로 판정하기 위해서다. |
| 파일 겹침 예측으로 병렬 쓰기를 허용하지 않는다. | 겹침 예측은 추정이라 충돌을 막지 못하기 때문이다. |
| worktree 설정을 켜면 git 저장소일 때만 별도 worktree와 브랜치에서 병렬로 쓴다. | 쓰기 격리를 git이 맡기 위해서다. |
| worktree 결과는 변경 요약을 보인 뒤 사용자 확인으로만 합친다. | 자동 병합으로 변경을 잃는 일을 막기 위해서다. |
| worktree 결과를 합칠 때 git에 없는 파일은 누락을 경고한다. | git이 옮기지 않는 파일을 모른 채 잃는 일을 막기 위해서다. |
| 쓰기 잠금은 트리 유휴일 때 푼다. | 하위 에이전트가 쓰는 중에 다음 쓰기가 시작되는 일을 막기 위해서다. |
| 대기열은 에이전트 세션이 아니라 채팅에 둔다. | 세션 교체 중 들어온 입력이 옛 세션을 가리키는 일을 막기 위해서다. |
| 세션 교체는 턴이 끝난 경계에서만 한다. | 진행 중인 턴이 세션 교체로 끊기는 일을 막기 위해서다. |
| 세션 교체 중 들어온 입력은 새 세션에 순서대로 보낸다. | 입력 순서를 세션 교체와 무관하게 지키기 위해서다. |
| 멈춤은 Saturn 세션의 모든 에이전트와 하위 에이전트에 닿는다. | 에이전트 하나만 멈추는 기능은 내부(취소, 모델 교체)에서만 쓰기 때문이다. |
| 보류를 닫아도 기록은 지우지 않고 수정된 파일은 되돌리지 않는다. | 사용자가 멈춘 작업의 결과를 사용자 뜻 없이 지우는 일을 막기 위해서다. |
| 하위 에이전트 사용과 공급자 설정은 막거나 바꾸지 않고 추적만 한다. | 공급자 설정을 사용자에게 맡기기 위해서다. |
| 추적만 하는 규칙의 예외는 판단기 키 보안뿐이다. | 판단기 키가 공급자 자식 프로세스로 새는 일을 막기 위해서다. |
| 이어 갈 내용은 공급자 요약이 아니라 맥락의 정본인 Saturn 기록 원문에서 고른다. | 공급자 원격 압축 요약은 암호화되어 보이지 않기 때문이다. |
| 발동 기준은 공급자별 토큰 `T_abs`와 안전 비율 `N`으로 정한 `T = min(T_abs, N% × 창 크기)`다. | 품질 저하는 창 대비 비율이 아니라 절대 길이에 따라 생기기 때문이다. |
| 본전 턴 수는 패킷 P, 캐시 읽기 배수 r, 캐시 쓰기 배수 w로 계산한 `k* = (P×w − A×r) / ((A − P) × r)`다. | 여유가 있을 때 먼저 끊는 쪽이 이득인지 계산으로 정하기 위해서다. |
| A를 잴 수 없으면 Saturn 재시작 없이 공급자 자동 압축에 맡긴다. | 측정하지 못한 맥락으로 재시작을 판정하지 않기 위해서다. |
| 공급자 자동 압축은 끄지 않고 턴당 증가량의 p95인 H(관측 전에는 창의 10%)를 더한 `T_hard = T + H`에 둔다. | 한 턴이 갑자기 커져 T를 넘어도 공급자가 처리하게 하기 위해서다. |
| 사용자가 공급자 설정에 자동 압축 값을 정해 두면 안전망 값을 넣지 않는다. | 사용자의 공급자 설정을 Saturn 기본값보다 우선하기 위해서다. |
| 공급자가 스스로 읽는 문서(`AGENTS.md`, `CLAUDE.md`)는 패킷에 넣지 않는다. | 중복을 막기 위해서다. |
| 공급자 압축 요약은 읽을 수 있을 때만 도구 호출 항목의 보조 후보로 쓴다. | 기록 원문을 정본으로 두기 위해서다. |
| 에이전트끼리 직접 통신하지 않는다. | 맥락 전달을 Saturn 기록 번호 하나로 맞추기 위해서다. |
| 서브 결과로 쉬는 메인을 깨우지 않고 메인의 다음 입력 때 전달한다. | 맥락 전달을 Saturn 기록 번호 하나로 맞추기 위해서다. |
| 질문 문장과 선택지는 `judges` 한 곳에서 버전으로 관리하고 릴리스로만 바꾼다. | 판단 기록의 `ID@버전`으로 같은 질문을 다시 찾기 위해서다. |
| 기준값은 설정 층에 둔다. | 기준값을 릴리스 없이 사용자 층과 폴더 층에서 조정하기 위해서다. |
| 질문과 기준은 영어로 쓰고 사용자 원문은 그대로 넣는다. | 영어 외 언어에서 판단 정확도가 떨어지는 일을 질문 쪽에서 줄이기 위해서다. |
| 뜻이 같은 작은 변경은 `route@3.1`, 뜻이나 선택지가 바뀌는 큰 변경은 `route@4`로 올린다. | 작은 변경에서 옛 답과 라벨을 그대로 쓰기 위해서다. |
| 큰 변경은 옛 선택지에서 새 선택지로 가는 대응표를 코드에 함께 둔다. | 옛 판단을 `/train` 때 새 질문으로 다시 채점하기 위해서다. |
| 답이 하나인 `choice` 질문에는 `기타`를 넣고, 여러 개가 맞을 수 있는 속성은 `noul`로 하나씩 묻는다. | 선택지를 늘려도 옛 답이 덜 깨지게 하기 위해서다. |
| 판단 방식 `jev`는 기준 판단기가, `saturn`은 Saturn 모델이 결정한다. | 행동을 정하는 판단기를 설정 하나로 고르기 위해서다. |
| 판단 기록은 판단 방식과 관계없이 전부 남긴다. | 어느 방식에서도 학습과 비교용 기록을 쌓기 위해서다. |
| `saturn` 방식에서 확신도가 기준보다 낮으면 행동하지 않고 질문별 대체 규칙으로 간다. | 확신 없는 판단으로 행동하는 일을 막기 위해서다. |
| 판단기 버전은 모델, 보정값, 질문별 목표 틀림 비율의 묶음이다. | 모델이 바뀌어도 같은 목표를 지키기 위해서다. |
| 기준값은 판단기 버전마다 목표 틀림 비율에서 다시 계산한다. | 기준값 숫자 대신 목표를 버전에 남기기 위해서다. |
| 느린 조정은 목표 틀림 비율(기본 5%)을 지키는 가장 낮은 값을 중심값으로 삼는다. | 목표 위험 안에서 행동 비율을 최대로 두기 위해서다. |
| 틀림 신호와 놓침 신호를 둘 다 쓴다. | 행동한 경우만 보면 기준값이 끝없이 오르기 때문이다. |
| 행동 비율이 하한 아래로 내려가면 경고한다. | 기준값이 올라 행동하지 않게 되는 일을 알리기 위해서다. |
| 모든 판단에서 확률 q로 맞았는지 묻는다. | 묻는 판단을 고르게 섞기 위해서다. |
| q는 기준값 근처에서 높고 확실한 판단에서 낮되 0이 아니다. | 기준값 근처의 판단에서 신호를 더 모으기 위해서다. |
| 계산 때 물은 판단을 1/q로 가중한다. | 확률적으로 물은 표본의 치우침을 바로잡기 위해서다. |
| 전체 묻는 빈도 상한은 판단 20번에 1번이다. | 사용자에게 묻는 횟수가 늘어나는 일을 막기 위해서다. |
| 판단 기록마다 판단기 버전, 그때 기준값, 물은 확률 q를 남긴다. | 기준값 조정 계산을 다시 하기 위해서다. |
| 빠른 조정 폭은 판단이 쌓일수록 줄고, 최근 100번 동안 ±0.01 안이면 멈춘다. | 기준값이 흔들리지 않게 하기 위해서다. |
| 틀림 비율이 급변하면 조정 폭을 다시 키운다. | 사용 방식 변화에 다시 맞추기 위해서다. |
| 질문별 최저값과 최고값을 두고, 되돌릴 수 없는 행동의 기준값은 0.8 미만으로 두지 않는다. | 되돌릴 수 없는 행동의 오판을 막기 위해서다. |
| 기준값을 바꾼 뒤 순차 검정으로 확실히 나빠지면 이전 값으로 되돌린다. | 나빠진 기준값이 굳는 일을 막기 위해서다. |
| AI 채점 라벨의 치우침은 사용자가 직접 답한 소량 라벨로 추정해 보정하고 뒤집기와 취소는 약한 라벨로 가중한다. | AI 채점 라벨은 AI 기준이기 때문이다. |
| `/train`은 지난 실행 뒤 채점 안 된 판단이 200건 이상일 때만 실행한다. | 적은 라벨로 한 조정이 잡음 수준이기 때문이다. |
| 기준값 자동 조정은 그 질문의 채점된 판단이 200건 이상일 때만 한다. | 적은 라벨로 한 조정이 잡음 수준이기 때문이다. |
| 채점은 사람 없이 코드가 아니라 설정으로 정한 채점 모델이 한다. | 채점 모델이 바뀌어도 워크플로를 그대로 쓰기 위해서다. |
| 학습용 라벨은 합의, 순서 일관, 반대 결과 없음을 통과해야 한다. | 틀린 라벨로 학습하는 일을 막기 위해서다. |
| 평가용 라벨은 만장일치와 결과 일치만 쓴다. | 틀린 라벨로 승격을 판정하는 일을 막기 위해서다. |
| 승격은 같은 평가용 데이터에서 정확도 차이 95% 신뢰구간 하한이 −1pp보다 클 때만 한다. | 새 모델이 현재 모델보다 나빠지는 일을 막기 위해서다. |
| 승격은 Brier와 ECE 악화, 처리 비율 감소, 선택지 순서 일관성 저하가 없어야 한다. | 보정과 처리 범위가 나빠지는 일을 막기 위해서다. |

## 인터페이스

| 항목 | 시그니처 | 보장 |
|---|---|---|
| 공급자 연결 | `trait ProviderClient` | 구현은 끼워 넣기, 멈춤 신호, 맥락 정리, 사용량 보고를 Saturn 용어로 넘긴다. |
| 판단기 | `trait JudgeClient` | 모든 판단기는 이 trait의 구현으로만 붙는다. |
| `choice` 답 | `choice` | 선택지별 확률과 확신도를 돌려주고, 선택지는 255개 이하다. |
| `noul` 답 | `noul` | P(yes)를 돌려준다. |
| `score` 답 | `score` | 2~10단계 분포를 돌려준다. |
| 확신도 | `(N·pmax − 1)/(N − 1)` | N은 선택지 수, pmax는 가장 높은 확률이다. |
| `route` 현재 유지 | `keep_current: noul` | 0.8 이상이면 유지하고, 판단이 없거나 0.3~0.8이면 현재 에이전트를 유지한다. |
| `route` 명확성 | `is_actionable: noul` | 0.7 이상이면 명확으로 보고, 판단이 없으면 명확으로 간주해 탐색을 생략한다. |
| `route` 모델 | `target_model: choice` | 허용 후보만 고르고, 확신도 0.6 미만이면 사용자 고정 모델이나 현재 모델을 쓴다. |
| `route` 난이도 | `difficulty: score` | 3단계로 답하고, 확신도 0.6 미만이면 쓰지 않는다. |
| `route` 스킬 | `skills: choice` | `none`을 포함하고, 확신도 0.6 미만이면 힌트를 넣지 않는다. |
| `route` 보류 재개 | `resume_held: noul` | 0.85 이상에서만 이어 가고, 아니면 무시 횟수를 1 올린다. |
| `relation` 실행 중 관계 | `relation_to_running: choice` | `refines`, `continues`, `independent`, `conflicts` 중 고르고, 확신도 0.6 미만이면 대기로 보낸다. |
| `send-opt` 보내는 방식 | `steer_or_spawn: choice` | `target_model`과 함께 묻고, 확신도 0.6 미만이면 현재 에이전트에 대기 뒤 보낸다. |
| `file-rank` 파일 관련성 | `file_<n>_relevant: noul` | 파일 20개와 `answer_present`를 묻고, 0.7 이상은 존재, 0.35 미만은 없음으로 본다. |
| `file-rank` 대체 | `file_<n>_relevant: noul` | 판단이 없으면 코드 검색 순서를 그대로 쓴다. |
| `context-select` 맥락 선택 | `pick: choice` | 게이트 `noul` 3개 평균이 0.3 미만이면 없음으로 보고, 2차로 `fits_<n>`을 묻는다. |
| `context-select` 대체 | `pick: choice` | 판단이 없으면 힌트를 넣지 않는다. |
| `compact` 도구 호출 유지 | `call_<id>_keep: noul` | 호출마다 `result_<id>_keep`과 함께 묻고, 0.5 이상이면 남긴다. |
| `compact` 대체 | `call_<id>_keep: noul` | 판단이 없으면 최근 3턴과 고정 항목만 넣고 나머지 도구 결과는 경로만 넣는다. |
| `doc-filter` 문서 조각 | `injection: noul` | 조각마다 `relevant`, `evidence`, `contradiction`과 함께 묻고, 0.7 이상이면 뺀다. |
| `doc-filter` 대체 | `injection: noul` | 판단이 없으면 문서 조각을 넣지 않는다. |
| `loop` 진행 여부 | `is_progressing: noul` | 0.2 미만이면 루프로 보고, 판단이 없으면 멈추고 사용자에게 알린다. |
| `feedback` 피드백 원인 | `wrong_doc: noul` | `misunderstood_intent`, `code_error`와 함께 묻고, 0.7 이상인 원인만 쓴다. |
| `feedback` 대체 | `wrong_doc: noul` | 판단이 없으면 원문을 그대로 전달한다. |

## 오류 처리

| 상황 | 동작 |
|---|---|
| 판단기 무응답 | 그 입력을 대기로 보낸다. |
| 적용 직전 revision 불일치 | 1회 다시 판단하고, 또 어긋나면 대기로 보낸다. |
| 판단 답의 후보 밖 선택, NaN, 확률 누락 | 판단을 `invalid`로 기록하고 인터페이스 절의 대체 규칙을 적용한다. |
| 판단 중 revision 변경 | 판단을 `superseded`로 기록한다. |
| 실행 중 판단기 일시 실패 | 인터페이스 절의 대체 규칙을 적용하고 건너뛴 판단을 사유와 함께 기록한다. |
| 끼워 넣기가 활성 턴 없음으로 실패 | 확정 미전달로 기록하고 다시 판단하지 않고 같은 세션에 새 턴으로 보낸다. |
| 크래시 뒤 증명되지 않은 `effect_scope` | 자동으로 재개하지 않고 보류한 뒤 재개를 한 줄로 제안한다. |
| 중간 사용량 보고 누락 | 차이가 여러 턴에 걸친다고 표시하고 0으로 채우지 않는다. |
