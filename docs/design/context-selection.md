# 맥락 고르기

| 항목 | 값 |
|---|---|
| 상태 | 결정 |
| 관련 결정 | [원본 인계 구현](https://github.com/woonyong-choi/saturn/issues/613) |

## 요약

Saturn은 전환 패킷의 대화 본문을 고르지 않고 모두 보존한다. 도구 기록은 전환 패킷의 남는 예산에 최근순으로 넣는다. 과거 도구 결과가 필요하면 채팅 기록에서 검색하고 원문 번호와 해시로 다시 읽는다.

## 동기

도구 결과가 많을 때 어떤 결과가 다음 작업에 필요한지는 사전 순위만으로 증명되지 않았다. 대화의 사용자 정정은 선택 대상에서 빼고, 부족한 근거는 원본 조회로 복구할 수 있어야 한다.

## 예시

### 오래된 도구 결과 읽기

1. Claude에서 Codex로 전환한 뒤 Codex가 이전 도구 결과가 필요하다고 판단한다.
2. Codex는 `saturn evidence search 로그인`으로 같은 채팅의 읽을 수 있는 후보를 찾는다.
3. 후보 번호와 해시를 사용해 `saturn evidence read <번호> --hash <해시>`로 원문을 읽는다.
4. engine은 채팅 범위, 읽기 권한, 해시를 다시 확인한다.

### 새 session 패킷 만들기

1. engine은 기록된 대화 본문과 남은 일을 고정 구역에 둔다.
2. 수정 파일을 경쟁 구역 앞에 두고 도구 호출과 결과는 최신 기록부터 넣는다.
3. 예산에 못 들어간 결과는 기록 저장소에 그대로 남는다.

## 상세 설계

### 고르기를 쓰는 곳

전환 패킷은 도구 기록의 최신순만 사용하며 제약과 대화 본문에는 순위를 적용하지 않는다. 근거 검색은 질의에 맞는 기록을 정렬한다. 제약 해제·예외 판단은 유효 제약이 10개를 넘을 때 후보를 제한하기 위해 별도의 순위를 사용한다. 이 세 경로를 하나의 패킷 선별 정책으로 취급하지 않는다.

### 순위 채널

근거 검색과 제약 후보 제한은 파일 경로 겹침, 단어 겹침, 기록의 최근성을 계산한다. 검색어와 기록의 단어 조각을 비교할 때는 `saturn-terminal/core/src/sessions/ranking.rs`의 BM25 점수를 사용한다. 이 순위는 전환 패킷의 도구 기록 선택에 쓰지 않는다.

### 순위 합치기

검색과 제약 후보 제한의 세 순위는 RRF로 합친다. `context.select.rrf_k`는 그 두 경로의 합치기 상수다. 전환 패킷에는 이 값이 영향을 주지 않는다. 검색 순위가 작업 완료 품질을 높인다는 독립 검증은 아직 없다.

### 근거 검색과 원문 조회

`engine`은 출입증이 가리키는 채팅의 도구 호출과 결과를 후보로 만든다. 현재 읽기 범위와 거부 규칙으로 후보를 거른 뒤 정렬하며 한 번에 최대 50개를 돌려준다. 후보에는 기록 번호, 시각, 길이, 발췌, SHA-256 해시를 싣는다.

| 명령 | 동작 |
|---|---|
| `saturn evidence search <검색어>... [--limit N]` | 후보 번호와 해시를 조회한다 |
| `saturn evidence read <번호> [--hash H] [--offset N] [--limit N]` | 원문을 한 번에 최대 20,000글자씩 읽는다 |

원문 읽기는 번호가 해당 채팅에 있는지, 읽을 수 있는 경로인지, 요청한 해시가 현재 원문과 같은지 다시 검사한다. 결과가 아직 없던 도구 호출에 나중에 결과가 붙으면 해시가 바뀌므로 새 후보를 조회해야 한다. 읽을 수 없는 기록의 내용은 검색 결과와 오류에 드러내지 않는다.

### 오류 처리

| 상황 | 동작 |
|---|---|
| 채팅 출입증 없음 또는 회수 | 요청을 거절한다 |
| 번호가 없거나 다른 작업 범위 | 원문을 돌려주지 않는다 |
| 해시 불일치 | 원문을 돌려주지 않고 새 검색을 요구한다 |
| 패킷의 도구 기록이 예산을 넘는 경우 | 항목을 줄이거나 빼고 기록 번호를 보존한다 |

### 요구사항

| 요구사항 | 검증 계획 |
|---|---|
| 패킷 보호 본문은 도구 기록 순위의 영향을 받지 않는다. | `saturn-terminal/engine/src/lifecycle/dialogue_preserved.rs`의 `four_reads_after_a_correction_do_not_push_it_out_of_the_switch_packet` |
| 검색과 읽기는 같은 채팅과 현재 읽기 권한 안에서만 동작한다. | `saturn-terminal/engine/src/lifecycle/evidence.rs`의 범위·권한 시험 |
| 잘린 원문은 번호와 해시로 이어 읽는다. | `saturn-terminal/core/src/sessions/evidence/tests.rs`의 원문 범위 시험 |
| 도구 결과는 최신순이고 수정 파일은 앞에 둔다. | `saturn-terminal/engine/src/handoff.rs`의 인계 패킷 순서 시험 |

## 단점

최근순 패킷은 오래된 중요한 도구 결과를 자동으로 찾지 못한다. 검색도 어휘와 파일 경로가 달라지면 놓칠 수 있다. 사용자가 provider를 바꾼 실제 작업에서 원문 재조회가 품질과 비용에 주는 영향은 더 측정해야 한다.

## 대안

- 패킷의 RRF 순위와 Jev `compact` 판단은 제품 경로에서 제거했다. 이전 비교 결과는 [실과제 진단](../experiments/context-net-effect/report.md)에 남긴다.
