# 용어 카탈로그

| 항목 | 값 |
|---|---|
| 상태 | 결정 |
| 관련 결정 | [후보 순위는 임베딩 없이 단어 기반과 용어 카탈로그로 시작한다](../decisions/2026-10-01-lexical-ranking-with-term-catalog.md) |

## 요약

용어 카탈로그는 같은 대상을 가리키는 말의 짝(`로그인`과 `login`)을 모은 사전이다. `core`의 `sessions`가 Saturn 기록에서 짝 후보를 캐고 증거를 쌓으며, judge가 기준을 넘은 짝을 확인한다. [맥락 고르기](context-selection.md)의 단어 조각은 조각마다 카탈로그를 열쇠로 조회해 짝의 조각을 더한다. 카탈로그는 기본 사전, 사용자 정본, 프로젝트 카탈로그 세 층이고 로컬에서만 자란다.

## 동기

단어 겹침 채널은 글자가 겹치지 않는 같은 뜻의 말을 찾지 못한다. 사용자는 한국어로 `로그인`이라고 말하고 기록에는 `login`, `auth`가 남는다. 사람이 대응표를 직접 채우게 하면 쓰기 어렵고, 아무도 채우지 않으면 한국어 입력과 영문 식별자가 이어지지 않는다. 이 기능은 이미 쌓인 기록에서 짝을 저절로 찾아 키운다.

## 예시

### 짝이 저절로 생기기

1. 에이전트가 답에 `로그인(login) 처리를 고쳤습니다`라고 쓴다.
2. `sessions`는 괄호 표기에서 `로그인`과 `login` 짝을 찾아 증거를 더한다.
3. 같은 채팅에서 사용자가 `로그인`을 말한 턴마다 에이전트가 `login.rs`를 고쳐 함께 나옴 연관도가 오른다.
4. 짝 점수가 기준을 넘고 증거가 3번 쌓이자 짝이 확인 대기에 오른다.
5. 트리 유휴가 되자 engine은 확인 대기 짝 여러 개를 judge 요청 한 번에 묶어 묻고, judge가 0.9를 답해 짝이 확인된다.
6. 다음 입력 `로그인 실패 고쳐 줘`의 단어 조각에 `login`이 더해진다.

### 새 프로젝트에서 시작하기

1. 사용자가 새 폴더에서 Saturn을 처음 실행한다.
2. `sessions`는 사용자 정본을 복사해 그 폴더의 프로젝트 카탈로그를 만든다.
3. 다른 프로젝트에서 확인된 짝이 첫 입력부터 쓰인다.

## 상세 설계

### 층

| 층 | 내용 | 시작 |
|---|---|---|
| 기본 사전 | Saturn에 들어 있는 개발 용어 짝 수십 개 | 릴리스에 포함 |
| 사용자 정본 | 이 사용자의 여러 프로젝트에서 확인된 짝 | 기본 사전을 복사 |
| 프로젝트 카탈로그 | 작업 폴더 하나에서 자라는 짝 | 사용자 정본을 복사 |

- 조회는 프로젝트 카탈로그를 쓴다. 같은 말도 프로젝트마다 가리키는 대상이 다르기 때문이다.
- 두 프로젝트 이상에서 확인된 짝은 사용자 정본으로 올린다. 한 프로젝트만의 고유 이름이 정본에 섞이지 않게 하기 위해서다.
- 프로젝트에서 거절된 짝은 그 프로젝트에서만 끈다. 정본을 지키면서 프로젝트마다 다른 뜻을 허용하기 위해서다.
- 사용자가 설정 `context.select.synonyms`에 적은 짝은 자동 짝보다 우선한다. 설정 층 규칙은 [설정](settings.md)에 있다.
- 카탈로그는 기록 저장소 안에 두고 engine만 쓴다. 지금은 서버와 통신하지 않는다.

### 짝 후보 캐기

`sessions`는 engine이 넘긴 기록(사용자 입력, 에이전트 답, 도구 호출 인자, 기록된 도구 결과)에서만 짝을 캔다. 파일을 새로 읽지 않아 `core`가 파일, 네트워크, 프로세스를 다루지 않기 위해서다.

| 출처 | 찾는 모양 | 증거 |
|---|---|---|
| 괄호 표기 | 같은 문장 안의 `한글(영문 식별자)`, `영문(한글)` | 찾을 때마다 1 |
| 같은 턴 함께 나옴 | 사용자 입력의 한글 조각과, 같은 턴에 에이전트가 건드린 파일 경로와 도구 인자의 영문 조각 | 턴마다 Dice 계수 `2 × 함께 나온 턴 ÷ (각자 나온 턴의 합)` |

```text
짝 점수 = 괄호 증거 × 3 + 함께 나옴 Dice
```

- `` `식별자` `` 바로 앞뒤의 한글 명사와 주석 아래 식별자는 캐지 않는다. Saturn 문서와 코드에서 두 규칙으로 캔 짝 후보의 정밀도가 각각 1.5%, 1.0%였기 때문이다([실험 결과](../experiments/term-catalog-precision/report.md)).
- 함께 나옴은 괄호 표기로 찾은 짝을 거드는 보조 증거다. Dice 최댓값 1은 기준 2.0보다 작아 함께 나옴만으로는 확인 대기에 오르지 못한다. 함께 나옴 후보의 정밀도가 0.5%였기 때문이다([실험 결과](../experiments/term-catalog-precision/report.md)).
- 가중치 3은 초안이다. 출처 사이 정밀도 차이를 가리지 못해 [#142](https://github.com/woonyong-choi/saturn/issues/142)에서 다시 잰다.
- 말 하나의 짝은 점수 상위 5개, 프로젝트 카탈로그 전체는 5,000개까지 두고 점수가 낮은 것부터 지운다(초안). 조회를 열쇠 하나의 색인 조회로 두기 위해서다.
- 오래 쓰이지 않은 짝은 점수를 서서히 낮춘다(초안).

### 출처별 가설

| 출처 | 가설 | 근거 | 확인 |
|---|---|---|---|
| 괄호 표기 | 에이전트와 개발 문서는 낯선 용어를 쓸 때 다른 언어 표기를 괄호나 코드 표시로 나란히 적는다. 한 문장 안에서 일부러 나란히 적은 두 말은 같은 대상을 가리킬 확률이 높다. 정밀도는 높고 재현율은 낮다고 본다. | 웹 문서의 괄호 번역 표기에서 번역어 짝을 대량으로 뽑은 연구(Lin, Zhao, Van Durme, Paşca, ACL 2008) | 기각. 코드 표시 앞뒤 모양 때문에 정밀도 1.5%였다([실험 결과](../experiments/term-catalog-precision/report.md)). |
| 같은 턴 함께 나옴 | 사용자가 한국어로 부른 대상을 에이전트는 같은 턴에 영문 식별자로 다룬다. 같은 작업 단위에서 반복해 함께 나오는 말은 같은 대상이고, Dice 계수는 어디서나 나오는 흔한 말을 낮게 매겨 우연한 짝을 거른다. | 함께 나옴 통계로 단어 연관을 재는 방법(Church & Hanks, Computational Linguistics 1990), Dice 계수로 두 언어의 연어 대응을 찾은 연구(Smadja, McKeown, Hatzivassiloglou, Computational Linguistics 1996) | 기각. 정밀도 0.5%였다([실험 결과](../experiments/term-catalog-precision/report.md)). |
| 주석 아래 식별자 | 코드 주석은 바로 아래 정의를 설명하므로 주석의 한글 명사와 정의 이름은 같은 대상이다. | 없음. 관찰에 기댄 가설 | 기각. 정밀도 1.0%여서 출처에서 뺐다([실험 결과](../experiments/term-catalog-precision/report.md)). |

### 짝 확인

1. 짝 점수가 기준(초안 2.0) 이상이고 증거가 3번 이상 쌓이면 `sessions`가 짝을 확인 대기에 올린다.
2. 트리 유휴가 되면 engine은 확인 대기 짝을 최대 20개씩 `term` 질문 세트로 묶어 judge에 묻는다. 질문은 `same_<n>`(`noul`) `이 프로젝트에서 두 말은 같은 대상을 가리킨다`이다.
3. 0.8 이상이면 확인, 0.3 미만이면 거절로 기록하고, 그 사이는 대기에 둔다.
4. 짝마다 한 번만 묻는다. 거절된 짝은 증거가 두 배가 되기 전까지 다시 묻지 않는다.

- 묶음 확인의 가설: judge는 state를 한 번 읽고 모든 질문에 답하고 비용은 입력 토큰에 비례한다. 짝을 유휴 때 묶어 보내면 요청 수와 공유 state 토큰이 줄어 비용이 줄고, 작업 중 호출이 몰리지 않는다. 짝 20개 묶음 요청의 입력은 글자 수로 추정한 중앙값 3,129토큰이다. 짝마다 한 요청보다 요청 수는 20분의 1이고 입력 토큰은 44.8% 적다([실험 결과](../experiments/term-catalog-precision/report.md)). 지연과 실제 토큰은 [#142](https://github.com/woonyong-choi/saturn/issues/142)에서 잰다.
- judge가 답하지 못하면 대기에 둔다. 확인되지 않은 짝은 단어 조각에 더하지 않는다. 틀린 짝이 순위를 흐리지 않게 하기 위해서다.

### 서버 동기화 대비

서버 기능이 생기면 카탈로그를 서버 정본과 동기화한다. 지금은 동기화하지 않고, 나중에 저장 형식을 바꾸지 않고 붙일 수 있게 다음을 미리 둔다.

1. engine이 주기적으로 로컬 카탈로그의 확인된 짝을 서버에 올린다.
2. 서버가 받은 짝으로 서버 정본을 갱신한다.
3. engine이 서버 정본을 받아 기존 카탈로그와 병합한다.
4. 병합된 상태에서 다시 1단계로 돌아간다.

| 미리 두는 것 | 이유 |
|---|---|
| 짝마다 정규화한 두 말로 만든 고정 열쇠 | 로컬과 서버가 같은 짝을 같은 열쇠로 가리키게 하기 위해서다 |
| 짝마다 층 표시(`builtin`, `user`, `project`, 나중의 `server`) | 병합할 때 어느 층에서 온 짝인지 가르기 위해서다 |
| 출처별 증거 수와 마지막 갱신 시각 | 서버와 로컬의 증거를 더하고 오래된 값을 가리기 위해서다 |
| 카탈로그 버전 번호 | 받은 정본이 이미 병합한 것인지 가리기 위해서다 |

- 병합에서도 사용자가 설정에 적은 짝과 프로젝트에서 거절된 짝을 서버 정본보다 우선한다. 사용자와 프로젝트의 판단을 서버가 덮지 않게 하기 위해서다.
- 서버로 올리는 것은 동의한 사용자의 짝만이다([결정 기록](../decisions/2026-09-29-local-first-judgment-collection.md)). 고유 이름을 거르는 규칙과 병합 규칙의 세부는 서버 기능을 설계할 때 정한다.

### 오류 처리

| 상황 | 동작 |
|---|---|
| 짝 확인 judge 무응답 | 짝을 대기에 두고 다음 유휴 때 다시 묻는다. |
| 프로젝트 카탈로그 상한 초과 | 점수가 가장 낮은 짝부터 지운다. |
| 사용자 설정 짝과 자동 짝 충돌 | 사용자 설정 짝을 쓴다. |
| 기록을 끈 채팅(`/record off`) | 그 채팅에서는 짝을 캐지 않는다. |

### 요구사항

| 요구사항 | 검증 계획 |
|---|---|
| 괄호 표기에서 짝 후보를 찾는다. | `로그인(login)`과 `login(로그인)`에서 같은 짝이 나오고, `` `login` 함수가 `` 문장에서는 짝이 나오지 않는지 확인한다. |
| 흔한 말의 Dice 계수는 짝보다 낮다. | 50턴에 나온 말과 10턴에 나온 짝의 Dice 계수를 비교한다. |
| 확인되지 않은 짝은 단어 조각에 더하지 않는다. | 대기 짝이 조각에 붙지 않는지 확인한다. |
| 짝 확인은 트리 유휴 때 최대 20개씩 묶어 보낸다. | 실행 중에는 `term` 요청이 없고 유휴 때 한 요청에 묶이는지 확인한다. |
| 두 프로젝트 이상에서 확인된 짝만 사용자 정본으로 올린다. | 한 프로젝트에서만 확인된 짝이 정본에 없는지 확인한다. |
| 짝마다 고정 열쇠, 층 표시, 출처별 증거 수, 마지막 갱신 시각을 저장하고 카탈로그에 버전 번호를 둔다. | 짝을 저장한 뒤 다섯 값이 모두 있는지 확인한다. |
| 세 출처의 짝 정밀도와 묶음 확인 비용이 가설과 맞는다. | [실험 결과](../experiments/term-catalog-precision/report.md) |

## 단점

- 출처별 가중치와 기준값을 실측으로 맞춰야 한다.
- 기록이 적은 새 프로젝트에서는 짝이 기본 사전과 사용자 정본에만 기댄다.
- Saturn 문서에서 괄호 번역 표기로 캔 짝은 6개뿐이라 괄호 표기의 재현율이 낮다.

## 대안

- 사용자가 대응표를 직접 채우는 방식은 쓰기 어렵고 채우지 않으면 동작하지 않아 버렸다.
- 임베딩 모델로 같은 뜻을 찾는 방식은 설치 크기, 상주 메모리, 계산 시간이 들고 이득이 실측 전이라 버렸다([결정 기록](../decisions/2026-10-01-lexical-ranking-with-term-catalog.md)).
- 주석 아래 식별자에서 짝을 캐는 방식은 주석 첫 단어가 정의 이름과 같은 대상을 가리키지 않아 버렸다([실험 결과](../experiments/term-catalog-precision/report.md)).
