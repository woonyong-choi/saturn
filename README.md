<h1 align="center">saturn-cli</h1>

<p align="center">Codex와 Claude Code를 하나의 대화로 이어 쓰는 터미널 도구</p>

## 풀려는 문제

코딩 에이전트를 여러 개 쓰다 보면 같은 불편이 반복됩니다.

- 에이전트를 바꾸면 맥락이 끊깁니다. 세션이 공급자마다 따로 있어서, 옮길 때마다 지금까지의 상황을 다시 설명해야 합니다.
- 대화가 길어지면 공급자가 알아서 맥락을 압축합니다. 언제, 무엇을 남기고 줄였는지 사용자는 알기 어렵습니다.
- 작업이 도는 중에 떠오른 요청을 어디에 넣을지 애매합니다. 지금 작업에 끼워 넣을지, 끝날 때까지 기다릴지, 새 작업으로 나눌지를 매번 사람이 정해야 합니다.
- 입력이 실제로 전달됐는지, 실행 중에 끊겼는지 남는 기록이 없습니다. 끊긴 뒤 다시 보내면 같은 작업이 두 번 실행될 수 있습니다.

## 접근 방식

- **먼저 기록하고 나중에 보냅니다.** 모든 입력은 로컬 SQLite에 접수된 뒤 에이전트로 갑니다. 전달 여부가 불확실하면 자동으로 다시 보내지 않고 사용자에게 확인합니다.
- **한 대화 안에서 에이전트를 바꿉니다.** 채팅 하나에 Codex와 Claude 세션이 차례로 붙을 수 있고, 넘길 때는 필요한 맥락만 골라 전달합니다.
- **판단은 작은 모델에 맡깁니다.** 새 입력이 하던 일을 이어 가는 것인지, 새 일인지, 어느 에이전트가 맞는지를 확률로 판단하고, 확신이 낮으면 안전한 쪽을 택합니다.
- **맥락 크기를 직접 잽니다.** 턴마다 크기를 기록하고, 정해 둔 기준에 가까워지면 정리한 뒤 새 세션으로 이어 갑니다.
- **판단 기록으로 판단 모델을 학습합니다.** 판단과 그 결과를 모아 로컬에서 도는 판단 모델을 만들고, 기존 판단과 나란히 비교한 뒤 더 나을 때만 바꿉니다.

## 구현 목표

- 입력 접수, 대기열, 취소, 멈춤, 보류, 이어서 하기를 기록 기반으로 처리
- Codex app-server와 Claude stream-json에 계속 연결해 실행 중 입력을 바로 반영
- 공급자와 모델이 바뀌어도 끊기지 않는 채팅 기록과 세션 이력
- 공급자별 맥락 측정, 압축 기준, 인수 패킷 기록
- 전체 화면 TUI와 입력창 아래 상태 줄, Saturn 명령과 공급자 명령을 함께 보여 주는 슬래시 메뉴
- 판단 모드 세 가지: 외부 판단 API, 나란히 비교, 로컬 판단 모델
- 사용자, 폴더, 채팅 단위로 겹쳐 적용되는 설정

## 계획

1. **저장소 기반**: 스키마 v9, 세션 세대, 설정 층, 기록 번호
2. **공급자 연결**: Codex app-server, Claude stream-json 상시 연결과 기존 단발 실행 대체
3. **판단 엔진**: 질문 정의와 버전, 호출 기록, 기준값 조정
4. **화면**: 전체 화면 TUI, 슬래시 메뉴, 작업 목록
5. **학습**: `/train`, 로컬 판단 모델, 버전 선택과 되돌리기

## 현재 상태

설계를 마치고 구현을 새로 시작하는 단계입니다. 아직 설치해서 쓸 수 있는 버전은 없습니다.

대상 환경은 macOS(Apple Silicon)이고, Codex CLI 또는 Claude Code가 설치되어 있어야 합니다.
